### continuation 判定的下一步核对

更正最初参数判读：`build_core_controller_config_with_layers` 的末尾 `None` 是 `additional_params`，覆盖层来自 `preparation.context_injection`；必须按被调用函数签名判断，不能按参数位置猜测。实际传输入口还会重建控制器并保留覆盖层。`build_public_continuation` 对未覆盖 `runtime-host:` 消息主动拒绝延续，需要继续确认该限制与最终编码、覆盖边界的关系；尚未证明安全前不直接删除保护条件。前缀稳定和服务端 continuation 复用是不同事实。

### bootstrap 与真实传输的顶部不一致

源码追踪：bootstrap 的 `system_preamble` 已是稳定文本，但其 `prompt_layers` 仍使用包含动态内容的完整装配层，影响初始控制器及请求快照。继续追踪发现实际流传输入口 `prepare_provider_transport_entry_inputs` 会用稳定 `system_preamble` 重新构造顶部，因此尚不能据此宣称真实网络请求已泄漏。现将 bootstrap 同样改为从稳定前导语构造顶部层，保持两个入口一致；动态候选和 V1 独立动态层继续保留。

实际 bootstrap 回归 `bootstrap_keeps_request_agent_instructions_out_of_top_layers` **1 项通过**。最终运行时生产编译 **0 错误、2 项既有警告**；三个修改的 Rust 文件格式及相关差异检查通过。所有验证已结束。此证据覆盖真实装配和控制器输入，不代替全部路由端到端、非 V1 历史恢复及实际供应商缓存验收。
