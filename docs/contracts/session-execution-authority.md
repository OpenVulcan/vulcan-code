# 会话载入与执行许可

## 归属

本契约约束服务启动恢复、历史会话读取、普通用户任务和显式继续之间的边界。修改启动恢复或提示准备入口时，应同步验证本文列出的回归。

## 规则

- 历史开放回合、持久运行标记和已经发布的业务钩子只证明历史归属，不能单独授权新的模型请求。
- 服务启动和打开普通历史会话不执行旧任务，包括此前失败、中断以及输入已保存但首个请求尚未发出的任务。
- 冷加载可将失去进程所有者的请求投影为中断；该投影必须先持久化再发布会话句柄，不能附带供应商调用。
- 用户点击继续，通过唯一继续动作标识、派发互斥及原请求的继续策略取得许可；禁止继续的错误不能被后台恢复绕过。
- 继续入口只采用最近业务 API 的持久终态。压缩与协作答疑终态不能授予或撤销业务继续许可；任何仍在执行的
  物理请求都保持排他。前端使用同一边界，避免把压缩中断误判为业务可继续，并将输入区的新消息错误改送 Continue。
- 用户发送新任务，在确认旧执行者不存在后，可原子收口遗留回合并接纳新输入；不能仅因缺少旧回合结束标记而永久拒绝。
- 当前进程内正常的用户队列、方向引导、目标续跑及协作消息，使用各自的明确来源和准入入口。不得用“扫描所有开放回合”补偿任何特定来源的唤醒遗漏。
- 协作启动恢复可以依据具体消息、问题或子执行的持久凭据，按既有契约恢复该项工作或补齐结果投递；这不授予任意普通历史主任务新的执行许可。仅修复子任务回执不需要创建主业务钩子或派发主任务。
- 目标模式的启动暂停与用户显式恢复沿用现有契约。

## 模型思考档位

- 用户显式选择思考档位时，服务按供应商 ID 与模型 ID 记忆选择。不同账号上的同一模型共用偏好，
  读取时以实际账号路线的能力为准。已有会话的设置仍在下一用户请求边界生效。
- 首次使用或切换模型时，从目标模型读取记忆档位。当前清单已移除该档位时，使用同一推理解析器给出的模型默认档位，
  不因该历史选择拒绝请求或改写用户设置。旧的跨模型记忆缺少模型归属，不迁移到任何模型。
- 已经准入的请求仍使用各自冻结的路线和档位。模型切换、草稿选择和工作台投影分别由
  `public_ai_settings/model_selection.rs`、`workbench_model_routes.rs` 和 `settings_provider_projection.rs` 持有。

## 子代理未结算时的新输入

- 普通用户提交同时读取 V1 文档的队列占用和当前开放回合的子任务完成义务。即使父级物理请求已经结束、
  运行时没有活动流或子代理镜像，只要该回合仍有 `reserved` 或 `active` 子任务，新消息就进入既有可见队列。
- 排队保留原父回合及精确子执行归属，用户仍可使用现有插队入口；不得通过删除
  `root_input.unsettled_execution_owner` 校验、关闭父回合或清除子任务义务来接纳新根输入。
- 已终结子任务和其他历史回合的子任务不单独阻塞当前提交；没有子任务义务的空闲遗留回合继续使用原子收口准入。
- 显式 Continue 不创建新根，仍按原业务终态判断资格；子任务义务不能单独使其返回 busy，已有队列和活动物理请求的排他检查保持不变。
- 插队不是 Continue。开放回合处于 `Stopped`、`MainOnly` 或 `MainAndSubagents` 时，V1 原子晋升拒绝新的插队，
  保留原排队消息、附件租约和动作身份；服务返回先继续会话的提示，不将消息显示为已成功插入。
  已经提交的插队回执仍可幂等重放，恢复运行后同一排队身份可正常晋升。等待者通知仅在可靠晋升后发送。

本节以 `conversation_submission/queue.rs` 为实现权威，回归见 `tests/conversation_submission_queue_tests.rs`
的 `idle_parent_submission_respects_durable_child_ownership`；不改变持久字段或自动恢复许可。
停止插队边界由 `document_tests/input.rs::guided_queued_input_rejects_stopped_turn_without_losing_message`
和 `webui_prompt_lifecycle/pending_dispatch.rs::tests::stopped_pending_insertion_preserves_queued_input` 约束。

## 同回合答疑与待发送投影

- `InTurnQuestion` 的执行记录属于原业务回合，直到该回合收口才结束；其 `running` 状态不单独证明仍有
  独占的辅助请求。恢复原业务 Hook 时，只允许与当前父回合一致且没有独立 `execution_turn_id` 的记录共存，
  不要求先答复才能继续处理同回合问题。活动物理 API、独立答疑回合、其他回合归属及停止控制仍阻止恢复。
- 上述判断只恢复已经发布的原 Hook，不创建首次业务身份、不结束问题记录、不丢弃未回答问题，
  也不替代服务层的精确来源校验与提交互斥。
- 待发送面板从 V1 输入状态重建。变更判定同时比较 process mirror 与已经发布的 workbench 投影，
  不能因为水合已经提前清空 mirror 就遗漏清除已消费的 `inserted` 行。
  retained workbench、revision 和客户端 delta 仍由原发送入口共同更新，只影响精确目标会话。

本节以 `business_hook.rs::business_hook_recovery_binding`、`pending_prompt_services.rs::rebuild_pending_prompt_panel_from_v1`
与 `pending_prompts.rs::emit_pending_prompts_changed_delta` 为实现权威；回归见
`internal_continuation_prepare/tests/questions.rs` 及 `pending_prompt_services::tests`。

## 最终回答后的插队批次交接

- 成功的主业务 API 返回正文且没有工具调用时，尚未消费的插队输入暂时保留在可靠输入状态中，
  交由逻辑回合结算决定归属。单次正文响应不能证明整个业务回合已经结束；工具循环中的插队继续沿用
  同回合续跑语义。
- 结算在同一文档写锁内检查子代理回流、协作续跑及仍在运行的子任务。若旧回合还要继续，先把全部待处理
  插队按原顺序投影为旧回合补充输入，并发布精确续跑回执；下一次请求同时读取协作内容和这些用户输入。
  子代理回流可以优先分发，但不能遗漏插队。普通排队保持原样，重复结算不能重复写入已提升输入。
  明确停止状态及辅助答疑回合不从插队取得新的执行许可。
- 确认逻辑回合结束后，结算在同一原子修改中关闭旧回合，并把当时全部未消费插队按原顺序写入一个新的用户回合。
  首条使用既有 `queued_scheduled` 来源开启回合，其余使用 `pending_in_turn` 来源加入首次请求；
  每条消息保留原始动作标识、输入标识、正文、附件及准备事实，批次使用最后一个已绑定的请求选择。
- 这批输入优先于普通排队，普通队列的成员与顺序保持原样，只有批次回合结束后才继续调度。
  派发入口从新回合的连续初始用户事件读取完整批次，准备提示覆盖全部正文，附件准备使用有序并集，
  最终供应商历史仍保留各条规范消息及其独立资源归属。
- 初始批次只包含调度首条和紧随其后的同回合补充输入。后续 `AgentMessage` 等其他来源结束批次；
  它们继续作为独立消息进入历史，不使已提交的批次失效，也不能把其后的输入追认为初始批次成员。
- 原排队处置回执的跨回合归属只在精确的已完成回合统计、新调度根及连续批次成员共同证明交接时接受；
  未证明的跨回合、重复身份、正文或附件漂移仍明确拒绝，不能靠关键词或邻近位置猜测归属。
- 在前驱最终回答处分叉时，后继批次不属于新分支。构建器先从完整来源验证精确交接，再仅在分支副本中
  把这些队列处置改为既有的 `removed` 终态并清除回合所有者，保留序号、动作、输入身份、正文和附件，
  修订审计版本。原会话不变；包含整个批次的分叉原样保留交接，二次分叉也不依赖已截断的父会话事件。
  缺失所有者或载荷不一致的普通历史仍报错，不因分叉而跳过严格校验。
- 普通会话可在后续请求仍运行时从已完成回合分叉。分叉以持久化的回合统计序号为边界，新分支空闲，来源继续运行。编辑重生成会替换原会话代次，仍要求活动请求结束。
- 服务层只有取得可靠回合闭合回执后才能完成旧业务 Hook。单次 API 或执行流结束不能自行清理仍开放
  回合的 Hook，也不能消费其记忆回合；新批次通过普通排队后继入口建立自身的 Hook 与预检。
- 上述转换复用现有事件和元数据字段，不改变持久形状。冷加载仅恢复已提交的归属，仍不自动执行普通
  历史任务；当前进程自动交接只消费本次明确的终态与后继回执，不扫描全部开放回合。

本节以 `vulcan-session-core/src/v1/document/input_handoff.rs`、`turns.rs`、`api.rs` 和服务层的
`session_runtime_registry_v1`、`provider_v1_sink`、`pending_prepare`、`execution_report_memory` 为权威。调整交接或批次选择时同步
`document_tests/input_handoff.rs`、供应商流终态与迟到插队回归。
批次边界及分叉审计同时由 `document_tests/input_handoff/boundaries.rs` 约束。
子代理回流、运行中子任务及停止边界同时由 `provider_v1_sink/tests/insertion_continuation.rs` 约束。

## 子代理连续执行与迟到回流

- 收件箱排队续跑在确认 `DelegateStarted` 的启动屏障之前建立自身的父侧持久预留。
  宿主按实时执行租约、精确根输入、父回合和代次验证归属，在一次父文档原子修改中结算旧执行并接纳后继，
  避免父回合在两次执行之间短暂失去完成约束。失败、停止与成功均使用该独立预留，不借用前驱执行标识。
  前驱未闭合、父回合替换、显式停止或来源漂移均拒绝交接，不能清除原始义务后跳过后继准入。
- 本次执行的可恢复配置可靠保存后才激活后继，之后才能发出供应商请求。冷启动发现该精确排队预留仍未捕获
  配置且已经没有运行时租约时，记录准备阶段进程退出的失败并释放义务，不沿用上一执行的配置或自动重放。
- 启动中止处理与排队准入使用相同的规范父子生命周期锁。即使准入等待器取消、后台写入仍在进行，
  中止消费者也必须等待写入退出后再判断预留是否存在；已接纳预留走可靠失败回流，未接纳的执行走精确启动清理。
- 同一子代理接着处理排队消息时，可以抑制中间的运行时完成通知，但不能以最后一条回复替代原始所属执行的完成回执。
  当前执行发布终态之前，宿主按父侧可靠预留、子会话身份和代次恢复先前执行的精确正文或非成功结果，再发布当前结果。
  恢复复用规范生命周期锁及原子回流／任务终态转换，不额外调用供应商。
- 历史后继回流可能把尚未返回的前驱区间包含在来源前缀里。该覆盖不表示前驱的最终正文已经投递。仅在所属执行身份、
  原父回合和真实成功终态均已验证，且前驱完整落在同任务后继的最终正文之前时，允许补回该原始结果。
  普通回流、交叉区间、复用根动作、不同任务及正文漂移仍拒绝；不能用后继正文替代原始结果或直接清除完成约束。
- 补回时保留既有事件、正文和来源区间。已发布结果的重试沿用其原始来源前沿，不能因为补回前驱而改变不可变回执。
  重复恢复及冷加载不得重复写入结果、释放其他子任务或自动执行历史主任务。
- 结果可靠发布后，若规范父回合已经关闭、被替换或明确停止，旧终态监听器只释放自身的精确重试归属，
  不再尝试旧父续跑，不把结果挂到新回合，也不把已完成子任务改成失败。父回合仍有执行许可时，准备错误
  继续保留重试；结果发布失败仍保留投递责任。异步准备期间的归属变化由原准入重验拒绝，下一次重试再收口。

本节以 `agent_stream/detached_subagent/queued_admission.rs`、`terminal.rs`、`agent_collaboration/startup_recovery/native_results.rs` 和
`vulcan-session-core/src/v1/document/subagent.rs` 为权威；调整时同步验证 `provider_v1_sink/tests/queued_child_returns.rs`
及 `provider_v1_sink/tests/terminal_return_owner.rs`、`document_tests/subagent/owned_returns/overlap.rs`。

## 手动压缩与尚未完成的业务回合

- 手动 `/compact` 只取得本次摘要请求的执行许可，不授予业务续跑。宿主先排除活动物理执行，
  再按与压缩规划同时捕获的规范来源校验；仅输入框草稿及其记账变化可忽略。
- 手动压缩从同一规范快照读取压缩历史与已保存的模型选择。待生效的供应商、连接或模型发生切换时，仅为本次摘要冻结新路由与采样配置。
  服务层在准备媒体前校验当前选择及摘要所有者，Core 在持久化 `ApiStarted` 时再次校验。摘要保留业务租约与待生效选择，
  下一次正常输入或继续动作仍按原边界应用选择。自动压缩沿用正在准备的业务请求路由。
- 压缩重试读取结束本次尝试的供应商错误类别。余额不足、鉴权拒绝、无效请求等确定性失败立即终止，
  界面摘要直接呈现供应商消息，展开错误卡保留请求诊断。
- 已结束的历史继续使用独立 `ContextMaintenance` 回合。物理空闲但业务仍开放时，手动压缩借用
  原回合的 `turn_id/start_seq/segment_generation`，不关闭、不替换、不重开原业务，也不改写其 Hook 和停止控制。
  活动 API、辅助回合、子会话、专职或归档会话、已有排队/插队输入，以及未结算子任务仍拒绝准入。
- 借用凭据仅存在内存，物理摘要仍以现有 `ApiStarted/ApiStats` 记录。节点发布在同一文档事务内
  校验借用归属与最终摘要 API；不是先写节点、后检查所有者。早期流错误只结算接收器持有的精确摘要 API。
- 摘要成功、准备失败、模型失败及后续 VMM 发布失败都不完成业务；已提交节点不会被后续错误伪称回滚。
  原业务 Continue 策略不受摘要终态改变，摘要不携带也不消费 Continue 动作。没有显式插入时，仍需明确继续原任务。
- 摘要期间新普通输入继续排队。用户点击插入时，活动手动压缩任务只记录对应队列身份，摘要请求的输入保持冻结。
  摘要与 VMM 投影均成功后，仍在队列中的所选消息按点击顺序自动分发，保留原正文、身份和附件。
  独立维护结束后开启新的业务回合，借用业务回合时在原回合续跑。未选中的普通队列顺序保持不变。
- 交接前失败、停止或进程重启时，消息保留在普通队列；已经移除或恢复到输入框的消息不再分发。
- 显式 Stop 仍是会话级停止；不因正在压缩而失效。普通用户业务的冷加载仅中断尚未结束的物理摘要请求，
  保留原业务回合和继续策略，不自动执行旧任务；目标或 Shell Job 自动续接回合仍遵守原有冷加载停止规则。
  独立维护回合仍沿用其原有冷加载结算。

权威入口为 `context_compaction/manual.rs`、`streaming.rs`、`completion.rs` 与
`vulcan-session-core/src/v1/document/child_execution/maintenance/manual/borrowed.rs`。
回归见核心 `tests/maintenance/manual/borrowed.rs` 和服务 `context_compaction/manual/tests.rs`、`tests/borrowed.rs`；
借用及待生效路由凭据仅存在于内存，沿用当前持久格式和元数据版本。

## 首个业务请求前的压缩检查

- 用户新输入、显式继续或重试进入请求准备阶段后，先检查本次请求预算及当前上下文已有的可靠实测用量。
  已知用量达到所选压缩窗口时，先执行压缩，再继续业务请求，不能为了刷新用量先发送一轮主模型请求。
- 历史实测读取完整持久化事件，包含冷加载后已不在常驻尾部的分段；用量必须由同一个 API 的起始与统计
  配对证明，且属于同一供应商、模型、协议、连接及尚未更换的上下文代次和保留前沿。
- 成功、失败、取消或中断的业务请求，只要存在可用输入或总量，都可以提供该观测。没有用量的失败不视为零，
  可继续查找同一上下文与路由内的上一条有效业务观测。不得跨越路由切换、历史编辑或已提交压缩复用更早用量。
  辅助摘要及答疑请求的用量不作为原业务上下文压力；压缩成功后，其之前的业务用量和摘要自身用量一并失效。
- 历史压力使用本次冻结的压缩策略，遵守自动压缩开关及前缀排除范围。它只是发送前的软压缩触发条件，
  不冒充本次请求精确 Token 数，也不放宽最终物理请求的指纹校准、硬窗口或 Continue 身份校验。

本节以 `context_compaction/auto_compaction.rs`、`context_compaction/budget/preflight.rs` 为实现权威；
修改时同步验证 `context_compaction/budget/preflight/tests.rs` 及最终 V1 准入的 `compaction_budget.rs` 回归。

## 会话图片预算与压缩

- 普通会话的首次请求和回合内后续请求共用物理准入检查。在自动压缩开启且会话基线匹配时，如果历史内联图片挤占了本轮待发图片的编码预算，并且移除历史图片后本轮图片可以准入，先完成压缩，再重建原业务请求。
- 宿主按会话冻结路由分批摘取历史图片。摘取请求只读取本批图片且禁用工具，最终摘要使用校验后的逐图记录。图片记录随本地摘要提交，压缩前沿以内的历史原图保留资源引用，待发图片由原业务请求完成首次投递。后续请求从同一条宿主续接消息读取已提交的图片记录。
- `compactions.json` 第二版包含图片记录与待发图片前沿。读取第一版时在发布锁内保留原字节并原子升级。该机制的入口是会话物理请求准备，独立多模态理解扩展使用自己的单次请求流程。

实现与回归入口为 `agent_stream/provider_v1_sink/media.rs`、`context_compaction/images.rs` 及 `workspace_store/session_v1/documents.rs`。

## 压缩后的请求续接

- 本地摘要提交后，由已发布的压缩节点派生一条宿主续接控制消息，固定在摘要 API 的终态边界之后。它采用隐藏用户角色进入模型请求，不作为真实用户输入、回合或 Continue 动作持久化，也不授予新的执行许可。
- 同一条控制消息用于压缩规划、控制器恢复和最终物理请求准备；因此不依赖动态上下文是否发生变化。读取、冷重载及重复投影不能额外写事件或不断追加控制消息。
- 后续用户输入、助手输出和协议切换通知保持在该固定边界之后。再次提交压缩时按新节点派生控制消息；旧节点的合成控制不会作为历史事件继续累积。
- VMM 锚点引用规范投影中的消息身份；投影插入或删除既有位置时，必须同时递增 `vulcan-vmm/src/context_epoch.rs` 的投影修订号。缓存纪元由该修订号、会话分片代次及压缩节点共同决定。旧纪元通过既有可靠对账流程撤销位置锚点、保留有效租约并重建活动基线；有真实用户输入时绑定其精确新身份，没有新用户输入时保持待绑定基线。不得按位置加减一猜测目标，也不得跳过最终锚点校验。
- 原生 Responses 不透明检查点保持其独立的路由约束，不附加本地摘要控制。跨协议请求仍由各自的精确编码器处理，不探测或降级协议。
- Continue 动作的消费与助手尾部恢复继续分开：辅助压缩请求不能消费待处理的 Continue 动作；业务请求消费后，后续请求不能再次携带该动作。请求指纹在准入前覆盖最终消息，幂等漂移校验保持严格。

上述规则以 `session_runtime_registry_v1/compaction_continuation.rs`、物理请求准备和领域 Continue 状态机为实现权威；调整压缩投影、提交边界或 Continue 交接时，同步验证 `provider_v1_sink/tests/compaction_continuation.rs`、`compaction_continuation/vmm_epoch.rs`、`compaction_budget.rs`、`remote_checkpoint.rs` 及 `session_runtime_registry_v1/tests/request_preparation/continuation.rs`。

## 会话时间线提示

- 宿主产生的显示提示由结构化记录类型决定展示方式。普通过程提示使用系统状态行，文字原样显示。记忆召回和上下文注入继续提供可展开详情，重试等既有提示使用其对应的状态组件。
- 请求失败按终态事实进入错误卡片，包含 Core 标记为警告的余额不足和网络断开。WebUI 的展示与回归入口为 `conversation-branch-presentation-v1.ts`、`conversation-transcript-parser.ts` 和 `conversation-branch-workspace-v1.test.tsx`。

## 快速清理历史

- 只有已经提交上下文压缩且空闲的普通会话可以清理。Core 从当前压缩节点的保留起点向前保护相交的完整回合，并验证活动重放检查点实际使用的分段窗口。仍有效的目标来源回合也受保护。
- 清理始终从最早尚未清理的完整旧回合开始，由用户选择最后纳入的回合。服务与 Core 共用候选回合规则。WebUI 的 `/clean-history` 和输入区加号菜单打开同一个弹窗，显示提示词开头和原始时间，默认选中最大可清理范围。旧版已清理的中段可跨过，已有独立条目和删除状态继续保留。
- 问答、追加输入、最终答复和图片／视频索引使用独立标识。素材索引引用项目资源，删除问答和删除索引分别生效。删除索引仅影响历史入口。
- 原事件流保留序号及恢复所需的回执和状态。清理移除已选旧回合的思考和工具载荷，原有压缩摘要和有依赖的协作回执继续用于恢复。清理可能使请求保留回合之前的旧重放信封失效，此时移除失效信封，保留受保护窗口的原始回合内容。
- 存储在同一个元数据提交中发布独立历史文件与改写的分段 bank。原有分段代次、稳定运行时身份和保留窗口不递增。再次打开仍通过常规加载器校验运行时。选中范围从原时间线隐藏，独立历史支持逐条删除与批删。
- 已清理的来源范围不再作为编辑或分叉入口。可执行的编辑及分叉目标必须能保留当前压缩节点。分叉在目录发布前复制独立历史，后续删除互不影响。
- 实现入口为 Core 的 `history_cleanup.rs`、工作区存储的 `session_v1/history_cleanup.rs`、服务的 `conversation_history_cleanup.rs` 与 WebUI 同名面板。调整保护或清理规则时应验证冷加载的完整请求投影、重放指纹、编辑和分叉。

## 持久化边界

本次修复没有改变持久字段或元数据版本。仅删除自动启动专用类型、方法与临时扫描字段；元数据中的开放回合指针仍用于历史重建和显式继续。不得为修复执行许可问题删除用户历史或改写原供应商错误。
