# 会话载入与执行许可

## 归属

本契约约束服务启动恢复、历史会话读取、普通用户任务和显式继续之间的边界。修改启动恢复或提示准备入口时，应同步验证本文列出的回归。

## 规则

- 历史开放回合、持久运行标记和已经发布的业务钩子只证明历史归属，不能单独授权新的模型请求。
- 服务启动和打开普通历史会话不执行旧任务，包括此前失败、中断以及输入已保存但首个请求尚未发出的任务。
- 冷加载可将失去进程所有者的请求投影为中断；该投影必须先持久化再发布会话句柄，不能附带供应商调用。
- 用户点击继续，通过唯一继续动作标识、派发互斥及原请求的继续策略取得许可；禁止继续的错误不能被后台恢复绕过。
- 继续入口只采用最近业务 API 的持久终态。压缩与协作答疑终态不能授予或撤销业务继续许可；任何仍在执行的
  物理请求都保持排他。前端使用同一边界，避免把压缩中断误判为业务可继续，并将输入区的新消息错误改送 Continue。
- 用户发送新任务，在确认旧执行者不存在后，可原子收口遗留回合并接纳新输入；不能仅因缺少旧回合结束标记而永久拒绝。
- 当前进程内正常的用户队列、方向引导、目标续跑及协作消息，使用各自的明确来源和准入入口。不得用“扫描所有开放回合”补偿任何特定来源的唤醒遗漏。
- 协作启动恢复可以依据具体消息、问题或子执行的持久凭据，按既有契约恢复该项工作或补齐结果投递；这不授予任意普通历史主任务新的执行许可。仅修复子任务回执不需要创建主业务钩子或派发主任务。
- 目标模式的启动暂停与用户显式恢复沿用现有契约。

## 最终回答后的插队批次交接

- 成功的主业务 API 返回正文且没有工具调用时，尚未消费的插队输入暂时保留在可靠输入状态中，
  交由逻辑回合结算决定归属。单次正文响应不能证明整个业务回合已经结束；工具循环中的插队继续沿用
  同回合续跑语义。
- 结算在同一文档写锁内检查子代理回流、协作续跑及仍在运行的子任务。若旧回合还要继续，先把全部待处理
  插队按原顺序投影为旧回合补充输入，并发布精确续跑回执；下一次请求同时读取协作内容和这些用户输入。
  子代理回流可以优先分发，但不能遗漏插队。普通排队保持原样，重复结算不能重复写入已提升输入。
  明确停止状态及辅助答疑回合不从插队取得新的执行许可。
- 确认逻辑回合结束后，结算在同一原子修改中关闭旧回合，并把当时全部未消费插队按原顺序写入一个新的用户回合。
  首条使用既有 `queued_scheduled` 来源开启回合，其余使用 `pending_in_turn` 来源加入首次请求；
  每条消息保留原始动作标识、输入标识、正文、附件及准备事实，批次使用最后一个已绑定的请求选择。
- 这批输入优先于普通排队，普通队列的成员与顺序保持原样，只有批次回合结束后才继续调度。
  派发入口从新回合的连续初始用户事件读取完整批次，准备提示覆盖全部正文，附件准备使用有序并集，
  最终供应商历史仍保留各条规范消息及其独立资源归属。
- 初始批次只包含调度首条和紧随其后的同回合补充输入。后续 `AgentMessage` 等其他来源结束批次；
  它们继续作为独立消息进入历史，不使已提交的批次失效，也不能把其后的输入追认为初始批次成员。
- 原排队处置回执的跨回合归属只在精确的已完成回合统计、新调度根及连续批次成员共同证明交接时接受；
  未证明的跨回合、重复身份、正文或附件漂移仍明确拒绝，不能靠关键词或邻近位置猜测归属。
- 在前驱最终回答处分叉时，后继批次不属于新分支。构建器先从完整来源验证精确交接，再仅在分支副本中
  把这些队列处置改为既有的 `removed` 终态并清除回合所有者，保留序号、动作、输入身份、正文和附件，
  修订审计版本。原会话不变；包含整个批次的分叉原样保留交接，二次分叉也不依赖已截断的父会话事件。
  缺失所有者或载荷不一致的普通历史仍报错，不因分叉而跳过严格校验。
- 服务层只有取得可靠回合闭合回执后才能完成旧业务 Hook。单次 API 或执行流结束不能自行清理仍开放
  回合的 Hook，也不能消费其记忆回合；新批次通过普通排队后继入口建立自身的 Hook 与预检。
- 上述转换复用现有事件和元数据字段，不改变持久形状。冷加载仅恢复已提交的归属，仍不自动执行普通
  历史任务；当前进程自动交接只消费本次明确的终态与后继回执，不扫描全部开放回合。

本节以 `vulcan-session-core/src/v1/document/input_handoff.rs`、`turns.rs`、`api.rs` 和服务层的
`session_runtime_registry_v1`、`provider_v1_sink`、`pending_prepare`、`execution_report_memory` 为权威。调整交接或批次选择时同步
`document_tests/input_handoff.rs`、供应商流终态与迟到插队回归。
批次边界及分叉审计同时由 `document_tests/input_handoff/boundaries.rs` 约束。
子代理回流、运行中子任务及停止边界同时由 `provider_v1_sink/tests/insertion_continuation.rs` 约束。

## 首个业务请求前的压缩检查

- 用户新输入、显式继续或重试进入请求准备阶段后，先检查本次请求预算及当前上下文已有的可靠实测用量。
  已知用量达到所选压缩窗口时，先执行压缩，再继续业务请求，不能为了刷新用量先发送一轮主模型请求。
- 历史实测读取完整持久化事件，包含冷加载后已不在常驻尾部的分段；用量必须由同一个 API 的起始与统计
  配对证明，且属于同一供应商、模型、协议、连接及尚未更换的上下文代次和保留前沿。
- 成功、失败、取消或中断的业务请求，只要存在可用输入或总量，都可以提供该观测。没有用量的失败不视为零，
  可继续查找同一上下文与路由内的上一条有效业务观测。不得跨越路由切换、历史编辑或已提交压缩复用更早用量。
  辅助摘要及答疑请求的用量不作为原业务上下文压力；压缩成功后，其之前的业务用量和摘要自身用量一并失效。
- 历史压力使用本次冻结的压缩策略，遵守自动压缩开关及前缀排除范围。它只是发送前的软压缩触发条件，
  不冒充本次请求精确 Token 数，也不放宽最终物理请求的指纹校准、硬窗口或 Continue 身份校验。

本节以 `context_compaction/auto_compaction.rs`、`context_compaction/budget/preflight.rs` 为实现权威；
修改时同步验证 `context_compaction/budget/preflight/tests.rs` 及最终 V1 准入的 `compaction_budget.rs` 回归。

## 压缩后的请求续接

- 本地摘要提交后，由已发布的压缩节点派生一条宿主续接控制消息，固定在摘要 API 的终态边界之后。它采用隐藏用户角色进入模型请求，不作为真实用户输入、回合或 Continue 动作持久化，也不授予新的执行许可。
- 同一条控制消息用于压缩规划、控制器恢复和最终物理请求准备；因此不依赖动态上下文是否发生变化。读取、冷重载及重复投影不能额外写事件或不断追加控制消息。
- 后续用户输入、助手输出和协议切换通知保持在该固定边界之后。再次提交压缩时按新节点派生控制消息；旧节点的合成控制不会作为历史事件继续累积。
- VMM 锚点引用规范投影中的消息身份；投影插入或删除既有位置时，必须同时递增 `vulcan-vmm/src/context_epoch.rs` 的投影修订号。缓存纪元由该修订号、会话分片代次及压缩节点共同决定。旧纪元通过既有可靠对账流程撤销位置锚点、保留有效租约并重建活动基线；有真实用户输入时绑定其精确新身份，没有新用户输入时保持待绑定基线。不得按位置加减一猜测目标，也不得跳过最终锚点校验。
- 原生 Responses 不透明检查点保持其独立的路由约束，不附加本地摘要控制。跨协议请求仍由各自的精确编码器处理，不探测或降级协议。
- Continue 动作的消费与助手尾部恢复继续分开：辅助压缩请求不能消费待处理的 Continue 动作；业务请求消费后，后续请求不能再次携带该动作。请求指纹在准入前覆盖最终消息，幂等漂移校验保持严格。

上述规则以 `session_runtime_registry_v1/compaction_continuation.rs`、物理请求准备和领域 Continue 状态机为实现权威；调整压缩投影、提交边界或 Continue 交接时，同步验证 `provider_v1_sink/tests/compaction_continuation.rs`、`compaction_continuation/vmm_epoch.rs`、`compaction_budget.rs`、`remote_checkpoint.rs` 及 `session_runtime_registry_v1/tests/request_preparation/continuation.rs`。

## 持久化边界

本次修复没有改变持久字段或元数据版本。仅删除自动启动专用类型、方法与临时扫描字段；元数据中的开放回合指针仍用于历史重建和显式继续。不得为修复执行许可问题删除用户历史或改写原供应商错误。
