# 插件容量策略的宿主持久事务

## 权威与范围

实现位于 `runtime/settings/policy.rs`、`runtime/formal/capacities/policy.rs` 及容量入场、清单要求、复用维护路径。
LuaSkills 的 `capacity_policy`／`revise_capacity` 是原生修订及资源计数的唯一权威；上游版本变化时须回读源码，
同步原子快照、前驱比较、忙碌及关闭语义。宿主只保留生效配置、事务证据和原生身份，不建立另一份 VM 账本。

当前管理接口只修订已登记的精确插件用途容量。父级总预算、插件聚合预算及执行超时继续冻结。
未登记容量可以通过下述可信管理入口建立；正式控制 RPC 与宿主插件页容量面板复用同一管理器，
自动排空推进和通用预热尚待接入。
独立进程后端不在此事务中实现。
这些是本地候选源码能力，不表示正式依赖、五平台验收或发布已完成。

## 显式管理接口

### 宿主管理界面

插件页的“插件 VM 容量”面板位于 `plugin-runtime-controls.tsx`，服务投影和校验位于
`plugin-runtime-service.ts`、`plugin-runtime-contract.ts`。面板初始折叠且不请求服务；
第一次展开只读取正式父级与目录，不登记容量、预热、写设置或推进事务。后续刷新由用户明确触发。
临时折叠保留草稿和未确认请求；离开页面不会取消宿主已接纳的工作。

用途采用宿主声明的六个精确变体。已安装 Lua 插件与目录中的保留所有者可供选择，后者不因卸载从视图消失。
当前完整配置来自真实容量；用途尚未登记时须明确登记后再编辑，浏览器不定义预算默认值。
公共／独立类型、五项数值和完整覆盖一起提交；恢复继承明确发送 `config: null`。
共享容量最小预留须为零，其他总预算与清单要求仍由宿主最终校验。
数字必须为非负安全整数；完整配置存在未知字段时拒绝进入编辑，避免覆盖时静默丢失上游字段。

草稿冻结原父级、原生容量、策略前驱、插件和用途。刷新与选择其他行均不改写草稿；
原容量关闭、退役、替换或策略变化后不得提交，用户须明确丢弃并重新编辑。
关闭、遗忘和继承重置先显示精确请求与影响说明，再由用户确认。
关闭应答不是物理排空证明，遗忘不删除持久预算，界面不得将两者投影为卸载或禁用插件。

全局保留事务独立于所选插件展示，包含完整原请求、阶段及持久化错误。
仅 `prepared` 可取消；`prepared`／`applied` 可明确恢复；终态须确认回执后才开始新策略事务。
查询、展开和刷新不自动恢复或确认。原生应用与磁盘持久化阶段的语义仍由下文事务协议拥有。

视图在刷新开始时同步撤销写入资格，拒绝旧读取覆盖新读取，并用同步互斥标志防止重复点击产生重复提交。
提交结果未知时保留完整原请求，只能明确重试同一请求或刷新核查；刷新不会自动丢弃它。
确认本地未知结果只停止当前视图追踪，绝不取消或回滚宿主工作，界面必须说明这一点。
服务包装不追加重试；共享传输层原有 HTTP 401 认证刷新可重发相同参数，不生成新请求身份。
成功修改后的读取失败只使观测失效，不把已确认修改重新归类为待重试。

父级和目录为独立 RPC 读取，父级身份不符时拒绝组合；同父级的计数不承诺全局同时采样。
策略修改后，用户通过既有 `service_refresh_luaskills_catalog` 明确重新发布插件业务目录；
此入口同时刷新插件目录和 Hook，不另建发布链。页面不将管理 API 注册进 PluginUiSdk。
插件 UI 与宿主仍共处浏览器执行环境，本面板不提供针对恶意插件 JavaScript 的独立安全沙箱。

浏览器夹具 `src/service/__fixtures__/plugin-runtime-wire.json` 来自真实管理 RPC 测试，
仅规范化每次运行的不透明身份，不改字段、数值或可空性。Rust 默认测试核对夹具，浏览器测试读取同一文件。
上游契约变化时先检查投影，再通过 `VULCAN_UPDATE_PLUGIN_WIRE_FIXTURE=1` 明确重新生成，并在不设标志时再次测试；
生成操作本身不算验证。隔离浏览器模拟服务验收与真实 Core 端到端验收须分别记录。

### 未登记用途与目录

`formal_capacities()` 只读返回当前父级的 `runtimeId`、不透明 `registryRevision` 及全部已登记用途。
未附加父级时返回空，不创建运行时。映射成员及其修订在同一宿主锁下读取，各用途的原生计数分别原子观测，
不能把这些计数相加后当作全运行时某一瞬间的原子快照。精确用途查询与目录行共用同一投影。

`register_formal_capacity(request)` 接受调用方新生成的 UUID `registrationId`、精确 `runtimeId`、
从目录读取的 `expectedRegistryRevision`，以及 `pluginId` 和 `purpose`。目标必须是具有合法 Lua 清单的
已安装插件，并且当前没有该用途的容量所有者。管理登记只使用当前完整用途策略，不执行 Lua、Hook、
业务初始化或 VM 预热，不写设置文件。当前策略不能满足业务要求时，仍允许管理登记供后续显式修复；
业务执行和目录可用性继续受完整要求校验约束，修复后需明确刷新目录。

每次真正插入或移除映射都会刷新注册表修订，包括业务懒登记、启用、补偿及退役；构造时预登记形成初始映射。
关闭保留原映射。原生容量策略修订是另一个令牌：它治理配置变化，不能替代映射前驱。
并发请求使用同一映射前驱时最多一个成功，其他请求必须重新观测后提交新的明确意图，不自动刷新重试。

成功的完整请求保留于原容量 `managementRequest`。原对象尚在时，精确重复提交只返回该对象当前状态，
包括已关闭状态，不新建身份；保留期间重复使用同一请求 UUID 携带不同参数会报冲突。
`capacity_registration_status(runtime_id, registration_id)` 无写入查询原登记；原对象被遗忘后返回空。
回执随容量释放，不保留无界历史，但原请求的映射前驱已经失效，不能在遗忘后重新创建对象或绑定另一对象。
调用方不得复用已确认释放的请求 UUID，新的管理意图必须分配新 UUID。重启后的精确父级不同，拒绝旧请求，
也不把原生瞬时登记写入持久设置；明确策略覆盖则仍由下面的事务持久保存。

新增用途的管理流程为：读取目录确认缺失 → 明确登记 → 用返回的精确原生容量及策略前驱提交策略事务。
登记本身不提供新权限；如果目标已经由正常业务或启动设置登记，直接使用已观测的原所有者进行策略修订。

### 精确关闭与遗忘

`control_formal_capacity(request)` 接受 `runtimeId`、`capacityId`、`expectedRevision`、
`pluginId`、`purpose` 和 `action`。动作仅为 `close` 或 `forget`，身份不可空或包含零字节。
在同一发布门及容量锁下完成精确父级、原容量和当前策略前驱校验，再调用原生操作，避免先查询再操作之间的替换窗口。
父级不符、容量已经替换或策略已修订均明确拒绝；不取新前驱重试，不让旧页面请求关闭新所有者。
已附加精确父级中映射缺失返回 `false`，表示未找到映射，不构成物理排空证据；未附加父级返回错误。

`close` 永久关闭入场并请求成员关闭，保留映射，可重复针对原对象执行；应答不表示已完成物理清理。
它可以用于关闭存在预备策略事务的原容量，但不会取消、推进或抹除该事务。
`forget` 要求无未完成策略事务、无宿主准备声明，并通过核心原生关闭及成员排空检查后才移除映射。
不会删除持久用途策略；后续业务或重启仍可能根据该策略登记新容量。
既有可信进程内的按插件／用途关闭及遗忘接口复用同一实现，但不暴露为远程无前驱管理入口。

### 控制服务线协议

全部方法复用已有 HTTP RPC 信封和来源／实例令牌准入，没有另一套运行时或管理状态。
解析发生在服务访问前，参数对象、请求内字段及动作严格校验；未知字段、遗漏身份或遗漏可空 `config` 均报错。

| RPC 方法 | 参数与结果 |
| --- | --- |
| `service_plugin_runtime_status` | 空参数；正式父级状态或空值 |
| `service_plugin_capacity_catalog` | 空参数；容量目录或空值 |
| `service_plugin_capacity_registration_status` | `runtimeId`、`registrationId`；原登记状态或空值 |
| `service_register_plugin_capacity` | `request` 为完整登记请求；返回原容量状态 |
| `service_control_plugin_capacity` | `request` 为精确控制请求；返回映射存在性 |
| `service_begin_plugin_capacity_policy_update` | `request` 为完整策略事务；返回保留检查点 |
| `service_plugin_capacity_policy_update_status` | `updateId`；返回原检查点或空值 |
| `service_resume_plugin_capacity_policy_update` | `updateId`；从原检查点明确恢复 |
| `service_cancel_plugin_capacity_policy_update` | `updateId`；明确取消尚未应用的原事务 |
| `service_forget_plugin_capacity_policy_update` | `updateId`；成功持久确认终态后返回空值 |

宿主包装沿用驼峰字段，内嵌 LuaSkills 类型沿用核心序列化结构，例如 `snapshot.capacity_id` 和
`config.max_queued_calls`；不猜测别名。核心类型更新时应同步消费契约，不能仅修改文档。
注册表及策略前驱均为不透明字符串。查询状态不触发目录发布；策略改变后由现有明确目录刷新流程重新发布业务可用性。

服务将同步锁及磁盘操作移到阻塞执行器，不在异步执行器上等待文件同步；服务状态锁仅用于克隆原管理器。
HTTP 观测者断线不撤销已进入工作者的操作，调用方必须保留原请求身份，使用查询接口确认结果，
不可将传输错误当作原生未执行而生成替代请求。未进入工作者前的取消不保证被接纳，应通过查询核实。
策略事务 UUID 持久保留，可以在重启后明确查询／恢复；原生登记回执只在原父级及原容量寿命内保留。

此权限边界是已认证宿主客户端。当前插件 UI 模块与宿主处在同一浏览器环境，不能宣称具有独立沙箱，
也不能把未向插件 UI SDK 暴露这些函数当作恶意界面脚本的隔离保障。Lua 原生能力表未增加管理权限。

### 已登记用途的策略事务

| 接口 | 行为 |
| --- | --- |
| `begin_capacity_policy_update(request)` | 校验当前目录和前驱，保留并推进一个原始事务 |
| `capacity_policy_update(update_id)` | 按调用方身份读取原回执，不写入、不推进 |
| `resume_capacity_policy_update(update_id)` | 从原检查点显式继续；原生成功之后仅补持久确认 |
| `cancel_capacity_policy_update(update_id)` | 仅取消未应用的预备事务；不回滚已确认原生变化 |
| `forget_capacity_policy_update(update_id)` | 仅在终态时持久确认并释放记录 |

请求由可信管理入口构造，不接受插件业务参数直接调用。调用方在提交前分配 UUID `updateId`，
并提供从状态查询取得的 `runtimeId`、`capacityId`、字符串 `expectedRevision`，
以及精确 `pluginId`、`purpose`。`config` 对象替换完整用途覆盖；空值明确移除覆盖，
重新使用当前冻结插件预算的公共、无预留默认策略。不逐字段合并，不把令牌转换为数值。

相同完整请求的重复提交只返回原回执，不推进、不重放。另一个请求必须等当前记录被明确确认；
记录数量始终最多一个。前驱过期、外来身份、关闭或当前清单要求冲突在接纳事务前明确拒绝。
目标下限、专用预留、聚合保证及有效数值继续由宿主完整配置校验和核心原生校验共同约束，不自动裁剪。

`formal_capacity_status` 的 `policyRevision`、`pendingConvergence` 与 `snapshot` 来自单个原生快照。
`formal_runtime_status` 在同一宿主锁下返回生效 `settings` 和 `policyUpdate`，可在管理页面刷新后发现原事务。
原生资源计数另行观察；持久提交不等于常驻缩容已收敛。

## 检查点与恢复

| 阶段 | 已证明的事实及下一步 |
| --- | --- |
| `prepared` | 原事务已在内存保留；先证明预备记录持久发布，再尝试原生修订 |
| `applied` | 原生修订成功，保留返回令牌及当前生效配置；恢复只补持久确认 |
| `committed` | 原生应用和持久设置替换均已确认，可显式释放管理回执 |
| `rejected` | 原生应用明确拒绝，或调用方在应用前明确取消；保持原生效配置 |
| `interrupted` | 原运行时已结束且未能证明持久完成；不将旧意图应用到新父级 |

`error` 保留原生忙碌、明确拒绝或中断诊断；`persistenceError` 单独表达文件发布或持久确认失败。
预备写入失败时不会调用核心，但若尚未成功落盘，不能承诺该内存回执在进程退出后仍可查询。
原生忙碌保留原目标和前驱，管理调用方待原准备／活动操作排空后显式恢复；不会自动取新令牌重试。
返回其他明确原生错误时记录拒绝。取消、等待者离开和关闭请求都不推断原业务副作用回滚。

未完成事务阻止对应用途的新成员准备、可复用域新借用及最终新业务提交，也阻止容量元数据被显式遗忘。
既有原生业务和固定会话保留原实例及状态；本阶段不会为完成缩容而强制终止它们。
持续向既有固定实例提交新工作可能延后执行额度缩减；当前管理面需要调用方协调并显式恢复，不承诺自动静默排空。

## 单一设置文件与磁盘边界

仍使用宿主状态根下唯一的 `plugin-runtime-settings.json`。新写入形状为版本四容器，
包含 `schemaVersion: 4`、完整版本三 `settings` 和可空的 `update`。
第一、二、三版继续按各自严格结构解码；历史字段仅按既有明确规则在内存迁移。
未知字段、重复字段、非法嵌套设置、未来版本和自相矛盾的事务检查点均拒绝，原字节保留。
可空的 `update`、请求 `config`、`appliedRevision` 和 `error` 必须明确出现；遗漏不得推断为确认、重置或证据删除。
`applied` 只存在于活动内存；磁盘最终设置必须与 `committed` 及其原生确认令牌同时发布。

一次事务先以旧已提交设置和预备记录写入，原生成功后更新活动内存，再一次替换为新设置及已提交回执。
因此原生成功而最终持久确认失败时，当前生效值可能已经变化，必须查看 `applied` 回执，
不能仅依磁盘旧值声称原生未执行。恢复不会再次调用原生修订。

实际操作系统排他租约使用独立稳定锁文件，由首次管理写入取得，并持有到原运行时宿主所有者结束。
另一个仍活跃的所有者不能恢复其事务；新运行时只有在取得该租约后，才能显式将旧父级预备记录确认为中断。
加载、状态查询和附加不取得写入租约、不改写配置；初始化前后设置发生变化则拒绝附加。
新运行时只加载磁盘已提交设置，不自动执行预备目标。

写入前比较原始完整文件字节，检测到独立外部编辑时返回冲突并保留外部内容。受管写入共用上述租约；
不遵守租约的外部编辑应在宿主停止后进行，字节比较不能提供对这类并发写入者的文件系统比较交换保证。
写入使用同目录暂存、文件同步、
原子替换及适用平台的目录同步。替换后的同步可能失败，因此保留原映像及自身精确候选映像；
恢复只接受这两个有证据的映像，不尝试未知路径、备用配置或按字段猜测合并。
读到此前已发布候选时先保留该映像，再尝试下一次替换，避免连续故障使自己的原字节丢失。
本地注入覆盖发布前失败与替换后确认失败；实际掉电耐久性及各平台文件系统行为仍须发行前验收。

## 执行修订与实例寿命

用途容量身份始终不变。全部新成员及清单要求使用同一活动用途配置；父级与插件聚合仍来自构造基线。
可复用域增加原生容量策略令牌，准备声明覆盖缓存选择和注册；未完成原准备不能被修订抢占。
策略变化后，新调用注册新的模块池和独立执行修订，不原地修改旧模块、权限或能力快照。
旧域停止新借用，原业务借用归还后才通过原关闭路径退役；原关闭失败及其确认归属继续保留。
明确父级／插件关闭仍按原关闭契约执行，不因策略事务忽略真实取消及清理。

固定会话和持久实例继续绑定原 VM。上调用途额度不自动扩大既有成员自己的不可变上限，
不自动分配或预热 VM。后续新实例按新额度注册；需要重建持久业务实例时应使用显式生命周期操作。
