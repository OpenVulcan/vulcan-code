# 服务诊断日志

## 归属与生命周期

Core 在取得数据根的服务实例锁后、启动服务线程前安装唯一 `tracing` 接收器。重复启动而未取得锁的进程不会打开或轮转日志。

日志位于**当前运行配置的权威数据根**下的 `logs/service.jsonl`。托盘的“打开日志”打开此目录。Debug、Release 和测试根仍遵循既有数据根规则，不在日志模块猜测用户目录。

每条记录是独立 JSON，包含时间、级别、模块目标和消息；调用方显式提供的字段也会保留。同步写入不依赖退出时排空异步队列，适用于既有 `process::exit` 路径；这不等于每条记录都执行磁盘 `fsync`，不承诺断电持久性。

## 留存与失败

单段上限为 8 MiB，保留活动段和 4 个归档段，日志总量上限约 40 MiB。上限的唯一源码定义位于 `apps/vulcan-code-service/src/logging.rs`。单条超大记录替换成明确的省略说明，避免破坏 JSON 或无限扩张。

安装接收器、打开目录或解析过滤器失败时，服务启动明确失败。运行期写入或轮转失败交给接收器的写入错误报告，不递归向同一日志写入。日志文件应视为诊断资料，可能含路径、会话标识与原始错误，不应直接公开上传。

接收器同时保留 stderr 输出。正式桌面壳即使丢弃 stderr，也有文件诊断。初始化前的命令行错误和实例锁竞争仍使用 stderr；`--describe` 保持原有 stdout JSON 协议，且不会为描述查询创建日志目录。

## 级别与调试

`vulcan_code_service`、`vulcan_service_kernel`、`vulcan_agent_runtime` 和 `vulcan_service_runtime` 默认记录 `info` 以上，其他目标默认 `warn` 以上；`RUST_LOG` 可显式指定过滤器。非法过滤器会拒绝启动，不静默替换配置。原有请求跟踪等显式诊断开关保持有效，安装接收器本身不会开启请求正文转储。

服务内核的生产代码禁止 `println!` / `eprintln!`（Clippy 门禁），使用 `tracing`；测试可输出测量结果。常规阶段信息使用 `info`，失败与异常使用 `warn` / `error`。其他 crate 的独立命令行与测试输出不属于此禁令。

已保存的排程回合在派发受阻时记录会话、回合、客户端动作标识及稳定原因。诊断不写入用户输入正文、附件内容或密钥。派发真正失败时，原回合保留可见诊断和原输入身份。

## 本机 Provider 请求追踪

Provider 请求追踪在捕获时把凭据请求头的值替换为 `{APIKEY}`。`Authorization` 保留已知的认证方式，例如 `Bearer {APIKEY}`。普通请求头、实际请求地址、请求正文和响应证据保留原有内容，存储层只替换调用方明确传入的精确凭据值。HTTP 发送失败的原因链在截断前替换其中回显的精确请求凭据，保留可供排障的地址和错误原因。

发送反馈时，附带的诊断内容通过反馈预览的外发过滤流程。相关规则见 [反馈](feedback.md)。

会话中的 HTTP 发送失败和响应头超时保留宿主解析的请求协议、主机和路径。URL 用户信息、查询串、片段及精确凭据值经过过滤，传输层提供的详情另行清理。
会话错误卡保留上游可读错误、普通链接和周围正文。宿主替换实际请求凭据的精确值，并根据解析出的 URL 用户信息和敏感查询参数就地替换携带凭据的地址。无可读错误字段的结构化响应以及技术诊断字段继续采用通用脱敏。

错误卡优先显示上游返回的错误码。未收到响应头时，使用宿主观测到的传输阶段作为错误码，例如 `response_headers_timeout`。

供应商重试设置以列表逐条添加、编辑和删除规则。编辑时选择关键词或正则表达式并查看对应样例，设置保存后应用。普通关键词匹配时忽略大小写，以 `regex:` 前缀存储的 Rust 正则默认区分大小写。规则匹配结构化错误消息、上游消息或错误码，继续受重试开关、次数、退避和终态判断约束。已登记的 HTTP 响应头截止时间到期时，即使分派结果未知，命中规则且尚无语义输出或已观测副作用也可同路由重试。

会话错误卡预览错误消息、供应商、模型及可用的错误码等信息。原始 JSON 默认隐藏，复制按钮始终复制当前错误的完整 JSON。使用重试分页时，复制和重试规则操作均对应当前页。

错误卡可以把当前错误加入重试列表。响应头超时会生成可匹配不同请求地址和超时时间的正则。服务在当前配置上追加并去重。

## 当前请求上下文

会话标题的「更多」菜单打开请求上下文。面板读取 Core 在实际传输分派时捕获的编码后上下文。HTTP 请求交给客户端发送、WebSocket 请求交给活动连接时更新。编码失败、凭据读取失败及未交给传输层的候选请求不替换当前快照。远端续接显示本次编码后的检查点引用和实际输入节点。

每个实时会话所有者只保留最新一次请求的有界预览，独立于磁盘请求追踪开关。面板打开时请求 `service_latest_request_context_v1`，请求未变更时只返回状态。Core 重启后需要一次新请求才有内容。预览不包含传输请求头，遮蔽精确请求凭据、结构化敏感字段和内联二进制内容，并显式标记达到显示上限的节点。

面板有实发记录时显示最近一次请求，模型、API 标识、用途、协议、时间与节点数放在标题下方。左侧按组装顺序列出语义节点，右侧提供 Markdown 和原始内容。初始系统提示词合并预览，来源由前缀生产者提供并与编码正文核对。编码将独立系统消息合成一个指令字段时保留段落分隔。工具定义在同一节点的独立标签页查看。带标签的注入正文以 Markdown 显示，信封标签与属性单列。Runtime 按受检请求的 API 标识附上已完成的可见助手正文，流式输出完成后也会更新。

没有实发记录时，面板自动使用 `service_simulate_request_context_v1` 组装，并在标题下标注「模拟组装」。组装解析当前项目、用户和内置基础提示词，使用与实发一致的固定指令渲染、项目规则注入、锁定前缀顺序、V1 历史投影和压缩续接。工具页复用发送前的本地宿主工具准入和 Schema，按当前发布的扩展代次解析，不占用模型路由租约或启动浏览器工具发现。模拟组装可以读取未加载的已有会话，无需准入 API 或发送请求。供应商专用编码、供应商原生工具和临时发现工具以实发请求为准。弹窗打开时继续观察实发记录，记录到达后自动更新。

工具调用与返回按请求中的真实顺序展示。工具名来自调用定义、精确调用标识或返回信封，预览显示调用参数与提供给模型的返回正文。对实际记录中可读的思考前缀，详情在对应回复或工具调用前展开；原始内容可核对当时的载荷。

工具定义展开后默认显示预览。参数按 Schema 的作用域列出类型、必填状态和约束，说明使用会话的 Markdown 渲染链路。组合关键字的分支分别显示，避免把某个备选分支的必填项当作全局必填。「原始内容」显示同一工具节点的原始有界载荷。

## 验证

```powershell
cargo test --locked -p vulcan-code-service logging::tests -- --test-threads=1
```

覆盖轮转与重新打开、JSON 完整性、超大记录，以及真实子进程丢弃 stderr 后仍保留启动错误和 panic、直接退出后日志仍可读。测试仅使用临时目录，不启动用户服务。
