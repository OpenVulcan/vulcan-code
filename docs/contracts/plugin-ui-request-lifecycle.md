# 插件界面请求生命周期

## 权威与适用范围

本契约对应插件清单、`vulcan-plugin-runtime`、服务 RPC 及 WebUI 查询协调器。字段形状以 Rust 类型和前端类型共同校验为准。修改任一边界时同步本文和对应测试。

LuaSkills 的目录隔离语义属于上游；当前正式依赖与核对入口见 [LuaSkills 接入指南](luaskills-skill-config-guide.md)。禁止修改注册表源码或生成目录替代正式升级。

## 清单策略

- 每个 Action 必须声明 `effect: read` 或 `effect: mutation`，不按名字猜测，也不保留旧清单自动分类。
- `result_cache_ms` 默认零，只允许读取声明正值；凭据明文与变更结果不得进入通用缓存。
- `snapshot_time_arguments` 只允许读取声明。宿主在一次实际调用中，把明确声明且值为 `null` 的顶层字段冻结为当前毫秒时间，然后执行原有输入 Schema 校验；显式历史时间保持原值。
- `timeout_ms` 是该 Action 从入场开始的唯一截止预算。队列、初始化、执行门、阻塞线程等待、Lua 与宿主调用消耗同一个预算。
- `max_active_sessions` 同时作为该插件可接受的活动和排队 Action 总数上限；满额立即返回错误，不建立无限队列。它不改变 Hook/UI 专用 VM 的既有隔离。

## 身份与生命周期

目录投影和模块源码都携带 `runtimeIdentity`，由服务实例随机标识和插件生命周期代次组成。目录身份用于触发模块缓存失效；新读取的认证模块身份是后续 Action 的权威身份，服务逐次校验。重连期间目录可能落后，不能拿旧目录身份拒绝新服务返回的合法模块。

模块读取先订阅启动事件，再读取权威启动快照，仅在完整运行时就绪后执行；启动失败明确返回错误。断连或插件退役取消旧模块的启动等待与读取，迟到模块不能发布。订阅在完成、失败或取消时释放，不重放业务变更。

初始化和排空以“插件标识、运行时用途”为键共用稳定同步门。注册表锁仅短暂查找和发布。初始化发布时在生命周期注册锁内再次校验启用状态和代次；失效结果关闭，关闭失败则保留身份供排空重试。删除记录比较实例身份，避免旧任务删除新对象。

初始化、Action、Hook 和排空均有独立监督所有者。调用方丢弃等待 Future 后，同步执行持有的 VM 门及临时租约仍由监督任务负责，直至实际返回与清理完成。

## 渲染器共享查询

同一个渲染进程内，以下字段共同形成查询键：

1. 服务与插件运行实例身份；
2. 插件、Action；
3. 宿主提供的工作区与会话身份；
4. 精确规范化 JSON 参数。

参数在等待前快照，不受调用方后续修改影响。不同结束时间、筛选、分页和局部投影不能共用结果。“截至现在”的 `null` 表达查询意图，同次在途请求只冻结一次；下一次主动刷新重新冻结时间。

普通导航只取消组件订阅。在途读取仍可被返回页面复用，成功后仅按清单策略保留。结果缓存总字节上限唯一位于 `plugin-ui-query-runtime.ts`；过期和超量结果被移除。无缓存许可、失败和失效结果不保留。

手动刷新复用已有同键在途请求；只有已完成缓存会被刷新取代。变更不去重、不自动重试，提交后即使卸载也继续执行。新读取等待同运行实例已提交的变更返回，避免写入事件提前触发刷新。旧服务未结束的变更不阻塞新实例。

停用、卸载、模块更新、服务重连和相关配置事件使旧查询失效。迟到结果不得重新填入新修订缓存。当前没有跨窗口去重；多个窗口由后端执行互斥和容量限制保护。

## 取消与状态查询

SDK 的 `invoke(action, arguments, { refresh, signal })` 中，`signal` 表示筛选已被替代，区别于组件卸载：

- 尚未发出的零订阅读取直接丢弃。
- 已发出的旧筛选等最后一个订阅者离开后，从查询表先移除，再撤回后端执行准入；新挂载不能加入已经撤回的条目。
- 后端仅在读取尚未进入执行时接受撤回；开始执行后继续有界完成，不能声称同步原生代码已被立即中止。
- 变更不接受筛选撤回。暂停 HTTP 等待不等于回滚或提交失败。

宿主为每次调用生成不可复用的调用 UUID 和渲染器随机 UUID。`service_plugin_action_status` 校验调用、客户端、插件与运行实例归属；不通过插件参数授权取消。

注册前状态为 `null`，也可能表示记录已过期。取消请求与原始请求竞速时，只轮询这条状态记录，直到找到记录或原始调用返回；不会重发 Action。网络错误不能被当作已取消。轮询间隔唯一位于宿主服务客户端。已完成状态最多保留 128 条，并有有限保留期；记录不可用意味着结果未知。

调用错误携带调用 ID 和状态查询能力。界面可知道实际执行是否结束；状态接口不返回业务结果、SQL、参数、密钥或原始异常。变更超时不得自动重放。

## 截止时间与真实资源归还

- Lua 指令钩子使用剩余预算。
- 受管外部进程使用 Action 剩余预算和命令自身上限的较小值；进程树管理由 LuaSkills 负责。
- 系统统计和插件私有 SQLite 的排队、忙等待与 SQL 执行使用宿主截止时间。每次连接有自己的中断句柄；中断只针对该连接。必须等待阻塞任务和连接清理真实结束，才归还数据库门。
- 已提交写入保留实际结果，不能仅因最后返回时间稍晚就声称提交失败。
- 数据库连接初始化、文件系统或不可中断的原生库调用仍可能超过等待方的截止时间；监督所有者继续持有资源。不能将截止预算解释为对任何原生调用的强制终止保证。
- LanceDB 和任意同步原生函数不具备本次新增的 SQLite 中断能力；其已开始操作继续归属于当前执行，直至真实完成。

## 诊断口径

每次调用记录初始化等待、初始化、执行门等待、执行、清理与终态；另记录阻塞队列、引擎锁、引擎操作和同步宿主回调耗时。

这些区间存在包含关系，例如引擎操作包含同步数据库回调和受管子进程等待，不能相加作为总耗时。子进程的具体命令正文、SQL 和结果均不保存；当前未提供每个子进程内部阶段的细分计时。

终态区分成功、失败、执行前取消、超时和监督异常。`deadlineExceeded` 不代表底层已停止；`terminal` 才表示该监督执行已返回。清理失败的原始租约另外保留在排空注册表，禁止静默遗失。

## 三个内置插件

- RTK 基础设置只读取设置；进入统计区域后才执行统计，统计有效期只在清单声明。
- Context7 保持单次初始化投影，不做隐式联网测试。
- 使用统计按当前区域、精确时间范围和分页读取，筛选替换撤回旧订阅；价格写入成功后刷新当前页面范围。

## 验证入口

- `runtime/persistent/tests.rs`：跨插件同步阻塞隔离、同 VM 独占、取消等待、初始化退役、新代次共用单个租约、变更持续执行。
- `local_sql.rs`：真实长 SQL 截止中断后下一次查询仍可执行。
- `plugin-ui-query-runtime.test.ts`：十次导航去重、筛选撤回、失效、刷新、写入屏障与新服务隔离。
- 三个插件的 `ui/index.test.mjs`：实际插件组件与宿主查询协调器集成。
- `plugin_storage_runtime_tests.rs`：真实内置插件、原生依赖、隔离 SQLite 的空数据、百条和十万条测量；通过环境变量显式指定只读原生包来源。
