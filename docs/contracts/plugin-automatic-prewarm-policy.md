# 自动预热策略事务

## 归属与交付边界

当前实现的权威为 `vulcan-plugin-runtime/src/runtime/settings/prewarm.rs`、
`settings/policy/prewarm.rs`、`formal/capacities/prewarm_policy.rs` 及
`vulcan-service-kernel/src/rpc_dispatch/plugin_runtime/prewarm_policy.rs`。
这些类型或发布逻辑变化时必须同步本文及浏览器契约测试。LuaSkills 的原生池能力仍以上游源码与生成契约为准。

本阶段提供设置持久化、精确回执管理、已认证宿主 RPC、浏览器服务适配与策略设置界面。
运行时另提供可信自动来源登记及逐次初始化策略校验，管理端可观测和取消原自动目标。
**自动生命周期触发尚未接入**。保存规则不执行 Lua、不准备调用、不分配 VM，
也不重放历史预热请求；不能把策略发布成功解释为已完成自动预热。
已有手动预热仍使用[原目标及回执](plugin-execution-engine.md#有界预热目标与保留回执)。

## 设置与迁移

唯一设置文件仍为宿主状态根下的 `plugin-runtime-settings.json`。
裸设置第五版增加 `automaticPrewarm`，默认空集合，包含精确的 `pluginId`、`toolId`、`targetIdle`。
空集合关闭策略；单条目标必须为正整数。插件与工具使用目录现有标识规则，工具身份全局唯一。
规则数量引用现有父级／插件注册池数，所有者数量引用父级注册插件数，目标值使用普通工具同一
`capacity_budget(plugin, ToolCall)` 上限，不另设一份容量默认值。

规则属于持久期望声明，允许暂时未安装、停用或更新中的工具保留其配置。
后续实际触发须校验工具存在、启用、可复用、当前代次、清单资源限制、会话授权工作区及初始化能力；
不得因为设置能被读取就跳过执行入场，也不能把持久规则视为永久最小常驻或循环补齐要求。
容量修订同样校验完整候选设置，不允许留下超过新上限的规则。

第四版根已经是容量事务容器，所以裸设置跳到第五版，受管容器使用第六版。
第六版包含完整第五版 `settings`，以及必须明确出现、允许空值的 `update` 与 `prewarmUpdate`；
两个回执不允许同时非空。原第一至第三版裸设置及第四版容器均直接从原字节按其严格历史结构解码；
第四版嵌套设置必须为第三版。重复字段、未知字段、未来版本及相互矛盾的回执被拒绝。
迁移只在内存执行，不创建缺失文件或改写用户原字节。

## 身份与发布状态

新请求包含调用方生成的 UUID `updateId`、精确 `runtimeId`、已观测 `expectedRevision` 和完整 `rules`。
同一保留请求再次提交只返回原回执；不同请求必须等待该回执明确确认。
修订在父级附加及确认提交时签发，不能用旧进程修订修改新父级。容量事务回执尚保留时，
即使其已提交，也必须先在容量管理中处理，才能开始预热策略更新。

| 阶段 | 含义及可用动作 |
| --- | --- |
| `prepared` | 准备发布待确认或已确认；可明确恢复或取消，尚未尝试最终设置发布 |
| `publishing` | 仅活动内存；最终文件可能已替换，但确认未返回，须恢复原发布，不能取消或遗忘 |
| `committed` | 最终设置与回执持久确认后，才更新当前生效规则及修订 |
| `cancelled` | 原准备请求已明确取消；不改变生效规则 |
| `interrupted` | 恢复时原父级已结束，准备意图保留为中断，不重放至新父级 |

回执保留原 `request`、一次冻结的 `resultRevision`、必需可空的 `error`。
仅活动内存可携带 `persistenceError`；不确定检查点绝不能作为已确认磁盘事实写入。
状态一次性返回当前父级、活动修订、活动规则、原回执及 `capacityUpdateRetained`，历史回执可以属于旧父级。
单独查询不取得写入租约，也不推进状态。

发布共用容量事务的操作系统排他租约、原始字节比较、同目录暂存与原子替换，不另建写入器。
先持久准备意图，再发布完整新设置与已提交回执；只有最终确认后才激活内存规则。
最终替换后确认失败仍保留 `publishing`，恢复不能退回准备阶段而把已发布新文件改回旧策略。
新的进程只加载磁盘已提交规则，保留原回执并签发自己的活动修订。
对旧已提交回执恢复仅确认其证据，不能把新进程修订改成旧令牌。

终态且没有发布不确定性时才允许精确遗忘回执。遗忘只删除事务证据，保留规则，
不取消任何已存在的执行目标。遗忘确认失败继续保留原回执，明确重试仍通过同一文件映像检查。
未遵守锁文件的外部编辑应在宿主停止时执行；字节比较不承诺对任意外部写入者提供原子比较交换。

## 管理协议

| 方法 | 参数及结果 |
| --- | --- |
| `service_plugin_prewarm_policy_status` | 空具名对象；返回当前策略及保留回执 |
| `service_begin_plugin_prewarm_policy_update` | `request` 包含完整原请求；返回原发布回执 |
| `service_resume_plugin_prewarm_policy_update` | 原 `updateId`；仅恢复原发布或确认 |
| `service_cancel_plugin_prewarm_policy_update` | 原 `updateId`；准备可取消，终态返回原证据，发布不确定时拒绝 |
| `service_forget_plugin_prewarm_policy_update` | 原 `updateId`；明确确认终态回执，成功返回空值 |

未知字段、位置数组、缺失或空值规则均拒绝；嵌套规则也必须为具名对象。
此协议属于已认证宿主管理面，不能从插件业务 Action 调用。阻塞文件操作使用服务既有阻塞执行器，
HTTP 等待者断线不撤销已接纳写入；未知结果必须先读取并处理原 UUID。
浏览器服务适配逐项核对完整原请求，只发送声明字段，不在传输失败后自动改换修订或重提初始化。

## 策略设置界面

插件页的 `PluginPrewarmPolicyControls` 初始折叠，挂载及展开均不提交请求；读取需明确操作。
`usePluginPrewarmPolicy` 拥有视图观测及原待核查请求，持久事务仍由宿主设置权威拥有。
这两个入口、原服务解码或线协议变化时，应同步本节及真实线协议夹具消费测试。

界面显示已确认生效规则与精确运行时／策略修订。开始编辑时复制当前规则，并冻结原前驱。
编辑采用完整替换，规则标识不猜测别名，目标要求明确正安全整数；空集合明确表示关闭自动预热。
工具标识不能重复；清单与容量限制继续由宿主唯一解析器验证。刷新只更新观测，不覆盖草稿，
也不能将旧草稿自动绑定到新修订。父级或修订变化后，需要用户明确从当前规则重新开始编辑。

每次写入前同步撤销视图操作资格，避免同一时刻重复点击。传输失败保留复制后的原请求及 UUID，
不自动重试，不因编辑器后续变化改写原意图。成功读取后才允许确认本页未知提示；该确认只结束
本地追踪，不取消或回滚宿主工作。折叠保留追踪，卸载后迟到响应不能写入新的观测者。
写入已经确认而后续读取失败时，独立展示已确认回执，维持陈旧状态，不能据此再次提交。

容量事务保留时禁止新预热策略；原策略事务按精确请求恢复／取消／确认，不改绑重启后的父级。
`publishing` 仅允许恢复原发布，`prepared` 可取消；仅没有持久化不确定性的终态可明确遗忘。
保存、恢复和遗忘策略都不启动插件初始化；执行目标仍由其独立原回执管理。

## 自动来源与原目标

`formal/calls/prewarm/automatic.rs` 是自动来源登记的权威；`prewarm/target.rs` 与
`formal/capacities/prewarm_policy.rs` 共同负责每次实际初始化前的策略校验。
上述实现变化时须同步本节、服务回执投影及浏览器解码测试。

可信宿主提交 `triggerId` 与已确认 `policyRevision`，来源和原目标共同计入现有调用输入预算。
首次登记必须匹配当前策略中精确插件、工具及目标；未提交候选、旧修订和更大目标都不能授权初始化。
来源登记本身不执行 Lua，宿主仍须先验证会话生命周期及工作区归属。

同一父级内，原控制器、来源（触发身份及策略修订）和工具共同选择原回执。
发布门及调用表锁保证并发首次登记只生成一个原调用；重复请求必须完整相同，不能更改目标、
工作区或包代次，也不能重签截止时间。保留回执的查询先于当前目录解析，因此包变化后仍能读取原证据。
显式遗忘会结束运行时的去重寿命；后续服务触发必须保留自己的生命周期一次性准入，不能借遗忘重放。

每次追加初始化及确认目标满足前，都在同一发布门内核对原策略修订和精确规则。
策略变化终止后续补起；已经进入原生初始化的工作保留其原操作、预算和清理归属，直到实际结束。
不把停止等待视为原生工作已经释放，也不因失败生成替代初始化。

回执的可选 `automatic` 字段原样投影来源；手动回执省略该字段，原线协议夹具保持不变。
手动准备 RPC 不接受自动来源，手动启动 RPC 拒绝自动回执；浏览器保留查询、取消、清理及遗忘入口，
禁用其手动启动。运行时可信接口尚不能替代服务层的会话触发和停止传播。

## 本地验证入口

- 设置测试覆盖旧裸设置／容器的内存迁移、重复字段、静态规则边界及缺失字段。
- 实际文件故障测试覆盖准备／最终发布前后故障、原映像恢复、外部编辑、独占写入、重启及原父级禁止重放。
- 真实管理器验证两类回执互斥、旧修订拒绝、发布期间零 VM 分配及容量原生身份保持。
- 真实自动目标验证并发首次登记、原截止时间保持、来源预算、旧策略拒绝，以及阻塞初始化期间
  撤销策略后不追加第二个实例；普通业务继续使用同一已经完成初始化的池域。
- 真实服务验证自动来源跨 RPC 保留、手动启动拒绝及原取消；浏览器验证来源解码与按钮权限。
- 设置界面与状态钩子覆盖空规则关闭、完整规则保存、重复工具与无效数量、草稿前驱变化、
  容量互斥、原准备取消、发布恢复与终态确认、未知结果跨折叠、确认写入后的读取失败及卸载迟到响应。
- 真实服务测试经顶层 RPC 验证严格参数及原回执；浏览器使用其生成的完整响应夹具。
  只有明确设置 `VULCAN_UPDATE_PLUGIN_PREWARM_POLICY_WIRE_FIXTURE=1` 时允许生成，
  随后的测试必须关闭该标志并作完整比较。容量原夹具使用原 `VULCAN_UPDATE_PLUGIN_WIRE_FIXTURE` 标志。

这些验证不替代自动触发、真实浏览器联调、多平台掉电耐久性、长稳或正式发布验收。
