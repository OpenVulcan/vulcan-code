# 插件不可变代次存储

## 归属与当前接入状态

存储权威实现为 `crates/vulcan-plugin-runtime/src/generation_store.rs` 及其子模块；目录接入实现为
`catalog/generations.rs` 与 `runtime/lifecycle.rs`。生产公开目录入口已经消费既有受管激活记录，
快照保留实际代次租约，宿主路由代次随物理身份及激活修订变化。
第二版激活记录已把包选择与完整权限批准放入同一次原子替换，运行时消费同一选定授权。
Service 的安装／更新流程尚未切换为不可变事务；跨 VM、会话与外部进程的引用传递仍未完整接入。
不能据此宣称完整插件更新事务、凭据共同提交、外部副作用补偿或整条运行时路由发布已经完成。

## 存储身份与目录

`VulcanPluginGenerationStore::open` 接受已经存在的用户插件根目录，并在其下显式创建私有
`.vulcan-generations/`。调用不会修改用户配置、授权文件或现有插件包。

```text
.vulcan-generations/
  active/<插件标识>.json
  locks/<插件标识>.lock
  locks/<插件标识>-<代次 UUID>.lease
  packages/<插件标识>/<代次 UUID>/
    generation.json
    <插件标识>/...
```

代次身份包含插件标识、规范 UUID、已校验版本和完整内容指纹。路径完全由固定布局及已校验身份派生，
记录不提供任意磁盘目标。包指纹和清单校验复用当前目录加载器的实现。
代次及旧激活格式由 `RECORD_VERSION` 决定，已授权激活格式由 `AUTHORIZED_ACTIVATION_VERSION` 决定；
两种记录共同复用 `MAX_RECORD_BYTES` 字节上限。未知版本、未知字段、
身份不匹配、重定向路径、缺失记录及超限记录明确拒绝。

## 目录选择与授权投影

`open_existing` 只接受既有完整存储；缺失返回空，不创建目录，也不补齐损坏布局。
普通目录刷新不安装新存储、不迁移旧平铺包、不改写授权或配置。
`activation_plugin_ids` 枚举规范 `.json` 激活名称，包含停用记录；原子写入器的 `.tmp` 暂存文件不提供选择权威。
该枚举不是跨插件的原子快照。加载器对枚举身份及旧包身份逐个调用 `pin_active`，在每个插件的选择锁内取得其实际租约。
查询已枚举身份时记录消失会明确报错，不解释为允许旧包接管。

存在受管记录时，以该记录为唯一用户包选择。显式空选择会隐藏同名旧目录；记录损坏、所选包缺失、内容变化或命名空间忙碌时，
该插件显示不可用并保留诊断，不加载同名旧包。无法读取完整布局或枚举全部身份时，阻止用户包暴露并保留根级诊断；内置包独立加载。
内置同名包仍优先于用户包。工具名冲突只在受管选择及内置优先级全部确定后检查，隐藏旧包不得占用工具名。

`VulcanPluginDescriptor::managed_package()` 返回持久激活修订及实际代次句柄。
完整快照或描述符克隆仍存活时，旧代次不能被回收；仅复制工具、技能、进程配置或路径不等于保留此所有权，
后续运行资源必须显式传递代次句柄。当前测试只证明目录／描述符层引用，不能代替 VM 或外部进程层验收。

第一版受管选择及旧平铺包沿用独立授权记录的精确插件、版本、内容指纹及完整权限比较；
第二版选择以同一激活记录中的完整批准为唯一权威，不读取或修补旧授权文件。
相同版本但字节变化必须重新确认精确包及权限。新增持久激活修订或物理 UUID 会推进进程内路由代次；
插件从目录消失后重新出现也不得复用旧路由代次，计数耗尽明确报错。
旧安装入口在开始复制前拒绝已观察到的受管激活或停用记录，避免报告成功却写入隐藏平铺包。
这项检查不是跨进程安装事务；完整管理流程仍须通过同一事务与选择屏障串联准备、授权、发布及恢复。

## 准备与实际引用

`prepare` 先对照用户已经检查的内容指纹，分配新代次及实际共享租约，保存准备身份，再复制文件、同步并复核完整内容。
只有全部成功才写入已准备状态并返回 `PinnedVulcanPluginGeneration`。失败不发布激活记录，保留诊断材料；
完成代次目录分配后发生的准备失败还返回 `retained_generation`，宿主可按精确身份查询或安排清理，不能解析诊断文本猜测路径。
如果第一份身份记录本身写入失败，后续清理仍须先验证实际记录，不以错误中的身份替代磁盘证据。

固定句柄的克隆共享真实租约，最后一个克隆被释放才结束该租约。使用 `package_root()` 对应文件期间必须保留固定句柄，
不能把复制出的路径字符串当成资源所有权。`pin_active` 在释放插件选择锁之前取得选定代次租约，封闭查询与回收之间的竞态。

锁使用标准库的非阻塞文件锁：同一插件的选择及阶段读取使用共享命名空间锁，选择变更及回收使用排他命名空间锁；
实际代次引用使用共享代次锁，回收另要求排他代次锁。并行目录读取可以共存，不会仅因另一个读取者而把插件投影为不可用。
这些约束覆盖遵守同一协议的线程和进程，不充当对非协作文件系统修改者的安全沙箱；锁文件不会在回收时删除，避免后继所有者锁住另一个文件对象。
标准库契约见 [Rust 文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock) 和
[共享文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock_shared)。

## 激活修订与边界

从未发布的命名空间观察为修订零。`activate` 和 `deactivate` 只接受精确当前修订，在同一插件的文件锁内写入后继记录。
停用保留记录及修订，不删除记录后重新使用零；修订耗尽明确拒绝。多个存储实例竞争同一前驱只能有一个成功，其他实例收到忙碌或修订冲突。

`generation` 是必需但可为空的字段：空值表示明确停用，字段缺失表示损坏，不能等同处理。
激活记录的原子写入错误不保证变更未发生，宿主必须回读精确记录后再决定如何继续，不能重放生命周期或业务回调。

### 包选择与权限共同发布

`activate_authorized` 接受实际固定代次、精确前驱修订及明确批准的完整权限集合。
权限键来自与授权预览共用的清单映射；发布前在同一命名空间锁内重新验证包字节，并要求权限完整且不重复。
调用方输入顺序可不同，存储使用清单派生的规范顺序。准备包本身不会批准权限。

该入口写入第二版激活记录，`approved_permissions` 是必需、非空值的列表；空列表只批准真实零权限包。
所选插件身份、物理代次、版本、指纹和批准权限在一次原子替换中可见，不存在第二个授权指针。
`activation` 检查版本及字段一致性、有序唯一性和停用记录的空权限；`pin_active` 在原选择锁内取得真实租约，
再对照实际已验证清单核查完整权限。缺失字段、JSON 空值、重复字段、未知版本或字段均明确拒绝，
与实际清单不一致的授权不能被固定并进入有效目录。

第一版仅允许缺失该字段，不允许携带新版授权，即使字段值为 JSON 空值也拒绝。普通读取不升级或改写。
只有显式已授权激活入口可以提升格式；升级后的命名空间不能使用旧 `activate` 降级。
`deactivate` 保留当前格式和单调修订；第二版停用记录保留明确空批准集合，后续启用仍要求已授权入口。
旧 `authorize_user_plugin` 在当前目录已选择第二版时明确拒绝，避免写入不再生效的旁路授权文件。

目录描述符保留与激活修订同源的批准快照及实际包租约；克隆旧描述符不会因新选择发布而改绑权限。
这一能力只证明存储及运行时投影的包／权限一致性；凭据版本、更新回执、候选就绪、路由和数据迁移
仍须由后续宿主事务协调，不把低层激活成功解释为完整插件更新成功。

磁盘选择成功只证明存储层选择。宿主仍须先完成新增权限授权、隔离候选就绪、旧写入者排空和路由事务准备，
并把磁盘记录、凭据、数据迁移、工具／Hook／UI 路由的实际阶段纳入持久事务。当前低层 API 不会替宿主执行这些动作。

## 回收与重开

回收先持有插件选择锁，拒绝当前选定代次，再尝试取得排他代次锁；有实际固定句柄时返回忙碌。
已准备代次在删除前复核原内容。准备未完成的代次可以按原持久身份明确清理，但不能直接固定或激活。

真正删除包字节前先保存正在回收状态。文件占用或其他删除失败保留此状态，禁止再次固定该代次；基础设施恢复后只能显式继续原清理。
完成后保留已回收身份记录和锁文件，不再保留插件包字节。重复回收返回已经完成，不重建旧内容。

当前测试覆盖真实 Windows 文件占用及子进程租约；中断准备的重开测试采用明确构造的实际磁盘阶段快照，
不等同进程崩溃或硬件断电验证。Windows 目录持久性、跨平台验证、孤儿目录扫描、保留容量策略及宿主重启恢复仍须按完整方案验收。
