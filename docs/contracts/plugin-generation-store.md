# 插件不可变代次存储

## 归属与当前接入状态

存储权威实现为 `crates/vulcan-plugin-runtime/src/generation_store.rs` 及其子模块；目录接入实现为
`catalog/generations.rs` 与 `runtime/lifecycle.rs`。生产公开目录入口已经消费既有受管激活记录，
快照保留实际代次租约，宿主路由代次随物理身份及激活修订变化。
第二版激活记录已把包选择与完整权限批准放入同一次原子替换，运行时消费同一选定授权。
第三版再共同选择明确的凭据修订，MCP 描述符和实际配置解析消费这份固定绑定。
第四版增加同次选择的普通配置文档，旧目录及独立 MCP 描述符保留原文档。
Service 的已停用用户插件更新入口已切换为不可变事务，原安装入口仍保留旧流程；
启用中热更新、跨 VM／会话／全部外部进程的排空与引用传递仍未完整接入。
已提供持久凭据暂存、候选清理、实际读者租约及退役回收原语，并接入 OS 后端；
已提供按原请求恢复的持久选择提交日志，区分选择发布与路由交接确认；
服务层回收调度与完整更新事务尚未完成。
不能据此宣称外部副作用补偿或整条运行时路由发布已经完成。

## 存储身份与目录

`VulcanPluginGenerationStore::open` 接受已经存在的用户插件根目录，并在其下显式创建私有
`.vulcan-generations/`。调用不会修改用户配置、授权文件或现有插件包。

```text
.vulcan-generations/
  active/<插件标识>.json
  locks/<插件标识>.lock
  locks/<插件标识>-<代次 UUID>.lease
  locks/<插件标识>-credential-<凭据修订>.lease
  locks/<插件标识>.transaction.<请求 UUID>.lock
  credentials/<插件标识>/<凭据修订>.json
  transactions/<插件标识>/current
  transactions/<插件标识>/<请求 UUID>.json
  packages/<插件标识>/<代次 UUID>/
    generation.json
    <插件标识>/...
```

代次身份包含插件标识、规范 UUID、已校验版本和完整内容指纹。路径完全由固定布局及已校验身份派生，
记录不提供任意磁盘目标。包指纹和清单校验复用当前目录加载器的实现。
代次及旧激活格式由 `RECORD_VERSION` 决定，已授权激活格式由 `AUTHORIZED_ACTIVATION_VERSION` 决定；
凭据绑定激活格式由 `CREDENTIAL_ACTIVATION_VERSION` 决定，配置绑定格式由 `CONFIGURED_ACTIVATION_VERSION` 决定。
原元数据和前三版激活使用 `MAX_RECORD_BYTES`；第四版使用从该上限及唯一配置上限派生的 `MAX_ACTIVATION_BYTES`。未知版本、未知字段、
身份不匹配、重定向路径、缺失记录及超限记录明确拒绝。

## 目录选择与授权投影

`open_existing` 只接受既有完整存储；缺失返回空，不创建目录，也不补齐损坏布局。
普通目录刷新不安装新存储、不迁移旧平铺包、不改写授权或配置。
`activation_plugin_ids` 枚举规范 `.json` 激活名称，包含停用记录；原子写入器的 `.tmp` 暂存文件不提供选择权威。
该枚举不是跨插件的原子快照。加载器对枚举身份及旧包身份逐个调用 `pin_active`，在每个插件的选择锁内取得其实际租约。
查询已枚举身份时记录消失会明确报错，不解释为允许旧包接管。

存在受管记录时，以该记录为唯一用户包选择。显式空选择会隐藏同名旧目录；记录损坏、所选包缺失、内容变化或命名空间忙碌时，
该插件显示不可用并保留诊断，不加载同名旧包。无法读取完整布局或枚举全部身份时，阻止用户包暴露并保留根级诊断；内置包独立加载。
内置同名包仍优先于用户包。工具名冲突只在受管选择及内置优先级全部确定后检查，隐藏旧包不得占用工具名。

`VulcanPluginDescriptor::managed_package()` 返回持久激活修订及实际代次句柄。
完整快照或描述符克隆仍存活时，旧代次不能被回收；仅复制工具、技能、进程配置或路径不等于保留此所有权，
后续运行资源必须显式传递代次句柄。当前测试只证明目录／描述符层引用，不能代替 VM 或外部进程层验收。

第一版受管选择及旧平铺包沿用独立授权记录的精确插件、版本、内容指纹及完整权限比较；
第二版及后续选择以同一激活记录中的完整批准为唯一权威，不读取或修补旧授权文件。
相同版本但字节变化必须重新确认精确包及权限。新增持久激活修订或物理 UUID 会推进进程内路由代次；
插件从目录消失后重新出现也不得复用旧路由代次，计数耗尽明确报错。
旧安装入口在开始复制前拒绝已观察到的受管激活或停用记录，避免报告成功却写入隐藏平铺包。
这项检查不是跨进程安装事务；完整管理流程仍须通过同一事务与选择屏障串联准备、授权、发布及恢复。

## 准备与实际引用

`prepare` 先对照用户已经检查的内容指纹，分配新代次及实际共享租约，保存准备身份，再复制文件、同步并复核完整内容。
只有全部成功才写入已准备状态并返回 `PinnedVulcanPluginGeneration`。失败不发布激活记录，保留诊断材料；
完成代次目录分配后发生的准备失败还返回 `retained_generation`，宿主可按精确身份查询或安排清理，不能解析诊断文本猜测路径。
如果第一份身份记录本身写入失败，后续清理仍须先验证实际记录，不以错误中的身份替代磁盘证据。

固定句柄的克隆共享真实租约，最后一个克隆被释放才结束该租约。使用 `package_root()` 对应文件期间必须保留固定句柄，
不能把复制出的路径字符串当成资源所有权。`pin_active` 在释放插件选择锁之前取得选定代次租约，封闭查询与回收之间的竞态。

锁使用标准库的非阻塞文件锁：同一插件的选择及阶段读取使用共享命名空间锁，选择变更及回收使用排他命名空间锁；
实际代次引用使用共享代次锁，回收另要求排他代次锁。并行目录读取可以共存，不会仅因另一个读取者而把插件投影为不可用。
这些约束覆盖遵守同一协议的线程和进程，不充当对非协作文件系统修改者的安全沙箱；锁文件不会在回收时删除，避免后继所有者锁住另一个文件对象。
标准库契约见 [Rust 文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock) 和
[共享文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock_shared)。

## 激活修订与边界

从未发布的命名空间观察为修订零。`activate` 和 `deactivate` 只接受精确当前修订，在同一插件的文件锁内写入后继记录。
停用保留记录及修订，不删除记录后重新使用零；修订耗尽明确拒绝。多个存储实例竞争同一前驱只能有一个成功，其他实例收到忙碌或修订冲突。

`generation` 是必需但可为空的字段：空值表示明确停用，字段缺失表示损坏，不能等同处理。
激活记录的原子写入错误不保证变更未发生，宿主必须回读精确记录后再决定如何继续，不能重放生命周期或业务回调。

### 包选择与权限共同发布

`activate_authorized` 接受实际固定代次、精确前驱修订及明确批准的完整权限集合。
权限键来自与授权预览共用的清单映射；发布前在同一命名空间锁内重新验证包字节，并要求权限完整且不重复。
调用方输入顺序可不同，存储使用清单派生的规范顺序。准备包本身不会批准权限。

该入口写入第二版激活记录，`approved_permissions` 是必需、非空值的列表；空列表只批准真实零权限包。
所选插件身份、物理代次、版本、指纹和批准权限在一次原子替换中可见，不存在第二个授权指针。
`activation` 检查版本及字段一致性、有序唯一性和停用记录的空权限；`pin_active` 在原选择锁内取得真实租约，
再对照实际已验证清单核查完整权限。缺失字段、JSON 空值、重复字段、未知版本或字段均明确拒绝，
与实际清单不一致的授权不能被固定并进入有效目录。

第一版仅允许缺失该字段，不允许携带新版授权，即使字段值为 JSON 空值也拒绝。普通读取不升级或改写。
只有显式已授权激活入口可以提升格式；升级后的命名空间不能使用旧 `activate` 降级。
`deactivate` 保留当前格式和单调修订；第二版停用记录保留明确空批准集合，后续启用仍要求已授权入口。
旧 `authorize_user_plugin` 在当前目录已选择第二版或后续版本时明确拒绝，避免写入不再生效的旁路授权文件。

目录描述符保留与激活修订同源的批准快照及实际包租约；克隆旧描述符不会因新选择发布而改绑权限。
这一能力只证明存储及运行时投影的包／权限一致性；凭据暂存、更新回执、候选就绪、路由和数据迁移
仍须由后续宿主事务协调，不把低层激活成功解释为完整插件更新成功。

### 包、权限与凭据修订共同选择

`VulcanPluginCredentialRevision` 是规范小写、带分隔符且非全零的 UUID 身份；解析拒绝别名，不能静默规范化。
它独立于物理包 UUID 和激活计数，因此仅轮换凭据可以继续使用同一物理包。
`activate_with_credentials` 接受固定包、精确前驱修订、完整批准及明确凭据修订，在原选择锁与原子写入器下共同发布。
该低层入口与 `pin_active` 都要求同一精确物理包身份的已暂存日志；缺失、准备中、回收中或已丢弃均拒绝。
日志还必须与实际包的完整声明键清单一致，不能因字段各自合法而接受漏键。权限和凭据清单由同一次包校验派生，固定句柄保留两者，不额外扫描包字节。
它不重新读取 OS 秘密，也不执行应用就绪；后续 OS 读取失败仍明确报告，不能因日志成功就声称插件或路由可用。

| 激活格式 | 权限字段 | 凭据字段 | 配置字段 | 凭据读取绑定 |
| --- | --- | --- | --- | --- |
| 第一版 | 必须缺失 | 必须缺失 | 必须缺失 | 原命名空间 |
| 第二版 | 必需且非空值的完整列表 | 必须缺失 | 必须缺失 | 原命名空间 |
| 第三版 | 必需且非空值的完整列表 | 必需且非空值的规范修订 | 必须缺失 | 指定修订命名空间 |
| 第四版 | 必需且非空值的完整列表 | 必需且非空值的规范修订 | 必需且非空值的明确选择 | 指定修订命名空间 |

任一不匹配组合、重复字段或未知字段均拒绝；JSON 空值不能代表旧绑定。第三版命名空间不能经旧激活入口降级。
停用保留第三版、空批准、空包选择及最后凭据修订；保留修订只提供后续清理身份，不构成执行授权。
重新激活必须再次明确提交修订。普通读取、目录刷新及旧格式加载不写入迁移。

受管包快照及每个 MCP 服务器描述符携带 `VulcanPluginCredentialBinding`，明确区分 `Legacy` 与 `Revision`。
HTTP、SSE、标准输入输出、会话 MCP 的 URL、请求头、OAuth、参数及环境变量中的秘密均通过同一描述符绑定解析。
`PluginMcpSecretStore::read_secret` 必须接收该绑定，不能查询当前全局目录来重选历史调用的修订。
旧远端描述符可继续解析原修订；旧标准输入输出描述符仍受既有启动器代次检查约束，不能绕过过时代次拒绝。
已经物化的配置保留原值。受管包及每个可独立克隆的 MCP 描述符同时持有实际凭据共享租约，
因此旧目录或脱离目录的旧服务器声明仍可读取原修订时，排他清理必须返回繁忙。
旧格式的普通 `config` 来源仍由 `plugin_server_configuration` 查询当前管理器配置；
第四版直接读取精确描述符持有的选定文档，不查询旧文件或最新目录来替换历史配置。

OS 适配器将新修订放入独立的 `vulcan-code.plugin-mcp.versioned-v1` 服务，账户摘要依次编码插件标识、
凭据修订、服务器标识和秘密键，每个 UTF-8 组件使用无符号六十四位大端字节长度分帧。
旧服务及旧账户算法保持原样；选定值缺失或后端失败直接报错，不查询旧修订或原命名空间。
错误不包含秘密值。当前普通凭据编辑入口观察到版本绑定时明确要求凭据修订事务，防止写入不再被使用的旧账户。

暂存、候选恢复及读者回收原语见下节。完整服务提交决定、配置／凭据编辑事务、卸载和回收调度仍待上层接入。
本地测试覆盖真实选择文件、全部 MCP 配置分支及 Windows 随机测试命名空间的实际安全存储隔离；
配置物化没有连接远端服务器或执行假启动器，也不能代替跨平台、掉电或端到端更新验收。

磁盘选择成功只证明存储层选择。宿主仍须先完成新增权限授权、隔离候选就绪、旧写入者排空和路由事务准备，
并把磁盘记录、凭据、数据迁移、工具／Hook／UI 路由的实际阶段纳入持久事务。当前低层 API 不会替宿主执行这些动作。

### 普通配置与全部选择共同发布

`activate_configured` 接受实际固定包、精确前驱修订、完整权限、已暂存凭据及明确配置选择，
使用相同插件屏障及原子写入器发布第四版记录。配置变化复用激活修订号，不新增第二个可变选择指针。
纯配置变化可以继续选择同一物理包和凭据；旧观察、旧目录和独立 MCP 描述符仍保留原配置。
目录中同一修订的贡献共用文档引用，避免按服务器复制完整配置。

`configuration` 必需且不能为 JSON 空值；`kind: not_declared` 仅适用于实际包未声明配置，
`kind: document` 必须带完整 `value`。文档值本身可以是 JSON 空值，但只有精确包内 Schema 允许时才可选择。
不从默认值、旧文件或新版本配置补齐任何字段。选择前及固定时都复用原包配置 Schema 校验，
版本、字段、声明或 Schema 不符明确拒绝；记录损坏不修复、不降级。

配置紧凑编码使用唯一 `MAX_PLUGIN_CONFIGURATION_BYTES` 上限（当前四兆二进制字节）。
第四版记录总上限由原元数据额度加该值派生，采用紧凑编码；前三版仍保留原较小记录上限。
实际读取同时限制文件长度与读取字节数，外部增长不能绕过。旧平铺配置不被自动迁移或裁剪；
显式迁入第四版时必须先通过新边界及实际 Schema 校验。调试输出隐藏配置内容，校验及解码错误不回显用户文档。

第四版不能经旧激活 API 回退至外部配置权威。停用保留原格式、最后配置及凭据身份，并使用空包和空批准；
保留值提供明确后续处理信息，不提供执行权限。重新激活须再次提交完整选择。

管理器读取第四版时返回原描述符选定文档；初始化入口识别已选文档并返回“未新建”，不触碰无关旧文件。
当前旧配置修改入口对第四版明确要求完整激活事务，避免写入不再被消费的状态文件后报告成功。
前三版和旧平铺包继续使用既有动态读取及写入契约。完整的第四版管理编辑、原生动态修订提交、
生命周期排空和路由发布仍待实现；这项临时拒绝不是完整配置编辑产品能力。

### 持久凭据暂存与候选恢复

权威实现为 `generation_store/credential_staging.rs` 及其子模块；OS 适配器位于服务内核的
`plugin_mcp_secret_store/staging.rs`。`begin_credential_staging` 在原插件命名空间屏障内重新验证实际包，
从生产 MCP 清单派生全部秘密槽位，要求请求逐项提供值或显式缺失，再持久保存原修订日志。
额外键、漏键及已配置空字符串均拒绝；日志只保存精确包身份、修订、键名、已配置子集和阶段，不保存值或值摘要。
此步骤没有 OS 副作用。已存在修订记录绝不复用，已被当前选择或停用记录引用的身份不能重新作为候选。

独立暂存继续使用第一版清单；原激活准备使用 `begin_activation_credential_staging`，第二版清单
额外保存必需的规范 `activation_request`，绑定原请求 UUID。版本与字段必须严格匹配，显式空值不能
冒充旧格式缺失。日志版本独立于激活记录及事务日志版本；升级时同时核对三者读取入口。
待处理命名空间不接受独立暂存；任何历史原请求预留的修订也不能通过独立入口重新使用，
即使尚未分配凭据清单、原请求已放弃且当前索引已变化。

`VulcanPluginCredentialStaging` 是不可克隆的原准备所有者，持有实际非阻塞排他修订文件锁。
同一修订的另一准备、恢复或清理得到繁忙结果；仅丢弃内存所有者会释放锁，不删除凭据或日志。
`write_and_finish` 先验证完整输入及原日志，再比较全部既有候选值：相同值保留，不同值拒绝覆盖，
仅写入缺失且声明已配置的值。全部槽位读回与输入一致后，才原子发布 `staged`。
明确缺失槽位也必须确实不存在；`staged` 表示凭据集合已暂存，不能代替 MCP 就绪或权限审批。
外部后端错误文本不会传播进日志，避免后端把秘密嵌入异常；保留稳定的失败类别和操作阶段。

第二版写入者另保留同一原激活请求的实际排他锁。前台准备所有者释放后，阻塞凭据工作仍持有它，
因此原请求不能被放弃、恢复或晋级；成功暂存也必须等待写入者实际释放。
重开第二版凭据写入时，先按持久父 UUID 取得原请求锁，核对仍为早期准备、索引、完整前驱、
包身份和凭据修订，再取得修订锁；父级缺失、终态、已经晋级或身份变化明确拒绝。
缺失索引需先显式恢复原准备请求，普通凭据恢复不猜测或修复它。
原激活意图未终结时，持久保留同时阻止包及凭据清理；放弃后再按各自原身份明确清理。

| 日志阶段 | 允许操作 | 禁止操作 |
| --- | --- | --- |
| `preparing` | 原所有者写入；释放原锁后显式恢复；显式丢弃 | 发布第三版选择 |
| `staged` | 精确包身份选择；真实共享固定；退役后排他回收；状态读取 | 再次写入、以候选清理接口删除 |
| `discarding` | 继续原清理、状态读取 | 恢复写入、共享固定、选择 |
| `discarded` | 状态读取、幂等清理确认 | 复用身份、写入、选择 |

发布检查点错误可能发生在 OS 写入之后，不能推断凭据没有写入。调用方按原修订回读：若仍为准备中，
可显式提交同一完整值集合，已经一致的值不会再次写入；若为已暂存，则消费原结果，不能重新暂存。
日志不保存尚未写入值的摘要，因此恢复者必须持有原请求值；丢失这些值时可以查询或丢弃原候选，不能猜测补齐。

`credential_plugin_ids` 与 `credential_revisions` 只读枚举持久身份，包括已完成记录；临时文件不提供恢复权威，
未知路径类型和不规范身份明确拒绝。枚举不是跨插件快照；随后必须逐条读取严格日志。
普通启动扫描不得因此自动重放写入、生命周期或清理。`resume_credential_staging` 只重取原准备排他锁，不调用 OS 后端。

`discard_credential_staging` 只清理未完成候选，并拒绝当前选择／停用记录引用和已暂存修订。
删除任何 OS 条目前先持久保存 `discarding`，按原完整键清单逐项删除并确认缺失，最后保存 `discarded`。
中途失败保留原清单，可按原身份继续；不需要从最新插件包猜测清理键，也不读取、覆盖或删除旧命名空间。
已暂存修订使用下述显式退役回收入口；候选丢弃入口不扩大语义。

### 凭据真实读者与退役回收

`PinnedVulcanPluginCredentials` 持有共享文件锁及原非秘密日志快照，克隆共用同一实际句柄。
`pin_credentials` 用于候选就绪或显式原修订读取；它重新校验精确包并要求已暂存日志。
`pin_active` 在同一插件选择屏障内固定实际包和所选凭据，随后才返回观察结果。
第一、二版以及显式停用观察没有凭据租约；停用只保留历史身份。

暂存所有者持有排他锁直到被释放，即使已经成功发布 `staged` 也不自动降级锁；
调用方必须先释放写入者，再固定共享读者。二者之间无所有权保证，若竞争回收先取得原屏障，
固定返回明确错误；调用方不能假定候选仍可读。实际事务协调须保留原身份并处理该结果。

受管包和每个 MCP 声明分别保留可克隆租约，目录刷新不会转移或释放外部仍持有的旧引用。
只复制 UUID、绑定或日志快照不会保留凭据；绕开描述符的调用方必须自行持有公开固定句柄直到最后一次读取。
已物化的秘密字符串不再查询安全存储，可与来源条目的生命周期分离。

`collect_credentials` 用于已暂存候选中止或旧修订退役。它在原插件选择屏障内取得排他修订锁，
拒绝仍为有效选择的修订，并要求所有真实读者及写者已经释放。停用记录不授予执行权限，
因此它引用的修订可在读者全部释放后回收。准备中候选须使用原丢弃接口。
回收与候选丢弃共用唯一清理实现：先持久写入 `discarding`，再释放插件屏障但持续保留排他修订锁，
按原完整清单删除并回读确认，最终比较原日志后发布 `discarded`。后端失败继续原清单，
发布检查点失败须回读原状态；过程中无法重新固定、写入或选择该修订。
保留终态记录及锁文件，禁止修订身份复用；源插件包已被回收也不影响按原日志清理。

实际跨进程测试通过独立测试进程取得 `pin_active`，父进程停用后回收仍繁忙，
终止并回收子进程后才可清理。此证据覆盖 OS 锁随进程退出释放，不代表凭据写入掉电恢复。
真实 Windows 安全存储测试另验证共享读者阻止 OS 删除、最后克隆释放后原条目被清理，
旧命名空间条目保持原值。当前仍未接入完整服务更新及自动回收调度。

以上入口使用既有有界记录写入器和真实文件锁，不新增平行选择指针。第三版及后续绑定修订的选择要求暂存日志；
本地开发阶段旧原型中没有日志的第三版记录明确不可用，普通加载不补写日志，不回退第一／二版或旧目录。
实际服务的已停用更新已将凭据暂存归入同一早期原请求，并接入原请求启动门控；安装、启用中更新和普通凭据编辑仍须接入，
不能把可独立调用的暂存 API 当成完整产品流程。

## 持久选择提交与路由交接

权威实现为 `generation_store/transactions.rs` 及其子模块。宿主在调用前签发非空 UUID，
`begin_activation_transaction` 保存完整前驱与第四版目标，目标修订必须恰为前驱加一；
实际包、完整权限、配置模式和已暂存凭据均须验证。准备不激活、不执行生命周期，也不表示候选已就绪。
同一插件的 `transactions/<plugin_id>/current` 仅索引唯一待交接请求，激活权威仍为原 `active` 记录。
每个 `<request_id>.json` 独立保留，不因后续请求而覆盖；配置文档属于用户数据，普通日志和调试输出不披露内容。
第一版完整日志及稳定索引由 `TRANSACTION_RECORD_VERSION` 控制；第二版原请求由
`PREPARATION_RECORD_VERSION` 控制，携带复制前固定的准备意图，并跨完整目标及终态保留。
第三版由 `UPDATE_RECORD_VERSION` 控制，要求同一准备意图包含 `update_policy`；
字段省略、显式空值、缺失布尔值、未知字段或在第二版中出现均拒绝。前两版按声明格式读取，
不能从当前设置或新包默认值补造原策略。晋级完整目标时保持原日志版本及全部准备字段。
索引格式不随请求格式提升，始终按原 UUID 指向单个明确记录；第一版既有记录保持可读。
统一严格解码器按声明版本、阶段及字段存在性验证，不尝试替代格式；早期阶段没有 `target` 字段，
完整阶段必须具有真实完整目标。显式空目标、未知字段及版本／结构不符均拒绝。
日志上限从两个激活记录额度和一个元数据额度派生；嵌套选择复用既有格式及大小校验，不新增独立配置上限。

| 阶段 | 含义与允许的下一步 |
| --- | --- |
| `preparing` | 已持久保存原准备意图，包／凭据可以尚未分配或仅完成部分；只能准备同一资源、完成准备或明确放弃，不授予候选执行 |
| `prepared` | 完整目标及包、凭据准备已验证，宿主可执行明确的候选就绪；可请求提交或显式中止 |
| `committing` | 提交意图已持久化；原选择必须为完整前驱或完整目标，按原请求恢复 |
| `published` | 目标选择已确认，尚待宿主完成路由交接；禁止自动回滚 |
| `completed` | 宿主显式确认路由交接；历史回执保留，新请求可进入 |
| `aborted` | 已确认前驱未变并明确放弃；历史回执保留，新请求可进入 |

### 复制前的原准备意图

`begin_activation_preparation` 在包复制或安全存储写入前固定原请求 UUID、完整前驱、
已批准指纹及权限、预分配代次身份、凭据修订与唯一后继修订。此时不读取可变来源的配置默认值
作为目标配置，不持久保存来源路径或秘密值，也不构造可执行的占位目标。
`VulcanPluginActivationRequestRecord` 明确区分早期意图和完整激活；`activation_request` 查询两类，
旧 `activation_transaction` 仅接受完整目标，早期记录明确报错。

`prepare_activation_package` 只向原意图预留的新目录复制，完整过程持有原请求实际锁。
现存的部分或完整候选目录均不覆盖或按最新包替换；中断后可按原身份查询、明确放弃并清理。
从已验证副本选择配置、派生凭据槽位并完成父绑定暂存后，`finish_activation_preparation`
复核完整包、权限、配置模式及凭据父 UUID，在同一个请求文件原子写入完整目标和 `prepared`。
晋级沿用同一 UUID、索引和实际请求锁，没有解锁后重新获取的窗口。
检查点写入失败必须回读原 UUID，以实际早期或完整阶段继续，不能分配新请求自动重做。

`resume_activation_preparation` 只恢复原早期所有权，核对完整前驱及唯一索引，必要时明确修复该原索引，
不会自动复制、写凭据或执行回调。`abort_activation_preparation_request` 等待全部实际所有者退出后
才能确认放弃；保留原资源身份与副作用证据，不删除包或凭据。早期记录只允许 `preparing` 或
`aborted`，安装回执在该阶段非法。旧版终态回执的幂等读取不会改写较新的早期请求索引。

### 更新请求的原用户策略

`begin_activation_update_preparation` 复用原准备分配与排他锁，在复制和凭据暂存前把
`VulcanPluginUpdatePolicy` 写入同一原请求正文；不创建可丢失后静默降级的附属策略文件。
策略仅包含此插件原显式启用／停用集合成员关系及前驱清单默认值。原有效目标按供应商配置契约
的启用优先、其次停用、最后原默认值解析；两个集合归一化之前的原成员关系也精确保留。
契约归属为 `vulcan-provider-config/src/config/runtime_persistence.rs`，其优先级变更时须同步
此策略解析和比较全部布尔组合的服务测试，不能把本文转录作为第二权威。

服务准备从原保留配置与原目录描述符捕获策略，期望状态不一致时在持久准备之前报错。
实际保存目标策略使用既有串行配置写入器，从最新配置仅比较并修改此插件的两个集合成员关系；
其他插件的后续编辑保留。即使有效状态相同，原覆盖成员关系变化仍为冲突，不覆盖新用户选择。
候选就绪后再次取得同一配置事务权威，按原记录复核当前明确停用目标，并持有至选择提交、
目录与扩展路由发布及请求完成；已提交恢复也使用同一顺序。因等待配置写入者而发生的策略变化
必须在发布前报错，不能仅在早期保存策略时检查。最终界面刷新前释放此权威，避免嵌套写入。
请求的早期及完整查询均可读取原策略；重开、晋级、完成或明确放弃不删除此证据，
原身份比较也包含它。记录及该写入步骤本身不表示启用中切换、旧代次补偿或整体路由恢复已实现。

### 完整目标的提交与所有权

不可克隆事务所有者持有实际排他请求锁、目标插件包共享租约和目标凭据共享租约。
候选视图、受跟踪准备与实际原生池通过共享所有权保留同一排他请求锁，不新增锁文件或格式。
其他实例不能恢复仍有实际所有者的请求；释放事务句柄不保证立即解锁，也不中止持久事务。
最后一个事务、候选视图及实际执行所有者退出后才解锁，完整请求日志继续保留。
同一可变事务提交或中止前，还要求它独占原锁的所有权；超时返回不能替代这项检查。
普通激活、带配置激活及停用共用待完成事务屏障，不能绕过提交顺序。
未终结请求的完整前驱、计划中或已完成目标均阻止包／凭据回收，即使原进程已退出；完成后仍由实际旧描述符租约保护在途调用。

`commit_activation_transaction` 先保存提交意图，再使用原原子写入器发布完整选择，最后保存已发布检查点。
发生错误后调用方查询原 UUID，原所有者及实际候选工作全部退出后，才可通过
`resume_activation_transaction` 取得原请求；仍在清理时返回忙碌，不能抢占原锁。
恢复不重放就绪回调；原激活为目标时只补确认，不再次递增或替换选择；原激活为前驱时允许显式重试提交。
其他完整记录、相同修订但不同内容、损坏记录均拒绝。`complete_activation_transaction` 要求精确已发布目标，
调用方必须先完成真实路由交接；该接口不代替路由协调器，也不等待插件自身调用退出。

中止只在原前驱完全未变时允许。候选损坏导致无法重新固定时，原所有者退出后可使用
`abort_activation_request` 按 UUID 明确放弃；它不需要重新执行候选、不删除包或 OS 条目。
已持久化的中止可按原请求幂等确认。已发布目标不能用此入口回滚。

请求正文先于索引写入，发生中断时原 UUID 始终由调用方保留。记录存在却缺少索引时，普通写入和回收被阻止，
不会扫描候选猜测当前权威。显式恢复原准备请求会复核前驱和候选，再补索引；发现其他未终结记录则拒绝重建，
历史已中止请求不能覆盖较新的未完成工作。只读命名空间／请求枚举及原请求查询均不自动恢复。
事务记录和锁文件暂不自动清理；保留策略须与最终操作历史及用户数据删除策略统一设计，不能擅自删除回执。

索引替换失败也可能保留较旧的终态指针，而不是产生缺失索引。普通选择写入、独立暂存及回收
必须检查非索引原请求，存在未终结正文即阻止变更；仅明确恢复该原请求才能补齐索引。
每次索引发布均核对其他未完成原请求，不因索引文件已经存在而跳过。此检查扫描单插件原历史，
长期历史规模及安全归档需要纳入后续性能、容量和回执保留策略验收。

本地测试包含两侧磁盘阶段快照，以及 Windows 真实不共享删除文件句柄引发的两次原子替换失败：
第一次选择替换失败而提交意图保留；第二次选择成功而最后日志替换失败。重开后确认原修订，原选择字节不被再次替换。
这些结果不等于硬件断电、多平台验证或服务完整更新验收。服务安装／启用中更新／配置编辑的完整事务仍须接入，
第四版旧配置写入守卫尚未移除。

### 原激活请求的启动恢复门控

权威实现为 `runtime/recovery.rs`、`runtime/lifecycle.rs` 与 `generation_store/transactions/records.rs`；
服务启动在正式运行时初始化和首次目录发布前调用 `initialize_activation_recovery`。
其他管理器首次发布目录时同样初始化，后续调用不能清空已观察义务。
既有存储缺失保持只读；读取失败不作为空清单。规范命名空间逐项检查索引和原请求正文，
孤立安装回执、早期意图上的不可能安装回执、与完整原请求不匹配的回执正文、损坏或悬空索引均保留诊断。
缺少索引的未完成原请求仍可列出，
不根据目录顺序选择权威；仅明确恢复原请求可以补索引。仅剩终态历史却缺少索引时也拒绝推断。

启动时存在未完成原请求的插件保留用户期望启用状态，实际运行时投影为不可用，
工具、钩子、MCP、提示词、技能及代理暴露面均关闭；无关健康插件继续工作。
不能识别受影响命名空间的根目录错误关闭全部插件暴露面，但不阻止服务管理与查询入口启动。
刷新只按已捕获 UUID 回读完整前驱及原准备意图／已观察完整目标；允许同一早期意图合法晋级，
已观察完整目标则必须保持完全一致。原请求消失或身份改变不表示完成。
明确完成或中止原请求后才解除对应义务。不透明日志错误要求修复后重新启动检查，
反复刷新或再次初始化不会将错误静默清除。

`refresh_catalog_for_activation_recovery` 仅接受既有存储中精确已发布请求的实际排他所有者，

不执行回调、不改写策略、不提前写入完成回执。许可仅作用于这次目录发布；
普通生命周期入场仍核对原恢复义务，以及启动后新建立的未终结请求。服务恢复入口先同步钩子和扩展代次，随后完成原请求，
最终普通刷新观察终态后解除门控。其他待恢复请求及不透明错误不能借此许可绕过。

本地验收覆盖真实磁盘、全新管理器、原请求明确恢复、停用发布后禁止提前启用、
历史终态、未索引准备、原记录消失、损坏索引、孤立回执和可选存储不创建。

这不表示启用中热更新或全部生命周期回调的崩溃恢复已经完成。

### 已停用用户插件的真实服务更新

实际入口为 `skills_services::service_update_local_plugin`，协调器位于服务内核
`skills_services/local_plugin_update.rs`。入口继续使用原服务自有管理任务和全局管理变更锁；
外层 RPC 等待取消不会取消其已启动工作。当前要求用户插件已停用且没有活动会话，
尚不能把该入口等同于启用中插件无中断热更新。

先核对已批准指纹、完整权限集合、网络依赖授权及声明的初始秘密输入。固定前驱描述符，
检查同插件未终结原请求，以及当前持久选择的完整包、权限、凭据、配置；仅修订相同不足以匹配。
随后先持久保存原准备意图，再按预留身份复制不可变包、从副本选择配置并准备父绑定凭据，
最后将同一原请求晋级为完整激活事务。中途失败仍可按原 UUID 查询，普通启用不能绕过未终结请求。
阻塞的依赖准备及安全读取在原管理工作线程中进行，原事务所有权随工作移动，
观察取消不会提前释放实际准备工作持有的请求。

配置转换以实际新旧清单为准：继续声明时完整保留旧选择并按新模式校验，首次声明时采用新包默认值，
移除声明时明确选择无配置且保留旧用户文件；不合并新默认值。新本地 MCP 输入采用明确提交值；
其他保留键只从旧描述符的原绑定读取，新槽位保持明确缺失，不能跨修订探测。
原目录字节与原 OS 秘密账户在候选验证及提交期间均不替换。

候选入场前检查原退役 MCP 分区并排空原 Lua 工作；此次明确更新持久保持用户停用策略，
避免新包默认启用值在崩溃后改变用户状态。它属于用户发起更新的变更，不属于启动或刷新回写。
候选依次进行原 Lua 探测、本地 MCP 初始化／发现／协议关闭／真实资源退出，再按原安装回执执行安装。
本地 MCP 验证保留旧入口的范围：全部已声明标准输入输出服务器，不验证远程服务器且不发布业务工具。
这些回调及进程启动可能产生外部副作用，不能称为无副作用检查。

持久提交后刷新并核对目标完整身份、实际可用性及停用状态，再同步钩子、发布原服务扩展代次并完成原请求。
刷新返回故障条目不能标记为完成。失败保留原请求，禁止用目录还原或新 UUID 自动重放安装。
状态投影不包含配置、凭据或原始回调错误；请求标识为规范非空 UUID，修订为十进制字符串。

| 服务方法 | 明确行为 |
| --- | --- |
| `service_local_plugin_update_requests` | 按 `pluginId` 只读列出全部原请求；不创建缺失存储、不猜测恢复目标 |
| `service_resume_local_plugin_update` | 按 `pluginId`、`requestId` 补齐已实际选中完整目标的 `committing`／`published` 请求；要求原停用策略仍成立，不重放候选准备、连接或安装 |

展开不查询或修改；用户明确输入插件标识后读取，不自动选定“最新”请求。既有插件列表仅提供输入建议，

修订保持字符串。操作错误后仍回读原记录；原记录缺失或回读失败时保留旧证据并关闭修改资格，
成功回读也不抹去此前操作错误。跨折叠保留状态，插件输入改变后迟到响应失效，重复点击同步拒绝。
缺失原记录或回读失败所留下的不确定请求跨后续空读取和插件切换保留；在读回它之前不接纳另一恢复变更。
放弃一律通过共享确认说明外部副作用保留；后端继续拥有实际繁忙、已提交及原权威校验，界面不代替它。
`preparing` 展示计划候选身份，允许明确放弃，不能使用路由恢复按钮；响应若同时含安装或候选副作用回执则拒绝。

空数组仅表示当前未记录这些尝试，不证明外部系统没有副作用。

本地界面测试覆盖真实组件和服务替身，不代表桌面壳、WebSocket/RPC、凭据及真实插件的全链路验收。
更新入口的包／凭据准备已归入同一原请求及启动恢复门控；其他独立安装和管理入口仍有各自记录，
因此此处请求列表尚不能解释为全部管理操作的全集。
启用中更新、全部拥有者排空、数据迁移、完整普通管理操作及回收仍属于后续完整交付。

### 候选安装的持久副作用回执

权威实现为 `generation_store/transactions/installation.rs`，与正式
`install_activation_candidate` 入场直接连接。首次声明安装在任何环境准备、模块初始化及安装回调之前，
在原请求目录写入 `<request_id>.install`。它是同一请求的附属证据，不是第二激活指针；
原事务／索引格式保持不变，附属格式由 `INSTALLATION_RECEIPT_VERSION` 独立控制，大小引用既有元数据预算。
记录只包含格式、插件、原请求、目标修订及类型化阶段，不含配置、秘密值或原回调错误文本。

| 回执阶段 | 实际含义 |
| --- | --- |
| `started` | 开始意图已落盘；执行可能尚未入场、仍存活、已经完成但观察者消失，或最终确认写入失败 |
| `succeeded` | 原调用在正常清理后返回成功，且结果已持久确认；不是外部系统当前状态或路由就绪证明 |
| `observation_failed` | 原观测返回错误或超时；实际工作及外部副作用仍可能存在 |

同一请求的任何既有回执都拒绝安装再次执行，包括已成功及已退役请求。原命名空间锁使并发尝试排序，
实际请求锁继续覆盖真实资源；取消观察不会删除开始记录，也不通过析构伪造成功。原安装参数包含
`request_id` 的规范 UUID 字符串，可用于插件外部操作去重。没有 Lua／安装声明时继续直接成功，不创建回执或环境。

`installation_receipt(plugin_id, request_id)` 是只读原身份查询，缺失原请求报错；返回无回执只描述当前磁盘状态，
不能证明其他渠道从未产生外部副作用。未知格式、损坏、身份或修订不匹配均拒绝，不修复字节。
已有尝试未确定成功时，`commit_activation_transaction` 拒绝发布；资源退出、空调用列表和重开存储均不能解除该限制。
回执不存在不等于已完成必需安装；是否需要安装仍由上层流程决定，存储层不会偷偷调用回调。

中止仍只放弃选择，保留安装历史，不宣称撤销外部副作用。服务协调器必须在旧写入者排空后才执行安装，
并对不确定副作用保持明确人工处理／恢复边界；本入口不提供伪造成功或自动重放的恢复接口。
新请求必须经过明确的新授权和副作用核对，不能用新 UUID 绕过旧失败。
本地验证包含真实回调成功／失败、观察取消、重开存储、同请求重复入场、损坏回执，
以及 Windows 实际文件共享冲突导致的“回调已成功、最终回执写入失败”；不代表服务完整更新或断电验收。

### 候选探测、启用与补偿的持久记录

权威实现为 `generation_store/transactions/effects.rs` 与正式候选调用入口。
同一原请求的 `<request_id>.effects` 固定格式、插件、规范 UUID、完整目标修订，
以可选字段分别保存 `probe`、`enable`、`enable_rollback` 观测；缺失字段表示未尝试，
显式空值、重复字段、未知字段／版本、身份不匹配及不可能的阶段组合均拒绝。
它不是新激活指针；安装仍仅以原 `.install` 文件为权威。两者复用同一观测枚举及元数据大小限制。

每种操作先保存 `started`，再进行环境准备、Lua 顶层初始化及声明回调。
探测并非无副作用检查，不能因未调用业务导出而省略此记录。
正常返回在实际清理后保存 `succeeded`；错误或观察超时保存 `observation_failed`；
观察取消保留 `started`。最终记录写入失败保持不确定，不重放回调。
独立记录观察者与实际原生调用分别保留原请求锁；前台销毁不能使尚未退出的原生工作变为可提交或可回收。

探测必须先于安装及启用。已尝试探测未确定成功时，安装及启用均拒绝。
候选启用还要求所有已尝试安装成功；清单声明了安装回调时，必须存在其成功回执。
已存在的原操作不再执行，包含已成功、已失败和中断状态。安装／启用／补偿不能与同请求仍保留的正式候选调用重叠。
清单原校验已经要求声明启用时同时声明停用补偿，新增接口继续消费此约束，不新增可缺失补偿的插件形态。
补偿只接受已观测成功或失败的原启用；未知完成状态先保留原请求，不猜测重放。
回调信封携带原规范 `request_id`，事件分别为 `enable`、`enable_rollback`，
能力作用域从类型化操作派生，不接受调用方指定任意导出。

任何已有探测／启用观测未成功均禁止提交；存在任何补偿尝试则永久禁止将此原候选发布，
即使补偿回调成功也不能把同一请求再次解释为就绪。
只读 `activation_effects`、启动清单及服务状态读取严格校验这些证据。
早期未配置请求拥有该文件、孤立文件或损坏正文均显式失败；终态历史也不跳过校验。

本地验证使用真实 Lua、原生能力、磁盘记录与精确原请求重开；覆盖所选配置、
事件 UUID、重复入场、正常／失败补偿、探测取消／超时、启用超时及实际锁保留。
这些接口是完整启用中更新的前置，当前生产更新入口仍要求停用插件；
原策略冻结及下节 Lua 排空授权已接入；旧停用回调、完整服务切换、迁移、整体路由交接、跨进程强杀及跨平台验收仍按方案推进。

### 原请求持有的前驱 Lua 排空

权威实现为 `runtime/update_drain.rs`、既有生命周期发布门、正式资源排空以及
`generation_store/transactions/effects/predecessor.rs`。`begin_activation_predecessor_drain`
接受真实原候选所有者及更新前目录快照，核对管理器实例、用户根、旧运行代次、包根、完整摘要、
完整持久前驱及原策略；只有仍启用的精确前驱可以进入。受管选择与旧平铺包显式区分，
旧平铺包没有受管选择不等于从未安装。普通启停不具有此例外，候选继续保持私有零代次。

同一 `.effects` 在签发排空代次和授予旧核心关闭权限之前保存 `predecessor_drain_identity`
与 `predecessor_lua_drain`。二者必须共同存在，包含原管理器实例、前驱与排空代次、旧版本及摘要；
要求第三版原策略的启用目标。该尝试必须先于候选探测、安装、启用及补偿，不能再次分配。
未确认成功的前驱 Lua 排空阻止候选副作用和选择提交。

原请求锁同时由管理器中的实际排空所有者及已经登记的核心执行域保留。监督任务跨前台取消继续；
有限排空返回后仍有受跟踪或实际核心资源时，保留原锁与 `started`，不能恢复、中止或提交。
仅有空调用注册表不构成退役证明。`activation_predecessor_drain` 按原 UUID 查询当前管理器保留的
同一不透明句柄；后续 `drain_activation_predecessor` 串行观察既有清理，不重新分配关闭回调。

全部资源退役后才持久确认该次资源排空观测，并释放原锁保留。已发生的清理错误不会因后续安静轮询
改写为成功。最终写入失败保留原观察者，可重写同一结果确认持久化，不能重新执行插件。
此处证明 Lua 资源退役，不代表旧插件停用回调已经执行、MCP 已退役、外部副作用已撤销或全部路由已交接。
历史句柄继续可读不会继续固定已经释放的请求锁。

普通生命周期回调、直接原生生命周期池注册以及普通生命周期完成入口，均不能借用未完成原更新
产生的排空状态。真实核心关闭仍使用已经授予的旧执行域权限；它与普通导出调用严格区分。
重启沿既有原请求启动门控处理，不从磁盘中的旧管理器实例重建内存权限或自动重放未知操作。

本地测试覆盖真实受管和旧平铺前驱、陈旧快照、代次耗尽、候选保持私有、普通回调越权拒绝、
前台取消、有限排空、实际原生工作／核心池／声明关闭函数保留及最终原请求锁释放。
生产服务目前仍仅支持已停用插件更新；启用中更新协调、旧停用回调及其补偿、MCP 和完整扩展交接继续实施。

### 候选 MCP 准备

候选 Lua 操作的持久边界见上一节及下述附属日志；MCP 准备与连接的实际所有权继续使用本节独立回执。

`prepare_mcp_activation_candidate` 只接受已检查的候选视图。它与 Lua 候选调用共用用户根目录及
内置命名空间校验，固定原请求、完整候选包及其凭据和配置。标准输入输出启动器从候选清单解析，
继续复用现有执行环境、平台及路径检查；不会为了通过普通解析而临时发布候选或分配代次。
普通 `resolve_mcp_stdio_launcher_descriptor` 仍要求公开目录中的精确代次，零代次候选继续被拒绝。

`VulcanPluginPreparedMcpCandidate` 的克隆共享原请求排他锁和实际包、凭据所有权；原事务句柄、
管理器或前台视图释放，都不替代最后准备所有者的释放。准备失败按正常所有权释放，不能留下隐藏锁。
单独复制服务器描述符、路径或 UUID 不足以替代该所有者，也不证明进程已经清理。
现有 `activation_candidate_calls` 仍只查询正式 Lua 调用，不包含 MCP 准备对象；
空调用列表不能用于推断候选 MCP 所有者已退出，原请求锁继续独立约束提交和恢复。

宿主 `candidate_global_mcp_server_configs` 消费准备对象并返回 `PreparedPluginMcpConfigs`，
同时保留原所有者及全局配置。它不接受公开管理器，不能读取最新公开配置；
HTTP、SSE、标准输入输出及 OAuth 值均使用候选捕获的配置与凭据修订。
缺失选定值直接报错，不能改用前驱或旧命名空间。会话作用域仍需要明确会话授权，不混入全局配置。

`candidate_local_mcp_server_configs` 通过同一密封物化链只选择标准输入输出声明，服务安装验证使用它；
包括会话声明的本地服务器，但用途仅为隔离初始化检查，不能赋予会话业务路由或跨会话调用权限。

物化本身只准备输入，不代表就绪。宿主 `CandidatePluginMcpRuntime::start` 同步消费密封的
`PreparedPluginMcpConfigs`，把同源准备所有者与服务器定义一起移交给原 MCP 生命周期。
调用方不能另传身份或替换配置。创建先交付唯一控制对象，随后通过可克隆观察对象等待就绪；
观察对象仅提供原请求身份、服务器状态、就绪及实际释放查询，不暴露业务工具或发布分区。

候选用途显式采用单次初始化与发现；失败、连接丢失或观察重试都不会自动重启候选。
普通托管分区保留既有有限重连策略，用途不从零代次推断。关闭请求锁存；控制对象销毁请求
原生命周期关闭，取消就绪／释放等待只结束该次观察，不推进事务或销毁后台工作。

原准备所有者进入聚合资源范围，全部生命周期任务及其每次实际传输共同保留该范围。
任务在首次轮询之前、OAuth 准备及启动许可等待期间同样保留它；每次后端启动继续使用原资源回执。
最终任务销毁撤销原注册表的传输引用，执行器丢失时记录未确认关闭的失败，不能让诊断句柄继续
持有实际传输。非正常销毁不伪造成功停止，实际后端所有者仍独立完成清理。

`wait_until_released` 只等待此聚合范围的最后实际引用释放，不要求失败状态被改写成已停止，
也不请求关闭。保留观察对象不会延长原包、环境、凭据及请求租约；其他独立准备克隆仍有自己的
所有权，聚合回执不证明它们也已释放。释放不代表协议关闭成功、远端副作用回滚或安装回调成功。
服务协调器仍须结合原失败／安装记录作出决定；此入口不自动提交持久事务，不替代原子路由交接。
`validate_and_release` 是服务更新使用的完整检查：按既有宿主预算分别等待就绪、原协议关闭及最终资源释放，
三个边界均成功才返回成功；就绪失败仍请求原关闭并保留各边界失败，取消通过原控制对象请求关闭。

### 候选执行环境租约

包含标准输入输出声明的候选在解析任何启动器前，取得执行环境的共享文件锁，并由
`VulcanPluginPreparedMcpCandidate` 的实际共享所有者保留。远端声明不创建环境或取得此锁。
环境创建函数也在整个复制、依赖安装、发布及暂存清理期间持有共享锁；
单代次删除、过期环境删除及卸载入口均先取得排他锁，占用时明确失败，不执行部分清理。
卸载在移动插件包或删除配置前检查该锁，防止前面状态已变更后才发现环境仍被使用。
最后一个准备所有者释放后才允许回收；失败准备必须同时释放环境与请求所有权。

原生 Lua 候选在已登记调用的阻塞准备阶段、创建或复用环境之前，也由原 `CandidateExecution`
取得同一共享文件锁。首次获取串行化，成功后不被后续观察替换或提前释放；原正式调用及实际
原生池的能力绑定共享该所有者，直到最后实际退役才结束环境租约。前台超时、取消和初始化结果
均不能替代此所有权。环境验证失败的调用沿既有清理退役路径释放租约，不创建额外监督管理器。
无 Lua 声明或缺失安装回调的直接成功分支不进入文件系统准备，因此不创建环境或租约文件。

锁位于 `<plugin_runtime_root>/.environment-leases/<plugin_id>.lock`，按宿主环境根及插件身份隔离，
不放入会被删除的版本或指纹目录，且不随回收删除。该永久身份也用于环境删除后的再次创建。
粒度为插件，匹配当前整版本和暂存目录删除方式；同插件多个代次可同时共享使用，
清理则等待全部实际共享所有者释放，不同插件互不阻塞。占用错误需由协调器保留为待清理，
不得通过删锁、抢锁或仅清空运行时计数消除。

此协议约束通过这些入口操作的宿主；旧版本宿主不能与新宿主并发管理同一环境根。
普通返回裸路径的准备接口只在函数执行期间保留锁，不自动授予返回路径持久所有权。
长期租约由候选 MCP 准备对象经专用入场移入实际后端，原生 Lua 候选则由原调用及原生池共享保留，
不能仅凭前台任务返回便释放。
该租约不是进程退出证明，也不代表其他普通执行路径已经完成所有权接入。

## 回收与重开

### MCP 关闭观测边界

标准输入输出、HTTP 与 SSE 传输共用一次关闭操作及五秒观测预算。关闭工作拥有原服务或监听器，
超时及等待方取消只结束当前观测；并发或后续关闭仍等待同一结果，不把已移交的服务槽位视为成功。
传输析构请求尚未启动的关闭，实际清理由独立任务继续；错误结果不被成功覆盖，执行器中断显式报错。

生命周期监督使用 `shutdown_and_wait` 等待同一次关闭的最终结果，不把五秒观察期限当成清理期限。
前台就绪和停止屏障仍按各自有限预算返回，后台继续持有精确传输；前台超时或取消不移交其所有权。
清理开始即撤销工具绑定并进入 `stopping`，隐藏缓存工具，保留触发清理的已脱敏错误；
实际结果到达后更新原运行时状态。普通连接重试必须先完成旧实例清理，真正清理失败时停止重连。
设置页面显示“停止中”，插件目录将该状态映射为 `draining`。自定义传输的默认最终等待入口
沿用其原关闭契约；具有有界关闭观测的实现必须覆盖最终等待入口，不能返回仅属于观察者的超时。

标准输入输出与 HTTP 还独立保留传给官方服务的底层传输关闭回执。当前锁定的
`rmcp 3.1.2` 会记录底层关闭错误但仍返回正常服务退出原因，因此服务任务等待成功不足以证明关闭成功。
最终结果同时检查服务任务与底层回执；后端错误或未报告完成就销毁均显式失败。
协议消息及原具体错误类型保持透传，鉴权错误来源链不改变。此处复述上游服务行为，
归属为锁文件指定版本的 `rmcp/src/service.rs`；升级该依赖时须回读关闭实现并运行真实服务回归。

退役登记保留独立运行时状态句柄，不延长执行租约；最后调用方释放仍立即请求关闭，
但旧分区的清理状态不会随执行租约的弱引用消失。旧 MCP 分区只有全部服务器状态为已停止且没有关闭错误，才通过当前退役状态检查。
错误状态必须继续阻止把旧分区当作已安全退役；该状态检查与关闭等待屏障保持一致。
后续退役登记及回收状态查询都会清除已经成功停止的历史，避免重复更新累计已完成运行时。
这些判断仅说明当前传输接口报告的关闭结果，不能代替操作系统进程树退出证据。
标准输入输出后端现使用官方 `AsyncRwTransport` 编解码及服务协商，直接子进程的创建、终止和等待
由 `stdio/child.rs` 的独立原生线程拥有。初始化观察取消、传输析构或调用方执行器退出只升级同一
子进程的停止请求，不把清理派生到已退出的 Tokio 执行器。正常关闭先启动三秒宽限计时，避免协议
写入管道刷新阻塞时永远无法触发终止；控制通道只有一个唤醒槽位，停止级别单调升级。
Windows 标准输入输出进程使用专用、不可继承且未开放脱离权限的 Job；先创建并配置 Job，
再以挂起状态创建根进程，绑定成功后才恢复线程。绑定或恢复失败明确终止启动，由原监督线程继续清理。
原生接口集中于 `vulcan-process-lifecycle`；MCP crate 保持禁止 `unsafe`。
线程恢复使用有效子进程与已打开线程句柄核对身份，枚举或恢复错误不会静默继续启动。

Windows 成功回执要求根进程实际 `try_wait` 完成且专用 Job 的 `ActiveProcesses` 归零，
随后释放根进程与 Job 句柄。父进程退出不能越过仍存活的后代；终止请求或任意完成端口事件不作为成功证据。
实际终止针对保留 Job 句柄；仅在绑定本身失败、子进程尚未恢复时，使用原根进程句柄清理失败启动。
真正等待／终止错误显式发布，原生线程继续持有实际进程范围并尝试清理，错误不意味着允许回收。
根进程先退出、后代继续持有真实文件锁的测试覆盖正常关闭、观察取消和调用方执行器销毁。

该实现每个根进程使用一个原生监督线程，需要纳入后续性能验收。Windows 的挂起创建与加入 Job
仍是两步操作；整个宿主在两步之间被强制终止的窗口尚未闭合，属于发布前必须处理的门槛。
当前 Unix 确认范围仍是直接子进程，完整进程组及跨平台验收待完成。
标准错误读取已由独立原生线程直接持有标准库管道，不经过 Tokio 管道适配器或阻塞读取任务。
输入持续分帧、脱敏及日志条目／字节上限沿用同一实现；正常 EOF 刷新最终完整尾行，
实际读取错误明确返回并丢弃未完成行，不能当作正常 EOF 发布部分诊断。
原生读取者先释放实际输入句柄，再发布共享回执；观察取消、重复等待及原执行器销毁不会取消读取。
回执发布者未报告结果便消失明确报错。实际后端只有在协议关闭、进程范围退出及全部三条管道的原释放回执均成功后才返回成功。
协议或进程清理已失败时立即保留该错误，原生诊断所有者继续持有实际管道直至结束；错误不证明资源已释放。
每个标准输入输出实例另有一个原生诊断线程，其成本需计入最终性能验收。

协议输入／输出由 `stdio/native_pipe` 直接消费原标准库句柄，官方 `AsyncRwTransport` 继续负责分帧、
解析及发送。空闲适配器与每次排队／在途阻塞操作共享同一原生所有者；最后所有者先释放实际句柄，
再发布原回执。一次输入输出最多缓冲 `PIPE_IO_CHUNK_BYTES` 定义的字节数，每条管道最多一个在途操作。
读取观察取消保留原操作及未交付字节；整个读取适配器释放会取消尚未开始的操作，已开始操作仍保留句柄。
写入接收采用缓冲语义，实际交付由刷新确认；排队写入／刷新被执行器拒绝或丢弃时，即使调用方不再观察，
也保留明确失败。实际输入输出错误、工作线程失败及所有权锁中毒均不能转成正常结束或成功交付。
关闭先启动原生进程宽限，再关闭官方写入端、释放协议适配器，最后等待进程范围及全部实际管道回执。
成功关闭可重复观察，取消等待不放弃原所有权。某项已失败时可以先返回错误，其他原生所有者仍负责其真实资源；
错误本身不是回收依据。

协议输入输出复用启动运行时的阻塞执行池，不为空闲未轮询句柄额外创建专用线程；但已挂起的实际读取会占用
阻塞工作线程，不能据此宣称所有空闲连接均无线程成本。最终须验证大量连接下的阻塞池容量、普通宿主任务延迟、
线程／内存和长时间稳定性；Windows 通过不能替代 Unix 管道调度与进程族验收。
标准输入输出底层已提供 `McpTransportResources` 与独立 `McpResourceRelease`：调用方在启动前把精确宿主
资源包移入单次启动范围，再调用 `StdioTransport::spawn_with_resources`。资源包对低层传输不透明，
不能从这里读取或重选插件、配置或凭据。原生进程线程在首次创建前取得所有权；待移交管道也保留它，
随后每条实际管道连同其阻塞操作分别持有同一范围。实际句柄先释放，宿主租约随后释放，最后发布原回执。
字段销毁次序依据 [Rust 析构契约](https://doc.rust-lang.org/reference/destructors.html#destructors.operation)，
并通过真实文件锁验证，不能交换原生资源与租约字段顺序。

释放回执不持有宿主资源，不依赖初始化成功返回传输对象；观察取消和重复观察均不影响实际清理。
该回执只证明本次启动持有的资源引用已释放，不能证明协议写入成功，也不能替代原进程／管道错误结果；
其他宿主对象若仍持有原候选资源，其锁仍然有效。普通启动复用同一所有权路径，资源包为空。
启动分派 `McpTransportLaunchSpec::launch_with_resources` 已将单次范围移交给声明的标准输入输出、
HTTP 或 SSE 入口。HTTP 客户端的每个克隆及独立 GET／POST 响应流保留同一范围；SSE 客户端、
监听任务和当前响应流也分别保留。释放包装时先销毁其实际资源，再释放宿主范围。
普通连接入口传入空宿主资源包，复用相同路径。

HTTP 使用官方工作任务的同一个取消令牌，覆盖初始化鉴权、等待响应头及响应体流。当前锁定
`rmcp 3.1.2` 的初始化直接等待请求及流，不独立选择工作任务取消，因此不能只依靠外层连接 future 析构。
客户端把该取消传递至原请求及响应流；会话删除仍沿官方单独清理流程进行，不因普通工作取消直接跳过。
SSE 监听器在打开连接、读取流及重连延迟期间均响应其原关闭令牌。上游行为归属为锁文件指定版本的
`transport/worker.rs`、`transport/streamable_http_client.rs` 和官方 reqwest 适配；
升级时须回读初始化、取消与会话删除实现并重跑真实回环连接测试。

远程释放回执证明绑定的应用层客户端、请求及响应流所有者已释放，不能证明远端操作撤销、
远端会话删除成功、对端确认断开或操作系统全部 TCP 状态消失。网络库内部连接驱动的生命周期
也不能由此回执冒充。SSE 传输对象自身保留客户端，宿主必须结束在途调用并释放传输引用后再等待
最终资源回执，不能在仍持有该对象时等待自身租约消失。

宿主在每次初始化开始前登记独立原回执，经注册表把同次资源范围移入启动分派。单个分区在启动
任何服务器前拒绝重复标识，确保每个服务器仅有一个生命周期写入者，不覆盖仍在清理的启动回执。
初始化、目录发现及连接阶段的关闭先退出选择表达式并销毁落选任务，再移交本地传输引用。
清理撤销公开入场，等待原关闭操作，释放自身传输引用，然后等待实际资源回执。初始化未返回传输
也走同一屏障；尚有实际所有者时保持停止中，前台超时或取消不能提前完成该屏障。
关闭或释放本身失败仍保留错误并阻止重连、成功停止及回收，不把失败回执改写成成功。

普通启动传入空宿主包，由实际底层所有者控制其释放回执；候选专用入场将真实物化对象的包、环境、
请求与凭据权威绑定至该次范围，并在外层聚合全部监督任务。该入场与存储层原事务屏障共同约束
候选工作期间的提交、中止及恢复，仍不能当作候选更新端到端完成。
完整服务更新和重启恢复继续属于未完成的交付范围。

### 所有者 MCP 的实际排空

所有者范围标准输入输出分区在同一个入场锁内同步启动并登记原聚合释放回执，早于连接等待。
聚合范围同时覆盖尚未发布的调用者、监督任务及实际底层资源；同一键的并发实例分别保留，
替换、撤销或从公开注册表移除不会删除其清理证据。登记仅持有控制及观察句柄，不保留执行租约。

`begin_plugin_owner_drain` 关闭目标入场并停止全部原实例，包括尚未发布或已经移除者。
`wait_plugin_owner_drain` 使用一个总期限等待原回执；取消或超时不清除证据、不重新开放。
`finish_plugin_owner_drain` 在同一锁内核对原资源已经释放后才允许重新开放；仍存活的所有者
以原插件、代次及会话标识报告。迟到启动检查锁存关闭状态，不能在重新开放后发布已经退役的实例。
全局关闭同时锁存所有者入场关闭，旧访问代次不能创建新进程。

服务启用、停用、相应回滚及已停用插件更新消费这条屏障，预算引用
`AgentRuntimeBridge::RETIRED_MCP_PARTITION_DRAIN_TIMEOUT`，不建立第二份时长定义。
停用清理失败进入既有告警投影；重新启用及更新在确认原资源释放之前不开始新安装或启用副作用。
此屏障仅证明原资源范围释放，历史协议失败不被改写为成功；它不扩展上文尚未完成的 Unix
进程族保证、Windows 整宿主强制退出窗口，也不等于完整启用中更新与重启恢复已经完成。

### 全局及所有者 MCP 的统一排空

`begin_plugin_mcp_drain` 关闭指定插件的所有者入场，撤销当前全局工具绑定，并停止该插件当前、
已退役及正在准备的原全局实例。登记仅保留独立控制及释放观察；同一原实例按控制身份去重，
不同启动即使插件、代次和服务器名相同也分别观察。用户 MCP 和其他插件保持原连接。

全局替换在首次就绪等待前登记原实例。取消或失败保留登记及关闭证据；成功交接在同一观察锁内
核对原关闭锁存位，随后移入候选访问。独立原实例索引跨就绪成功保留观察，直到实际释放；即使
候选已经就绪但尚未发布，旧服务访问也能排空它，应用关闭不会遗漏这段交接。全局管理操作仍由
服务的既有管理任务串行化；此接口不向
普通插件授予全局启动权限，也不以所有者闸门代替管理操作之间的互斥。

`wait_plugin_mcp_drain` 同时核对当前访问和共享原实例观察，使用一个总期限等待所有者资源、
全局协议关闭及原聚合范围释放，最后复核观察与所有者闸门。只关闭所有者入场不能满足仍在运行的
全局分区。取消、超时及清理错误保留原证据。协议终态与物理资源释放必须同时满足，历史错误不会
被删除后冒充成功；陈旧控制或传输对象引用的存在本身也不证明实际子进程仍存活。

旧全局工具绑定在撤销或原运行时关闭后拒绝新调用；实际传输读取在原注册表读锁内核对关闭状态，
不能在排空完成后重新取得原传输。绑定发现同时过滤已撤销及关闭的分区。

服务在停用策略持久化后关闭全局分区，持久化之前失败仍可保留原全局连接。已提交停用的回滚先
确认全部旧 MCP 排空，再按操作开始时固定的描述符重建候选，就绪后恢复启用策略及匹配扩展代次。
失败启用的候选在生命周期补偿前显式退役；候选清理及补偿错误均保留。已完成启用的回滚同时发布
停用目录和移除全局分区，不能仅修改内部管理器状态。成功发布新候选后，仅重新开放所有者入场，
不再次对新全局分区执行排空。

普通启用前清理与当前已停用插件更新同样使用统一屏障，预算仍只引用既有服务常量。
上述本地运行时与内容插件服务测试不代表真实桌面 RPC、跨平台进程族、完整启用中更新或启动恢复
已经验收；这些仍按方案后续实施。

### 包回收屏障

回收先持有插件选择锁，拒绝未完成事务保留的前驱／目标及当前选定代次，再尝试取得排他代次锁；有实际固定句柄时返回忙碌。
已准备代次在删除前复核原内容。准备未完成的代次可以按原持久身份明确清理，但不能直接固定或激活。

真正删除包字节前先保存正在回收状态。文件占用或其他删除失败保留此状态，禁止再次固定该代次；基础设施恢复后只能显式继续原清理。
完成后保留已回收身份记录和锁文件，不再保留插件包字节。重复回收返回已经完成，不重建旧内容。

当前测试覆盖真实 Windows 文件占用及子进程租约；中断准备的重开测试采用明确构造的实际磁盘阶段快照，
不等同进程崩溃或硬件断电验证。Windows 目录持久性、跨平台验证、孤儿目录扫描、保留容量策略及宿主重启恢复仍须按完整方案验收。
