# 插件不可变代次存储

## 归属与当前接入状态

存储权威实现为 `crates/vulcan-plugin-runtime/src/generation_store.rs` 及其子模块；目录接入实现为
`catalog/generations.rs` 与 `runtime/lifecycle.rs`。生产公开目录入口已经消费既有受管激活记录，
快照保留实际代次租约，宿主路由代次随物理身份及激活修订变化。
第二版激活记录已把包选择与完整权限批准放入同一次原子替换，运行时消费同一选定授权。
第三版再共同选择明确的凭据修订，MCP 描述符和实际配置解析消费这份固定绑定。
第四版增加同次选择的普通配置文档，旧目录及独立 MCP 描述符保留原文档。
Service 的安装／更新流程尚未切换为不可变事务；跨 VM、会话与外部进程的引用传递仍未完整接入。
已提供持久凭据暂存、候选清理、实际读者租约及退役回收原语，并接入 OS 后端；
已提供按原请求恢复的持久选择提交日志，区分选择发布与路由交接确认；
服务层回收调度与完整更新事务尚未完成。
不能据此宣称外部副作用补偿或整条运行时路由发布已经完成。

## 存储身份与目录

`VulcanPluginGenerationStore::open` 接受已经存在的用户插件根目录，并在其下显式创建私有
`.vulcan-generations/`。调用不会修改用户配置、授权文件或现有插件包。

```text
.vulcan-generations/
  active/<插件标识>.json
  locks/<插件标识>.lock
  locks/<插件标识>-<代次 UUID>.lease
  locks/<插件标识>-credential-<凭据修订>.lease
  locks/<插件标识>.transaction.<请求 UUID>.lock
  credentials/<插件标识>/<凭据修订>.json
  transactions/<插件标识>/current
  transactions/<插件标识>/<请求 UUID>.json
  packages/<插件标识>/<代次 UUID>/
    generation.json
    <插件标识>/...
```

代次身份包含插件标识、规范 UUID、已校验版本和完整内容指纹。路径完全由固定布局及已校验身份派生，
记录不提供任意磁盘目标。包指纹和清单校验复用当前目录加载器的实现。
代次及旧激活格式由 `RECORD_VERSION` 决定，已授权激活格式由 `AUTHORIZED_ACTIVATION_VERSION` 决定；
凭据绑定激活格式由 `CREDENTIAL_ACTIVATION_VERSION` 决定，配置绑定格式由 `CONFIGURED_ACTIVATION_VERSION` 决定。
原元数据和前三版激活使用 `MAX_RECORD_BYTES`；第四版使用从该上限及唯一配置上限派生的 `MAX_ACTIVATION_BYTES`。未知版本、未知字段、
身份不匹配、重定向路径、缺失记录及超限记录明确拒绝。

## 目录选择与授权投影

`open_existing` 只接受既有完整存储；缺失返回空，不创建目录，也不补齐损坏布局。
普通目录刷新不安装新存储、不迁移旧平铺包、不改写授权或配置。
`activation_plugin_ids` 枚举规范 `.json` 激活名称，包含停用记录；原子写入器的 `.tmp` 暂存文件不提供选择权威。
该枚举不是跨插件的原子快照。加载器对枚举身份及旧包身份逐个调用 `pin_active`，在每个插件的选择锁内取得其实际租约。
查询已枚举身份时记录消失会明确报错，不解释为允许旧包接管。

存在受管记录时，以该记录为唯一用户包选择。显式空选择会隐藏同名旧目录；记录损坏、所选包缺失、内容变化或命名空间忙碌时，
该插件显示不可用并保留诊断，不加载同名旧包。无法读取完整布局或枚举全部身份时，阻止用户包暴露并保留根级诊断；内置包独立加载。
内置同名包仍优先于用户包。工具名冲突只在受管选择及内置优先级全部确定后检查，隐藏旧包不得占用工具名。

`VulcanPluginDescriptor::managed_package()` 返回持久激活修订及实际代次句柄。
完整快照或描述符克隆仍存活时，旧代次不能被回收；仅复制工具、技能、进程配置或路径不等于保留此所有权，
后续运行资源必须显式传递代次句柄。当前测试只证明目录／描述符层引用，不能代替 VM 或外部进程层验收。

第一版受管选择及旧平铺包沿用独立授权记录的精确插件、版本、内容指纹及完整权限比较；
第二版及后续选择以同一激活记录中的完整批准为唯一权威，不读取或修补旧授权文件。
相同版本但字节变化必须重新确认精确包及权限。新增持久激活修订或物理 UUID 会推进进程内路由代次；
插件从目录消失后重新出现也不得复用旧路由代次，计数耗尽明确报错。
旧安装入口在开始复制前拒绝已观察到的受管激活或停用记录，避免报告成功却写入隐藏平铺包。
这项检查不是跨进程安装事务；完整管理流程仍须通过同一事务与选择屏障串联准备、授权、发布及恢复。

## 准备与实际引用

`prepare` 先对照用户已经检查的内容指纹，分配新代次及实际共享租约，保存准备身份，再复制文件、同步并复核完整内容。
只有全部成功才写入已准备状态并返回 `PinnedVulcanPluginGeneration`。失败不发布激活记录，保留诊断材料；
完成代次目录分配后发生的准备失败还返回 `retained_generation`，宿主可按精确身份查询或安排清理，不能解析诊断文本猜测路径。
如果第一份身份记录本身写入失败，后续清理仍须先验证实际记录，不以错误中的身份替代磁盘证据。

固定句柄的克隆共享真实租约，最后一个克隆被释放才结束该租约。使用 `package_root()` 对应文件期间必须保留固定句柄，
不能把复制出的路径字符串当成资源所有权。`pin_active` 在释放插件选择锁之前取得选定代次租约，封闭查询与回收之间的竞态。

锁使用标准库的非阻塞文件锁：同一插件的选择及阶段读取使用共享命名空间锁，选择变更及回收使用排他命名空间锁；
实际代次引用使用共享代次锁，回收另要求排他代次锁。并行目录读取可以共存，不会仅因另一个读取者而把插件投影为不可用。
这些约束覆盖遵守同一协议的线程和进程，不充当对非协作文件系统修改者的安全沙箱；锁文件不会在回收时删除，避免后继所有者锁住另一个文件对象。
标准库契约见 [Rust 文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock) 和
[共享文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock_shared)。

## 激活修订与边界

从未发布的命名空间观察为修订零。`activate` 和 `deactivate` 只接受精确当前修订，在同一插件的文件锁内写入后继记录。
停用保留记录及修订，不删除记录后重新使用零；修订耗尽明确拒绝。多个存储实例竞争同一前驱只能有一个成功，其他实例收到忙碌或修订冲突。

`generation` 是必需但可为空的字段：空值表示明确停用，字段缺失表示损坏，不能等同处理。
激活记录的原子写入错误不保证变更未发生，宿主必须回读精确记录后再决定如何继续，不能重放生命周期或业务回调。

### 包选择与权限共同发布

`activate_authorized` 接受实际固定代次、精确前驱修订及明确批准的完整权限集合。
权限键来自与授权预览共用的清单映射；发布前在同一命名空间锁内重新验证包字节，并要求权限完整且不重复。
调用方输入顺序可不同，存储使用清单派生的规范顺序。准备包本身不会批准权限。

该入口写入第二版激活记录，`approved_permissions` 是必需、非空值的列表；空列表只批准真实零权限包。
所选插件身份、物理代次、版本、指纹和批准权限在一次原子替换中可见，不存在第二个授权指针。
`activation` 检查版本及字段一致性、有序唯一性和停用记录的空权限；`pin_active` 在原选择锁内取得真实租约，
再对照实际已验证清单核查完整权限。缺失字段、JSON 空值、重复字段、未知版本或字段均明确拒绝，
与实际清单不一致的授权不能被固定并进入有效目录。

第一版仅允许缺失该字段，不允许携带新版授权，即使字段值为 JSON 空值也拒绝。普通读取不升级或改写。
只有显式已授权激活入口可以提升格式；升级后的命名空间不能使用旧 `activate` 降级。
`deactivate` 保留当前格式和单调修订；第二版停用记录保留明确空批准集合，后续启用仍要求已授权入口。
旧 `authorize_user_plugin` 在当前目录已选择第二版或后续版本时明确拒绝，避免写入不再生效的旁路授权文件。

目录描述符保留与激活修订同源的批准快照及实际包租约；克隆旧描述符不会因新选择发布而改绑权限。
这一能力只证明存储及运行时投影的包／权限一致性；凭据暂存、更新回执、候选就绪、路由和数据迁移
仍须由后续宿主事务协调，不把低层激活成功解释为完整插件更新成功。

### 包、权限与凭据修订共同选择

`VulcanPluginCredentialRevision` 是规范小写、带分隔符且非全零的 UUID 身份；解析拒绝别名，不能静默规范化。
它独立于物理包 UUID 和激活计数，因此仅轮换凭据可以继续使用同一物理包。
`activate_with_credentials` 接受固定包、精确前驱修订、完整批准及明确凭据修订，在原选择锁与原子写入器下共同发布。
该低层入口与 `pin_active` 都要求同一精确物理包身份的已暂存日志；缺失、准备中、回收中或已丢弃均拒绝。
日志还必须与实际包的完整声明键清单一致，不能因字段各自合法而接受漏键。权限和凭据清单由同一次包校验派生，固定句柄保留两者，不额外扫描包字节。
它不重新读取 OS 秘密，也不执行应用就绪；后续 OS 读取失败仍明确报告，不能因日志成功就声称插件或路由可用。

| 激活格式 | 权限字段 | 凭据字段 | 配置字段 | 凭据读取绑定 |
| --- | --- | --- | --- | --- |
| 第一版 | 必须缺失 | 必须缺失 | 必须缺失 | 原命名空间 |
| 第二版 | 必需且非空值的完整列表 | 必须缺失 | 必须缺失 | 原命名空间 |
| 第三版 | 必需且非空值的完整列表 | 必需且非空值的规范修订 | 必须缺失 | 指定修订命名空间 |
| 第四版 | 必需且非空值的完整列表 | 必需且非空值的规范修订 | 必需且非空值的明确选择 | 指定修订命名空间 |

任一不匹配组合、重复字段或未知字段均拒绝；JSON 空值不能代表旧绑定。第三版命名空间不能经旧激活入口降级。
停用保留第三版、空批准、空包选择及最后凭据修订；保留修订只提供后续清理身份，不构成执行授权。
重新激活必须再次明确提交修订。普通读取、目录刷新及旧格式加载不写入迁移。

受管包快照及每个 MCP 服务器描述符携带 `VulcanPluginCredentialBinding`，明确区分 `Legacy` 与 `Revision`。
HTTP、SSE、标准输入输出、会话 MCP 的 URL、请求头、OAuth、参数及环境变量中的秘密均通过同一描述符绑定解析。
`PluginMcpSecretStore::read_secret` 必须接收该绑定，不能查询当前全局目录来重选历史调用的修订。
旧远端描述符可继续解析原修订；旧标准输入输出描述符仍受既有启动器代次检查约束，不能绕过过时代次拒绝。
已经物化的配置保留原值。受管包及每个可独立克隆的 MCP 描述符同时持有实际凭据共享租约，
因此旧目录或脱离目录的旧服务器声明仍可读取原修订时，排他清理必须返回繁忙。
旧格式的普通 `config` 来源仍由 `plugin_server_configuration` 查询当前管理器配置；
第四版直接读取精确描述符持有的选定文档，不查询旧文件或最新目录来替换历史配置。

OS 适配器将新修订放入独立的 `vulcan-code.plugin-mcp.versioned-v1` 服务，账户摘要依次编码插件标识、
凭据修订、服务器标识和秘密键，每个 UTF-8 组件使用无符号六十四位大端字节长度分帧。
旧服务及旧账户算法保持原样；选定值缺失或后端失败直接报错，不查询旧修订或原命名空间。
错误不包含秘密值。当前普通凭据编辑入口观察到版本绑定时明确要求凭据修订事务，防止写入不再被使用的旧账户。

暂存、候选恢复及读者回收原语见下节。完整服务提交决定、配置／凭据编辑事务、卸载和回收调度仍待上层接入。
本地测试覆盖真实选择文件、全部 MCP 配置分支及 Windows 随机测试命名空间的实际安全存储隔离；
配置物化没有连接远端服务器或执行假启动器，也不能代替跨平台、掉电或端到端更新验收。

磁盘选择成功只证明存储层选择。宿主仍须先完成新增权限授权、隔离候选就绪、旧写入者排空和路由事务准备，
并把磁盘记录、凭据、数据迁移、工具／Hook／UI 路由的实际阶段纳入持久事务。当前低层 API 不会替宿主执行这些动作。

### 普通配置与全部选择共同发布

`activate_configured` 接受实际固定包、精确前驱修订、完整权限、已暂存凭据及明确配置选择，
使用相同插件屏障及原子写入器发布第四版记录。配置变化复用激活修订号，不新增第二个可变选择指针。
纯配置变化可以继续选择同一物理包和凭据；旧观察、旧目录和独立 MCP 描述符仍保留原配置。
目录中同一修订的贡献共用文档引用，避免按服务器复制完整配置。

`configuration` 必需且不能为 JSON 空值；`kind: not_declared` 仅适用于实际包未声明配置，
`kind: document` 必须带完整 `value`。文档值本身可以是 JSON 空值，但只有精确包内 Schema 允许时才可选择。
不从默认值、旧文件或新版本配置补齐任何字段。选择前及固定时都复用原包配置 Schema 校验，
版本、字段、声明或 Schema 不符明确拒绝；记录损坏不修复、不降级。

配置紧凑编码使用唯一 `MAX_PLUGIN_CONFIGURATION_BYTES` 上限（当前四兆二进制字节）。
第四版记录总上限由原元数据额度加该值派生，采用紧凑编码；前三版仍保留原较小记录上限。
实际读取同时限制文件长度与读取字节数，外部增长不能绕过。旧平铺配置不被自动迁移或裁剪；
显式迁入第四版时必须先通过新边界及实际 Schema 校验。调试输出隐藏配置内容，校验及解码错误不回显用户文档。

第四版不能经旧激活 API 回退至外部配置权威。停用保留原格式、最后配置及凭据身份，并使用空包和空批准；
保留值提供明确后续处理信息，不提供执行权限。重新激活须再次提交完整选择。

管理器读取第四版时返回原描述符选定文档；初始化入口识别已选文档并返回“未新建”，不触碰无关旧文件。
当前旧配置修改入口对第四版明确要求完整激活事务，避免写入不再被消费的状态文件后报告成功。
前三版和旧平铺包继续使用既有动态读取及写入契约。完整的第四版管理编辑、原生动态修订提交、
生命周期排空和路由发布仍待实现；这项临时拒绝不是完整配置编辑产品能力。

### 持久凭据暂存与候选恢复

权威实现为 `generation_store/credential_staging.rs` 及其子模块；OS 适配器位于服务内核的
`plugin_mcp_secret_store/staging.rs`。`begin_credential_staging` 在原插件命名空间屏障内重新验证实际包，
从生产 MCP 清单派生全部秘密槽位，要求请求逐项提供值或显式缺失，再持久保存原修订日志。
额外键、漏键及已配置空字符串均拒绝；日志只保存精确包身份、修订、键名、已配置子集和阶段，不保存值或值摘要。
此步骤没有 OS 副作用。已存在修订记录绝不复用，已被当前选择或停用记录引用的身份不能重新作为候选。

`VulcanPluginCredentialStaging` 是不可克隆的原准备所有者，持有实际非阻塞排他修订文件锁。
同一修订的另一准备、恢复或清理得到繁忙结果；仅丢弃内存所有者会释放锁，不删除凭据或日志。
`write_and_finish` 先验证完整输入及原日志，再比较全部既有候选值：相同值保留，不同值拒绝覆盖，
仅写入缺失且声明已配置的值。全部槽位读回与输入一致后，才原子发布 `staged`。
明确缺失槽位也必须确实不存在；`staged` 表示凭据集合已暂存，不能代替 MCP 就绪或权限审批。
外部后端错误文本不会传播进日志，避免后端把秘密嵌入异常；保留稳定的失败类别和操作阶段。

| 日志阶段 | 允许操作 | 禁止操作 |
| --- | --- | --- |
| `preparing` | 原所有者写入；释放原锁后显式恢复；显式丢弃 | 发布第三版选择 |
| `staged` | 精确包身份选择；真实共享固定；退役后排他回收；状态读取 | 再次写入、以候选清理接口删除 |
| `discarding` | 继续原清理、状态读取 | 恢复写入、共享固定、选择 |
| `discarded` | 状态读取、幂等清理确认 | 复用身份、写入、选择 |

发布检查点错误可能发生在 OS 写入之后，不能推断凭据没有写入。调用方按原修订回读：若仍为准备中，
可显式提交同一完整值集合，已经一致的值不会再次写入；若为已暂存，则消费原结果，不能重新暂存。
日志不保存尚未写入值的摘要，因此恢复者必须持有原请求值；丢失这些值时可以查询或丢弃原候选，不能猜测补齐。

`credential_plugin_ids` 与 `credential_revisions` 只读枚举持久身份，包括已完成记录；临时文件不提供恢复权威，
未知路径类型和不规范身份明确拒绝。枚举不是跨插件快照；随后必须逐条读取严格日志。
普通启动扫描不得因此自动重放写入、生命周期或清理。`resume_credential_staging` 只重取原准备排他锁，不调用 OS 后端。

`discard_credential_staging` 只清理未完成候选，并拒绝当前选择／停用记录引用和已暂存修订。
删除任何 OS 条目前先持久保存 `discarding`，按原完整键清单逐项删除并确认缺失，最后保存 `discarded`。
中途失败保留原清单，可按原身份继续；不需要从最新插件包猜测清理键，也不读取、覆盖或删除旧命名空间。
已暂存修订使用下述显式退役回收入口；候选丢弃入口不扩大语义。

### 凭据真实读者与退役回收

`PinnedVulcanPluginCredentials` 持有共享文件锁及原非秘密日志快照，克隆共用同一实际句柄。
`pin_credentials` 用于候选就绪或显式原修订读取；它重新校验精确包并要求已暂存日志。
`pin_active` 在同一插件选择屏障内固定实际包和所选凭据，随后才返回观察结果。
第一、二版以及显式停用观察没有凭据租约；停用只保留历史身份。

暂存所有者持有排他锁直到被释放，即使已经成功发布 `staged` 也不自动降级锁；
调用方必须先释放写入者，再固定共享读者。二者之间无所有权保证，若竞争回收先取得原屏障，
固定返回明确错误；调用方不能假定候选仍可读。实际事务协调须保留原身份并处理该结果。

受管包和每个 MCP 声明分别保留可克隆租约，目录刷新不会转移或释放外部仍持有的旧引用。
只复制 UUID、绑定或日志快照不会保留凭据；绕开描述符的调用方必须自行持有公开固定句柄直到最后一次读取。
已物化的秘密字符串不再查询安全存储，可与来源条目的生命周期分离。

`collect_credentials` 用于已暂存候选中止或旧修订退役。它在原插件选择屏障内取得排他修订锁，
拒绝仍为有效选择的修订，并要求所有真实读者及写者已经释放。停用记录不授予执行权限，
因此它引用的修订可在读者全部释放后回收。准备中候选须使用原丢弃接口。
回收与候选丢弃共用唯一清理实现：先持久写入 `discarding`，再释放插件屏障但持续保留排他修订锁，
按原完整清单删除并回读确认，最终比较原日志后发布 `discarded`。后端失败继续原清单，
发布检查点失败须回读原状态；过程中无法重新固定、写入或选择该修订。
保留终态记录及锁文件，禁止修订身份复用；源插件包已被回收也不影响按原日志清理。

实际跨进程测试通过独立测试进程取得 `pin_active`，父进程停用后回收仍繁忙，
终止并回收子进程后才可清理。此证据覆盖 OS 锁随进程退出释放，不代表凭据写入掉电恢复。
真实 Windows 安全存储测试另验证共享读者阻止 OS 删除、最后克隆释放后原条目被清理，
旧命名空间条目保持原值。当前仍未接入完整服务更新及自动回收调度。

以上入口使用既有有界记录写入器和真实文件锁，不新增平行选择指针。第三版及后续绑定修订的选择要求暂存日志；
本地开发阶段旧原型中没有日志的第三版记录明确不可用，普通加载不补写日志，不回退第一／二版或旧目录。
实际服务安装、更新、普通凭据编辑和启动恢复仍须串联这些入口与完整事务，不能把可独立调用的暂存 API 当成完整产品流程。

## 持久选择提交与路由交接

权威实现为 `generation_store/transactions.rs` 及其子模块。宿主在调用前签发非空 UUID，
`begin_activation_transaction` 保存完整前驱与第四版目标，目标修订必须恰为前驱加一；
实际包、完整权限、配置模式和已暂存凭据均须验证。准备不激活、不执行生命周期，也不表示候选已就绪。
同一插件的 `transactions/<plugin_id>/current` 仅索引唯一待交接请求，激活权威仍为原 `active` 记录。
每个 `<request_id>.json` 独立保留，不因后续请求而覆盖；配置文档属于用户数据，普通日志和调试输出不披露内容。
日志与索引由单一 `TRANSACTION_RECORD_VERSION` 控制，独立于包元数据及激活格式演进。
日志上限从两个激活记录额度和一个元数据额度派生；嵌套选择复用既有格式及大小校验，不新增独立配置上限。

| 阶段 | 含义与允许的下一步 |
| --- | --- |
| `prepared` | 已保存原意图，宿主可执行明确的候选就绪；可请求提交或显式中止 |
| `committing` | 提交意图已持久化；原选择必须为完整前驱或完整目标，按原请求恢复 |
| `published` | 目标选择已确认，尚待宿主完成路由交接；禁止自动回滚 |
| `completed` | 宿主显式确认路由交接；历史回执保留，新请求可进入 |
| `aborted` | 已确认前驱未变并明确放弃；历史回执保留，新请求可进入 |

不可克隆事务所有者持有实际排他请求锁、目标插件包共享租约和目标凭据共享租约。
候选视图、受跟踪准备与实际原生池通过共享所有权保留同一排他请求锁，不新增锁文件或格式。
其他实例不能恢复仍有实际所有者的请求；释放事务句柄不保证立即解锁，也不中止持久事务。
最后一个事务、候选视图及实际执行所有者退出后才解锁，完整请求日志继续保留。
同一可变事务提交或中止前，还要求它独占原锁的所有权；超时返回不能替代这项检查。
普通激活、带配置激活及停用共用待完成事务屏障，不能绕过提交顺序。
未终结请求的完整前驱和目标均阻止包／凭据回收，即使原进程已退出；完成后仍由实际旧描述符租约保护在途调用。

`commit_activation_transaction` 先保存提交意图，再使用原原子写入器发布完整选择，最后保存已发布检查点。
发生错误后调用方查询原 UUID，原所有者及实际候选工作全部退出后，才可通过
`resume_activation_transaction` 取得原请求；仍在清理时返回忙碌，不能抢占原锁。
恢复不重放就绪回调；原激活为目标时只补确认，不再次递增或替换选择；原激活为前驱时允许显式重试提交。
其他完整记录、相同修订但不同内容、损坏记录均拒绝。`complete_activation_transaction` 要求精确已发布目标，
调用方必须先完成真实路由交接；该接口不代替路由协调器，也不等待插件自身调用退出。

中止只在原前驱完全未变时允许。候选损坏导致无法重新固定时，原所有者退出后可使用
`abort_activation_request` 按 UUID 明确放弃；它不需要重新执行候选、不删除包或 OS 条目。
已持久化的中止可按原请求幂等确认。已发布目标不能用此入口回滚。

请求正文先于索引写入，发生中断时原 UUID 始终由调用方保留。记录存在却缺少索引时，普通写入和回收被阻止，
不会扫描候选猜测当前权威。显式恢复原准备请求会复核前驱和候选，再补索引；发现其他未终结记录则拒绝重建，
历史已中止请求不能覆盖较新的未完成工作。只读命名空间／请求枚举及原请求查询均不自动恢复。
事务记录和锁文件暂不自动清理；保留策略须与最终操作历史及用户数据删除策略统一设计，不能擅自删除回执。

本地测试包含两侧磁盘阶段快照，以及 Windows 真实不共享删除文件句柄引发的两次原子替换失败：
第一次选择替换失败而提交意图保留；第二次选择成功而最后日志替换失败。重开后确认原修订，原选择字节不被再次替换。
这些结果不等于硬件断电、多平台验证或服务完整更新验收。服务安装／更新／配置编辑与启动恢复仍须接入，
第四版旧配置写入守卫尚未移除。

## 未发布候选检查

`inspect_activation_candidate` 接受本存储的实际排他事务所有者，在同一命名空间屏障内核对当前索引、
完整日志及完整前驱，只接受 `prepared`。它重新固定并校验目标实际包、完整权限、配置模式及暂存凭据，
不修改激活记录、事务检查点或公共目录；提交中、已发布和终态请求必须继续原恢复路径，不能重分类为新候选。

返回的 `VulcanPluginActivationCandidate` 借用原事务所有者。视图仍在使用时，Rust 借用规则阻止通过
同一所有者提交或中止；独立恢复者仍受原实际排他请求锁限制。它与正式发现共用
`catalog/generations.rs::load_pinned_package`，从同一完整目标投影包、权限、配置及凭据，
每个 MCP 描述符继续持有对应配置快照和实际凭据读者。

候选描述符显式停用，忽略清单默认启用选择，不分配运行时代次，`runtime_execution_available` 为假。
克隆描述符可保留候选包及凭据租约，但不授予普通执行入场；释放借用视图不会替代最后实际所有者的释放。
该入口不构造父运行时、不执行 Lua、不连接 MCP、不执行安装回调，也不确认候选已经就绪。
实际候选初始化通过 `probe_activation_candidate` 复用原正式父级、容量和取消监督；
可选安装回调通过 `install_activation_candidate` 在精确安装作用域执行，同样保留原事务锁。
按原请求查询与排空的边界见[插件执行引擎](plugin-execution-engine.md#未发布候选初始化与事务所有权)。
完整服务事务仍须接入连接验证、安装副作用回执、恢复及统一路由交接；
初始化或回调成功本身不推进持久检查点，不能根据进程重启或空调用列表自动重放安装。

### 候选 MCP 准备

`prepare_mcp_activation_candidate` 只接受已检查的候选视图。它与 Lua 候选调用共用用户根目录及
内置命名空间校验，固定原请求、完整候选包及其凭据和配置。标准输入输出启动器从候选清单解析，
继续复用现有执行环境、平台及路径检查；不会为了通过普通解析而临时发布候选或分配代次。
普通 `resolve_mcp_stdio_launcher_descriptor` 仍要求公开目录中的精确代次，零代次候选继续被拒绝。

`VulcanPluginPreparedMcpCandidate` 的克隆共享原请求排他锁和实际包、凭据所有权；原事务句柄、
管理器或前台视图释放，都不替代最后准备所有者的释放。准备失败按正常所有权释放，不能留下隐藏锁。
单独复制服务器描述符、路径或 UUID 不足以替代该所有者，也不证明进程已经清理。
现有 `activation_candidate_calls` 仍只查询正式 Lua 调用，不包含 MCP 准备对象；
空调用列表不能用于推断候选 MCP 所有者已退出，原请求锁继续独立约束提交和恢复。

宿主 `candidate_global_mcp_server_configs` 消费准备对象并返回 `PreparedPluginMcpConfigs`，
同时保留原所有者及全局配置。它不接受公开管理器，不能读取最新公开配置；
HTTP、SSE、标准输入输出及 OAuth 值均使用候选捕获的配置与凭据修订。
缺失选定值直接报错，不能改用前驱或旧命名空间。会话作用域仍需要明确会话授权，不混入全局配置。

此路径只完成输入准备及值物化，不启动传输、不创建 Lua 引擎、不发布运行时分区。
真实验证任务必须进一步把准备所有者接到实际后端和诊断管道，覆盖初始化取消及执行器退出；
私有执行环境回收也须接入实际所有者屏障。完成这些连接前，不能将配置物化成功作为候选就绪证明。

## 回收与重开

### MCP 关闭观测边界

标准输入输出、HTTP 与 SSE 传输共用一次关闭操作及五秒观测预算。关闭工作拥有原服务或监听器，
超时及等待方取消只结束当前观测；并发或后续关闭仍等待同一结果，不把已移交的服务槽位视为成功。
传输析构请求尚未启动的关闭，实际清理由独立任务继续；错误结果不被成功覆盖，执行器中断显式报错。

生命周期监督使用 `shutdown_and_wait` 等待同一次关闭的最终结果，不把五秒观察期限当成清理期限。
前台就绪和停止屏障仍按各自有限预算返回，后台继续持有精确传输；前台超时或取消不移交其所有权。
清理开始即撤销工具绑定并进入 `stopping`，隐藏缓存工具，保留触发清理的已脱敏错误；
实际结果到达后更新原运行时状态。普通连接重试必须先完成旧实例清理，真正清理失败时停止重连。
设置页面显示“停止中”，插件目录将该状态映射为 `draining`。自定义传输的默认最终等待入口
沿用其原关闭契约；具有有界关闭观测的实现必须覆盖最终等待入口，不能返回仅属于观察者的超时。

标准输入输出与 HTTP 还独立保留传给官方服务的底层传输关闭回执。当前锁定的
`rmcp 3.1.2` 会记录底层关闭错误但仍返回正常服务退出原因，因此服务任务等待成功不足以证明关闭成功。
最终结果同时检查服务任务与底层回执；后端错误或未报告完成就销毁均显式失败。
协议消息及原具体错误类型保持透传，鉴权错误来源链不改变。此处复述上游服务行为，
归属为锁文件指定版本的 `rmcp/src/service.rs`；升级该依赖时须回读关闭实现并运行真实服务回归。

退役登记保留独立运行时状态句柄，不延长执行租约；最后调用方释放仍立即请求关闭，
但旧分区的清理状态不会随执行租约的弱引用消失。旧 MCP 分区只有全部服务器状态为已停止且没有关闭错误，才通过当前退役状态检查。
错误状态必须继续阻止把旧分区当作已安全退役；该状态检查与关闭等待屏障保持一致。
后续退役登记及回收状态查询都会清除已经成功停止的历史，避免重复更新累计已完成运行时。
这些判断仅说明当前传输接口报告的关闭结果，不能代替操作系统进程树退出证据。
当前标准输入输出后端仍由 `rmcp` 管理，后端析构可能派生清理任务；
候选事务锁与真实子进程、初始化取消、完整服务更新和重启恢复的连接仍须完成。

### 包回收屏障

回收先持有插件选择锁，拒绝未完成事务保留的前驱／目标及当前选定代次，再尝试取得排他代次锁；有实际固定句柄时返回忙碌。
已准备代次在删除前复核原内容。准备未完成的代次可以按原持久身份明确清理，但不能直接固定或激活。

真正删除包字节前先保存正在回收状态。文件占用或其他删除失败保留此状态，禁止再次固定该代次；基础设施恢复后只能显式继续原清理。
完成后保留已回收身份记录和锁文件，不再保留插件包字节。重复回收返回已经完成，不重建旧内容。

当前测试覆盖真实 Windows 文件占用及子进程租约；中断准备的重开测试采用明确构造的实际磁盘阶段快照，
不等同进程崩溃或硬件断电验证。Windows 目录持久性、跨平台验证、孤儿目录扫描、保留容量策略及宿主重启恢复仍须按完整方案验收。
