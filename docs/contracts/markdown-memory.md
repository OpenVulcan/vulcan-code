# Markdown 记忆模式

## 权威与同步条件

本文说明 Markdown 记忆的存储、工具、注入与模式切换边界。实际字段、格式与数值约束以当前源码为准：

- `crates/vulcan-markdown-memory/`：节点解析、元数据注释、分区、修订、原子写入、搜索、大纲、注册表、
  注入快照与预算、导入导出包，以及全部边界常量。
- `crates/vulcan-agent-runtime/src/tooling/native/markdown_memory.rs`：三工具的 Schema、执行与结果投影。
- `crates/vulcan-agent-runtime/src/agent_runtime/markdown_memory_hooks.rs`：提示回合准备时追加的注入快照块。
- `crates/vulcan-service-kernel/src/markdown_memory_services.rs`：模式设置、页面服务与 RPC。
- `apps/vulcan-code-web/src/service/markdown-memory-service.ts`：WebUI 调用；TUI 一对一镜像。

修改上述类型、常量、工具暴露链、RPC、持久格式或页面行为时同步本文与行为测试；本文不建立第二套 Schema。

## 模式

- 全局记忆模式为 `off`、`vmm`、`markdown` 三选一，所有项目共用，不按项目混用。
- WebUI 在「记忆 → 模型与服务」配置全局模式和 VMM 内部推理。首次配置与缺模型提示中的 Markdown 快捷操作使用同一设置接口，保留已保存的 Markdown 注入预算。
- 模式保存在 `<user vulcan root>/memory/settings.json`。文件不存在时运行时默认 `vmm`（保持既有行为），
  启动与刷新不得回写该文件；只有用户显式保存设置才写入。
- 非 `vmm` 模式下 VMM 的钩子、召回、写回、工具与原生后台工作器一律不生效：宿主在内存中把全局
  VMM 层视为关闭，不改写已保存的 VMM 配置，也不删除任一后端的数据，可随时切回。保存模式时立即
  重新发布钩子投影与工作器开关；工具可见性在下一次请求生效。
- `vmm` 与 `off` 模式下 Markdown 记忆工具不注册、不注入。
- Markdown 模式下单个记忆项目可以关闭记忆（默认开启）；关闭的项目不注入、不注册工具，用户层与空间层
  在该项目中同样不生效。开关保存在记忆注册表，不写入项目目录。
- 专职会话按其契约不使用记忆；子会话（子代理）不注入快照。

### 免费云端向量记忆

- 「模型与服务」的记忆引导提供 Markdown、免费云端和自有模型。首次登录后，如果仍使用 VMM、缺少可用自有模型且当前站点发布了免费模型，会显示一次相同的引导。
- 云端目录与调用使用当前 OpenVulcan 账号所属站点的记忆专用接口。启用前展示每个阶段的上游模型、供应商、处理地区与数据安全说明。用户选择本机 PII 规则地区并确认后，宿主保存账号、站点、发布模型与同意版本。
- 专用接口只接收用途及经本机 PII 规则处理的业务输入。系统提示词和结构化输出由云端控制。重排只在模型支持且用户启用时调用。
- 已选模型下架或同意版本变更时暂停云端调用，并提示重新选择。账号不匹配时停止发送；切换到 Markdown 或关闭记忆不删除云端选择。重新确认后，如果向量代次改变，使用现有的本机向量重建流程。
- 服务端返回的实际 Token 按预检、事后分析、画像、向量和重排阶段写入用量账本。未报告的分项保持未知，专用入口的费用为零。

## 存储

```
<user vulcan root>/memory/markdown/
  registry.json        记忆项目注册表
  user.md              用户层（画像）
  space.md             空间层（对所有项目生效）
  projects/<id>.md     项目层
```

- 全部记忆存放在用户目录，绝不写入项目目录。
- 节点为 H1–H4 标题及其下直到同级或更高级标题前的正文；标题解析交给 `pulldown-cmark`，代码围栏内的 `#`
  不是标题。空间与项目文件的 H1 是分区，分区键记录在 H1 元数据注释的 `section=<key>` 字段中（预置分区与 `newSection` 新建的分区都有）。
- 标题下第一行为宿主维护的元数据注释 `<!-- mem id=... [section=...] created=... updated=... [session=...] source=ai|user -->`。
  `id` 随机生成，改名与移动（含跨层）不变。没有注释的节点照常可读；只在通过工具或界面写入该节点时补全，
  读取绝不改写文件。
- 每个节点的修订令牌是其内容哈希；修改、移动、删除已有节点必须携带 `expectedRevision`，不一致即拒绝。
  批次按顺序校验，后续操作看到前序操作产生的暂存修订。若暂存修订导致冲突，整批不落盘，报错分别列出
  暂存修订和该节点标识在批次前的已提交修订（如有）。同一节点的依赖修改应分开调用，每次成功后重新读取修订。
- 进程内全部写入口共用同一写锁，覆盖读取原文、比较修订、暂存与提交；提交函数必须持有该锁的类型凭证。
  正向与回滚字节均预先暂存到同目录，替换失败时逆序还原已完成的文件，原先不存在的文件被移除。
  Windows 临时拒绝访问与共享冲突按源码中的统一有界策略重试。
- 回滚失败，或回滚时发现已替换文件又被外部编辑时，返回专门的 `RollbackIncomplete` 错误，列出不一致文件与保留的原文恢复副本；
  不覆盖外部编辑，不把部分提交报告成普通失败或成功。当前不提供断电／进程崩溃后的事务日志恢复。
- 注册表与导出包各有独立格式版本，从 1 开始；版本不符明确拒绝，不迁移、不降级。

## 记忆项目身份

宿主项目 ID 由根路径哈希得出，目录移动即变化，因此记忆项目另设随机身份。注册表记录显示名、已绑定的宿主
项目 ID、历史路径、提示信号与已忽略的宿主项目。宿主项目尚未绑定且存在孤立记忆项目（历史路径均已不存在）
时，界面给出非打断提示，由用户选择关联、新建或忽略；候选只排序与说明原因，不预选、不自动绑定。用户作出选择
之前，AI 首次写入项目层会新建并绑定记忆项目，孤立项目之后只能经导出导入合并。关联后把当前路径追加到历史。

## AI 工具

| 工具 | 主会话 | 子代理 | 计划模式 |
| --- | --- | --- | --- |
| `memory_outline` | ✓ | ✓ | ✓ |
| `memory_search` | ✓ | ✓ | ✓ |
| `memory_write` | ✓ | ✗（父会话专属工具名单） | ✗（`available_in_plan: false`） |

- 工具名、描述、Schema 与结果为英文；权限分类为 `Ungoverned`（只读写用户记忆存储）。
- 查询不依赖 codekit 或 LuaSkills：Rust 进程内扫描已解析节点，匹配使用 `regex`，不建索引、不启动外部进程。
- 命中归属到最深节点；返回层、标题路径、节点正文与元数据，子节点只列标题。同节点多处命中合并。
  超长节点按节点边界分页，不在正文中途截断。元数据注释不参与匹配。
- 写入回执报告疑似重复节点与基础区预算占用；标题质量、分层与基础/目录归属只在工具说明与记忆守则中建议，
  工具不做拒绝。AI 默认只能写入已有分区，新建分区必须显式声明。
- 冲突优先级：项目 > 空间 > 用户。

## 注入

- 快照块在提示回合准备时（画像线路之后）生成，标签 `long_term_memory`，带 `MemoryProfile` 锁定基线来源；
  专职会话与关闭记忆召回的执行（子代理）在执行准备中移除该块。读取失败只记入画像失败说明，请求照常继续。
- 块内先是写入守则（`crates/vulcan-runtime-assets/resources/tool-guides/markdown-memory.md`，英文），再是快照；
  记忆为空时仍注入守则，让 AI 从第一个会话起按守则写入。整理流程由系统技能 `memory-curator` 承担。
  会话锁定基线一经初始化即按字节复用，
  因此快照只在新会话与上下文压缩后的基线刷新时更新；会话中途的写入立即落盘但不改变已注入内容，
  不破坏提示词缓存。模式切换同样只影响新会话与压缩后的请求，工具可见性在下一次 Provider 请求生效。
- 默认注入预算合计 4000 tokens（用户画像 500、空间基础 400、项目基础 600、空间目录 1000、
  项目目录 1500），默认值与上限只在 crate 中定义一处；token 估算统一使用 `vulcan-context` 的
  `estimate_mixed_language_text_tokens`。
- 全文部分超出时按节点边界截断并列出被省略的标题；目录按 H3 → 只到 H2 → 只剩 H1 与计数逐级降级，
  AI 侧只附一行 `use memory_outline` 提示。任一部分 ≥80% 为提醒，超出为警告。
- 不做后台召回与自动提交，不新增压缩前捕获回合或压缩钩子。

## 导入导出

导出范围可选用户层、空间层、指定项目或全部，产物为带 `manifest.json` 的压缩包。导入先预览后应用，
不调用 LLM：包内每个项目必须由用户指定匹配、新建或忽略；节点按 ID 与标题路径合并，相同跳过、冲突由用户
选择；应用前备份当前文件，整批原子写入。同一包重复导入时所有节点判为相同并跳过。

- 包结构（实现：`vulcan-markdown-memory/src/package.rs`）：zip 内只允许 `manifest.json`、`user.md`、`space.md`、
  `projects/<记忆项目ID>.md`；清单 `format` 固定为 `vulcan-markdown-memory`，`version` 即
  `EXPORT_FORMAT_VERSION`。项目数上限 `MAX_PACKAGE_PROJECTS`，包体上限 `MAX_PACKAGE_BYTES`，每个条目受
  `MAX_FILE_BYTES` 约束并须为 UTF-8；任何多余条目、超限或版本不符都明确拒绝。
- 导出写入用户所选的既有目录，文件名为新生成的 `vulcan-memory-<时间>-<随机>.zip`（时间为 UTC，如 `20261020T1559Z`；导入备份目录同理），从不覆盖已有文件。
- 预览不写入。候选关联按 `same_path`、`same_first_commit`、`same_directory_name` 给出，只作提示、不预选；
  未指定去向的项目只列出，不参与合并预览。H1 分区按分区键匹配，其余节点按 ID 匹配；冲突的 `newer` 取自
  双方元数据的 `updated`，界面以较新一侧为默认选择，无法判断时默认保留本地。
- 应用时必须携带预览返回的 SHA-256，包字节变化即拒绝；每个包内项目都要有去向，每个冲突都要有且只有一个
  解决方式。被替换的文件先复制到 `<记忆根>/backups/import-<时间>-<随机>/`，再与注册表一起整批提交。
  “新建”产生不绑定宿主项目的记忆项目，之后可在项目页关联。
- 服务与 RPC：`service_export_markdown_memory`、`service_browse_markdown_memory_packages`（列出 `.zip`，与
  知识库 `.vkb` 浏览共用 `browse_package_files`）、`service_preview_markdown_memory_import`、
  `service_import_markdown_memory`。
