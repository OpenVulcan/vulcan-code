# 插件执行引擎归属

## 当前边界

服务启动通过 `vulcan-service-runtime/src/luaskills_bridge.rs::bootstrap_luaskills`，从同一份已解析宿主选项构造两种独立所有者：

- `TauriLuaSkillsHandle::engine` 是普通技能管理引擎，保持原有读写锁及目录、配置管理入口。
- `TauriLuaSkillsHandle::plugin_engine` 是不可变的 `Arc<LuaEngine>`，不加载普通技能目录，也不进入普通技能管理锁。

`vulcan-service-kernel/src/service_bootstrap.rs::prepare_vulcan_plugin_runtime` 将后者交给插件管理器。
句柄克隆只增加同一引擎的强引用，不重新创建插件引擎。插件与普通技能使用相同的宿主路径及启动设置来源，
但有各自的上游受管运行服务及 VM 所有权；这不表示两者共享一份进程级资源预算。

插件管理器的引擎槽仅保护一次性附加及短暂取得强引用，已经附加后明确拒绝替换。
实际 Lua 创建、执行、查询及清理直接持有不可变引擎，不在普通技能读写锁内运行。
异步等待方离开不结束实际工作的强所有权。管理器销毁请求正式父级关闭，实际退役仍由核心完成。

## 当前迁移状态

生产启动在附加独立插件引擎后，显式调用 `initialize_formal_runtime` 建立管理器唯一的
`ManagedFormalRuntime`。管理器克隆只共享该父级，不另建 VM 治理器；重复附加返回错误，
即使原运行时已完全关闭也不允许在同一管理器中静默替换身份。纯内容管理器不创建正式运行时。
初始化阶段注册原生能力、显式配置的用途容量及对应插件预算，并创建有界核心工作线程，没有提前执行插件 Lua。

正式预算从宿主状态根下的 `plugin-runtime-settings.json` 读取，权威实现为
`vulcan-plugin-runtime/src/runtime/settings.rs`。当前设置版本为 `schemaVersion: 3`，顶层字段为
`schemaVersion`、`parent`、`pluginBudgets`、`capacityBudgets`、`maxCapabilityCallMs`、`shutdownTimeoutMs`；
`parent` 直接反序列化上游 `EmbeddedRuntimeConfig` 的字段和命名，不维护宿主复制 Schema。
除可缺省的 `pluginBudgets` 和 `capacityBudgets` 外，既有文件必须提供完整结构；未知字段、未知版本、非法父级、
插件或用途限制及非正或不可表示的时长均报错。第一、二版各按原严格结构解码，随后在内存升级至第三版，
保留父级、时长及第二版插件覆盖原值，仅补入当时不存在的空覆盖表；旧版携带新版字段同样拒绝。
重复版本字段、插件键和用途键报错，
不会通过中间 JSON 映射消除重复证据。原生能力注册容量另由适配器
在分配核心线程前验证。文件缺失使用唯一 `Default` 中的内存值，不创建目录、不写回配置。
这些默认值是当前开发联调起点；完整方案的性能基准、最终默认值冻结和发布验收仍待完成。

配置在构造时冻结；文件外部修改不替换运行中的父级。`formal_runtime_status` 可读取核心身份、
生效预算、队列与操作、实际 VM 记账；这些是控制接口的实时观测，不是跨字段事务快照。
`request_formal_runtime_close` 仅永久关闭入场并请求取消，`poll_formal_runtime_closed`
须确认宿主准备和监督工作已经结束，并由核心确认工作线程及 VM 真实终止后才返回完成。最后一个管理器释放时先请求正式父级关闭；
实际生命周期关闭仍应走显式控制和排空，不能把析构触发理解成完整排空验收。

父级已覆盖本管理器的工具、Hook、Action、生命周期和启用探测生产执行路由。
核心统计不等同于整个进程、插件环境磁盘或外部服务的资源预算。

### 插件聚合预算

`pluginBudgets` 是按精确插件 ID 索引的宿主覆盖表。缺省表或表中缺少某个 ID 时，明确从冻结
父级派生该插件的全部七项聚合上限；不是另一份编译默认值。存在覆盖时，必须完整提供上游
`EmbeddedPluginConfig` 的七个 snake_case 字段：`max_registered_pools`、`max_sessions`、
`max_resident_vms`、`max_running_calls`、`max_queued_calls`、`max_queued_bytes`、`max_operations`。
不做逐字段合并、裁剪或未知名称兼容。全部字段必须为正、不超过父级，并通过上游组合约束；
无效插件 ID 和未来尚未安装插件的无效预算，也在启动线程前统一拒绝。

权威实现为宿主 `runtime/settings/budgets.rs`、`runtime/formal/budgets.rs` 及上游
`runtime/embedded/plugin_config.rs`。具有显式用途配置的插件在父级发布前注册预算，其余插件首次入场在目录发布门内注册；随后所有生产路径
复核同一冻结配置。既有核心所有者配置不一致或已永久关闭时明确报错，不能重新注册来绕过。
无状态工具、工具固定会话、Hook、持久 UI、瞬时 Action、生命周期与启用探测均共用同一插件
核心所有者，包括尚未退役的旧代次。执行域队列上限从下述用途容量派生，用途配置又受此有效插件预算约束，
避免较小插件覆盖被父级大小的域声明绕过或导致声明冲突。

聚合计数由 LuaSkills 核心执行，包括创建中、空闲、运行中及退役中的 VM，排队请求与字节，
保留池、会话与操作。一个插件占满自身常驻额度后，其他插件仍能使用父级剩余容量；
同一插件的 Hook 与 UI 也相互消耗该额度，因此仅配置一个 VM 时，两者不能同时常驻。
插件聚合提供上限隔离；下述用途容量可显式增加专用预留。单次调用的独立 Lua 状态本身不代表专用容量。

`formal_plugin_status(plugin_id)` 返回原 `runtime_id`、整份策略来源 `parent` 或
`host_override`，以及核心 `EmbeddedPluginSnapshot`。该读取不创建插件；父级未附加或 ID
尚未注册时返回空值，非法 ID 或实际配置不一致返回错误。它目前是 Rust 管理接口，完整
RPC／WebUI 暴露尚待完成。原始核心字段命名由上游类型决定，上游升级时须同步回读和验证。
宿主准备阶段的保留记录及序列化输入仍使用既有父级预算；不能把核心插件计数当成宿主准备
内存、进程总内存或外部服务硬配额。运行中的配置保持冻结，文件编辑不触发隐式重载；
显式策略修订与相应状态查询仍待交付。此次内存迁移不执行持久配置写入，也不声称提供持久迁移工具。

### 用途容量、专用预留与成员寿命

`capacityBudgets` 按精确插件 ID、用途两层索引。用途仅允许 `tool_call`、`tool_session`、`hook`、
`ui_action`、`lifecycle`、`activation_probe`，由宿主类型化入场选择，业务参数不能指定或覆盖。
瞬时和持久 UI Action 共用用途额度，但各自的 Lua 状态、安全分区和寿命仍隔离。
权威实现为宿主 `runtime/settings/capacities.rs`、`runtime/formal/capacities.rs`，以及上游
`EmbeddedCapacityConfig`、`VmCapacityConfig`、容量调度器和资源治理器；上游升级时须回读源码同步本文。

缺省用途明确使用 `Shared`、最小预留零，所有最大值从有效插件聚合预算派生。
显式覆盖必须完整提供上游字段 `resources`、`max_queued_calls`、`max_queued_bytes`；
`resources` 包含 `kind`、`min_resident_vms`、`max_resident_vms`、`max_running_calls`。
不合并单字段，不通过其他用途补齐。核心约束决定类别、正数边界及父级／插件上限；
所有显式用途最小预留的插件内总和和全父级总和必须同时可满足，注册数量也必须合法。
包括尚未安装插件在内的显式配置均参与校验与承诺，空用途表不创建原生所有者。

全部显式容量在父级公开前注册，公共业务无法先消费这些承诺；失败不发布局部运行时。
此阶段只保留预算，不创建、初始化或预热 VM。无显式覆盖的用途在第一次真实成员准备时登记。
`Dedicated` 的最小预留不可被其他容量借用，实际总量仍受用途、插件及父级共同限制；
最低常驻预留不等于 CPU 时间、公平调度或端到端延迟保证。

每个插件用途保留一个核心签发身份，跨包代次共用容量；每个模块成员仍由原注册路径校验目录、
冻结源码并保留独立身份和状态。成员的最小预留为零，不按每个会话或代次重复承诺用途最小值。
本阶段不改变 `SingleCall`／`Session` 复用语义、单实例串行策略或 `InProcess` 后端；
专用容量不是独立操作系统进程，不提供进程崩溃隔离。

`formal_capacity_status(plugin_id, purpose)` 返回原父级身份、用途、策略来源 `plugin_budget`／
`host_override`、宿主准备计数、`retirementRequested` 及原生 `EmbeddedCapacitySnapshot`；无注册时返回空值且不分配资源。
`request_formal_capacity_close` 永久关闭该身份及成员入场，只确认关闭请求，不证明物理排空；
后续调用不会自动选择另一用途或创建替代身份。宿主成员注册准备守卫保留原映射，直到真实准备返回，
关闭期间尚未完成的注册会明确失败。`forget_formal_capacity` 必须等待全部准备结束、成员实际清理且
原生成员池显式遗忘；失败保留同一身份和预留。只有显式遗忘成功后，后续合法入场才可重新注册。
目录刷新、普通会话结束或包代次切换本身不释放用途容量；调用方应按生命周期安排成员排空及显式释放。
父级物理关闭也不能替代元数据遗忘。策略修订、通用预热和 RPC／WebUI 控制仍待完成；清单资源要求见下节。

生命周期容量实现位于 `runtime/formal/capacities/lifecycle.rs`。停用、启用补偿等事务调用
`finish_lifecycle_transition` 时，按扫描得到的最终策略决定是否回收该插件全部用途容量。
最终策略为停用时，容量回收、清理诊断和目录发布共用原发布门；不会与新的成员准备交错。
服务仍先排空旧成员、执行停用或补偿回调，再最终发布，因此普通排空入口不提前关闭生命周期容量。
回收先确认所有用途均无准备声明或保留成员池，再关闭及逐项遗忘；前置检查失败不关闭任何健康容量。
原生移除途中失败保留剩余精确身份，已完成项立即确认，不重放。

失败回收保留插件级明确意图，阻止普通调用登记新成员，并保持既有清理告警；仅实际 VM 清零
不能让诊断提前消失。进入 `Enabling` 前，包括停用回滚，先重试有明确意图的旧回收，再恢复全部
显式用途保证；无法同时满足时回滚本次新建空容量，不发布新启用代次，也不静默降低最小值。
恢复失败而尚有原生归属时保留诊断。手工关闭但未请求生命周期回收的容量仍须显式遗忘，不能借启用绕过。
停用重试的真实生命周期回调也可在原成员排空后明确完成此前回收，并按原配置恢复容量；
该入口先核对精确目录代次及事件作用域，普通业务入口不执行这种恢复。

物理卸载入口 `uninstall_user_plugin` 在包改名、删除环境和配置之前，在原发布门内回收容量；
成员或准备未结束时保留包、容量身份及停用告警。卸载回调仍由服务在此入口前完成。
这些规则管理容量保证和成员寿命，不删除尚未确认的操作历史或原生插件聚合元数据，
也不等同于持久更新、凭据、路由和全部外部资源事务已经完成。直接目录刷新仍不隐式释放显式策略。

真实生产测试覆盖启动承诺、公共会话无法占用他人预留、六种用途路由、原生身份跨代次保留、
准备期间拒绝遗忘，以及实际常驻成员排空之前拒绝释放保证。生命周期测试还覆盖真实回调先于释放、
启用前恢复保证、第二份预留失败时撤销第一份、未排空告警持续保留、停用重试和实际包卸载。
目录修订在最终发布时从唯一计数器签发，清理诊断的中间发布不能令最终修订倒退。容量元数据受现有核心注册上限约束，
已关闭但未显式释放的用途仍占额度；性能与最终默认值须在后续负载、长稳和多平台验收后冻结。

`begin_draining` 在目录发布门内为该管理器持有的正式运行时中、精确源代次的既有启用域
签发本次排空代次。仅核心 `CapabilityBudget::is_finalization()` 证明的自动关闭阶段可使用，
普通业务调用、名为关闭的普通导出及业务参数均不能选择该授权。能力入场及实际宿主副作用前
仍检查实时核心授权、预算、包内容、目录路径和当前排空代次；回滚、下一轮转换、内容变化或
撤权均不能复活原授权。转换代次耗尽明确报错，不以饱和递增复用身份。
各宿主服务自己的约束仍有效，例如配置写入的精确代次检查不会因进入关闭阶段而放宽。
该接入提供关闭权限边界；已迁移路由沿原身份完成入场、取消及物理排空，完整更新事务仍待实施。

普通无状态工具、工具固定会话、持久 Hook 及持久 UI Action 已通过管理器唯一 `EmbeddedRuntime` 执行，具体所有权见下文。
生命周期、瞬时 Action 与启用探测也已复用正式调用所有权，管理器业务不再创建旧 System 租约。
这完成了执行路由迁移，完整混合池策略、自动预热、性能冻结及更新事务仍须后续交付。

核心候选中的类型化模块已经在真实宿主句柄上验证：普通引擎写锁持续持有期间能初始化和调用插件模块，
普通目录真实重载后，同一插件模块保留原 Lua 状态并继续执行。现有初始化退役测试改用真实宿主回调屏障，
不会再依赖已经移除的引擎写锁模拟初始化。

测试现使用 System 根之外的不可变代次目录布局。核心候选的正式模块按可信宿主 `ModuleDefinition` 授权精确包根，
保留包内依赖、授权工作区／cwd 及原生对象身份校验，旧 System 租约仍维持其信任根限制。
此测试直接创建真实模块，尚未验证生产插件管理器的混合池路由或安装更新事务；实际代次固定句柄
现由下述原生适配器交给核心生命周期持有。
宿主正式接入仍须从已核验目录及授权记录构造定义，并完整限制第三方 Lua 的能力；路径声明本身不是插件沙箱。

## 第二版清单的兼容性与资源必需条件

清单结构由本仓库 `manifest.rs`、`manifest/requirements.rs` 与 `catalog.rs` 共同校验。
`schema_version: 1` 保留既有语义，禁止新增 `runtime_requirements`；第二版 Lua 插件必须明确声明该对象，
非 Lua 插件不得声明。省略与空值不等价，未知版本、字段、用途、重复字段或重复用途直接拒绝。
不会在发现、刷新或启动时重写插件清单及宿主配置。内置包尚保留第一版，迁移工具及完整清单 Schema 仍待交付。

下面为第二版 Lua 插件的新增顶层片段，其余 Lua 声明保持现有结构：

```yaml
schema_version: 2
runtime_requirements:
  protocol_version: 1
  backend: in_process
  core_capabilities: [capacity_groups_v1]
  capacities:
    - purpose: tool_call
      reserved_resident_vms: 1
      resident_vms: 2
      running_calls: 1
      queued_calls: 4
      queued_bytes: 65536
```

示例数字是插件的业务要求，不是生产默认值或自动写入值。`protocol_version` 指 LuaSkills 嵌入式核心协议，
与插件清单版本独立；版本、核心后端和语义功能的实际支持集合直接读取链接核心的
`ffi_embedded::embedded_core_description()`，上游版本升级时须回读此描述及对应实现。
后端还须匹配宿主 `VULCAN_PLUGIN_EXECUTION_BACKEND`，该单一定义同时用于三条真实生产注册路径；
核心新增后端不会自动使尚未适配的宿主宣称支持。
`core_capabilities` 只声明版本化语义功能，不授予权限，也不代替宿主回调的名称、版本及授权契约。
预留的 `worker_process` 当前被明确拒绝，没有静默回退。未知复用或顺序字段同样拒绝，尚未接入相应生产策略。

用途与宿主 `capacityBudgets` 使用同一 `VulcanPluginCapacityPurpose` 类型，支持普通工具、工具会话、Hook、
界面动作、生命周期和启用探测。每项完整要求的含义如下：

| 字段 | 约束与对应宿主配置 |
| --- | --- |
| `reserved_resident_vms` | 非负，对应不可出借的 `resources.min_resident_vms`；零不要求预留 |
| `resident_vms` | 正数，要求 `resources.max_resident_vms` 至少达到该值 |
| `running_calls` | 正数，不超过本项 `resident_vms`；要求 `resources.max_running_calls` 至少达到该值 |
| `queued_calls` | 正数，要求 `max_queued_calls` 至少达到该值 |
| `queued_bytes` | 正数，要求 `max_queued_bytes` 至少达到该值 |

预留数不得超过常驻要求。`capacities: []` 明确表示没有额外资源下限，`core_capabilities: []` 明确表示没有额外
语义功能要求。宿主用生产容量解析器逐项比较冻结配置，错误包含插件、用途、字段、所需值、实际值及配置来源。
插件声明不能提高宿主预算、改写设置、自动选择专用池或分配 VM。公共配置的最小预留为零，因此不能满足正数预留要求。
这些是可接受策略的下限，不保证调用时存在空闲实例、实际执行并发或已经预热；真实入场仍受核心当前占用、队列、
插件聚合、父级预算及原业务顺序约束。

管理器发布目录时先验证完整插件的要求；不满足则设置 `runtime_execution_available = false` 并移除全部活动暴露面，
保留诊断、原包和既有生命周期状态，保证仍可进入停用及卸载流程。进入启用中状态前再次检查，实际工具、
安装／启用回调、固定会话、持久 Hook／界面准备也检查同一冻结策略。明确停用、启用回滚、卸载回调仅要求
其生命周期用途的资源下限；工具等业务额度不足不能阻止清理，生命周期自身下限仍不能绕过。精确代次、事件作用域、
能力授权及核心当前预算检查保持不变。检查没有执行 Lua。第二版 Lua 插件在正式父级尚未附加时不发布活动能力；附加之后须正常显式刷新目录。
服务启动已有“附加正式父级 → 刷新目录”顺序。停用资源回收及重新启用恢复继续遵循前节规则。

[编写辅助 Schema](plugin-runtime-requirements.schema.json) 只描述 `runtime_requirements` 对象的结构，不是完整插件清单 Schema。
精确版本、链接核心支持、同用途重复、数值间关系、机器整数范围和有效宿主策略由 Rust 校验，不能仅凭 Schema 通过宣称可激活。
结构对照测试、真实目录拒绝测试及实际启用探测／业务调用测试共同验证此边界。完整清单 Schema、显式迁移、入口复用、
调用顺序、宿主回调版本要求及预热仍须后续交付，第一版不会被自动升级为可复用或可并行。

## 原生能力适配入口

`VulcanPluginEmbeddedHost` 使用插件管理器已经附加的独立引擎，创建一个显式预算的正式运行时。
每个运行时原子注册既有十八项宿主能力；回调仅持有当前运行时的权威表和管理器弱引用，
不进入进程级旧回调路由。核心继续独占池、队列、操作、会话、撤权和实际关闭的生命周期，
宿主适配器不再创建第二套 VM 所有者。宿主须先注册插件聚合预算，再通过适配器注册执行域。

执行域只接受可信宿主构造的模块源码及声明。插件身份、目录代次、包根、依赖声明和生命周期作用域
必须匹配实际目录；工作区显式解析。注册时生成独立不透明执行修订；对应描述符交由
`ModuleResourceOwner` 保留，因此受管不可变包的物理固定句柄随真实池及 VM 清理释放。
权威表仅保存弱引用，容量派生自同一核心池注册限制，失败注册撤销预留。

能力调用从核心 `CapabilityInvocation.caller` 取得可信身份，核对运行时、插件、
`package_generation`、执行修订、工作区声明及安全分区，并检查当前目录代次及生命周期。
业务参数中的同名字段无法替换这些权威。权限按清单映射为逐能力可撤销授权，发现和执行共同受限。
短元数据锁不跨越实际服务执行；开始服务前再次检查实时撤权、取消及截止时间。
存储与 VLDB 请求显式接收由原调用剩余预算派生的有限截止时间，不依赖旧 Action 线程局部变量。

原生服务仍使用既有返回值协议，尚未提供持久提交或去重确认。因此服务执行后的副作用保守记为
未知，准备阶段拒绝记为尚未开始；不能由业务返回成功推断提交成功，也不能自动重放。
配置读取使用原描述符；配置写入在既有发布门内再次核对代次、指纹及包根，避免旧任务按新 Schema 写入。
进程规格解析使用原描述符及宿主工作区，不重新选择当前新包。

类型化模块入参使用核心既有 JSON 容器标记，保证空对象、空数组及嵌套空值转交宿主能力时不丢失类型。
Lua 自行创建空对象时使用已有 `vulcan.json.object()`；未标记 Lua 空表不被猜测为对象。
该转换的权威实现位于上游 `runtime/engine/lease/embedded.rs` 与既有 JSON 转换器；升级上游时同步检查。

本入口已通过真实 Lua 的身份伪造、撤权、目录内容刷新、旧代次配置写入拒绝、双宿主隔离、
失败注册回收、界面事件边界及等待服务期间取消验证。普通无状态工具、工具固定会话、持久 Hook 及持久 UI Action 已接入该入口，
生命周期、瞬时 Action 和启用探测也已接入同一原生能力适配器。后续仍须
将插件环境副本、进程与外部资源纳入实际寿命，并完成更新事务后才能宣称完整上线。
当前入口的代次检查是服务入场检查，不能代替更新期间对已入场服务的等待和持久事务协调。

## 真实清单与受限模块加载

`VulcanPluginBundlePoolRequest` 只接收宿主选择的插件身份、目录代次、已授权工作区、安全分区、
生命周期作用域及显式池策略；不接收调用方提供的 Lua 源码或导出列表。
请求另可显式携带核心 `ModuleFinalizer`：其导出只允许选择当前清单的 `shutdown_function`
或已声明的 `hook_shutdown_function`。宿主路由提供自身版本一关闭信封及独立有限预算；参数在
注册时冻结，对该池实例统一使用。工具请求关联号等不能从上一业务参数猜测，宿主须按其用途
构造；关闭操作的执行身份和去重证据仍以核心操作记录为准。未声明自动关闭时显式为 `None`。
`register_bundle_pool` 从真实目录和执行包根读取清单指定 bundle，复用固定桥的受限环境构造器。
所有源码在注册前冻结，初始化仍在核心操作实际入场后发生；没有绕过核心预算提前初始化。

原生适配器同时提供 `register_pool_in_capacity` 与 `register_bundle_pool_in_capacity`，显式接收
核心签发的容量身份；原两个注册入口保持独立归属。两种归属共用目录、包、依赖、工作区、权限和
执行修订检查，最终分别调用核心独立注册或带容量的原生所有者注册，不复制包所有权或 VM 账本。
缺失、关闭、外来容量或冲突的成员策略直接报错，失败注册回收原生权威表中的预留。
真实 bundle 测试确认新旧目录代次可归属同一容量而各自保留 Lua 状态；旧代次原生服务仍被实时
目录校验拒绝。容量关闭会关闭成员入场，成员显式遗忘后才能释放空容量保证；父级物理关闭
本身不替代成员元数据的显式关闭／遗忘。生产入口使用上文的用途容量，旧独立入口仍供明确选择独立归属的调用方使用。

固定桥的 `load_module` 使用原生能力传输，不生成旧 JSON 身份信封。旧 `load` 保留明确的兼容
传输及原逐次工作区语义。两种入口共享全局能力限制、模块白名单、进程规格解析和 JSON 容器处理。
bundle 仅按 Lua 文本编译；宿主包装中的 bundle 和清单值作为转义数据传入，不能成为包装代码。

正式模块捕获清单声明的工具分发、工具关闭、Hook、Hook 关闭、UI Action 和生命周期函数引用。
私有辅助函数不进入核心导出表，未声明导出在操作入场前被拒绝；插件后续修改返回表不会重定向
已经捕获的函数。现有版本一协议保持对象入参及 JSON 帧字符串返回值。

当前入口要求清单显式声明依赖文件，与 `catalog.rs::validate_runtime_files` 对版本一 Lua 组件的
既有要求一致。清单类型允许省略该字段，是为不含 Lua、Node、Python 等需依赖清单组件的包保留；
不能仅凭字段类型可选推断 Lua 插件允许省略，也不应为此生成空文件或扩大核心协议。
调用方仍需执行完整业务语义：无状态工具的分发和关闭须在同一 VM
完成，持久 Hook 和会话保留实例，关闭回调执行完毕不等于核心 VM 资源已经释放。
配置 `finalizer` 后，核心自动调度同实例关闭，支持单次调用、固定会话及可复用实例；
未配置时维持原显式调用契约。本入口不创建默认池策略；普通无状态工具和工具固定会话分别
显式使用下述单次及会话策略。配置自动关闭的路由不得再把同一关闭函数作为普通业务手动调用。

固定加载器为选定关闭函数保留原引用，并校验其版本一 JSON 帧。非字符串、无效 JSON、
缺少布尔真值 `ok=true` 或明确 `ok=false` 均转换为核心关闭失败；成功字符串保持原字节。
Lua 抛错与独立预算超时也由核心记录。原业务与关闭结果分别保留，整体失败不删除业务成功值。

真实测试覆盖受限全局环境、初始化原生配置读取、已捕获引用、私有导出拒绝、缺失导出和非法源码、
空对象／数组及特殊字符，以及同 VM Hook 关闭状态。仓库内 Context7 配置读取与关闭、用量统计
插件初始化与关闭已通过正式入口；这些检查不覆盖联网、原生扩展实际加载或实际数据库业务。

开发期核心候选只通过完整方案第 13.1 节规定的隔离检出和临时 Cargo 配置消费。
本契约不改变正式依赖来源；候选锁文件差异及本机工具路径不得提交为生产配置。
正式发布后仍须取消本地覆盖，以真实注册表核心重新验证。

## 普通无状态工具的正式所有权

生产 `sessions.rs::invoke_stateless` 现在调用 `runtime/formal/calls.rs::invoke_formal_stateless`。
该路径要求管理器已经附加正式父级，缺失时明确失败。每次调用在包准备之前登记稳定调用身份、
原包代次、控制器会话和宿主容量；目录发布门统一排序登记、停止入场及代次检查。准备前后均可取消，
提交前再次核对当前启用代次，不能因准备期目录切换而执行新包或复活旧业务。

当前无状态工具每次在 `tool_call` 容量下显式创建一个 `SingleCall` 单实例串行池，类别由用途配置决定。插件聚合、池及实际
VM 仍由同一核心父级计数；该选择保留原每次调用的新 Lua 状态，不代表已经实现所有插件的
专用池策略、自动预热或持久实例迁移。插件聚合目前保留至运行时关闭，受父级注册容量限制。

业务与关闭分别冻结版本一信封、不同请求关联号及各自有限预算。业务截止时间覆盖包准备和
核心排队；关闭预算独立来自已冻结宿主设置。核心流式 `json_size` 在构造大信封前检查输入，
宿主调用保留记录总数受父级 `max_operations` 限制；调用与固定会话的序列化输入预留
共同受同一父级 `max_queued_bytes` 限制。
预留保守保留至确认结果，不等同于进程堆内存硬限制。旧清单 `max_active_sessions` 继续约束
正式单次工具调用、工具固定会话、生命周期回调与瞬时 Action 总数；计数更新和目录投影在同一发布门下完成。

异步等待方离开只请求取消。监督任务通过核心状态短轮询等待，没有为每个 Lua 等待创建阻塞
线程；文件准备在有界保留记录下进入 Tokio 阻塞池。执行器停止时，实际阻塞准备保持独立归属，
监督中断会留下明确证据；后续显式排空仅在准备真正结束后接续原操作和池的清理，不重新加载
或提交业务。不可中断原生回调尚未返回时继续占据原 VM 和宿主容量。

管理器提供按控制器所有者隔离的 `formal_calls`、`formal_call_status`、`cancel_formal_call`
及 `forget_formal_call`。正常成功调用在收到结果后自动确认；失败或放弃等待的记录保留原
宿主／核心身份，须显式确认才能释放结果容量。确认前必须实际退役、监督结束且有结果。
这些当前为 Rust 管理接口，尚未暴露完整 WebUI／RPC 操作入口；容量耗尽明确拒绝新请求。
`formal_runtime_status` 仍是核心统计，准备阶段和保留结果须通过宿主调用查询接口观察。

插件及控制器排空包含这些受跟踪调用。有限排空等待到期报告未完成并保留容量；实际核心池
关闭且 `forget_pool` 成功后才释放宿主活动计数；记账失败明确保留未完成状态，重试不重复遗忘
已经释放的池。原业务、独立关闭及物理退役分别保留，关闭
失败不会删除原核心业务证据。请求父级关闭同时取消宿主准备，轮询完成也检查宿主所有权。

## 工具固定会话的正式所有权

生产 `sessions.rs` 的开启、调用及关闭路径接入 `runtime/formal/pinned/`。
每个会话在阻塞准备前登记宿主身份、控制器所有者、原包描述符与容量；宿主记录数受父级
`max_sessions` 限制，序列化输入与单次工具共用父级预算。包准备及首次核心入场在有界
阻塞池和发布门下执行；准备期取消保留所有者直到真实准备结束，不提交取消后的业务。
该入口要求 Tokio 执行器；无执行器时在登记前明确拒绝。

每个会话在 `tool_session` 容量下显式使用 `Session` 单实例串行池，类别由用途配置决定。核心独占 VM 固定、排队、执行和关闭；
宿主会话身份映射原核心身份，不另设 VM 租约表。开启先等待模块初始化，再执行一次清单
开启业务；成功后后续调用沿原 VM 累积状态。入场拒绝不销毁健康会话，版本一业务错误帧
保留查询记录；Lua 运行失败等核心终止条件仍由核心执行关闭。代次验证与业务提交共享发布门，
开启结果发布遇到代次变化时保留原业务记录。

自动关闭冻结清单 `shutdown_function` 与唯一 `session_close` 工具的操作名、独立请求关联号，
预算由该工具的 `timeout_ms + timeout_grace_ms` 受检计算。显式关闭、空闲超时、会话取消、
插件／所有者排空最终使用同一核心关闭身份，不再次手动调用关闭函数。会话关闭操作的空值
业务基线不作为插件返回值；宿主从独立关闭阶段投影版本一结果。重复关闭读取原证据，不重放。

正常显式关闭及干净空闲关闭只在实际退役、关闭成功且没有未确认业务记录时自动确认。
失败、取消或放弃等待产生的证据仍保留，可通过 `formal_sessions`、
`formal_session_status`、`formal_session_operations` 按控制器所有者查询；
`cancel_formal_session` 仅记录取消意图，`forget_formal_session` 在真实退役后显式确认全部
保留操作。它们目前是 Rust 接口，完整 WebUI／RPC 暴露仍待完成。结果保留耗尽明确拒绝新入场，
不自动删除失败证据。已退役且保留结果的会话可以在重复排空报告中再次计为已关闭，报告数量
表示本次确认完成的记录，不是新执行的关闭回调次数。

监督任务只持有管理器弱引用度过空闲等待。执行器退出保留原会话／操作，后续显式排空恢复
清理，不重新准备或重放业务。实际原生工作返回、独立关闭结束、核心会话及池遗忘完成后，
才释放宿主活动计数。记账故障保留未完成状态；重试只完成尚未完成的步骤，不能重复释放。
单次排空使用同一有限绝对等待预算，超时仍保留实际容量；父级关闭同时覆盖准备中会话。
旧工具、Hook、持久 UI 及瞬时调用的 System 租约表和失败租约重试表均已删除。
正式临时调用、固定会话与持久实例分别保留实际核心身份及物理退役检查点。

真实生产测试覆盖同 VM 状态、所有者隔离、关闭信封、并发排空与原生工作等待、
输入拒绝、业务与关闭失败保留、准备阶段取消、执行器退出恢复、记账失败恢复和空闲回收。
这些是本地行为验证，不表示完整混合池策略、RPC 控制、更新事务或长稳验收已完成。


## 持久 Hook 的正式所有权

生产预热与 Hook 调用进入 runtime/formal/instances/。每个插件只保留一个精确代次的记录，在阻塞
包准备之前发布；准备闭包和监督者分别持有完成检查点。核心在 `hook` 用途容量下显式使用 Session、
单实例串行池，多个工作区的 Hook 保留同一 Lua 状态；UI Action 使用同一所有权实现中的独立正式实例。
Hook 记录数受父级 max_sessions 限制，真实 VM、队列和操作继续由核心父级及插件聚合计数。
Hook 不占用清单中面向工具调用的旧 max_active_sessions 配额，保留原按类别独立的语义。
类别由用途配置决定；性能验证和最终默认值冻结仍待实施。

Hook 业务保留真实版本一 invocation_json 与 host_timeout_ms 入参，以及注册、上下文和载荷。
总预算在派发监督任务前建立，覆盖执行器调度、工作区校验、初始化门、包准备、核心排队及执行。
工作区元数据有值时必须是宿主规范化的现存目录，缺省明确使用包工作区。每次提交签发不可复用
请求关联并绑定真实核心操作；不同工作区不分裂实例，业务参数不能扩大进程目录权限。
原调用方放弃等待后，已有外层监督任务继续遵守原有限预算；执行器丢弃实际操作观察者时请求
核心取消。取消和超时均不能提前释放实际运行的 VM、原生回调或工作区登记。

初始化与业务分开观测。已结束且已完成宿主观测确认的业务记录才从核心回收；等待结束前取消的
操作仍留在原 Hook 注册记录中，监控确认其真实终态后回收，防止长期调用耗尽操作历史。
该内部 Hook 路径当前没有面向用户的逐次历史查询 API，不应把回收后的记录描述为可持久追溯。
监督错误保持明确，实例不能通过重新调用偷偷初始化；上一代记录需要显式排空后才能替换。

关闭仅选择清单可选 hook_shutdown_function，冻结 hook_runtime_shutdown 事件、插件身份和
宿主唯一关闭预算。未声明时不执行工具关闭函数。核心在原实例自动执行一次独立关闭，
宿主从独立关闭阶段读取结果；关闭失败仍完成可完成的物理清理并在排空报告中返回错误。
有限排空先停止已登记准备，再等待初始化门；超时保留原所有者。
执行器停止后，后续显式排空恢复同一记录，不重新加载或重放业务。
初始化、业务及关闭操作分别确认，核心会话与池成功遗忘后才标记退役。
父级关闭请求和完成检查同时覆盖 Hook 准备、业务和实际退役。

真实生产回归覆盖跨工作区状态及越界拒绝、超过操作保留容量的连续调用、运行中与排队超时、
原生阻塞回调的实际资源归属、准备期间停止、执行器中断恢复、关闭失败和重复排空、
无可选关闭函数时父级真实关闭、初始化错误原因保留，以及监督调度不能续期预算；仓库 RTK Hook 也通过此生产入口验证。
这些是本地证据，不替代完整控制暴露、更新事务、外部资源、长稳或发布验收。

## 宿主请求工作区作用域

候选核心在入场时冻结 `CapabilityCaller.request_id`。正式适配器的
`submit_in_workspace` 与 `submit_session_in_workspace` 要求宿主明确提供关联和现存工作区，
不从业务参数读取、不生成替代关联。后者同时核对传入池与真实固定会话所属池。
普通 `runtime().submit` 的无关联调用继续使用模块声明工作区；原生能力遇到带关联调用时，
必须找到本适配器登记的同一核心操作，未知关联或另一操作借用关联明确拒绝，不能回退。
该约束属于宿主适配器，不改变 LuaSkills 通用请求关联仅用于关联的语义。

工作区在宿主入场时规范化，拒绝缺失目录和有损 UTF-8 转换。截止时间在调用入口建立，
会话查询、路径准备和入场等待消耗同一预算；阻塞文件系统调用不能被此进程内预算强制中断，
但到期后不会再提交业务。固定模块工作区、安全分区、包代次和能力授权仍须分别通过原校验。
工作区作用域仅影响宿主进程规范解析的允许目录，不修改 Lua 进程目录，不扩大原声明权限，
也不把关联字符串变成独立授权令牌。

请求登记锁跨越核心的非阻塞队列入场，在返回真实操作 ID 后发布关联、工作区及原操作观察者，
随后释放锁。源码确认这一核心入口只排队，不内联运行 Lua；快速初始化回调等待同一登记锁，
因此不能在原操作身份发布前访问宿主服务。执行服务前释放登记锁。运行时与执行域先由现有
原生入口核验，关联再严格匹配同一操作，另一池甚至同一池的新操作都不能借用已知关联。

注册表由适配器持有，记录数量派生父级 `max_operations`，关联与规范路径的累计 JSON 字节
独立受父级 `max_queued_bytes` 限制；它与核心排队字节分别计账，不表示总堆内存硬上限。
取消、观察者离开和核心运行中状态均不释放记录。新入场先回收已证明终结的记录，
`reap_workspace_requests` 也可显式回收并返回数量；查询失败保留记录，回收不遗忘核心历史。
观察者不持有核心调度器或模块资源，因而不创建管理器与运行时的循环引用。

单次自动关闭仍属于原操作，保留原请求工作区直到真实关闭结束；会话开启及独立会话／
可复用实例关闭无业务关联，使用模块声明工作区，不能继承最近一次请求。真实测试覆盖
同一 Lua 状态跨工作区调用、越界目录拒绝、初始化发布竞争、独立关闭、单次关闭两个回调、
观察者离开与取消、关联借用拒绝、运行中与排队元数据共同超额拒绝及实际完成后的容量恢复。
持久 Hook 和持久 UI Action 生产入口已使用该逐次作用域；生命周期回调每次创建独立实例，固定模块工作区为原生命周期环境。瞬时 Action 使用每次请求固定的原授权工作区，并保留临时初始化及实际退役所有权。

## 业务关闭协议与其余生产路由待办

上游候选通过 `ModuleDefinition.finalizer` 和调度器完成同实例独立关闭阶段；
`ModuleLease::invoke` 仍明确禁止单次实例的第二次普通业务调用。因此不能用两个普通 `submit`
替代同 VM 自动关闭，也不能通过悄然改变复用模式改变现有状态隔离要求。

上游 `embedded/retirement.rs::run_retirement` 会重试受管资源清理。插件关闭函数可能产生业务副作用，
不能直接放入这个自动重试循环。已有 `EmbeddedModule::close` 当前只负责受管资源退役，不执行
清单关闭函数。自动关闭位于独立调度阶段。以下约束同时适用于后续生产路由及更新事务迁移，
不能由当前直接适配器测试推断生产停用／更新已经完成：

- 原调用和关闭回调保留同一实例归属；关闭使用独立有限预算，不恢复原业务调用，也不重复初始化。
- 原业务结果、关闭结果和实际资源退役分别记录；关闭失败不能丢失原结果或伪造 VM 已释放。
- 关闭回调只执行一次；错误、超时和持久回执确认丢失都不能触发自动重放。
- 关闭阶段的可信身份及能力授权由宿主和核心建立；插件业务参数不能指定关闭作用域或恢复撤销的权限。
- 等待方取消、停用、更新和运行时退出均保留真实资源所有者；不可中断原生工作仍占用预算。

核心接口、持久记录、C ABI 与三个 SDK 已共同实现三种复用模式的自动关闭；宿主真实 bundle
适配覆盖工具／Hook 关闭选取、同实例状态、原生关闭回调及版本一错误帧转换。普通无状态工具
及工具固定会话、持久 Hook、持久 UI Action 的管理器路由已经切换，其真实测试还覆盖放弃等待、阻塞准备、执行器停止恢复和有界结果保留。
生命周期业务使用正式单次调用；瞬时 Action 与探测使用正式临时会话，分离初始化与业务入场。
全部生产路由保留原协议及精确身份；当前验证不能代替完整混合池策略、更新事务、外部资源及发布验收。


## 持久 UI Action 的正式所有权与诊断

持久 UI Action 已进入 runtime/formal/instances，与 Hook 共用初始化、原始身份保存、
物理排空和执行器中断恢复逻辑。两种用途保留不同注册表、安全分区、固定会话及串行入场门；
UI 不执行工具或 Hook 关闭函数。实例在 `ui_action` 用途容量下使用核心 Session、单实例串行策略，
尚未把该阶段策略声明为经过性能冻结的最终混合池默认值。

生产入口继续校验当前代次、调用方、输入及输出 Schema、声明的空时间快照参数，
使用原 arguments 信封。持久 UI 的宿主进程目录权限仍固定于包工作区；
请求工作区只完成原有规范化校验，不扩大持久实例权限。瞬时 Action 则由下述正式临时会话
保留每次请求的授权工作区，两者的工作区语义保持独立。

读取型调用仅在执行入场前允许撤回，变更型调用在外部等待者断开后继续；
执行入场原子关闭取消窗口。这里的 executing 表示已开始入场，不证明 Lua 已开始执行。
实例串行门移动到真实操作登记中，核心操作到达真实终态后才释放，观察者丢失不会提前释放。
宿主调用计时通过已认证的请求与真实操作关联取得记录，不借用其他工作线程的局部状态。
初始化不带业务关联，其回调继续使用固定包权威，不记为业务回调耗时。

Action 入场许可现在由诊断记录持有。持久实例准备、初始化和业务操作分别保留物理守卫；
瞬时调用的物理守卫覆盖准备、初始化、业务和整个临时会话及池的退役。监督结果先记录为待发布结果；仍有真实工作时显示
cleanup_wait，terminal 保持 false，许可仍被占用。物理守卫全部离开后才发布最终结果。
执行器丢弃未轮询监督任务也能归还未使用容量；执行器异常退出产生 supervisor_failed，
它只描述宿主监督结果，不能推断业务无副作用或允许重放。后续显式排空在原实例恢复清理。

本地回归覆盖初始化撤回后不执行业务、初始化和业务回调期间执行器退出、有限排空保留容量、
新执行器恢复原身份、超出历史容量的连续调用、包工作区拒绝越界，以及父级关闭不调用错误
关闭器。原有读取撤回、变更等待者断开、其他插件继续执行、Hook/UI 状态隔离均继续验证。
这是持久 UI 的本地迁移证据；持久更新事务、完整控制暴露、
长稳性能、多平台分发和正式发布仍须后续交付。

当前清单权限与创建时冻结的核心授权共同约束原生调用：调用入场和服务查询等待结束后，
都在同一次目录观测下校验包身份、生命周期与该能力的当前权限。当前权限撤回会立即阻止
尚未进入服务的调用；新增当前权限不会扩大旧核心授权。该复核也适用于独立关闭，
排空授权不恢复已撤回能力。真实统计插件和等待服务期间撤回存储权限的回归均验证无新宿主调用。

进程解析继续使用原包、入口及环境声明，仅权限取原声明与当前清单的交集。二进制、Node、Python
及会话模式分别校验；撤回二进制权限不能借用仍有效的 Node 权限，单独撤回会话权限也不禁止
仍获授权的 exec 模式。真实生产 UI 测试覆盖这两个选择性撤权边界，没有启动外部进程。

## 生命周期回调的正式所有权

生产 invoke_lifecycle 的安装、启用、启用补偿、停用及卸载回调现已使用 runtime/formal/calls。
它们与普通单次工具共用入场、原始包描述符、阻塞准备检查点、实际核心操作、物理退役及显式恢复；
类型化所有者区分控制器与宿主生命周期，空控制器标识不能查询、取消或确认生命周期记录。

生命周期入口先固定唯一绝对截止时间，再按已声明事件选择函数及作用域。安装与卸载要求停用，
启用及启用补偿要求启用中，停用要求排空中；宿主发布门下检查代次及状态，核心提交前再次检查。
未声明回调或没有 Lua 运行时的插件仍直接成功。需要执行的回调缺少正式父级时明确失败。

可写环境准备现在发生在调用登记及活动容量预留之后的受跟踪阻塞任务内，复用原有
ensure_plugin_execution_environment 的复制、校验、依赖安装及发布实现。等待方或执行器离开
不释放仍在进行的准备；截止时间覆盖该阶段，准备队列到期后不会继续创建环境或提交 Lua。
无法中断的文件系统或依赖安装工作仍须真实结束，不能把有限观测超时解释为已经终止它们。
生成环境路径后，在调用与固定会话共用的注册表锁下重新核对输入总字节预算并更新该调用预留；
预算不足不提交核心操作，原登记继续负责清理。此计量不表示对临时堆分配或磁盘占用的硬限制。

每次回调在 `lifecycle` 用途容量下显式使用 SingleCall 单实例串行池，固定模块工作区为原包代次的可写环境。
入参仍是 event、plugin_id、environment_root 对象，不套用工具或 Action 信封。
没有工具或 Hook 自动关闭函数；实际 VM／受管资源清理由同一核心父级完成。
调用完成及排空必须等待实际池关闭和遗忘，之后才归还宿主活动计数，不再在关闭失败后无条件释放。
这是生命周期入口的迁移，不是完整混合池默认值冻结。

生命周期调用方消费结果或离开后，只有实际退役且监督结束的记录才自动确认核心历史并回收；
明确失败、成功和放弃等待均不会提前释放实际工作。正常业务失败通过原返回值报告，
内部记录回收后不承诺逐次历史查询。物理清理未完成或监督中断保留原记录与诊断，后续插件排空
恢复同一个操作，不能重建实例或重放回调。控制器工具的失败历史仍保留至显式确认。
逐条回收在开始下一次可能失败的确认前先提交已完成移除，避免后续失败使先前成功步骤被重放。

真实回归覆盖五种事件、启用补偿错误、原工作区及父目录越界拒绝、独立实例与错误关闭器排除、
连续失败超过保留容量、控制器身份隔离、等待者及执行器丢失、父级关闭和有限排空期间容量保留，
以及包准备排队期间的截止时间与代次变化。生命周期回归不代替其他路由验证，也不证明环境回收政策、
持久更新事务、外部资源、长稳／多平台及正式发布已完成。

## 瞬时 Action 与启用探测的正式所有权

两条生产入口均进入 runtime/formal/calls；类型化入场意图共同决定所有者、初始化方式和业务导出。
Action 与探测分别在 `ui_action`、`activation_probe` 用途容量下使用私有 Session 单实例串行核心池，先记录真实初始化操作，再决定业务入场。
此 Session 仅服务一次瞬时请求，不登记为持久 UI 实例；下一次请求重新初始化独立 Lua 状态。
普通工具和生命周期仍使用原 SingleCall 协议，不能把临时会话策略推广为所有路由的复用默认值。

瞬时 Action 在原入口完成调用方、代次、输入 Schema、声明时间快照及工作区检查；
初始化结束后，在目录发布门内再次核对代次及生命周期，再原子关闭执行前取消窗口并提交唯一业务。
入参仍是 arguments 对象。每个业务操作绑定可信请求关联、实际操作身份、原规范化工作区及 Action 诊断，
回调计时由该绑定取得，不再传播线程局部的旧引擎上下文。输出 Schema 仍在返回边界验证。
读取可以在执行业务前撤回；变更在外层等待者断开后继续，始终受原清单截止时间约束。
取消仅在截止时间前进入记录；到期后的 HTTP 等待断开或显式取消查询不能把超时改写为主动撤回。
已经入场的业务不能由读取取消重放或重新初始化。

探测只接受启用中代次，在受跟踪阻塞任务中解析原执行包工作区并重算保留输入预算。
真实模块初始化检查清单全部导出；成功后直接清理，不构造虚假的探测业务导出。
初始化本身仍可执行插件顶层 Lua 和已获授权宿主能力，不承诺无副作用或完整沙箱。
探测不占清单工具活动计数，保持原类别语义；父级 VM、会话、队列和历史预算仍然有效。
清理诊断额外检查未退役正式调用，不能因探测的工具计数为零就提前清除警告。

两条路由都不声明工具或 Hook 业务关闭器。关闭等待原核心会话实际 Closed，再依次确认会话、
初始化操作、请求工作区、池和活动容量；各成功步骤保留独立检查点，失败不重复遗忘或创建替代身份。
瞬时 Action 的容量守卫跨越整个过程；原生回调未返回时，即使 HTTP 超时或执行器退出，容量仍不可复用。
执行器退出后，显式排空只恢复原身份的清理；初始化尚未完成时绝不补执行业务，已开始业务也不重放。
内部调用在观察确认且实际退役后回收核心历史；Action 诊断仍由原有有界诊断记录保存。
