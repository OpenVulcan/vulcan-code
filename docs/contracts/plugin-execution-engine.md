# 插件执行引擎归属

## 当前边界

服务启动通过 `vulcan-service-runtime/src/luaskills_bridge.rs::bootstrap_luaskills`，从同一份已解析宿主选项构造两种独立所有者：

- `TauriLuaSkillsHandle::engine` 是普通技能管理引擎，保持原有读写锁及目录、配置管理入口。
- `TauriLuaSkillsHandle::plugin_engine` 是不可变的 `Arc<LuaEngine>`，不加载普通技能目录，也不进入普通技能管理锁。

`vulcan-service-kernel/src/service_bootstrap.rs::prepare_vulcan_plugin_runtime` 将后者交给插件管理器。
句柄克隆只增加同一引擎的强引用，不重新创建插件引擎。插件与普通技能使用相同的宿主路径及启动设置来源，
但有各自的上游受管运行服务及 VM 所有权；这不表示两者共享一份进程级资源预算。

插件管理器的引擎槽仅保护一次性附加及短暂取得强引用，已经附加后明确拒绝替换。
实际 Lua 创建、执行、查询及清理直接持有不可变引擎，不在普通技能读写锁内运行。
异步等待方离开不结束实际工作的强所有权。管理器销毁请求正式父级关闭，实际退役仍由核心完成。

## 当前迁移状态

生产启动在附加独立插件引擎后，显式调用 `initialize_formal_runtime` 建立管理器唯一的正式槽。
其私有 `FormalRuntimeAttachment` 明确区分就绪与失败：成功保存 `ManagedFormalRuntime`；
核心已经构造但能力或配置容量注册失败时，保存同一个核心、原设置及原初始化错误，再返回该错误。
失败不会发布部分就绪状态，业务 getter 继续返回原错误；关闭控制仍能访问同一个原核心。
管理器克隆只共享该父级，不另建 VM 治理器；重复附加返回错误，
即使原运行时已完全关闭也不允许在同一管理器中静默替换身份。纯内容管理器不创建正式运行时。
初始化阶段注册原生能力、显式配置的用途容量及对应插件预算，并创建有界核心工作线程，没有提前执行插件 Lua。

正式预算从宿主状态根下的 `plugin-runtime-settings.json` 读取，权威实现为
`vulcan-plugin-runtime/src/runtime/settings.rs`。预算对象版本为 `schemaVersion: 5`，顶层字段为
`schemaVersion`、`parent`、`pluginBudgets`、`capacityBudgets`、`automaticPrewarm`、`maxCapabilityCallMs`、`shutdownTimeoutMs`；
`parent` 直接反序列化上游 `EmbeddedRuntimeConfig` 的字段和命名，不维护宿主复制 Schema。
除可缺省的 `pluginBudgets`、`capacityBudgets` 和默认空集合的 `automaticPrewarm` 外，既有文件必须提供完整结构；
未知字段、未知版本、非法父级、插件或用途限制及非正或不可表示的时长均报错。
第一至第三版各按原严格结构解码，随后在内存升级至第五版，保留全部原预算及时间值，
仅补入当时不存在的空集合；旧版携带新版字段同样拒绝。第四版已用于事务容器，不能解释为裸设置。
重复版本字段、插件键和用途键报错，
不会通过中间 JSON 映射消除重复证据。原生能力注册容量另由适配器
在分配核心线程前验证。文件缺失使用唯一 `Default` 中的内存值，不创建目录、不写回配置。
默认值的唯一来源仍为当前 `Default`。核心零点六点一的冻结负载、长稳及五平台正式发布已经分别验收；
宿主正式 registry 依赖和真实浏览器提示提交也有独立来源证据，各阶段结果不能互相替代。

父级、插件聚合及执行超时在构造时冻结；用途覆盖通过[显式策略事务](plugin-capacity-policy-transactions.md)修订。
受管写入使用版本六容器，将完整版本五设置与互斥的容量／预热策略回执一起原子发布；
第一至第三版裸设置及第四版容器继续严格读取。自动预热策略的持久控制见
[自动预热策略事务](plugin-automatic-prewarm-policy.md)，实际回合触发已接线并通过运行时／服务专项及真实浏览器提示提交验收。
文件外部修改不替换运行中的父级。`formal_runtime_status` 可读取核心身份、生效设置及 `policyUpdate`；
设置与事务在同一锁下取得，队列、操作及 VM 计数仍为独立实时观测，不是整个父级的跨字段事务快照。
`request_formal_runtime_close` 仅永久关闭入场并请求取消，`poll_formal_runtime_closed`
须确认宿主准备和监督工作已经结束，并由核心确认工作线程及 VM 真实终止后才返回完成。最后一个管理器释放时先请求正式父级关闭；
实际生命周期关闭仍应走显式控制和排空，不能把析构触发理解成完整排空验收。

服务通过 `native_plugin_shutdown.rs` 在同一个原服务短保护区内，先保留唯一原管理器，再附加引擎、
初始化正式父级；初始化错误也保留该所有者。首次发布及最终就绪均检查实际关闭准入门，
不能在服务已经进入关闭后迟到创建父级。插件更新和旧扩展代次继续共享这个原管理器，
不从当前目录或历史代次重新寻找关闭对象。
关闭协调器在原不可恢复阶段、MCP 拆除之前，于服务锁外调用 `close_formal_runtime_blocking`。
该等待以原实际设置的 `shutdownTimeoutMs` 为预算，使用原操作观测节奏，必须由核心确认执行与退役线程实际退出。
超时或错误保留原管理器及日志订阅供明确重试；不可恢复关闭门保持，不允许重新开放同一父级。

父级已覆盖本管理器的工具、Hook、Action、生命周期和启用探测生产执行路由。
核心统计不等同于整个进程、插件环境磁盘或外部服务的资源预算。

### 插件聚合预算

`pluginBudgets` 是按精确插件 ID 索引的宿主覆盖表。缺省表或表中缺少某个 ID 时，明确从冻结
父级派生该插件的全部七项聚合上限；不是另一份编译默认值。存在覆盖时，必须完整提供上游
`EmbeddedPluginConfig` 的七个 snake_case 字段：`max_registered_pools`、`max_sessions`、
`max_resident_vms`、`max_running_calls`、`max_queued_calls`、`max_queued_bytes`、`max_operations`。
不做逐字段合并、裁剪或未知名称兼容。全部字段必须为正、不超过父级，并通过上游组合约束；
无效插件 ID 和未来尚未安装插件的无效预算，也在启动线程前统一拒绝。

权威实现为宿主 `runtime/settings/budgets.rs`、`runtime/formal/budgets.rs` 及上游
`runtime/embedded/plugin_config.rs`。具有显式用途配置的插件在父级发布前注册预算，其余插件首次入场在目录发布门内注册；随后所有生产路径
复核同一冻结配置。既有核心所有者配置不一致或已永久关闭时明确报错，不能重新注册来绕过。
无状态工具、工具固定会话、Hook、持久 UI、瞬时 Action、生命周期与启用探测均共用同一插件
核心所有者，包括尚未退役的旧代次。执行域队列上限从下述用途容量派生，用途配置又受此有效插件预算约束，
避免较小插件覆盖被父级大小的域声明绕过或导致声明冲突。

聚合计数由 LuaSkills 核心执行，包括创建中、空闲、运行中及退役中的 VM，排队请求与字节，
保留池、会话与操作。一个插件占满自身常驻额度后，其他插件仍能使用父级剩余容量；
同一插件的 Hook 与 UI 也相互消耗该额度，因此仅配置一个 VM 时，两者不能同时常驻。
插件聚合提供上限隔离；下述用途容量可显式增加专用预留。单次调用的独立 Lua 状态本身不代表专用容量。

`formal_plugin_status(plugin_id)` 返回原 `runtime_id`、整份策略来源 `parent` 或
`host_override`，以及核心 `EmbeddedPluginSnapshot`。该读取不创建插件；父级未附加或 ID
尚未注册时返回空值，非法 ID 或实际配置不一致返回错误。该原生聚合读取目前是 Rust 接口；
用途容量页面与下文宿主保留资源诊断具有各自状态来源，不能将它们当成此原生聚合快照。
原始核心字段命名由上游类型决定，上游升级时须同步回读和验证。
宿主准备阶段的保留记录及序列化输入仍使用既有父级预算；不能把核心插件计数当成宿主准备
内存、进程总内存或外部服务硬配额。运行中的父级及插件聚合预算保持冻结，文件编辑不触发隐式重载。
用途策略的显式修订及持久恢复见前述事务契约；历史格式读取仍只执行内存迁移，不自动回写配置。

### 用途容量、专用预留与成员寿命

`capacityBudgets` 按精确插件 ID、用途两层索引。用途仅允许 `tool_call`、`tool_session`、`hook`、
`ui_action`、`lifecycle`、`activation_probe`，由宿主类型化入场选择，业务参数不能指定或覆盖。
瞬时和持久 UI Action 共用用途额度，但各自的 Lua 状态、安全分区和寿命仍隔离。
权威实现为宿主 `runtime/settings/capacities.rs`、`runtime/formal/capacities.rs`，以及上游
`EmbeddedCapacityConfig`、`VmCapacityConfig`、容量调度器和资源治理器；上游升级时须回读源码同步本文。

缺省用途明确使用 `Shared`、最小预留零，所有最大值从有效插件聚合预算派生。
显式覆盖必须完整提供上游字段 `resources`、`max_queued_calls`、`max_queued_bytes`；
`resources` 包含 `kind`、`min_resident_vms`、`max_resident_vms`、`max_running_calls`。
不合并单字段，不通过其他用途补齐。核心约束决定类别、正数边界及父级／插件上限；
所有显式用途最小预留的插件内总和和全父级总和必须同时可满足，注册数量也必须合法。
包括尚未安装插件在内的显式配置均参与校验与承诺，空用途表不创建原生所有者。

全部显式容量在父级公开前注册，公共业务无法先消费这些承诺；失败不发布局部运行时。
此阶段只保留预算，不创建、初始化或预热 VM。无显式覆盖的用途在第一次真实成员准备时登记。
`Dedicated` 的最小预留不可被其他容量借用，实际总量仍受用途、插件及父级共同限制；
最低常驻预留不等于 CPU 时间、公平调度或端到端延迟保证。

每个插件用途保留一个核心签发身份，跨包代次共用容量；每个模块成员仍由原注册路径校验目录、
冻结源码并保留独立身份和状态。成员的最小预留为零，不按每个会话或代次重复承诺用途最小值。
容量归属本身不改变实例复用语义或 `InProcess` 后端；默认路由仍采用原 `SingleCall`／`Session` 策略，可复用工具的显式例外见下文；
专用容量不是独立操作系统进程，不提供进程崩溃隔离。

`formal_capacity_status(plugin_id, purpose)` 返回原父级身份、用途、策略来源 `plugin_budget`／
`host_override`、宿主准备计数、`retirementRequested` 及原生 `EmbeddedCapacitySnapshot`；无注册时返回空值且不分配资源。
另含 `policyRevision` 和 `pendingConvergence`，与原生快照来自同一次核心原子观测。
`formal_capacities()` 提供已登记用途目录及独立映射前驱。管理端通过 `register_formal_capacity`
可以先登记尚未执行过业务的用途，再用策略事务设置专用额度；登记不启动 Lua 或写配置。
成功请求由原容量的 `managementRequest` 保留，可按父级和提交身份查询，原对象遗忘后旧请求不可重放。
完整前驱、只读及恢复语义见[容量策略管理契约](plugin-capacity-policy-transactions.md)。
`request_formal_capacity_close` 永久关闭该身份及成员入场，只确认关闭请求，不证明物理排空；
后续调用不会自动选择另一用途或创建替代身份。宿主成员注册准备守卫保留原映射，直到真实准备返回，
关闭期间尚未完成的注册会明确失败。`forget_formal_capacity` 必须等待全部准备结束、成员实际清理且
原生成员池显式遗忘；失败保留同一身份和预留。只有显式遗忘成功后，后续合法入场才可重新注册。
目录刷新、普通会话结束或包代次切换本身不释放用途容量；调用方应按生命周期安排成员排空及显式释放。
父级物理关闭也不能替代元数据遗忘。未完成策略事务阻止该用途新增准备及元数据遗忘；
已有操作、固定会话和真实清理继续保留。可复用无状态工具的目标预热已有独立 Rust、RPC 及
WebUI 链路，见下文；该目标流程不为其他用途推导预热导出。清单资源要求见下节。

生命周期容量实现位于 `runtime/formal/capacities/lifecycle.rs`。停用、启用补偿等事务调用
`finish_lifecycle_transition` 时，按扫描得到的最终策略决定是否回收该插件全部用途容量。
最终策略为停用时，容量回收、清理诊断和目录发布共用原发布门；不会与新的成员准备交错。
服务仍先排空旧成员、执行停用或补偿回调，再最终发布，因此普通排空入口不提前关闭生命周期容量。
回收先确认所有用途均无准备声明或保留成员池，再关闭及逐项遗忘；前置检查失败不关闭任何健康容量。
原生移除途中失败保留剩余精确身份，已完成项立即确认，不重放。

失败回收保留插件级明确意图，阻止普通调用登记新成员，并保持既有清理告警；仅实际 VM 清零
不能让诊断提前消失。进入 `Enabling` 前，包括停用回滚，先重试有明确意图的旧回收，再恢复全部
显式用途保证；无法同时满足时回滚本次新建空容量，不发布新启用代次，也不静默降低最小值。
恢复失败而尚有原生归属时保留诊断。手工关闭但未请求生命周期回收的容量仍须显式遗忘，不能借启用绕过。
停用重试的真实生命周期回调也可在原成员排空后明确完成此前回收，并按原配置恢复容量；
该入口先核对精确目录代次及事件作用域，普通业务入口不执行这种恢复。

物理卸载入口 `uninstall_user_plugin` 在包改名、删除环境和配置之前，在原发布门内回收容量；
成员或准备未结束时保留包、容量身份及停用告警。卸载回调仍由服务在此入口前完成。
这些规则管理容量保证和成员寿命，不删除尚未确认的操作历史或原生插件聚合元数据，
也不等同于持久更新、凭据、路由和全部外部资源事务已经完成。直接目录刷新仍不隐式释放显式策略。

真实生产测试覆盖启动承诺、公共会话无法占用他人预留、六种用途路由、原生身份跨代次保留、
准备期间拒绝遗忘，以及实际常驻成员排空之前拒绝释放保证。生命周期测试还覆盖真实回调先于释放、
启用前恢复保证、第二份预留失败时撤销第一份、未排空告警持续保留、停用重试和实际包卸载。
目录修订在最终路由发布时从唯一计数器签发；实时会话计数和清理诊断不签发路由修订或替换路由分配。容量元数据受现有核心注册上限约束，
已关闭但未显式释放的用途仍占额度。核心冻结负载、长稳、五平台正式分发、宿主正式依赖及实际业务用途验证各自保存准确来源，
本地测试不替代公开分发或真实宿主验收，未执行的业务组合不从这些结果推定。

`begin_draining` 在目录发布门内为该管理器持有的正式运行时中、精确源代次的既有启用域
签发本次排空代次。仅核心 `CapabilityBudget::is_finalization()` 证明的自动关闭阶段可使用，
普通业务调用、名为关闭的普通导出及业务参数均不能选择该授权。能力入场及实际宿主副作用前
仍检查实时核心授权、预算、包内容、目录路径和当前排空代次；回滚、下一轮转换、内容变化或
撤权均不能复活原授权。转换代次耗尽明确报错，不以饱和递增复用身份。
各宿主服务自己的约束仍有效，例如配置写入的精确代次检查不会因进入关闭阶段而放宽。
该接入提供关闭权限边界；已迁移路由沿原身份完成入场、取消及物理排空。
更新服务已通过 `skills_services/local_plugin_update/` 接入原请求、候选及前驱交接，
其正式 registry 与实际页面更新、刷新及原请求恢复验收已取得独立证据；冻结 Provider 工具的插件身份与代次绑定已通过真实生产桥回归及独立审核，具体调用边界见下文。

普通无状态工具、工具固定会话、持久 Hook 及持久 UI Action 已通过管理器唯一 `EmbeddedRuntime` 执行，具体所有权见下文。

普通正式调用与持久 UI Action 直接异步观测上游 `OperationHandle::wait_terminal` 的真实终态，
计时器仍由宿主唯一观测间隔限制；观察超时仅重新查询同一操作，继续原截止时间和取消检查。
原已终态快速路径、工作区守卫、实际退役和观察确认保持。Core 阻塞等待、C 接口及 SDK 契约不变；
通知只提示重查原状态，不授予执行、取消、完成或释放资源的权限。上游实现变化时须回读对应源码。
生命周期、瞬时 Action 与启用探测也已复用正式调用所有权，管理器业务不再创建旧 System 租约。
执行路由、混合用途容量、自动预热策略和更新协调器均已有当前生产源码链路，详见对应章节。
本地核心性能证据、服务专项测试及正式分发／实际浏览器验收保持各自归属，不能合称整个目标已完成。

核心候选中的类型化模块已经在真实宿主句柄上验证：普通引擎写锁持续持有期间能初始化和调用插件模块，
普通目录真实重载后，同一插件模块保留原 Lua 状态并继续执行。现有初始化退役测试改用真实宿主回调屏障，
不会再依赖已经移除的引擎写锁模拟初始化。

测试现使用 System 根之外的不可变代次目录布局。核心候选的正式模块按可信宿主 `ModuleDefinition` 授权精确包根，
保留包内依赖、授权工作区／cwd 及原生对象身份校验，旧 System 租约仍维持其信任根限制。
此测试直接创建真实模块，尚未验证生产插件管理器的混合池路由或安装更新事务；实际代次固定句柄
现由下述原生适配器交给核心生命周期持有。
宿主正式接入仍须从已核验目录及授权记录构造定义，并完整限制第三方 Lua 的能力；路径声明本身不是插件沙箱。

## 第二版清单的兼容性与资源必需条件

清单结构由本仓库 `manifest.rs`、`manifest/requirements.rs` 与 `catalog.rs` 共同校验。
`schema_version: 1` 保留既有语义，禁止新增 `runtime_requirements`；第二版 Lua 插件必须明确声明该对象，
非 Lua 插件不得声明。省略与空值不等价，未知版本、字段、用途、重复字段或重复用途直接拒绝。
不会在发现、刷新或启动时重写插件清单及宿主配置。五个内置包已显式迁移到第二版，保留原有权限和执行语义；
完整生成 Schema、迁移及包校验命令、各包运行验收边界见[插件清单编写工具](plugin-manifest-authoring.md)。

下面为第二版 Lua 插件的新增顶层片段，其余 Lua 声明保持现有结构：

```yaml
schema_version: 2
runtime_requirements:
  protocol_version: 1
  backend: in_process
  core_capabilities: [capacity_groups_v1]
  capacities:
    - purpose: tool_call
      reserved_resident_vms: 1
      resident_vms: 2
      running_calls: 1
      queued_calls: 4
      queued_bytes: 65536
```

示例数字是插件的业务要求，不是生产默认值或自动写入值。`protocol_version` 指 LuaSkills 嵌入式核心协议，
与插件清单版本独立；版本、核心后端和语义功能的实际支持集合直接读取链接核心的
`ffi_embedded::embedded_core_description()`，上游版本升级时须回读此描述及对应实现。
后端还须匹配宿主 `VULCAN_PLUGIN_EXECUTION_BACKEND`，该单一定义同时用于三条真实生产注册路径；
核心新增后端不会自动使尚未适配的宿主宣称支持。
`core_capabilities` 只声明版本化语义功能，不授予权限，也不代替宿主回调的名称、版本及授权契约。
预留的 `worker_process` 当前被明确拒绝，没有静默回退。复用与顺序只接受下文无状态工具入口的明确声明，未知字段及未支持模式仍拒绝。

用途与宿主 `capacityBudgets` 使用同一 `VulcanPluginCapacityPurpose` 类型，支持普通工具、工具会话、Hook、
界面动作、生命周期和启用探测。每项完整要求的含义如下：

| 字段 | 约束与对应宿主配置 |
| --- | --- |
| `reserved_resident_vms` | 非负，对应不可出借的 `resources.min_resident_vms`；零不要求预留 |
| `resident_vms` | 正数，要求 `resources.max_resident_vms` 至少达到该值 |
| `running_calls` | 正数，不超过本项 `resident_vms`；要求 `resources.max_running_calls` 至少达到该值 |
| `queued_calls` | 正数，要求 `max_queued_calls` 至少达到该值 |
| `queued_bytes` | 正数，要求 `max_queued_bytes` 至少达到该值 |

预留数不得超过常驻要求。`capacities: []` 明确表示没有额外资源下限，`core_capabilities: []` 明确表示没有额外
语义功能要求。宿主用生产容量解析器逐项比较生效配置，错误包含插件、用途、字段、所需值、实际值及配置来源。
插件声明不能提高宿主预算、改写设置、自动选择专用池或分配 VM。公共配置的最小预留为零，因此不能满足正数预留要求。
这些是可接受策略的下限，不保证调用时存在空闲实例、实际执行并发或已经预热；真实入场仍受核心当前占用、队列、
插件聚合、父级预算及原业务顺序约束。

管理器发布目录时先验证完整插件的要求；不满足则设置 `runtime_execution_available = false` 并移除全部活动暴露面，
保留诊断、原包和既有生命周期状态，保证仍可进入停用及卸载流程。进入启用中状态前再次检查，实际工具、
安装／启用回调、固定会话、持久 Hook／界面准备也检查同一生效策略。明确停用、启用回滚、卸载回调仅要求
其生命周期用途的资源下限；工具等业务额度不足不能阻止清理，生命周期自身下限仍不能绕过。精确代次、事件作用域、
能力授权及核心当前预算检查保持不变。检查没有执行 Lua。第二版 Lua 插件在正式父级尚未附加时不发布活动能力；附加之后须正常显式刷新目录。
服务启动已有“附加正式父级 → 刷新目录”顺序。停用资源回收及重新启用恢复继续遵循前节规则。

[运行时要求片段](plugin-runtime-requirements.schema.json) 与[完整清单 Schema](plugin-manifest.schema.json) 均从真实 Rust 类型生成。
精确版本、链接核心支持、同用途重复、数值间关系、机器整数范围和有效宿主策略由 Rust 校验，不能仅凭 Schema 通过宣称可激活。
结构对照测试、真实目录拒绝测试及实际启用探测／业务调用测试共同验证此边界。显式迁移保留第一版执行语义，
不自动开启复用或并行；内置包已逐个升级，通用预热仍须后续交付，已接入的无状态工具复用与分区顺序见下文。

第二版 `runtime_requirements.host_capabilities` 可声明宿主回调要求；省略或空数组表示不要求额外回调，
显式空值、未知字段及重复名称拒绝。每项必须包含 `name`、`version`、`execution`、`scope`：
名称精确匹配，版本必须是完整语义版本并逐字匹配已注册版本，不接受版本范围、探测别名或自动升级；
传输与作用域直接使用核心枚举 `native`／`queued` 和 `invocation`／`session`。
结构片段见同一要求 Schema，语义版本与名称唯一性由 Rust 校验，实时注册身份由核心快照校验。

目录发布及激活使用当前真实注册表检查；注册模块时再次检查其精确捕获快照，然后将同一绑定传给核心，
不会在校验后重新读取另一份注册成员。热复用的分区键和实际池绑定也使用同一快照。
发现和校验复用实际执行的清单权限派生器；缺失与未授权统一报告，必需条件不能授予新权限。
已授权但版本、传输或作用域不符时返回具体冲突。回调注册不证明外部数据库、网络或其他业务后端就绪，
实际回调仍独立检查调用范围、撤权、取消和截止时间。

显式停用、启用回滚和卸载清理不受不相关业务回调要求阻断；实际清理调用仍使用核心捕获身份及全部权限检查。
替换回调不热改旧 VM 的函数目的地，显式注销仍禁止该身份的新调用；目录显式刷新发布不兼容诊断并撤下活动能力。
即使刷新尚未发生，新模块注册也会拒绝不兼容绑定。清单声明、用户设置和版本不会因此被自动回写。

可信 Rust 宿主通过 `VulcanPluginRuntimeManager::formal_capabilities()` 取得已附加父级的真实
`CapabilityRegistry`，直接使用上游注册、注销、状态、遗忘和 `host_requests()` 分发接口。
未附加时明确报错，不隐式创建父级；管理器克隆取得同一注册表。保留句柄不会绕过父级关闭，
新注册仍由核心拒绝，已有注册的排空状态继续可查。
宿主变更注册后显式刷新目录，并自行管理排队处理器的执行及完成；注册不自动生成 AI 工具或扩大插件权限。
处理器须按可信调用身份及原始预算校验自己的业务范围；此接口只提供可信宿主扩展点，不向插件或 AI 暴露注册权限。
真实测试同时验证原生及排队回调的 Lua 调用、精确注册身份、结果投影和关闭后的拒绝行为。
热复用测试还验证相同版本的同名回调替换：不依赖目录刷新，新调用使用新模块及新池，
旧模块按原身份真实退役，模块内计数状态不能跨替换继承。

## 原生能力适配入口

`VulcanPluginEmbeddedHost` 使用插件管理器已经附加的独立引擎，创建一个显式预算的正式运行时。
每个运行时原子注册既有十八项宿主能力；回调仅持有当前运行时的权威表和管理器弱引用，
不进入进程级旧回调路由。核心继续独占池、队列、操作、会话、撤权和实际关闭的生命周期，
宿主适配器不再创建第二套 VM 所有者。宿主须先注册插件聚合预算，再通过适配器注册执行域。

执行域只接受可信宿主构造的模块源码及声明。插件身份、目录代次、包根、依赖声明和生命周期作用域
必须匹配实际目录；工作区显式解析。注册时生成独立不透明执行修订；对应描述符交由
`ModuleResourceOwner` 保留，因此受管不可变包的物理固定句柄随真实池及 VM 清理释放。
权威表仅保存弱引用，容量派生自同一核心池注册限制，失败注册撤销预留。

能力调用从核心 `CapabilityInvocation.caller` 取得可信身份，核对运行时、插件、
`package_generation`、执行修订、工作区声明及安全分区，并检查当前目录代次及生命周期。
业务参数中的同名字段无法替换这些权威。权限按清单映射为逐能力可撤销授权，发现和执行共同受限。
短元数据锁不跨越实际服务执行；开始服务前再次检查实时撤权、取消及截止时间。
存储与 VLDB 请求显式接收由原调用剩余预算派生的有限截止时间，不依赖旧 Action 线程局部变量。

原生服务仍使用既有返回值协议，尚未提供持久提交或去重确认。因此服务执行后的副作用保守记为
未知，准备阶段拒绝记为尚未开始；不能由业务返回成功推断提交成功，也不能自动重放。
配置读取使用原描述符；配置写入在既有发布门内再次核对代次、指纹及包根，避免旧任务按新 Schema 写入。
进程规格解析使用原描述符及宿主工作区，不重新选择当前新包。

类型化模块入参使用核心既有 JSON 容器标记，保证空对象、空数组及嵌套空值转交宿主能力时不丢失类型。
Lua 自行创建空对象时使用已有 `vulcan.json.object()`；未标记 Lua 空表不被猜测为对象。
该转换的权威实现位于上游 `runtime/engine/lease/embedded.rs` 与既有 JSON 转换器；升级上游时同步检查。

本入口已通过真实 Lua 的身份伪造、撤权、目录内容刷新、旧代次配置写入拒绝、双宿主隔离、
失败注册回收、界面事件边界及等待服务期间取消验证。普通无状态工具、工具固定会话、持久 Hook 及持久 UI Action 已接入该入口，
生命周期、瞬时 Action 和启用探测也已接入同一原生能力适配器。后续仍须
将插件环境副本、进程与外部资源纳入实际寿命，并完成更新事务后才能宣称完整上线。
当前入口的代次检查是服务入场检查，不能代替更新期间对已入场服务的等待和持久事务协调。

## 真实清单与受限模块加载

`VulcanPluginBundlePoolRequest` 只接收宿主选择的插件身份、目录代次、已授权工作区、安全分区、
生命周期作用域及显式池策略；不接收调用方提供的 Lua 源码或导出列表。
请求另可显式携带核心 `ModuleFinalizer`：其导出只允许选择当前清单的 `shutdown_function`
或已声明的 `hook_shutdown_function`。宿主路由提供自身版本一关闭信封及独立有限预算；参数在
注册时冻结，对该池实例统一使用。工具请求关联号等不能从上一业务参数猜测，宿主须按其用途
构造；关闭操作的执行身份和去重证据仍以核心操作记录为准。未声明自动关闭时显式为 `None`。
`register_bundle_pool` 从真实目录和执行包根读取清单指定 bundle，复用固定桥的受限环境构造器。
所有源码在注册前冻结，初始化仍在核心操作实际入场后发生；没有绕过核心预算提前初始化。

原生适配器同时提供 `register_pool_in_capacity` 与 `register_bundle_pool_in_capacity`，显式接收
核心签发的容量身份；原两个注册入口保持独立归属。两种归属共用目录、包、依赖、工作区、权限和
执行修订检查，最终分别调用核心独立注册或带容量的原生所有者注册，不复制包所有权或 VM 账本。
缺失、关闭、外来容量或冲突的成员策略直接报错，失败注册回收原生权威表中的预留。
真实 bundle 测试确认新旧目录代次可归属同一容量而各自保留 Lua 状态；旧代次原生服务仍被实时
目录校验拒绝。容量关闭会关闭成员入场，成员显式遗忘后才能释放空容量保证；父级物理关闭
本身不替代成员元数据的显式关闭／遗忘。生产入口使用上文的用途容量，旧独立入口仍供明确选择独立归属的调用方使用。

固定桥的 `load_module` 使用原生能力传输，不生成旧 JSON 身份信封。旧 `load` 保留明确的兼容
传输及原逐次工作区语义。两种入口共享全局能力限制、模块白名单、进程规格解析和 JSON 容器处理。
bundle 仅按 Lua 文本编译；宿主包装中的 bundle 和清单值作为转义数据传入，不能成为包装代码。

正式模块捕获清单声明的工具分发、工具关闭、Hook、Hook 关闭、UI Action 和生命周期函数引用。
私有辅助函数不进入核心导出表，未声明导出在操作入场前被拒绝；插件后续修改返回表不会重定向
已经捕获的函数。现有版本一协议保持对象入参及 JSON 帧字符串返回值。

当前入口要求清单显式声明依赖文件，与 `catalog.rs::validate_runtime_files` 对版本一 Lua 组件的
既有要求一致。清单类型允许省略该字段，是为不含 Lua、Node、Python 等需依赖清单组件的包保留；
不能仅凭字段类型可选推断 Lua 插件允许省略，也不应为此生成空文件或扩大核心协议。
调用方仍需执行完整业务语义：无状态工具的分发和关闭须在同一 VM
完成，持久 Hook 和会话保留实例，关闭回调执行完毕不等于核心 VM 资源已经释放。
配置 `finalizer` 后，核心自动调度同实例关闭，支持单次调用、固定会话及可复用实例；
未配置时维持原显式调用契约。本入口不创建默认池策略；普通无状态工具和工具固定会话分别
显式使用下述默认单次及会话策略；第二版可复用无状态入口有独立注册方法。配置自动关闭的路由不得再把同一关闭函数作为普通业务手动调用。

固定加载器为选定关闭函数保留原引用，并校验其版本一 JSON 帧。非字符串、无效 JSON、
缺少布尔真值 `ok=true` 或明确 `ok=false` 均转换为核心关闭失败；成功字符串保持原字节。
Lua 抛错与独立预算超时也由核心记录。原业务与关闭结果分别保留，整体失败不删除业务成功值。

真实测试覆盖受限全局环境、初始化原生配置读取、已捕获引用、私有导出拒绝、缺失导出和非法源码、
空对象／数组及特殊字符，以及同 VM Hook 关闭状态。仓库内 Context7 配置读取与关闭、用量统计
插件初始化与关闭已通过正式入口；这些检查不覆盖联网、原生扩展实际加载或实际数据库业务。

开发期核心候选只通过完整方案第 13.1 节规定的隔离检出和临时 Cargo 配置消费。
本契约不改变正式依赖来源；候选锁文件差异及本机工具路径不得提交为生产配置。
正式发布后仍须取消本地覆盖，以真实注册表核心重新验证。

## 冻结供应商工具声明的执行身份

供应商请求从冻结扩展目录取得工具描述及参数结构，`tooling/bridge.rs` 同时从该原描述符捕获
`plugin_id` 与 `plugin_generation`。执行闭包通过 `sessions.rs::invoke_in_generation` 传递这对身份；
运行时读取当前工具后，在无状态调用、会话打开、会话调用及会话关闭四种分派之前同时比较两值。
不同插件的代次分别计数，数值相同不能表示同一所属插件。旧声明跨插件更新或相同工具标识接管时
明确拒绝，不能转投当前新业务，业务参数也不能提供或修改该身份。

比较通过后仍执行原代次、生命周期及正式准入检查；准备期间的更新不会由这次比较获得放行。
普通 `invoke` 保留按当前工具标识选择的既有语义，旧固定会话由该普通入口关闭的原清理协议保持。
真实生产桥覆盖冻结旧声明拒绝及新声明正常执行；运行时回归另覆盖四种分派、实际会话计数、
普通入口及不同插件具有相同数值代次的接管。该验收不替代整个目标的连续五轮审核。

## 普通无状态工具的正式所有权

生产 `sessions.rs::invoke_stateless` 现在调用 `runtime/formal/calls.rs::invoke_formal_stateless`。
该路径要求管理器已经附加正式父级，缺失时明确失败。每次调用在包准备之前登记稳定调用身份、
原包代次、控制器会话和宿主容量；目录发布门统一排序登记、停止入场及代次检查。准备前后均可取消，
提交前再次核对当前启用代次，不能因准备期目录切换而执行新包或复活旧业务。

未声明复用的无状态工具每次在 `tool_call` 容量下显式创建一个 `SingleCall` 单实例串行池，类别由用途配置决定。插件聚合、池及实际
VM 仍由同一核心父级计数；该选择保留原每次调用的新 Lua 状态，不代表已经实现所有插件的
专用池策略、自动预热或持久实例迁移。插件聚合目前保留至运行时关闭，受父级注册容量限制。

业务与关闭分别冻结版本一信封、不同请求关联号及各自有限预算。业务截止时间覆盖包准备和
核心排队；关闭预算独立来自已冻结宿主设置。核心流式 `json_size` 在构造大信封前检查输入，
宿主调用保留记录总数受父级 `max_operations` 限制；调用、固定会话与复用域路由的序列化输入预留
共同受同一父级 `max_queued_bytes` 限制。
预留保守保留至确认结果，不等同于进程堆内存硬限制。旧清单 `max_active_sessions` 继续约束
正式单次工具调用、工具固定会话、生命周期回调与瞬时 Action 总数；计数更新和目录投影在同一发布门下完成。

异步等待方离开只请求取消。监督任务使用核心已有操作条件变量，在共享 Tokio 阻塞池中每次等待一个
有限观察窗口，返回后继续原取消检查；窗口预算不包含阻塞池排队及操作系统调度时间。调用者通过
原调用的完成通知等待，并在监督结束后读取原结果，不以固定定时轮询取得结果。文件准备仍在有界
保留记录下进入同一阻塞池。执行器停止时，已启动的实际阻塞准备及观察保持独立归属，
监督中断会留下明确证据；后续显式排空仅在准备真正结束后接续原操作和池的清理，不重新加载
或提交业务。不可中断原生回调尚未返回时继续占据原 VM 和宿主容量。

管理器提供按控制器所有者隔离的 `formal_calls`、`formal_call_status`、`cancel_formal_call`
及 `forget_formal_call`。正常成功调用在收到结果后自动确认；失败或放弃等待的记录保留原
宿主／核心身份，须显式确认才能释放结果容量。确认前必须实际退役、监督结束且有结果。
这些当前为 Rust 管理接口，尚未暴露完整 WebUI／RPC 操作入口；容量耗尽明确拒绝新请求。
`formal_runtime_status` 仍是核心统计，准备阶段和保留结果须通过宿主调用查询接口观察。

插件及控制器排空包含这些受跟踪调用。有限排空等待到期报告未完成并保留容量；实际核心池
关闭且 `forget_pool` 成功后才释放宿主活动计数；记账失败明确保留未完成状态，重试不重复遗忘
已经释放的池。原业务、独立关闭及物理退役分别保留，关闭
失败不会删除原核心业务证据。请求父级关闭同时取消宿主准备，轮询完成也检查宿主所有权。

## 第二版无状态工具的热实例复用

第二版清单的 `lua_runtime.tools[].execution.reusable` 为完整、可选对象；省略保持单次实例，
出现空值、不完整字段、未知字段、非无状态入口或第一版声明均拒绝。编写片段见
[工具复用结构](plugin-tool-reuse.schema.json)，它不是完整清单 Schema。
唯一运行契约仍为 `manifest/reuse.rs`、目录语义校验、生效宿主策略和真实核心调度。

完整对象包含 `before_call`、`after_call`、`reuse_check` 三个不同私有函数名，
`ordering`、`max_resident_vms`、`max_running_calls`、`idle_ttl_ms` 和 `max_uses`。
函数名不得与任何公开业务／关闭导出重叠；三个回调由原始模块加载器捕获，不进入核心公开导出表。
上限必须为正且执行不超过常驻；逐入口要求不得超过生效工具调用用途容量，超出直接拒绝激活和调用，
不裁剪数值或改写配置。复用仍须由第二版包显式声明，已迁移的内置包未新增复用或并行声明。

宿主在核心提交前按清单选择复用池。每次调用先执行 `before_call(envelope)`，必须返回真；
随后执行业务，再执行 `after_call(envelope, succeeded)`，必须返回真。
`succeeded` 表示业务没有抛出 Lua 异常，应用层 `ok=false` 帧仍是正常返回的业务结果。
最后 `reuse_check()` 必须返回真。业务抛错时仍尝试调用后清理，再报告错误；
任意准备、清理或检查失败都作为 Lua 执行失败交给核心退役。准备失败不执行业务及调用后清理，
原实例的自动关闭和受管资源清理仍由核心负责。应用失败且清理通过可以复用。
该契约是插件作者对请求状态清理的明确承诺，不是对任意全局变量或非受管外部副作用的沙箱证明。

复用身份包含父级所有者、插件代次、控制器、规范化工作区、工具入口、已校验配置内容身份和核心能力修订号。
配置摘要仅保存在私有内存，不通过状态接口公开。请求参数和关联号不进入缓存键；回调必须清理请求状态。
原生服务仍按现有权威路径读取实时配置，本机制不承诺单次调用内的配置快照隔离。
受管配置更新主动关闭旧域；外部直接编辑配置会在后续准备及最终提交检查时被发现。
能力修订、插件代次或非启用状态也会阻止旧域继续复用，已运行工作保持原身份并真实排空。

`key_serial` 将同一精确域的核心提交串行执行，要求执行上限为一；不承诺文件准备之前的 HTTP 到达顺序。
`parallel` 允许同域内多个独立 VM，仍受逐域、用途、插件及父级真实预算共同约束。
这些模式不代表跨控制器或跨工具的插件全局串行，也不创建第二个 VM 调度器。
并发首次准备只发布一个域，等待者保留原有界宿主准备及绝对截止时间。
域注册数量包含准备中、活跃、关闭中及未确认失败元数据，并同时受父级和插件注册池上限约束。
路由身份按实际序列化字节计量，与请求和固定会话共用父级 `max_queued_bytes`，不另加缓存字节上限。
所有增加按调用表、固定会话、复用域的同一锁序串行；实际准备和 Lua 执行在释放锁后进行。
域保留插件身份及真实受管包租约，不再克隆完整目录描述符。路由预留一直保持到域实际移除；
物理池遗忘后若仍有未确认关闭失败，原身份及字节预留继续保留。状态只投影数值 `retainedInputBytes`，
不公开私有配置摘要。该计量约束保留输入，不冒充包文件、核心操作历史或整个进程堆的硬内存上限。

请求结束只释放已完成请求的借用及活动额度；复用池和空闲 VM 继续由核心真实计数。
单个弱持有维护任务收集空闲、最大使用次数、异常退役产生的独立关闭操作；
它不在等待期间强持有管理器。成功关闭历史在实际确认允许后回收，业务失败历史仍由原调用方确认。
独立关闭失败保留原核心快照并停止该域新借用；已观测失败尚未确认时也拒绝同分区替代池，物理池遗忘与失败历史确认分开记账。
控制器可用 `reusable_tool_domains` 查询原身份，用 `forget_reusable_tool_domain` 明确确认已完全退役域；
其他控制器不能确认。维护错误保留在状态中，并在同一发布门下阻止新的复用借用与业务提交。
同一维护任务在失败后按有上限的退避重试，完整健康轮次后才清除错误；关闭失败诊断的发布状态单独保留，
诊断存储暂时失败时会重试原证据。执行器中断后，后续调用可重新启动维护，显式排空及父级关闭轮询也能恢复原身份清理。
这些仍是 Rust 管理接口，完整 RPC／WebUI 暴露未完成。

插件排空、控制器排空、容量退休和父级关闭均纳入复用域；有资源或未确认失败时不得清除原诊断。
清理过程中没有替换池、重放业务或为回收容量而删除失败证据。
本地真实测试覆盖同 VM 多次调用、跨控制器／工作区隔离、首次并发注册、分区串行、
两个原生回调实际重叠的多 VM 并行、业务与 Lua 错误、三个清理阶段失败、配置更新、
最大使用次数、空闲失败确认、缺少私有清理函数的激活探测拒绝、父级关闭、原生初始化及业务阻塞时的执行器中断恢复、
诊断发布故障重试，以及真实缓存占满后普通调用和固定会话的聚合字节拒绝与排空恢复。性能基线、长期压力、多平台、
完整能力变更矩阵及发布验收仍须继续完成。容量策略事务还覆盖旧业务回调持续执行、
新调用选择新执行绑定，以及原生忙碌后显式恢复；持久协议和适用边界见前述策略事务契约。

### 明确预热一个额外工具实例

可信宿主可调用 `prewarm_reusable_tool_instance`，提供精确插件标识、已启用工具标识、精确插件代际、控制器及授权工作区。
代次计数按插件独立维护，因此同时校验插件标识，防止不同插件的相同代次数值被当作同一授权。
入口仅接受清单明确声明复用的工具；不接受替代工具描述符、不选择最新代次、不创建单次或固定会话池来模拟预热。
超时复用普通工具的唯一解析器，使用声明默认值及宽限；原绝对截止时间覆盖准备、排队及初始化。

预热与后续普通调用使用同一复用域、用途容量、能力快照和容量修订。宿主准备和在途初始化进入原正式调用表，
继续受输入字节、保留操作、插件活动槽及核心物理预算限制。最终核心提交前再次核验代际、权限和策略；
实际操作由 LuaSkills 的 `prewarm_instance` 执行，每次初始化一个额外 VM，不调用业务派发或逐请求清理函数。
成功返回核心 `instance_id` 对象。满池失败保留原控制器可查询的正式调用及核心错误，普通缓存借用继续可用；
等待方退出仅请求取消，初始化宿主回调、原包及域借用保持至真实清理结束。插件更新不得把在途操作重绑至新代际。
初始化成功后仅释放当前借用；预热实例的空闲回收、压力退役及独立关闭继续由既有核心与域维护负责。

这是显式 Rust 管理入口，尚未接入自动启动或 RPC／WebUI。复用工具的源码初始化由
`execution.reusable.initialization_capabilities` 声明精确回调名称；省略或空列表表示全部拒绝，
未知名称、重复名称及超出原插件权限的能力不能通过实际入场。声明不会新增权限，名单变化属于新插件代际。
普通冷启动和显式预热均使用同一冻结名单；已捕获业务及关闭导出继续使用原业务权限。
允许的初始化回调仍可能产生副作用；该名单也不是对全部 Lua 内建／原生接口的独立沙箱。
该接口只确认此次额外初始化，不保证永久驻留或目标总数。有界目标入口见下节；持久自动策略已有独立真实宿主验收，冻结性能和五平台分发的来源分别保存。
上游契约归属于正式 LuaSkills 零点六点一的 `EmbeddedPrewarm`、正式调度器及操作上下文，上游版本提升时须回读验证。

### 有界预热目标与保留回执

`prepare_reusable_tool_prewarm(VulcanPluginPrewarmTargetRequest)` 先登记请求、插件活动槽和输入预算，
不运行 Lua，也不启动后台工作。请求冻结当前父运行时标识、精确插件／代次、工具、可信控制器、授权工作区与
`targetIdle`。零为合法目标；目标不得超过清单驻留上限。重复准备产生另一份未启动回执；
调用方应通过 `formal_calls` 找回原控制器回执，选择明确的原 `invocationId` 后再启动。

`start_reusable_tool_prewarm(invocationId, ownerSessionId)` 仅转移原输入一次。重复启动返回原记录，
已遗忘身份明确失败；监督者中断后也不重启收敛，可通过
`recover_reusable_tool_prewarm_cleanup(invocationId, ownerSessionId)` 或既有排空入口恢复原清理。
恢复接口只处理原预热回执；中断清理需要可用执行器，活动或已退役回执仅返回当前证据。
尚未启动的首次请求需要执行器；已转移或退役回执的重复观测不依赖进入执行器。
准备与启动间的等待也占用原工具截止时间。未启动请求的取消及父级关闭归还活动槽，保留失败回执至明确遗忘。

目标是同一原执行域在某次调度器观测中达到的已确认可借用空闲数量，不是永久驻留保证。
唯一权威为上游 `reusable_pool_status`：活动、退役、初始化未完成、持久确认失败及过期实例不能抵充，
物理 `idle` 不可替代它。真实域确定后不再选池；每次提交及目标成功前重新核验原代次、配置、能力及容量策略。
同域至多一个目标收敛者，普通业务仍走核心公平队列；目标逐次初始化，最多提交 `targetIdle` 次，
与业务竞争或空闲回收导致有界尝试仍未满足目标时明确失败，不无限重试，也不从部分成功推断整体完成。
原域物理上限已满时等待既有工作归还，所有等待仍受原截止时间约束；更高层容量与操作记录限制由核心继续执行。

目标使用原正式调用表，没有第二套 VM 账本。`prewarm.completed` 保留先前原生操作，
外层 `operation` 保留当前操作；`prewarm.satisfied` 仅保存满足目标时的历史观测。
成功、失败、取消和执行器中断均保留回执，沿既有状态、取消、遗忘接口管理；
遗忘逐个记录原生操作确认成功，后续确认失败时保留尚未确认部分，且不会重新执行。
普通单实例同步入口仍维持原成功即消费行为。

直接替换插件源码后，旧终结器的宿主回调可能因原权限已失效而失败；真实 VM 退役与失败证据确认分离。
此类失败必须保留在原域并显式确认，不能以物理常驻数为零宣称全部关闭完成，
也不能给旧代次借用新包权限。本地六项目标测试覆盖真实实例、零目标、重复启动、准备取消／关闭、
输入及操作预算、控制器隔离、部分成功、同域冲突、源码切换及执行器丢失。
初始化回调名单已接通核心 Rust 与本宿主复用域，目标管理 RPC 见下节；
预热 WebUI、自动预热策略及更新服务均见对应章节；五平台正式分发及实际宿主验收已有独立证据，最终整体审核仍在进行。

上游就绪字段的唯一归属是正式 LuaSkills 零点六点一调度器；升级时必须回读上游对应源码及持久化测试。
核心就绪查询已同步至 C JSON `pool_reusable_status` 及三个 SDK 的类型化池句柄，能力标识为 `reusable_pool_readiness_v1`；均从正式调度器取得同一快照，控制通道不执行 Lua。契约归属为 LuaSkills `EmbeddedReusablePoolSnapshot` 与其生成协议，上游升级时须重新核对。该能力已随核心零点六点一及 TypeScript／Python 零点六点二、Go 零点六点一正式发布并通过独立消费；SDK 查询不替代本宿主的精确代次验证及目标流程。

核心初始化名单也已同步至 C JSON `pool_register.initialization_capabilities` 和三个 SDK 的类型化注册，能力标识为 `initialization_capability_policy_v1`。通用上游 API 为兼容明确旧行为，省略或空值继承、空数组全部拒绝；本宿主复用工具从清单显式传入集合，因此清单省略仍按宿主策略全部拒绝。两层默认的归属不同，升级时须同时核对上游 `ModuleCapabilities` 与本宿主清单转换，不能把 SDK 的省略语义移用于插件清单。该能力已随上述核心及三语言正式包发布并通过独立消费。

已认证宿主服务提供以下精确方法，不从插件业务 Action 进入：

| `service_plugin_prewarm_targets` | `runtimeId`、`ownerSessionId`；返回同父级的已启用复用工具声明及该控制器原预热回执 |
| `service_prepare_plugin_prewarm` | `request` 对象包含 `runtimeId`、`ownerSessionId`、`pluginId`、`toolId`、`pluginGeneration`、`targetIdle`；返回未启动原回执 |
| `service_plugin_prewarm_status` | `runtimeId`、`ownerSessionId`、`invocationId`；读取原回执 |
| `service_start_plugin_prewarm` | 同一原回执参数；至多一次启动原输入 |
| `service_cancel_plugin_prewarm` | 同一原回执参数；请求取消并返回当前证据 |
| `service_recover_plugin_prewarm_cleanup` | 同一原回执参数；仅恢复原清理并返回当前证据 |
| `service_forget_plugin_prewarm` | 同一原回执参数；完整退役后确认，成功返回空值 |

参数必须为具名对象，未知字段、位置数组、非 UUID 会话以及数字形式的插件代次被拒绝。
`pluginGeneration` 在声明、请求与回执中使用规范十进制字符串，精确覆盖上游 `u64`。
准备和启动先从 SQLite 会话索引确认会话存在与项目身份，再从宿主保留的活动会话／项目投影，
调用普通插件工具准备共用的 `workspace_path_for_session` 取得执行工作区，不接收客户端 `workspaceRoot`。
会话存储定位器的 `project_directory` 是持久化目录，不能用于此执行用途。明确声明的项目必须存在且与索引一致；
合法无项目会话遵守共用解析器的既有无项目策略，不能用缺失会话或悬空项目触发该分支。
它们共同持有服务外层准入与存储生命周期门至真实阻塞提交结束；前者与整个会话删除事务互斥，
覆盖其在存储加锁之前的插件排空。HTTP 观测者离开不会释放已接纳阻塞任务的这些守卫。
新初始化要求会话仍在活动投影中，索引与活动项目共同验证范围；当前导航选择不参与路径推断，对话运行时无需提前加载。
查询、取消、恢复清理和遗忘只核对原父级及控制器归属，因此会话不再可定位后仍能处理保留证据。

回执投影包含原身份、宿主解析的工作区、目标数、是否已启动、真实退役、清理恢复需求、成功或错误，
以及当前原生 `operation`、先前 `completed`、历史 `satisfied`。后三项直接来自核心原证据，
字段命名遵从各自上游类型，不从物理空闲推断成功，也不建立第二套任务状态。
准备不具备幂等创建语义；未知 HTTP 结果应先列出原会话回执，不自动重提准备。
启动、查询和清理始终使用选中的原 `invocationId`；工具、代次及工作区变化不能令原任务转投新身份。
工具原截止时间包含准备后等待，管理界面不能通过重试启动延长它。
本节接口与下述 WebUI 已通过正式 registry 宿主的独立管理验收，自动持久策略已接入原回合触发链并完成真实提交。宿主源码、受测二进制和上游公开包分别保存来源；后续源码修复不冒充重新执行此前现场。

### 预热管理界面与恢复边界

插件页面提供独立、默认折叠的「插件 VM 预热」入口。展开只读取父运行时；选择会话、读取目录、
准备回执和启动初始化是分别明确的操作。初次展开可采用当前活动会话作为初始选择，后续导航不会
替换原控制器。工具选择包含精确代次；目标空闲数不设置隐式默认值，并由目录声明上限约束。
浏览器提交只携带规定的身份及目标字段，工作区路径仅展示宿主回执结果。

管理状态按运行时及会话组合保留。跨会话迟到结果只更新原范围；同一时刻重复点击不能产生第二次
浏览器提交。折叠面板保留未知结果。父级替换后旧回执及未知请求只作为历史证据展示，不转投新父级。
页面卸载不取消宿主工作；重新进入后必须明确查询原回执，不在挂载、重连、刷新时重放准备或启动。

准备不具有幂等创建语义，因此响应丢失后禁止自动重试。成功读取原会话目录后，用户可确认本地未知
结果提示；这不取消、回滚或证明宿主工作结束，迟到准备仍可能产生另一份未启动回执。准备确认后
自动追加的动作仅为只读目录查询；该查询失败时保留已确认回执并标记观测过期，不重提准备。

会话退出活动列表后保留原查询、取消、恢复清理和遗忘入口，准备及启动被禁用。页面重载后若会话
已删除，可明确输入原规范会话 UUID 重新选择查询对象；UUID 格式校验不代替每次 RPC 的宿主归属
检查，也不创建会话或授予初始化权限。未启动回执只能启动原输入；恢复操作只继续原清理；完整退役
且无需清理恢复后方可申请遗忘，最终条件仍由宿主再次校验。

界面明确区分是否提交、真实清理完成、原目标成功与清理恢复需求。`satisfied.ready` 标注为完成时的
历史确认，不能作为实时空闲数、自动补齐依据或未来常驻保证。原生操作对象保持只读诊断形状，不用于
浏览器操作授权。十种现有界面语言均提供对应文案。

线协议夹具 `apps/vulcan-code-web/src/service/__fixtures__/plugin-prewarm-wire.json` 来自真实 Rust RPC
准备及完成响应，Rust 测试比较完整 JSON；仅规范化已观测到的不透明身份和临时路径。明确重新生成开关
为 `VULCAN_UPDATE_PLUGIN_PREWARM_WIRE_FIXTURE=1`，入口测试为
`plugin_prewarm_rpc_uses_indexed_workspace_and_original_receipts`。上游类型或服务投影变化必须先核对
浏览器解码和语义，再重新生成。组件及状态测试验证原身份、恢复和不重放边界；它们不替代真实浏览器
连接候选 Core 的端到端验收。

## 工具固定会话的正式所有权

生产 `sessions.rs` 的开启、调用及关闭路径接入 `runtime/formal/pinned/`。
每个会话在阻塞准备前登记宿主身份、控制器所有者、原包描述符与容量；宿主记录数受父级
`max_sessions` 限制，序列化输入与单次工具共用父级预算。包准备及首次核心入场在有界
阻塞池和发布门下执行；准备期取消保留所有者直到真实准备结束，不提交取消后的业务。
该入口要求 Tokio 执行器；无执行器时在登记前明确拒绝。

每个会话在 `tool_session` 容量下显式使用 `Session` 单实例串行池，类别由用途配置决定。核心独占 VM 固定、排队、执行和关闭；
宿主会话身份映射原核心身份，不另设 VM 租约表。开启先等待模块初始化，再执行一次清单
开启业务；成功后后续调用沿原 VM 累积状态。入场拒绝不销毁健康会话，版本一业务错误帧
保留查询记录；Lua 运行失败等核心终止条件仍由核心执行关闭。代次验证与业务提交共享发布门，
开启结果发布遇到代次变化时保留原业务记录。

自动关闭冻结清单 `shutdown_function` 与唯一 `session_close` 工具的操作名、独立请求关联号，
预算由该工具的 `timeout_ms + timeout_grace_ms` 受检计算。显式关闭、空闲超时、会话取消、
插件／所有者排空最终使用同一核心关闭身份，不再次手动调用关闭函数。会话关闭操作的空值
业务基线不作为插件返回值；宿主从独立关闭阶段投影版本一结果。重复关闭读取原证据，不重放。

正常显式关闭及干净空闲关闭只在实际退役、关闭成功且没有未确认业务记录时自动确认。
失败、取消或放弃等待产生的证据仍保留，可通过 `formal_sessions`、
`formal_session_status`、`formal_session_operations` 按控制器所有者查询；
`cancel_formal_session` 仅记录取消意图，`forget_formal_session` 在真实退役后显式确认全部
保留操作。这些控制方法目前是 Rust 接口；下文只读管理诊断独立投影真实固定会话和原事务阻塞者，
不授予取消或遗忘权限。结果保留耗尽明确拒绝新入场，
不自动删除失败证据。已退役且保留结果的会话可以在重复排空报告中再次计为已关闭，报告数量
表示本次确认完成的记录，不是新执行的关闭回调次数。

监督任务只持有管理器弱引用度过空闲等待。执行器退出保留原会话／操作，后续显式排空恢复
清理，不重新准备或重放业务。实际原生工作返回、独立关闭结束、核心会话及池遗忘完成后，
才释放宿主活动计数。记账故障保留未完成状态；重试只完成尚未完成的步骤，不能重复释放。
单次排空使用同一有限绝对等待预算，超时仍保留实际容量；父级关闭同时覆盖准备中会话。
旧工具、Hook、持久 UI 及瞬时调用的 System 租约表和失败租约重试表均已删除。
正式临时调用、固定会话与持久实例分别保留实际核心身份及物理退役检查点。

真实生产测试覆盖同 VM 状态、所有者隔离、关闭信封、并发排空与原生工作等待、
输入拒绝、业务与关闭失败保留、准备阶段取消、执行器退出恢复、记账失败恢复和空闲回收。
这些是固定工具会话的本地行为验证；其他用途、更新服务、本地核心长稳及正式界面验收具有各自证据，
不能由这组测试推出全部通过。


## 只读管理诊断与原身份定位

权威源码为 `runtime/formal/diagnostics.rs`、各真实所有者注册表的诊断投影、
`runtime/update_drain.rs`、服务 `plugin_runtime_services/diagnostics.rs` 及
`skills_services/local_plugin_uninstall/owner.rs`。公开读取通过已认证管理 RPC：

- `service_plugin_resource_diagnostics` 要求原 `runtimeId` 与精确 `pluginId`。
- `service_plugin_update_drain_diagnostics` 另要求原 `requestId`，只读取该管理器仍保留的真实前驱排空授权。
- `service_plugin_uninstall_drain_diagnostics` 另要求原 `requestId`，只读取相同强注册表槽中的实际卸载所有者。

参数严格拒绝未知字段及非对象载体；请求 UUID 在服务访问前解码，过期原生父级明确失败。
读取不附加运行时、不创建 VM、不取消或确认操作、不恢复或重放事务。固定工具会话数量仅来自
宿主 pinned 注册表中尚未物理退役的记录；原 `activeSessionCount` 同时包含普通调用，不得冒充该数量。
资源类别区分固定工具会话、普通调用、可复用工具域、持久 Hook 和持久 UI；通用读取保留明确标注的终态历史。

更新和卸载真实排空按插件命名空间选择全部保留代次；原描述符和排空转换代次仅作为上下文，
不能过滤掉更早清理记录。原请求读取仅返回仍持有物理资源的所选宿主记录，取样后再次检查相同原授权或槽。
更新实时授权缺失返回空值，卸载原所有者缺失明确失败；两者均不能解释成已经成功排空。
跨注册表及原生状态是非原子采样。独立原生资源或用途容量退役仍可能未完成，空宿主记录集合不证明整个事务完成。

查询仅短暂克隆实际注册表记录；同步状态争用返回明确 Busy，不等执行中的异步资源锁。
卸载所有者保留同一管理器句柄、实际服务实例和来源代次供读取，该句柄不创建第二原生父级、命名空间预留或执行授权。
输出仅含稳定身份、真实阶段、操作关联及错误来源／分类；原始业务值、异常正文、配置和宿主副作用正文不进入此投影。
路由代次使用十进制字符串；核心固定会话快照没有通用 VM 身份，界面不能以池或会话身份代替它。

前端 `plugin-resource-diagnostics-contract.ts` 严格读取上述实际字段，拒绝未知形状及不安全整数。
卡片显示权威 `runtimeIdentity`，包版本另行显示；插件、原更新请求及原卸载请求能定位同一个只读诊断区域。
固定会话所有者定位只携原 `ownerSessionId`，经诊断专用工作台回调调用既有 `service_select_conversation`。
服务可能因原存储缺失合法返回其他选择；诊断入口仅在响应精确确认原所有者且本地观察仍有效时切换聊天并提交快照。
空响应、替代身份、服务失败及离开页面、折叠、卸载后的迟到响应均不得打开其他会话；保留诊断及不可用反馈。
观察取消只约束本地导航，不取消 RPC 或业务，也不构造服务回滚协议；通用侧栏选择语义保持。
生命周期更新先推进既有工作台接受版本，再更新活动会话投影；定位必须在路由或流变化前复用该版本闸门，
并确认当前与响应的活动投影均含原所有者。原所有者消失时行观察立即失效，历史资源证据仍保留。
诊断接管共享会话选择版本时同时结束旧视觉过渡，旧侧栏响应失效后不能让聊天持续隐藏。
所有者已归档或当前不可用时明确显示，不能切换到其他会话。原请求刷新失败保留原身份、已观测报告和错误；
选择改变、取消观测及组件销毁使旧响应失效，取消观测不触发服务业务取消。

本阶段的本地源码、协议解析及组件测试不代表正式 registry 或真实浏览器验收。
Core 可选诊断另有真实 VM 身份、阶段计时、嵌套能力等待及 Lua 活堆采样；这些不在本页的会话快照中。
HOST 现已沿下节的唯一服务采集器自动订阅该可选日志。同步日志回调不得阻塞或重入，不能直接转交会同步写盘的宿主接收器。
创建／回收事件次数只能描述明确完整的捕获窗口，不是当前原生累计计数器；活堆采样也不是内存峰值。
上游诊断或任一资源快照变化时须回读 LuaSkills 当前源码与真实测试，同步本节及前端严格解析。

### 服务原生日志采集与真实尾部确认

权威实现为 `runtime/native_identity.rs`、正式操作准入和遗忘路径、服务
`native_diagnostics.rs`、`logging.rs` 与 `service_runtime.rs`。服务实例锁和原日志初始化后、
首个服务工作者创建前安装唯一采集器；插件更新不更换订阅。上游 setter 没有旧订阅读回或比较交换，
当前全源码只有此宿主使用者，以服务排他锁、唯一采集所有权及实际公开 emit 探针确认安装。
未来增加其他使用者必须重新核对所有权，不得静默覆盖。

Core 回调与宿主类型化身份回调仅向同一有界队列尝试发送。队列容量、单记录字节额度、
检查点节奏与尾部预算仅由 `native_diagnostics.rs` 的常量定义；回调不解析 JSON、不写盘、
不执行 tracing 或查询运行时。未安装观察器时身份接线不查询原操作或分配事件。
已安装时，正常调用、固定会话、预热、持久 Hook／UI 和独立关闭均在原操作遗忘前发布安全关联。
运行时、池、操作、插件和原代次身份来自真实原所有者；原生会话、控制器会话、宿主调用与可信请求
分别保留实际可空值，不能互相补造。消费者不保留业务历史映射、运行时、VM 或操作强句柄。

消费者严格选择当前上游数字标记 `luaskills_embedded_diagnostic: 1`，拒绝选中记录的重复、
未知或缺失字段及未知阶段。普通日志和未选中形状不转录正文。退役形状的操作身份必须为空，
不能归给最后一次业务调用。身份与阶段记录以真实键对账，允许阶段先于关联写入。
业务输入、结果、效果、异常正文、配置、工作区路径及密钥均不进入投影。

全部记录使用原唯一 `LogWriter` 写入现有服务文件，遵守原 `RUST_LOG` 过滤和原轮转限制，
不建立第二日志。检查点在同一原日志互斥锁内确定实际落点、必要轮转及最终序列化长度；
当前分段计数按真实落点重置，交接丢失差值保留独立的检查点间范围。空闲时不持续写空心跳。
队列丢失、超限、过滤、选中 Schema、观察器及真实 IO 错误均披露不完整，不能把创建／回收事件次数
当作原生累计计数器或把活堆采样当作内存峰值。

原生关闭失败时保留同一采集器。只有实际原生关闭成功后，才撤销原订阅，等待已经取得的原 callback Arc
与身份快照退出，关闭发送端，排空消费者并等待真实文件 flush 回执；全部步骤共用唯一有界尾部预算。
文件终态检查点仅声明最终 flush 前队列已排空，完整确认还要求原采集所有者收到实际 flush 成功回执。
尾部或遥测失败记录固定不完整分类，但不把已经完成的物理业务关闭改成失败。
未经协调析构、启动失败、强制退出、轮转外窗口及未确认尾部不得宣称完整。
flush 不等同于抗断电持久化或整个生命周期永久留存；正式依赖与真实隔离服务日志仍须独立验收。

修改这些接线或升级上游诊断时，须回读 Core 实际阶段 Schema、原公开日志接口、宿主安全身份
及原文件写入实现，同时运行对应严格投影、快照尾部、实际文件轮转与关闭测试。

## 持久 Hook 的正式所有权

生产预热与 Hook 调用进入 runtime/formal/instances/。每个插件只保留一个精确代次的记录，在阻塞
包准备之前发布；准备闭包和监督者分别持有完成检查点。核心在 `hook` 用途容量下显式使用 Session、
单实例串行池，多个工作区的 Hook 保留同一 Lua 状态；UI Action 使用同一所有权实现中的独立正式实例。
Hook 记录数受父级 max_sessions 限制，真实 VM、队列和操作继续由核心父级及插件聚合计数。
Hook 不占用清单中面向工具调用的旧 max_active_sessions 配额，保留原按类别独立的语义。
类别由用途配置决定；当前核心负载证据不代替 Hook 真实业务及正式 registry 宿主验收。

Hook 业务保留真实版本一 invocation_json 与 host_timeout_ms 入参，以及注册、上下文和载荷。
总预算在派发监督任务前建立，覆盖执行器调度、工作区校验、初始化门、包准备、核心排队及执行。
工作区元数据有值时必须是宿主规范化的现存目录，缺省明确使用包工作区。每次提交签发不可复用
请求关联并绑定真实核心操作；不同工作区不分裂实例，业务参数不能扩大进程目录权限。
原调用方放弃等待后，已有外层监督任务继续遵守原有限预算；执行器丢弃实际操作观察者时请求
核心取消。取消和超时均不能提前释放实际运行的 VM、原生回调或工作区登记。

初始化与业务分开观测。已结束且已完成宿主观测确认的业务记录才从核心回收；等待结束前取消的
操作仍留在原 Hook 注册记录中，监控确认其真实终态后回收，防止长期调用耗尽操作历史。
该内部 Hook 路径当前没有面向用户的逐次历史查询 API，不应把回收后的记录描述为可持久追溯。
监督错误保持明确，实例不能通过重新调用偷偷初始化；上一代记录需要显式排空后才能替换。

关闭仅选择清单可选 hook_shutdown_function，冻结 hook_runtime_shutdown 事件、插件身份和
宿主唯一关闭预算。未声明时不执行工具关闭函数。核心在原实例自动执行一次独立关闭，
宿主从独立关闭阶段读取结果；关闭失败仍完成可完成的物理清理并在排空报告中返回错误。
有限排空先停止已登记准备，再等待初始化门；超时保留原所有者。
执行器停止后，后续显式排空恢复同一记录，不重新加载或重放业务。
初始化、业务及关闭操作分别确认，核心会话与池成功遗忘后才标记退役。
父级关闭请求和完成检查同时覆盖 Hook 准备、业务和实际退役。

真实生产回归覆盖跨工作区状态及越界拒绝、超过操作保留容量的连续调用、运行中与排队超时、
原生阻塞回调的实际资源归属、准备期间停止、执行器中断恢复、关闭失败和重复排空、
无可选关闭函数时父级真实关闭、初始化错误原因保留，以及监督调度不能续期预算；仓库 RTK Hook 也通过此生产入口验证。
这些是本地证据，不替代完整控制暴露、更新事务、外部资源、长稳或发布验收。

## 宿主请求工作区作用域

候选核心在入场时冻结 `CapabilityCaller.request_id`。正式适配器的
`submit_in_workspace` 与 `submit_session_in_workspace` 要求宿主明确提供关联和现存工作区，
不从业务参数读取、不生成替代关联。后者同时核对传入池与真实固定会话所属池。
普通 `runtime().submit` 的无关联调用继续使用模块声明工作区；原生能力遇到带关联调用时，
必须找到本适配器登记的同一核心操作，未知关联或另一操作借用关联明确拒绝，不能回退。
该约束属于宿主适配器，不改变 LuaSkills 通用请求关联仅用于关联的语义。

工作区在宿主入场时规范化，拒绝缺失目录和有损 UTF-8 转换。截止时间在调用入口建立，
会话查询、路径准备和入场等待消耗同一预算；阻塞文件系统调用不能被此进程内预算强制中断，
但到期后不会再提交业务。固定模块工作区、安全分区、包代次和能力授权仍须分别通过原校验。
工作区作用域仅影响宿主进程规范解析的允许目录，不修改 Lua 进程目录，不扩大原声明权限，
也不把关联字符串变成独立授权令牌。

请求登记锁跨越核心的非阻塞队列入场，在返回真实操作 ID 后发布关联、工作区及原操作观察者，
随后释放锁。源码确认这一核心入口只排队，不内联运行 Lua；快速初始化回调等待同一登记锁，
因此不能在原操作身份发布前访问宿主服务。执行服务前释放登记锁。运行时与执行域先由现有
原生入口核验，关联再严格匹配同一操作，另一池甚至同一池的新操作都不能借用已知关联。

注册表由适配器持有，记录数量派生父级 `max_operations`，关联与规范路径的累计 JSON 字节
独立受父级 `max_queued_bytes` 限制；它与核心排队字节分别计账，不表示总堆内存硬上限。
取消、观察者离开和核心运行中状态均不释放记录。新入场先回收已证明终结的记录，
`reap_workspace_requests` 也可显式回收并返回数量；查询失败保留记录，回收不遗忘核心历史。
观察者不持有核心调度器或模块资源，因而不创建管理器与运行时的循环引用。

单次自动关闭仍属于原操作，保留原请求工作区直到真实关闭结束；会话开启及独立会话／
可复用实例关闭无业务关联，使用模块声明工作区，不能继承最近一次请求。真实测试覆盖
同一 Lua 状态跨工作区调用、越界目录拒绝、初始化发布竞争、独立关闭、单次关闭两个回调、
观察者离开与取消、关联借用拒绝、运行中与排队元数据共同超额拒绝及实际完成后的容量恢复。
持久 Hook 和持久 UI Action 生产入口已使用该逐次作用域；生命周期回调每次创建独立实例，固定模块工作区为原生命周期环境。瞬时 Action 使用每次请求固定的原授权工作区，并保留临时初始化及实际退役所有权。

## 业务关闭协议与其余生产路由待办

上游候选通过 `ModuleDefinition.finalizer` 和调度器完成同实例独立关闭阶段；
`ModuleLease::invoke` 仍明确禁止单次实例的第二次普通业务调用。因此不能用两个普通 `submit`
替代同 VM 自动关闭，也不能通过悄然改变复用模式改变现有状态隔离要求。

上游 `embedded/retirement.rs::run_retirement` 会重试受管资源清理。插件关闭函数可能产生业务副作用，
不能直接放入这个自动重试循环。已有 `EmbeddedModule::close` 当前只负责受管资源退役，不执行
清单关闭函数。自动关闭位于独立调度阶段。以下约束同时适用于后续生产路由及更新事务迁移，
不能由当前直接适配器测试推断生产停用／更新已经完成：

- 原调用和关闭回调保留同一实例归属；关闭使用独立有限预算，不恢复原业务调用，也不重复初始化。
- 原业务结果、关闭结果和实际资源退役分别记录；关闭失败不能丢失原结果或伪造 VM 已释放。
- 关闭回调只执行一次；错误、超时和持久回执确认丢失都不能触发自动重放。
- 关闭阶段的可信身份及能力授权由宿主和核心建立；插件业务参数不能指定关闭作用域或恢复撤销的权限。
- 等待方取消、停用、更新和运行时退出均保留真实资源所有者；不可中断原生工作仍占用预算。

核心接口、持久记录、C ABI 与三个 SDK 已共同实现三种复用模式的自动关闭；宿主真实 bundle
适配覆盖工具／Hook 关闭选取、同实例状态、原生关闭回调及版本一错误帧转换。普通无状态工具
及工具固定会话、持久 Hook、持久 UI Action 的管理器路由已经切换，其真实测试还覆盖放弃等待、阻塞准备、执行器停止恢复和有界结果保留。
生命周期业务使用正式单次调用；瞬时 Action 与探测使用正式临时会话，分离初始化与业务入场。
全部生产路由保留原协议及精确身份；当前验证不能代替完整混合池策略、更新事务、外部资源及发布验收。


## 持久 UI Action 的正式所有权与诊断

持久 UI Action 已进入 runtime/formal/instances，与 Hook 共用初始化、原始身份保存、
物理排空和执行器中断恢复逻辑。两种用途保留不同注册表、安全分区、固定会话及串行入场门；
UI 不执行工具或 Hook 关闭函数。实例在 `ui_action` 用途容量下使用核心 Session、单实例串行策略，
尚未把该阶段策略声明为经过性能冻结的最终混合池默认值。

生产入口继续校验当前代次、调用方、输入及输出 Schema、声明的空时间快照参数，
使用原 arguments 信封。持久 UI 的宿主进程目录权限仍固定于包工作区；
请求工作区只完成原有规范化校验，不扩大持久实例权限。瞬时 Action 则由下述正式临时会话
保留每次请求的授权工作区，两者的工作区语义保持独立。

读取型调用仅在执行入场前允许撤回，变更型调用在外部等待者断开后继续；
执行入场原子关闭取消窗口。这里的 executing 表示已开始入场，不证明 Lua 已开始执行。
实例串行门移动到真实操作登记中，核心操作到达真实终态后才释放，观察者丢失不会提前释放。
宿主调用计时通过已认证的请求与真实操作关联取得记录，不借用其他工作线程的局部状态。
初始化不带业务关联，其回调继续使用固定包权威，不记为业务回调耗时。

Action 入场许可现在由诊断记录持有。持久实例准备、初始化和业务操作分别保留物理守卫；
瞬时调用的物理守卫覆盖准备、初始化、业务和整个临时会话及池的退役。监督结果先记录为待发布结果；仍有真实工作时显示
cleanup_wait，terminal 保持 false，许可仍被占用。物理守卫全部离开后才发布最终结果。
执行器丢弃未轮询监督任务也能归还未使用容量；执行器异常退出产生 supervisor_failed，
它只描述宿主监督结果，不能推断业务无副作用或允许重放。后续显式排空在原实例恢复清理。

本地回归覆盖初始化撤回后不执行业务、初始化和业务回调期间执行器退出、有限排空保留容量、
新执行器恢复原身份、超出历史容量的连续调用、包工作区拒绝越界，以及父级关闭不调用错误
关闭器。原有读取撤回、变更等待者断开、其他插件继续执行、Hook/UI 状态隔离均继续验证。
这是持久 UI 的本地迁移证据；更新协调器、管理查询及本地核心长稳均有独立链路与证据。
正式 registry 宿主、实际界面业务、多平台分发和正式发布仍须完成。

当前清单权限与创建时冻结的核心授权共同约束原生调用：调用入场和服务查询等待结束后，
都在同一次目录观测下校验包身份、生命周期与该能力的当前权限。当前权限撤回会立即阻止
尚未进入服务的调用；新增当前权限不会扩大旧核心授权。该复核也适用于独立关闭，
排空授权不恢复已撤回能力。真实统计插件和等待服务期间撤回存储权限的回归均验证无新宿主调用。

进程解析继续使用原包、入口及环境声明，仅权限取原声明与当前清单的交集。二进制、Node、Python
及会话模式分别校验；撤回二进制权限不能借用仍有效的 Node 权限，单独撤回会话权限也不禁止
仍获授权的 exec 模式。真实生产 UI 测试覆盖这两个选择性撤权边界，没有启动外部进程。

## 生命周期回调的正式所有权

生产 invoke_lifecycle 的安装、启用、启用补偿、停用及卸载回调现已使用 runtime/formal/calls。
它们与普通单次工具共用入场、原始包描述符、阻塞准备检查点、实际核心操作、物理退役及显式恢复；
类型化所有者区分控制器与宿主生命周期，空控制器标识不能查询、取消或确认生命周期记录。

生命周期入口先固定唯一绝对截止时间，再按已声明事件选择函数及作用域。安装与卸载要求停用，
启用及启用补偿要求启用中，停用要求排空中；宿主发布门下检查代次及状态，核心提交前再次检查。
未声明回调或没有 Lua 运行时的插件仍直接成功。需要执行的回调缺少正式父级时明确失败。

可写环境准备现在发生在调用登记及活动容量预留之后的受跟踪阻塞任务内，复用原有
ensure_plugin_execution_environment 的复制、校验、依赖安装及发布实现。等待方或执行器离开
不释放仍在进行的准备；截止时间覆盖该阶段，准备队列到期后不会继续创建环境或提交 Lua。
无法中断的文件系统或依赖安装工作仍须真实结束，不能把有限观测超时解释为已经终止它们。
生成环境路径后，在调用与固定会话共用的注册表锁下重新核对输入总字节预算并更新该调用预留；
预算不足不提交核心操作，原登记继续负责清理。此计量不表示对临时堆分配或磁盘占用的硬限制。

每次回调在 `lifecycle` 用途容量下显式使用 SingleCall 单实例串行池，固定模块工作区为原包代次的可写环境。
入参仍是 event、plugin_id、environment_root 对象，不套用工具或 Action 信封。
没有工具或 Hook 自动关闭函数；实际 VM／受管资源清理由同一核心父级完成。
调用完成及排空必须等待实际池关闭和遗忘，之后才归还宿主活动计数，不再在关闭失败后无条件释放。
这是生命周期入口的迁移，不是完整混合池默认值冻结。

生命周期调用方消费结果或离开后，只有实际退役且监督结束的记录才自动确认核心历史并回收；
明确失败、成功和放弃等待均不会提前释放实际工作。正常业务失败通过原返回值报告，
内部记录回收后不承诺逐次历史查询。物理清理未完成或监督中断保留原记录与诊断，后续插件排空
恢复同一个操作，不能重建实例或重放回调。控制器工具的失败历史仍保留至显式确认。
逐条回收在开始下一次可能失败的确认前先提交已完成移除，避免后续失败使先前成功步骤被重放。

真实回归覆盖五种事件、启用补偿错误、原工作区及父目录越界拒绝、独立实例与错误关闭器排除、
连续失败超过保留容量、控制器身份隔离、等待者及执行器丢失、父级关闭和有限排空期间容量保留，
以及包准备排队期间的截止时间与代次变化。生命周期回归不代替其他路由验证，也不证明环境回收政策、
持久更新事务、外部资源、长稳／多平台及正式发布已完成。

## 瞬时 Action 与启用探测的正式所有权

两条生产入口均进入 runtime/formal/calls；类型化入场意图共同决定所有者、初始化方式和业务导出。
Action 与探测分别在 `ui_action`、`activation_probe` 用途容量下使用私有 Session 单实例串行核心池，先记录真实初始化操作，再决定业务入场。
此 Session 仅服务一次瞬时请求，不登记为持久 UI 实例；下一次请求重新初始化独立 Lua 状态。
默认普通工具和生命周期仍使用原 SingleCall 协议，显式可复用工具按专属声明执行；不能把临时会话策略推广为所有路由的复用默认值。

瞬时 Action 在原入口完成调用方、代次、输入 Schema、声明时间快照及工作区检查；
初始化结束后，在目录发布门内再次核对代次及生命周期，再原子关闭执行前取消窗口并提交唯一业务。
入参仍是 arguments 对象。每个业务操作绑定可信请求关联、实际操作身份、原规范化工作区及 Action 诊断，
回调计时由该绑定取得，不再传播线程局部的旧引擎上下文。输出 Schema 仍在返回边界验证。
读取可以在执行业务前撤回；变更在外层等待者断开后继续，始终受原清单截止时间约束。
取消仅在截止时间前进入记录；到期后的 HTTP 等待断开或显式取消查询不能把超时改写为主动撤回。
已经入场的业务不能由读取取消重放或重新初始化。

普通公开探测只接受启用中代次，在受跟踪阻塞任务中解析原执行包工作区并重算保留输入预算。
真实模块初始化检查清单全部导出；成功后直接清理，不构造虚假的探测业务导出。
初始化本身仍可执行插件顶层 Lua 和已获授权宿主能力，不承诺无副作用或完整沙箱。
探测不占清单工具活动计数，保持原类别语义；父级 VM、会话、队列和历史预算仍然有效。
清理诊断额外检查未退役正式调用，不能因探测的工具计数为零就提前清除警告。

两条路由都不声明工具或 Hook 业务关闭器。关闭等待原核心会话实际 Closed，再依次确认会话、
初始化操作、请求工作区、池和活动容量；各成功步骤保留独立检查点，失败不重复遗忘或创建替代身份。
瞬时 Action 的容量守卫跨越整个过程；原生回调未返回时，即使 HTTP 超时或执行器退出，容量仍不可复用。
执行器退出后，显式排空只恢复原身份的清理；初始化尚未完成时绝不补执行业务，已开始业务也不重放。
内部调用在观察确认且实际退役后回收核心历史；Action 诊断仍由原有有界诊断记录保存。
普通工具的失败历史继续要求控制器显式确认，不受内部自动回收影响。

管理器旧租约创建、执行、关闭、失败租约表及其专属测试已经删除，排空报告使用正式调用计数。
通用旧桥协议仍存在于其独立兼容入口，但这些插件生产执行路由不会回退到该入口；
它没有 Action 线程局部上下文，正式原生能力的真实有限截止时间仍来自核心预算。

本地真实回归覆盖独立状态、原工作区及同级目录拒绝、连续成功／失败超过历史容量、
初始化期间读取撤回及变更等待断开、初始化和业务超时、两阶段执行器退出恢复、初始化跨代次业务拒绝、错误关闭器排除、
探测无业务执行、缺失声明导出的加载失败、探测中断保留诊断及真实退役后回收。
真实 Context7 包通过公开探测入口。验证范围为当前本地宿主候选，不代表混合池默认值冻结、
环境／外部资源完整治理、持久更新、完整控制暴露、长稳、多平台或正式发布已经完成。

## 未发布候选初始化与事务所有权

`probe_activation_candidate` 只接受代次存储检查出的实际借用视图。私有权威绑定精确用户根、
原管理器、原请求 UUID 及冻结目标，包含包、配置、凭据及已批准权限；同名内置插件不能被候选覆盖。
普通公开路由仍检查已发布代次及生命周期，零代次、包路径或克隆描述符不能自行取得候选权限。
私有权威还固定操作种类：探测为 `EnablingProbe`，安装为 `LifecycleInstall`，
候选启用为 `LifecycleEnable`，候选启用补偿为 `LifecycleEnableRollback`。
每次权威仅接受其自身操作对应作用域，不能凭同一描述符取得其他生命周期或普通业务权限。

候选在原正式父级内使用 `activation_probe` 用途容量，与同一插件旧版本及其他用途共同消耗
原父级和插件预算。调用先登记，再准备原环境及执行真实模块初始化；不创建第二父级，不把候选
临时投影到公开目录，也不执行业务导出或业务关闭器。纯内容包没有 Lua 初始化步骤。
配置读取来自事务固定文档，不读取包默认值或当前公开版本文档。

入口沿用唯一探测截止预算，涵盖准备和初始化，并对调用方提供有界等待。
成功要求初始化及实际清理完成；超时或等待方取消后，原调用、准备工作和原生资源继续按真实状态保留。
模块顶层可以产生已授权副作用，自动清理不重放初始化。初始化失败或取消不代表外部副作用已撤销。

`install_activation_candidate` 执行固定清单的可选安装回调，参数保持
`event = install`、`plugin_id`、原事务规范 UUID 字符串 `request_id` 与原受跟踪准备注入的 `environment_root`。
没有 Lua 或未声明安装回调时直接成功，不创建父级、不执行初始化。
有回调时使用原生命周期期限、`lifecycle` 用途容量和 SingleCall 全新状态，返回原业务帧结果；
不选择工具／Hook 关闭器，不使用已发布目录的活动会话计数，但仍受原父级、插件与用途全部核心预算限制。
公开探测与安装分别为显式操作，安装不自动追加第二次探测，探测不隐式调用安装。
`enable_activation_candidate` 与 `rollback_activation_candidate_enable` 分别调用固定清单的
启用和停用导出，事件为 `enable`、`enable_rollback`，携带同一原请求 UUID。
它们复用上述期限、SingleCall、能力绑定和生命周期容量，不临时发布候选，不替代上层旧业务排空。

在本管理器原父级中，同一请求的生命周期回调与任何仍保留候选工作互斥；
在发布门及原调用注册表内先判定，再保留新调用。
探测、安装、启用和启用补偿在原命名空间锁内分别写入持久开始记录，再进行环境准备或执行。
同一原操作只允许尝试一次，即使原调用已经退役、管理器重新创建或进程重启。
成功、观测失败及不确定状态保留在原请求的附属回执；观察取消不重放，空调用列表不证明成功。
存储提交检查该回执及实际资源所有权，两项都满足才可能继续。无回调直接成功路径不创建回执。
详见[安装副作用回执](plugin-generation-store.md#候选安装的持久副作用回执)
及[候选探测、启用与补偿记录](plugin-generation-store.md#候选探测启用与补偿的持久记录)。
探测必须先于生命周期；已尝试前置操作未成功时拒绝后续安装或启用。
补偿只能针对已观测的原启用，任何补偿尝试均禁止将此请求再次提交为就绪目标。
服务协调器仍须在旧写入者排空之后才执行安装，并处理外部副作用，不能把存储中止解释为外部效果回滚。

全部候选调用的 `process.resolve` 保留私有事务权威，精确进程子类型及会话权限从已批准候选清单取得；
工作区、声明二进制、依赖环境和路径校验继续共用原解析器。普通已发布调用仍把原声明与实时授权取交集，
候选不会从旧公开版本借用权限。配置写入继续受第四版受管配置事务守卫限制。

实际执行共享原事务的排他文件锁；候选视图及所有保留调用、准备和原生池退出前，
同一事务提交／中止、其他所有者按 UUID 恢复／中止均被阻止。仅复制 UUID 不保留资源。
该所有权模型复用原锁路径，未增加第二套就绪锁或新的事务格式。

`activation_candidate_calls(request_id)` 查询原父级中属于精确请求的保留调用；
`initialization` 返回尚被保留的原初始化操作快照，`operation` 仍表示业务／预热操作。
初始化探测不存在业务操作。查询不创建父级；空列表仅说明当前无保留记录，不证明初始化从未运行
或持久事务已经完成。恢复不能依据空列表自动重放副作用。

`drain_activation_candidate_calls(request_id)` 只取消当前已登记的同一请求候选调用，覆盖探测、安装、启用和补偿；
不取消同一插件的普通调用。它复用父级的有限关闭预算，等待者退出后清理监督仍可继续；
实际原生工作未退出时返回未完成诊断，资源与锁继续保留。此入口不阻止未来新入场，
提交前仍必须通过存储的实际所有权检查。内部调用退役并确认后按原规则回收历史，
管理器的既有清理诊断仍可记录未完成工作，不把旧版本的公开目录替换成候选。

初始化探测在 `initialization` 中报告操作；SingleCall 生命周期在 `operation` 中报告原业务操作。
上述入口完成候选 Lua 初始化、显式生命周期回调及资源寿命管理。它不确认 MCP 连接，
不推进持久事务、不执行服务路由交接，也不代替完整安装／更新／配置及启动恢复流程。

## 会话插件 Hook 的扩展代次归属

服务 `ExtensionGeneration` 同时持有插件目录、MCP 访问面、提示词技能目录及插件会话 Hook 分区。

准备请求仍保留实际目录包／凭据租约，最后处理器和调用任务释放后才归还这些引用。

现有生命周期同步保留基础注册及校验路径，基础中尚未共同发布的插件条目不会泄漏到服务执行快照。
显式独立调用方可以不提供插件会话分区，维持原独立调度器契约；服务启动和插件发布使用带冻结分区的构造器。

目录刷新发布目录与会话分区，但继续保留当前 MCP 访问面；MCP 连接替换仍由插件生命周期流程完成。
旧快照只保留路由选择与实际所有权，不赋予过期插件新的执行权限：正式运行时仍检查代次、生命周期和准入。
此机制不代表磁盘选择、候选就绪、外部资源和所有服务发布步骤已经组成完整更新事务。

## 服务卸载原所有者与明确继续

权威实现为 `skills_services/local_plugin_uninstall.rs` 及 `owner.rs`、`execution.rs`、
`publication.rs`、`collection.rs`。在首次回调或策略效果之前，服务单强注册表保留实际受管选择／状态

取得；旧账户仅从实际旧来源或捕获休眠平铺描述符取得，不能从当前修订猜测。部分错误保留原实例及

`lifecycle`、`publishing`、`collection`；它们是资源借用及待办步骤观察，不是资源退役权威。

不从磁盘重建。成功返回既有目录更新；界面空查询、请求缺失或错误字符串不能证明已完成。

签发者，仅替换任务／工作台投影，不二次发布 Full。相邻保存同真实更新；广播回调异常后继续重发
同修订，不能重放回调、删除或再增修订。恢复区独立于插件卡片，允许发现已从 Full 隐藏的请求。

关闭只排空已保留回调和真实资源，不自动接受失败副作用、不发布卸载终态或清空强槽。仍有原请求时
阻止不可逆关闭，保持既有失败关闭后的恢复路径。没有安全撤销卸载或跨重启复建实际文件／资源的入口。

实际初始化及完整工具发现期间，业务门保持关闭。等待只借用原资源，任务故障不释放该执行租约。
明确没有全局声明的分支没有候选工作，其分区移除只发生于完整发布；物化失败尚未准入原生副作用。

`publish_legacy_secret_extension_generation` 使用实际服务当前完整指针及其当前无关分区准备后继，
完整目录也来自该实际当前指针，不能重新发布等待前的旧快照。捕获插件须在同一管理器实例和单调插件
代次内仍为启用状态；缺失、代次变化或停用均在指针写入之前拒绝，随后恢复不撤销后来合法发布的目录。
当前无关目录更新保持存在。先完成目录与会话处理器准备，再取得原入场、登记、所有权、业务、传输及
就绪守卫。非空候选必须具有
相同实际租约和完整谱系、正确启用目录代次、每个启用声明的实际传输与完成发现；全部可失败校验先于
唯一完整指针写入。相邻不可失败尾段将实际租约交给完整后继，把历史控制改为弱身份，移除同一待处理
登记，开放业务并记录服务原请求 `committed`。守卫释放后才开始被替换旧分区的既有排空，不能提前
关闭或重建原先运行中的前驱。临时强租约须在原生锁守卫之后析构，避免最后租约关闭时重入业务写锁。

失败或按原 UUID 恢复先借用同一个原控制，取消仅未发布候选，等待实际清理及聚合物理释放，再恢复并
回读精确操作系统前像。清理、补偿或回读失败均保留同一原请求和文件屏障。未派发取消使用明确类型
阶段证明没有任务，仍验证实际资源释放；不能把连接中状态当成未启动证明。已提交控制拒绝候选取消，
历史控制不持有执行资源，其析构不关闭实际后继。旧凭据前像不得在未证明原生退役时提前恢复，已删除
原先允许这种顺序的中间阶段。纯凭据或原生清理后的成功恢复进入 `restored`。

完整发布与工作台投影分别记录：`committed` 表示实际值及所需完整发布已确认，工作台刷新或事件返回
失败仍保留原请求。常规成功路径完成投影及事件后才退役原请求；明确恢复已提交原请求时，仅重新投影

投影失败仍可使用同一原 UUID 重试。公共 RPC 的恢复返回仍为空值，前端阶段与服务枚举同步维护。

此旧格式路径始终为未证明原始来源，不授予密封目标完成、普通已发布来源或前驱恢复权限。

真实能力读取，回调可变替换沿既有不可变选择规则拒绝；未携带不可变配置的旧选择仍须服务先记录前像。

精确停用记录实际发布之后，`refresh_catalog_with_deactivation` 在原文件内构造管理器目录，目标从贡献
中消失，无关插件仍由普通权威读取。未发布原记录、错误根或两次实际读取之间的外来替换均拒绝，不使用
普通读取补救目标失败。这项管理器发布不等于服务完整快照提交，也不代表 MCP 活动、连接中、失败、私有
或退役集合已全部排空。核心已提供同原文件的包及版本化凭据回收，按原完整身份、真实读者租约及完整
已验证日志恢复；详见代次存储契约。调用这些入口仍要求宿主独立确认实际完整移除和物理排空，核心原语
不能替代该证明。服务原协调器已调用下述受管状态／环境原对象、旧账户及历史资源回收，
并通过原插件与请求身份提供查询、恢复和明确失败效果确认。
进程内强所有者状态与持久终态、真实重启和实际界面验收仍须区分；
不能把核心停用观测或单独回收成功作为整条卸载成功回执。

## 平铺移除的写前原对象与隐藏后回收

权威入口为 `runtime/installation/uninstallation.rs` 及 `runtime/installation/retained.rs` 共用的普通文件树
检查和移除实现。`VulcanPluginLegacyUninstallationReservation` 不可克隆、序列化或从 UUID 重建；
当前服务以 `reserve_legacy_user_plugin_uninstallation` 保留此实际原对象，交由同一卸载协调器推进。
下述核心验证不等于服务完整发布、系统凭据卸载或桌面验收。

`reserve_legacy_user_plugin_uninstallation` 接受宿主写前分配的非空请求 UUID，只保留实际当前停用、
零会话、无受管选择的用户平铺包。实际会话登记门先于来源检查；原命名空间文件先于任何状态捕获。
固定当前物理路径、内容指纹、原描述符及声明清单，预先分配唯一隐藏目标，保留授权、安装与配置三个
文件的实际原字节或明确缺失。受管有效和停用记录均不能取得这份平铺路径权威；包字节变化、错误根、
既有隐藏目标、非普通目录和状态路径均在副作用前拒绝。原对象本身不执行回调、改策略或写系统凭据。

普通状态快照的唯一容量来源为 `installation.rs` 的 `MAX_PLUGIN_STATE_SNAPSHOT_BYTES`，当前每文件
十六 MiB。这是原／清理前像的不透明字节资源额度，不沿用其他协议的 JSON 元数据容量。共用读取器同时
检查路径及实际文件句柄的类型和大小，实际读取最多该额度加一个溢出字节，拒绝读取期间增长越界。
超限明确报错且保留原文件，不截断前像；此额度同样适用于既有安装补偿和旧卸载使用的共用读取器。

`original_state_preimages` 仅借出这些前像供宿主明确恢复决策，不自动回写，不授予序列化或回滚权威。
宿主必须强保留原对象后再登记并保留同守卫的原卸载调用。回调或诊断仍借用真实守卫时，包隐藏和清理
均阻挡；借用计数不能证明整个实际原生或 MCP 集合排空。原调用仍沿既有明确平铺来源执行，未声明卸载
回调也须确认其实际守卫释放。

`hide_legacy_user_plugin_uninstallation` 在实际会话登记门内重新确认相同当前停用零会话来源，先一次性
固定所有回调后清理字节或缺失，再准入唯一重命名意图。旧前像继续独立保留。固定发现路径与固定隐藏路径
是明确协议的两种状态；缺失、同时出现或字节改变拒绝，不能搜索其他目录或换 UUID。首次效果被拒绝
重放；`resume_legacy_user_plugin_uninstallation` 只明确恢复同意图，实际已隐藏为只读成功，不再重命名。
真实系统重命名失败、成功后返回丢失及工作者异常均保留外部调用方持有的相同原对象和文件。

隐藏后可用既有 `refresh_catalog_with_legacy_mutation` 在同文件内准备目标已消失的管理器目录；这仍不是
服务完整指针提交。宿主须另行确认实际完整移除及全部原生／MCP 排空，之后才能调用
`collect_legacy_user_plugin_uninstallation`。回收沿既有正式容量退役检查，先取得并保留真实排他环境文件，
再核对所有固定清理状态。实际环境读者阻挡任何状态或包删除；外来或未准入的缺失状态拒绝，不以重读
当前字节替换原清理快照。逐文件删除意图先于实际删除，重试仅接受相同字节或本请求已准入的实际缺失。

状态、环境及隐藏包清理只寻址原固定路径，复用完整链接检查及规范边界限定的普通目录树删除。真实部分
删除保持隐藏，原对象、前像和环境文件继续保留，不能把部分包重新改回可发现名称。最终真实缺失确认
与原内存终态标志相邻保留；成功后返回丢失或异常可只读确认同一终态，不再次删除。确认时重新出现的包、
状态或环境拒绝并保留。成功和失败都不消费原对象，实际原对象释放之前命名空间及环境文件仍保持排他。

会话登记门的当前类型为 `Mutex<()>`，只用于排序，不持有业务数据。真实工作者异常可能污染该门；仅持有
原对象的明确隐藏／回收恢复入口可在取得同一实际污染守卫后，重新核验原管理器与规范文件、可读实际目录、
原路径结果及回调借用释放，再清除这份排序门污染。保护实际目录或正式注册表数据的锁不在此修复；目录
数据锁污染时新入口明确拒绝，保留所有原字节及排序门污染。普通快照读取的旧污染观测行为不作为这条
删除链路的授权读取方式。首次预留仍拒绝已污染登记门，不能用新请求绕过原恢复。

本节没有提供持久卸载请求或进程重启恢复，没有执行系统凭据清理，也没有处理失败回调的通用外部副作用
补偿。服务原协调器、策略比较更新、实际完整发布与原请求回执、明确恢复和查询页面仍须接入；受管选择
的旧状态及执行环境已有下述核心原对象，生产服务仍须接入。修改上述原对象、来源、隐藏、实际租约或回收
入口时回读源码并同步本节。

## 受管移除的原状态与环境回收

当前权威为 `runtime/installation/uninstallation/deactivation.rs`、`local_state.rs` 以及
`generation_store/deactivation.rs` 的唯一原选择关联与发布检查。`VulcanPluginDeactivationStateReservation`
不可克隆、序列化或从 UUID 重建。服务卸载已在 `owner.rs` 保留原选择及状态对象，并在 `collection.rs`
调用状态／环境、包及版本化凭据历史回收。本节核心观测不代替整条服务、持久终态或桌面验收。
选择原预留的有界历史清单、同文件独立回收和完整终态核验仍以代次存储契约及当前源码为准。

宿主在回调或策略效果之前先强保留实际选择原预留，再借用该可变原对象调用 `reserve_deactivation_state`，
强保留返回状态对象。构造要求当前精确停用零会话受管来源、相同实际管理器、完整原选择和实际既有规范
存储，捕获授权、安装、配置三个普通文件的实际字节或明确缺失；其自身不发布选择、不改策略、不执行回调
或安全存储效果。同一构造还捕获实际同名休眠平铺前驱或明确缺失，详见下节；不增加另一状态原对象。
状态对象保留来源代次、路径及实际休眠描述符元数据，不强保留包、凭据或命名空间读者。

实际命名空间守卫的弱分配身份与完整原记录、请求及管理器身份共同绑定这份状态。相同 UUID 和完整记录的
另一真实文件所有者也不能接纳它；只保留状态对象不能重新取得原选择文件。每次操作必须另行传入相同实际
原选择对象。原选择仅允许关联一份本地状态原对象，失败的未启动捕获不登记；已登记对象即使被释放也不
允许替代快照。宿主必须共同强保留两个对象，不能把前台响应丢失或观察结束当成对象可消费的条件。

`freeze_deactivation_state` 要求相同当前来源及实际回调借用释放，在原选择仍被选定且写入意图尚未准入时，
一次性读取全部回调后清理文件。全部读取成功才赋值；原前像继续独立保留。平铺与受管读取共用唯一每文件
十六 MiB 额度与有界读取器，读取失败不部分接纳快照，不截断或删除文件。实际成功固定与原选择的固定完成
标志相邻记录；关联本地前像后，选择发布被此真实标志约束，尚未固定不能准入停用写入。重复固定拒绝；
`observe_deactivation_state` 仅只读观察这份本地原对象。

精确停用后继已发布，而且宿主独立确认实际完整路由移除及整个原生／MCP 集合退役后，才能调用
`collect_deactivation_state`。该入口与平铺移除共用唯一状态、环境检查及删除实现。实际会话排序门、正式
容量退役、实际排他环境文件及规范根保留先于任何删除；仍有真实环境读者时，全部状态字节保持原样。
固定状态先整体预检，逐文件意图先于实际删除；每个效果前核验原已准入停用记录。仅接受固定清理字节或
本请求已准入的缺失，外来字节拒绝并保留。环境只删除同租约规范根下的该插件子级，复用既有完整链接
检查和普通目录树删除。原环境文件跨错误或异常保留，部分环境删除可使用相同原配对明确继续。

全部本地状态及环境实际缺失之后，相邻保存本地终态，再返回 `Collected`。实际完成后的返回丢失或异常
可只读确认同一终态，不再次删除；重新出现的状态或环境拒绝并保留。明确原配对可沿平铺共用的排序门恢复
规则验证实际所有权、实际选择、可读目录和本地阶段后恢复只排序空元组门，业务数据锁仍严格拒绝污染。
终态也继续持有实际环境文件，直至宿主明确释放原对象。

包回收及版本化凭据回收仍独立借用同一原选择文件，不以本地回收结果替代。状态对象不保留额外包固定，
因此管理器移除原来源并释放真实读者后，可先回收原包再清理本地状态；这不能证明旧系统账户、其他历史
修订或休眠平铺前驱已清理。其他受管包／版本化修订须逐一按选择原清单回收并独立核验；该清单也不能
代替旧系统账户及休眠平铺前驱的来源和清理权威。当前本地局部观测为预留、已固定、清理中及已回收四种，不推断实际服务完整提交、
整个原生集合排空或持久卸载成功。服务原请求槽、策略比较更新、旧／版本化安全账户、所有原资源清单、
完整发布、查询恢复与进程重启验收仍按完整目标实现。修改关联、固定、真实租约或回收时回读上述源码并
同步本节和代次存储契约。

## 受管移除的休眠平铺前驱

当前权威为 `runtime/installation/uninstallation/flat_predecessor.rs` 及 `deactivation.rs`。既有受管选择可以
覆盖磁盘仍存在的同名平铺包；目录中看不到旧包不等于旧包已回收。`reserve_deactivation_state` 在任何回调、
策略或删除效果前检查唯一实际用户根／插件子级，规范根与普通目录边界先于唯一独立包检查器。完整身份、
内容指纹及旧凭据声明来自该实际平铺包，不从当前受管描述符、历史代次标记或版本化凭据日志推定。
不存在的来源明确捕获为缺失；不接受随后发现的替代目录。来源无效或重定向使未启动构造失败，尚未关联
原选择；已成功关联后仍只允许这一份实际状态对象，释放不能重捕前像。

`original_flat_predecessor` 仅借出原检查结果或明确缺失，供宿主构建可证明的旧账户清单，不提供独立文件
或删除权威。该描述符没有受管包或凭据固定。实际原根、管理器分配、命名空间弱分配、完整选择及请求
共同约束后续操作；回调前后三文件冻结、本地回收和休眠回收都检查这一份原来源的物理阶段。

宿主独立证明完整移除及整个实际原生／MCP 集合退役之后，先完成相同原对象的本地状态和环境回收，再用
`collect_deactivation_flat_predecessor` 独立回收休眠来源。该入口复用已经强保留的实际排他环境文件，
不取得另一租约，避免与自身所有者冲突。三个本地文件及环境仍须实际缺失，精确停用记录及实际回调借用
释放仍须成立。本地 `Collected` 只证明本地范围，不能直接表示休眠包或旧账户已回收。

首次清理在任何删除之前核对完整原指纹，并将实际来源改名至唯一 `.uninstall-<插件标识>-<原请求 UUID>`
隐藏子级；该布局与平铺原卸载共用唯一路径生产者。真实重命名失败或成功后确认丢失继续使用同一原请求。
明确来源及隐藏路径是固定协议阶段，不搜索备用目录；首次删除准入前仍核对完整字节。部分删除只能继续
这一隐藏子级，每次效果前都要求可发现来源缺失；新包出现时拒绝并保留其字节，不能把它加入旧清理。
共享普通目录树删除器继续检查全部后代、规范包含边界并拒绝链接或非普通条目。

实际树删除器确认隐藏目录缺失后立即保存内存终态，先于任何可失败的原选择回读和测试确认观察。
后续回读错误或真实异常展开不能清除终态；重复清理及 `confirm_deactivation_flat_predecessor_collected`
只读核对当前实际缺失，不重新删除。可见来源或隐藏目录重新出现均拒绝并保留。排序空元组门可按既有
严格同原对象规则恢复，业务数据锁不能据此清除污染。该终态仍只证明本地／休眠存储范围，不证明旧凭据、
受管历史、宿主完整提交、持久请求或进程重启完成。当前生产服务协调器已在回收阶段调用这一原对象链路。

修改实际休眠检查、共享隐藏路径、同原环境租约或回收终态时，须回读上述当前源码并同步本节和代次存储契约。
