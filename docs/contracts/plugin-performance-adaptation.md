# 内置插件性能适配指南

## 依据与交付边界

本文于 2026-10-05 对照当前源码编写。LuaSkills 版本以根 `Cargo.toml` 和 `Cargo.lock` 为准，本次核对为 `0.6.1`。
本轮完成五个内置插件的适配分析及多语言实现，**尚未给业务插件启用无状态工具复用、调整容量或发布性能提升数据**。
下文的收益均为待测假设，不把基座的合成负载结果作为业务插件收益。

上游类型与实现拥有契约，本文提供作者使用方法。升级 LuaSkills、修改以下宿主路径或改变插件入口时，必须回读源码并同步本文：

- [复用声明类型](../../crates/vulcan-plugin-runtime/src/manifest/reuse.rs)：字段、清理回调、顺序和限制。
- [正式调用选择](../../crates/vulcan-plugin-runtime/src/runtime/formal/calls.rs)：普通工具、复用工具与固定会话。
- [清理包装](../../crates/vulcan-plugin-runtime/src/runtime/bridge/embedded/bundle/hygiene.rs)：失败与退役语义。
- [兼容桥](../../plugin-bridge/vulcan-plugin-bridge/runtime/bridge.lua)：旧加载入口与正式模块入口。
- [执行引擎](plugin-execution-engine.md)、[容量管理](plugin-capacity-policy-transactions.md)、[自动预热](plugin-automatic-prewarm-policy.md)：当前管理接口及其事务边界。

## 先区分四件事

1. **无状态工具的 VM 复用**：工具显式声明 `lua_runtime.tools[].execution.reusable` 后，宿主才复用通过清理检查的实例。未声明的普通工具保持单次生命周期。
2. **固定会话**：调试会话、持久 Hook 和 UI Action 已有各自的固定会话路径，不能把它们都当作每次冷建 VM，也不能给这些入口直接添加普通工具的复用字段。
3. **公共或专用容量**：解决资源归属、配额和竞争。专用容量不是独立进程，不隔离 CPU、数据库或网络，也不自动让业务更快。是否复用与容量归属是两项选择。
4. **预热**：当前可复用工具预热只初始化模块，不执行业务函数或 `before_call`。它不等价于启动浏览器、连接外部服务、预取文档或打开调试会话。

旧桥接文件仍存在，但正式执行通过插件独立的 `EmbeddedRuntime` 与受限宿主回调完成。上层 Lua API 的兼容保留并不妨碍底层换用新的执行路径。是否需要业务适配，取决于插件自己的入口和资源寿命。

## 五个插件的结论

| 插件 | 当前关键入口和已复用资源 | 建议优先处理 | 容量判断 | 本轮状态 |
| --- | --- | --- | --- | --- |
| Context7 | 两个普通无状态工具；UI Action 独立；每次 HTTP 调用新建并关闭 curl easy handle | 首先试验逐工具 VM 复用，保留模块加载结果，严格清理请求状态 | 先共享；出现其他插件竞争后再评估专用工具容量 | 分析完成，未启用复用 |
| RTK | Shell 改写已由宿主原生执行；插件只剩 Git 上下文 Hook 与统计 Action（有结果缓存） | 分离进程启动、Git 查询与排队时间 | 只在 Hook 入场竞争明确时考虑预留；不能消除外部进程耗时 | Shell 改写已原生化，其余未改变 |
| 调试运行时 | 固定工具会话；一个会话 VM 持有其 Node sidecar | 保持会话亲和，优化连接与事件读取，分别测首次和连续调用 | 长会话受竞争影响时评估专用会话容量 | 保持现有固定会话 |
| 浏览器 | 持久 Hook、UI Action；实际浏览工作由 MCP 与浏览器承担 | 测量 MCP 准备、浏览器启动、导航和截图传输 | Lua Hook 容量仅影响入场，不代表浏览器性能 | 保持现有 MCP 与会话链 |
| 使用统计 | 持久 UI Action；已有按视图查询、分页和版本核查 | 分析 SQL 查询计划、重复扫描、数据规模和宿主回调次数 | 先共享；专用 Action 容量不能修复数据库瓶颈 | 分析完成，未调整 SQL |

### Context7：适合直接验证新基座能力

源码：[清单](../../plugins/context7/plugin.yaml)、[Lua 业务](../../plugins/context7/runtime/plugin.bundle.lua)。
关键函数为 `runtime_module`、`ensure_schema`、`request_credential`、`perform_get`、`execute_context7_request` 与 `dispatch`。

当前两个工具分别解析库名及查询文档。模块依赖按需加载；数据库初始化用 `schema_ready` 记忆；凭据按请求读取和解密；HTTP 请求的 header、body 缓冲及 easy handle 属于单次调用。业务还写入额度和请求记录，因此不能把“查询文档”误判成完全无副作用的纯函数。

推荐首个适配实验：

1. 给两个工具分别补齐私有清理回调，证明仅保留模块表、只读定义及已经完成的初始化标志。请求参数、凭据、响应缓冲、错误和句柄不得挂在下一次可见的模块状态中。
2. 先采用 `key_serial` 验证同一工具分区的顺序和资源回收，再按真实请求限额评估 `parallel`。两个工具、不同控制器或工作区仍可以并发；单键串行不能替代 SQLite 和额度写入的并发验证。
3. 始终按调用读取凭据。插件私有数据库中的密钥变更不自动等同于宿主配置修订，不能仅依靠配置变更使缓存失效。
4. 逐条覆盖成功、HTTP 错误、超时、取消、凭据轮换、配额写入失败及清理失败。不能在未知结果后自动重放请求或记录写入。
5. 再测预热。当前 `perform_get` 才懒加载 curl；仅预热模块不一定提前支付这部分成本。若把确定的依赖加载提前至模块初始化，需要重新审核初始化能力和成本，仍不应预先消费远端额度。

预期节省的是 Lua 建立、源码加载、模块初始化及重复初始化检查。当前每个请求仍新建 easy handle，**不能宣称已经实现 HTTP 连接池或节省远端服务耗时**。
两个工具的复用键不同，也不能宣称它们共用一个 VM。不要因复用而缓存带鉴权的文档、额度或密钥，除非另有明确的数据缓存契约。

### RTK：先处理外部调用成本

源码：[清单](../../plugins/vulcan-rtk/plugin.yaml)、[Lua 业务](../../plugins/vulcan-rtk/runtime/plugin.bundle.lua)。
Shell 命令改写已移到宿主原生 `shell_command`（见 [`tooling-and-terminal-runtime.md`](tooling-and-terminal-runtime.md)），
不再经过插件 Hook。`transform_git_commit_context` 顺序取得 Git 上下文；`statistics_get` 调用统计命令。配置按调用读取。
Hook 已使用持久运行路径，统计界面已有延迟加载和清单声明的结果缓存。

应记录每次 Hook 的等待时间、配置回调、RTK 进程启动和执行时间，再判断是否值得改变调用粒度。
暂不基于命令字符串猜测可跳过的重写，也不缓存可能受当前目录、RTK 版本或配置影响的结果。
没有已验证的常驻 RTK 服务协议时，不设计一个假想 daemon 作为优化前提。

固定 Hook 实例的串行限制不会因增加容量而自动消失。若发现跨工作区的队头阻塞，应先明确现有所有者和顺序需求，再单独设计分区，不能直接给 Hook 添加 `execution.reusable`。
Git 上下文优化仍须保留现有未跟踪文件信息和宿主数据归属。

### 调试运行时：保留会话与 sidecar 的绑定

源码：[Lua 入口](../../plugins/vulcan-debug-runtime/runtime/plugin.bundle.lua)、[Node 实现](../../plugins/vulcan-debug-runtime/node/sidecar.mjs)、[清单](../../plugins/vulcan-debug-runtime/plugin.yaml)。
`ensure_sidecar` 在会话 VM 中建立受管进程；`dispatch` 使用已有 sidecar 的帧协议；`shutdown` 负责关闭。
关闭的 sidecar 不应被悄悄换成另一进程后继续使用旧会话身份。

优化测量分为首次 Node 启动、目标连接、连续协议请求和事件拉取，保留输出上限与取消边界。
不要把会话工具改成可借给其他会话的无状态池，也不要让不相关调试目标共用一个 sidecar。
专用会话容量可以减少长会话挤占或被挤占，但仍受父级、插件及会话数量预算约束；预留过大也会妨碍其他插件。
普通工具的预热入口不适用于提前启动所有调试 sidecar。

### 浏览器：测量 MCP 与浏览器的真实链路

源码：[清单](../../plugins/vulcan-browser/plugin.yaml)、[Lua Hook](../../plugins/vulcan-browser/runtime/plugin.bundle.lua)、[使用说明](../../plugins/vulcan-browser/README.md)。
Lua 承担配置、截图注册与调用前约束；实际自动化经过会话范围 MCP 和浏览器。
把 Lua VM 调整成专用容量不能替代浏览器实例复用，也不代表 CDP 或 MCP 连接已预热。

分别测量会话准备、MCP 握手、首个浏览器请求、连续导航、截图编码及传输。保持当前浏览器生命周期和权限撤销规则。
不得为提速跳过截图参数治理、危险代码门控、工作区授权或将互不相关的浏览器上下文合并。
只有证明 Hook 排队成为瓶颈，才评估其专用预留；否则优先处理外部链路。

### 使用统计：优先验证数据库与界面请求

源码：[Lua 查询](../../plugins/vulcan-usage-statistics/runtime/plugin.bundle.lua)、[UI](../../plugins/vulcan-usage-statistics/ui/index.mjs)。
`load_dashboard` 根据视图和分页选择查询分支，多个查询使用筛选后的 CTE，并核查聚合修订。UI 已有按区域加载、分页、旧响应防护和快照保留。
因此不能再把“改成分页”或“保留 Lua 价格目录”描述成新的适配成果。

后续使用具有不同记录规模的隔离数据库，记录各查询耗时、调用次数与 `EXPLAIN QUERY PLAN`，定位是否重复扫描或索引不足。
数据量、筛选范围、供应商、币种、分页和价格目录版本必须进入测试维度。
新增索引或改写聚合属于数据库调整，需要独立验证迁移和写入成本；不要只优化读取而阻塞事件写入。

若新增结果缓存，必须覆盖聚合修订、完整筛选条件、定价配置与权限上下文，并在写入后失效。
保留大整数和十进制定价的准确性，格式化不得通过浮点数往返改变金额。
专用 UI Action 容量只解决入场竞争，不解决数据库 I/O 或计算成本；也不应无约束并发所有查询。

## 正确声明复用

仅对清单第二版的**普通无状态工具**使用以下片段。数值是说明字段关系的实验例子，既不是产品默认值，也不是所有插件应复制的性能标准；正式值由实验和宿主预算决定。

```yaml
execution:
  reusable:
    initialization_capabilities: []
    before_call: prepare_request
    after_call: finish_request
    reuse_check: request_state_is_clean
    ordering: key_serial
    max_resident_vms: 1
    max_running_calls: 1
    idle_ttl_ms: 60000
    max_uses: 100
```

该片段放在某个 `lua_runtime.tools[]` 条目中；还必须真实实现对应模块函数并通过完整包校验，不能直接粘贴到 Hook、Action 或会话工具。
三个私有函数名称须互不相同且不与普通导出冲突。完整约束参见[生成的复用 Schema](plugin-tool-reuse.schema.json)。

| 回调 | 输入与成功结果 | 失败时的含义 |
| --- | --- | --- |
| `before_call` | 本次信封；必须返回 `true` | 业务与 `after_call` 不再运行，实例退役；不要把必须释放的资源只交给 `after_call` |
| `after_call` | 本次信封、Lua 业务是否正常返回；必须返回 `true` | 清理失败导致实例退役，不交给下一次调用 |
| `reuse_check` | 无参数；必须返回 `true` | 拒绝复用并退役 |

业务返回 `{ok: false}` 仍是正常 Lua 返回，传给 `after_call` 的成功标志为 `true`；该标志不是业务成功率。
业务抛 Lua 异常时，包装器尝试清理，然后仍报告业务失败。不要依赖异常、取消或进程终止一定能完整执行插件代码；底层资源还须有正确的宿主管理和关闭归属。
仅写三个总是返回 `true` 的函数不能证明清理正确，测试必须污染实际会跨调用保留的状态并验证下一次调用。

复用分区包含父级、插件代次、控制器、规范化工作区、工具、配置内容身份、能力修订及容量策略修订。
配置或权限修订不能继续使用旧复用身份；它们也不等价于插件私有数据的通用缓存失效通知。
`key_serial` 只在同一精确分区串行；`parallel` 使用相互独立的 VM，不表示同一 Lua 状态能够被多个请求并发操作。
旧代次排空仍消耗资源，容量规划须留出更新窗口。

## 预热、权限与更新

- 插件声明自己需要的能力和容量下限，宿主决定批准的共享或专用策略。清单的空容量列表不表示无限资源。
- 在宿主插件实现中，`initialization_capabilities` 省略和空列表都拒绝模块源码初始化阶段的宿主回调；显式列表只能收窄既有授权。不要把此规则泛化为其他 SDK 的所有加载入口。
- 源码初始化尽量只加载确定的代码和只读定义。把请求、密钥访问、数据库写入和目标连接放在明确的业务阶段。
- 自动预热规则默认空集合；保存策略本身不执行 Lua。实际触发位于提示准备流程，还要检查启用、代次、工作区、能力和当前预算。
- 预热成功只证明模块初始化完成；前置清理、外部依赖连接和真实业务仍须分别验收。不能靠预热远端写入或消耗额度伪造首调用收益。
- 更新走不可变代次、旧调用排空和新目录发布。旧工具、旧固定会话和旧 UI 模块不得在更新后被静默重绑为新代次。
- 停用、卸载、撤权、清理失败和初始化失败均需检查最终资源释放。业务数据迁移仍是单独交付范围，不因运行时代次安全而自动成立。

## 如何证明优化有效

先保存基线提交、候选提交、正式依赖版本、插件包、配置、CPU/内存、外部服务与数据规模；优化前确定指标与准入标准。
不要看到测量结果后调宽阈值。此前基座验收的毫秒门槛不直接成为所有业务插件的 SLA。

每个实验分别报告：冷调用、连续调用、同键并发、跨键并发、其他插件竞争和更新过程。
记录端到端 P50/P95、吞吐、成功及错误数、排队时间、初始化次数、宿主回调耗时、常驻/峰值内存、进程与句柄数量。
正常暖池阶段验证常驻量有界；排空、停用或关闭完成后再检查对应资源归零，不把有意保留的暖实例误判为泄漏。
短测至少重复独立批次，预先固定批次数和样本数，保留全部失败；不要只挑最快的一次。
有真实外部服务的测试固定请求内容并控制额度；模拟服务结果只能解释本地机制成本，不能冒充线上业务延迟。

| 插件 | 定向测试负载 | 不能退化的行为 |
| --- | --- | --- |
| Context7 | 同工作区交替解析/查询；多工作区与两工具并发；成功、超时、限流、凭据轮换、更新 | 无密钥串用、记录重复和跨请求状态泄漏；失败后可继续正常调用 |
| RTK | 真实 shell 重写；不同 Git 仓库；Git 上下文与统计同期开启 | 命令和上下文语义、失败诊断、取消及输出边界保持 |
| 调试运行时 | 打开后多次调用/事件拉取；多会话；目标退出、sidecar 关闭、停用和更新 | 会话归属正确；旧身份拒绝；进程最终释放 |
| 浏览器 | 新会话与连续轮次；导航、截图及禁止的调用；撤权和重连 | 页面生命周期、权限和 Hook 约束保持 |
| 使用统计 | 空库及不同数据规模；概览、明细、翻页、配置变更、并发记录写入 | 数值精度、筛选和分页一致性；修订变化与旧响应处理正确 |

建议实施顺序：先做 Context7 的有限复用实验；并行收集 RTK 与使用统计的瓶颈证据；调试和浏览器保持现有亲和关系，只在外部链路测量显示收益时改动。
只有真实的资源竞争证据才支持增加专用预留，不把五个插件统一切到专用池作为默认方案。

## 本轮多语言验证与性能边界

本轮语言资源、展示格式及语言切换测试见[开发指南](plugin-development-guide.md#多语言资源与界面)。
这些测试覆盖插件展示与宿主 SDK 边界，不测 VM 复用收益，也不替代上表的外部服务和故障验收。
本次没有修改五个插件的 Lua 业务、池配置、数据库查询或 Node sidecar 协议。
