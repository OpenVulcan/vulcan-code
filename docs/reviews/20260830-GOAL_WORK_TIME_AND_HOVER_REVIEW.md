# 目标状态、工作时长与悬浮详情修复记录

日期：2026-08-30

## 本轮范围

本轮只处理目标功能的新反馈：受阻目标播放恢复、目标条紧凑布局、实际工作时长、重启暂停，以及完整目标与用量的延迟悬浮展示。保留原有未提交改动，不把此前子代理与会话审核的结论冒充本轮桌面验收。

## 已修复的根因

1. 按钮和控制器原先都把“非暂停”误当作“应暂停”，受阻目标因此请求了领域层禁止的转换。现在共享同一动作映射：受阻显示“已暂停”和播放，发送恢复命令；预算耗尽保留独立编辑入口。
2. 恢复与编辑同一目标原先重设统计起点，丢失此前累计。现在保留目标生命周期起点；创建新目标才产生新起点。
3. 原先的目标用时只是累计物理 API 耗时。现在根据目标状态事件计算活动区间，包含工具执行和回合交接，扣除暂停、受阻、完成后的区间。
4. 预算停止原先只改元数据，没有可重放的停止时刻。现在与回合完成一起写入既有目标状态通知，不增加每秒写盘。
5. 重启投影原先只处理在途 API，两个请求之间的活动目标仍会继续。现在在发布会话句柄前暂停活动目标，关闭旧开放回合，用户播放后才创建续跑回合；普通非目标会话的未派发 Continue 恢复规则保持不变。
6. 已关闭回合之后的目标状态事件原先仍可能绑定该回合，违反闭合后不得追加的约束。现在这些状态事件归属会话。
7. 尾段加载器遗漏目标早期统计，且仍只识别旧的 Goal 回合起点。现在按当前领域规则识别目标起点，并精确加载保留目标所需的分片。没有目标的会话仍保持普通尾段加载路径。
8. 已存在但未派发的暂停 Goal 回合恢复时，原先只有“新建了回合”才调度。现在按权威空闲分发条件重新准入，现有互斥仍防止重复派发。

## 展示与计时契约

- 目标条保留状态、单行省略的目标内容、工作时长和操作按钮，移除可见的 tokens 数字。
- 悬停目标内容 500 毫秒后显示完整正文，以及用量预算、请求数、工具数、输入、缓存、输出、思考、总量和缓存命中率；采用双列统计卡结构，不再使用五行单列清单。
- 目标条实测高度 35 像素，目标字体保持 13 像素；悬浮卡为 380 像素，并限制为视口宽度以内。
- 计时精度在后端保留毫秒。新增的接口时钟快照只供前端插值；本地每秒重绘不请求网络、不写文件。
- 暂停、受阻、预算停止和完成均不继续走时。旧快照或草稿缺少精确时钟时不自行外推；旧版暂停时改写过起点的记录不会误计后续等待时间。
- 闪退后恢复到最后已持久化的运行观察点，并处于暂停状态。最后检查点与真实闪退之间未落盘的时间无法精确恢复，不承诺精确到闪退发生的那一秒，也不以重新打开时间补齐。
