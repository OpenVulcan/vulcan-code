## 已实施契约与边界

- `MediaDeliveryPolicy` 为可选持久化字段内的独立版本化结构；旧配置缺失时内存默认有效，真实加载测试证明文件字节不变。
- 主会话无上传默认 512 KiB，独立扩展无上传默认 10 MiB；8 项有上传阈值默认零。用途累计编码预算分别为 2 MiB 和 16 MiB。
- 后端可配置原始内联阈值上限 48 MiB、累计编码预算上限 64 MiB；仅限制内联策略分配，不限制附件保存或真实大文件上传。接口与完整正文更小限制尚待发送链统一接入。
- `service_save_public_ai_media_delivery_policy` 接收完整 `request.policy` 和 `request.expected_revision`；`service_reset_public_ai_media_delivery_policy` 接收 `request.expected_revision`，显式恢复继承默认值。两者均在配置事务内比较生效指纹。快照 `mediaDelivery` 返回策略、独立修订和后端上限。
- 两个设置方法均走现有配置事务及工作台补偿发布。现有浏览器 RPC 在分派前统一验证服务令牌，当前只完成此鉴权链的源码核查，未新增真实服务网络调用。
- `ResolvedPublicAiSelection`、`ResolvedPublicAiExecution` 与新调用的 `ResolvedProviderToolTarget` 持有冻结策略；模型代替及专用扩展已消费，V1 准备仍待接入。恢复中的既有异步任务只观察已创建任务，不以当前设置替换原输入。
- 纯规划器区别新意图、已证明的历史内联、已证明的历史上传；它不读文件、不上传、不修改历史。真实历史来源尚未接通，不得对旧数据猜测默认来源。
- 实际执行编码通过 `InternalResponsesRequest` 构造请求局部资源表，并独立投影9种既有协议配置；媒体不再先受标准 Responses 联合类型限制。来源能力注册表已与实际编码器做189种组合比较；这证明编码表示能力一致，不代表线上供应商或模型接受全部类型。
- 独立扩展的真实上传、内联和已有 URL 直通已分开；文件大小、接口硬上限和累计预算在完整负载分配或网络动作之前检查。主会话草稿及显式提交也已接入冻结策略，但V1最终物化、附件提示和历史链尚未闭环，不能把局部成功当成完整附件发送成功。
