# 中英文记忆提示词无思考优化记录

## 目标与边界

用户报告“我喜欢吃香蕉、橘子，你感觉如何？”可能不产生画像，而删除后半句后可以。目标是在无思考模式下提高事实提取准确性，保留原有实测约束和 JSON 契约。本轮只调整权威提示词及验证入口，不修改生产 Schema、解析器、重试策略、模型路由或用户提示词覆盖。

## 五个阶段的实际职责

| 场景 | 中文/英文实际职责 | 本次处理 |
| --- | --- | --- |
| 召回预检第一层 | 判断是否需要旧记忆，生成有范围的检索查询；不是画像提取器 | 澄清当前披露事实不自动触发历史查询，不影响后续提取 |
| 召回相关性第二层 | 从输入编号中筛选回答必需的最小集合；不能生成记忆 | 保留原文及编号/排序约束 |
| 回合提取第一层 | 从当前回合提取普通记忆和画像候选，给出来源和准入 | 明确逐事实判断、混合句与稳定偏好、正反样例 |
| 回合复审第二层 | 普通记忆去重，用户/项目画像准入、刷新、替代及生命周期 | 独立审核三个分块，不能用普通记忆重复或问句外壳否决画像 |
| 手动画像指令 | 显式修改、替代、退役；保留旧复合节点仍有效的事实 | 保留原文、权威下限、唯一旧节点引用和部分事实承接约束 |

两种语言十份原文均已完整阅读，含 JSON 输出样例。中英文的主要规则一致；遗漏风险也共同存在。

## 源码证据与原因边界

- `native_vmm/driver.rs` 的生产模型请求固定 `ReasoningEffort::None`、隐藏思考输出和严格 JSON Schema。本轮保留。
- `vulcan-memorymesh-core-engine/src/engine.rs::advance_analyze_analysis` 按候选 `Admission::Accept` 过滤画像，没有按整句 `question` 禁止画像。
- L1 只要漏掉画像，L2 就没有对应候选可恢复。不能只在 L2 添加“不要遗漏”。
- 原文先要求判断整句类型，之后要求 drop 问答、通识、回显；缺少“先识别用户事实，逐事实决定”的具体优先级。较弱模型可能将末尾提问传播为整轮否决。
- “稳定”没有解释为“用户明确的一般偏好不必重复陈述或带长期字样”，可能被过度保守理解。
- 用户报告的实际历史调用没有在本轮取得原始 L1/L2 输出，不能断言那次一定是某一个模型阶段导致；本轮用新的可追溯测试核对。

## 必须保留的约束

1. 只有当前目标回合是新事实来源；历史摘要仅消歧，禁止从旧画像回显中重新生成事实。
2. 用户陈述、确认、纠正与助手推测/建议分开；不可把虚构、引文、反问或第三人偏好变成用户事实。
3. 直接写入去重只针对普通记忆，不能阻断用户当前明确事实形成画像候选。
4. 画像按领域拆分，同领域同方向同生命周期可合并；不将水果清单机械拆成单词节点，也不能泛化为喜欢所有水果。
5. 临时状态、一次性展示格式、工具能力说明及通识保持原来的排除规则。
6. 时间锚点、上下文边、来源枚举、准入原因、分类和画像类型保持。
7. L2 普通记忆与画像的候选分区必须完整且互斥；所有引用只能来自准确输入集合。
8. 不增加输出字段或外部思考过程；输出契约及原 JSON 样例保留。

## 验证设计

真实测试复用已有保存路由验收的隔离装配，增加显式 `NATIVE_VMM_PROMPT_ACCEPTANCE=1` 分支。供应商、端点、模型和凭据均运行时读取，没有写死。每个样例使用独立会话，按该次完成回合的 `source_turn_ids` 核对画像，不能拿先前手动画像指令结果冒充成功。

中英文分别覆盖直接偏好、偏好加问句、纯偏好询问、虚构假设、否定偏好，共十例。使用相同本地保存路由比较修改前后。此为有明确样本的功能回归，不代表所有弱模型均通过；语义断言不代替大样本质量统计。

结构验证同时核对六份修改提示词的输出契约保持不变、十份提示词中的 JSON 样例可解析、未改四份原文一致、资源清单长度/哈希与真实内容匹配。资源变化后执行 `make.ps1 sync`，内嵌资源还需要重编译才能进入新二进制。已有完整用户覆盖会继续优先，不能自动被内置更新替换。

## 执行与结果

以下区分原始基线、首次追加版与当前融合版；真实模型结果不能跨版本冒用。

### 本轮实际变更

- 中英文回合提取第一层、回合复审第二层及召回预检第一层共六份权威提示词已由追加版改为融合版，不再以“原文零删除”为目标，而以规则保真、单一归属和篇幅控制为目标。
- 提取层：将事实级规则、原判断流程和重复样例合并为来源归属、持久性、独立准入、逐事实过滤、整轮标注五步；对象完整性与否定约束归入节点内容规则，保留三组有判别力的边界示例。
- 复审层：将跨块独立性归入输入边界，单次偏好和混合句归入接纳规则，用户再次确认归入替代规则，假设/引用归入拒绝规则；分级归入画像评审，不再设置重复的独立决策附录。
- 召回层：合并判断流程与召回/不召回列表，把“当前事实不等于缺失历史”直接放入不召回条件，避免三处重复说明。
- 召回相关性第二层及手动画像指令共四份原文未改。
- 更新资源清单中六项长度/摘要，资源文件总数仍为 49；原始总字节为 89,818，追加版为 100,669，当前融合版为 93,246。对应精确资源测试同步，不放宽完整性校验。
- 新增 `native_vmm/prompt_quality_acceptance.rs`，复用既有真实模型测试装配；既有测试增加显式分支，不改变默认忽略及收费调用开关。
- 为确保重新嵌入资源，仅清除配置 crate 的可再生编译缓存；未删除用户数据。已执行资源同步，未手工编辑运行产物。

### 首次追加版真实模型结果与限制（非当前融合版验收）

| 批次 | 结果 | 说明 |
| --- | --- | --- |
| 原提示词基线 | 中文五例全部通过；英语三个有画像的样例输出中文 | 这次没有复现用户报告的中文遗漏；英语结果受到同一固定用户既有中文画像影响，不能计作未提取事实 |
| 优化后中文首次独立运行 | 一个矩阵测试通过，21.03 秒 | 使用独立临时数据，五个样例全部最终通过 |
| 优化后中文原始输出复核 | 五例全部通过、零重试，21.94 秒 | 直接陈述与附带提问都保留香蕉/橘子；纯问题和虚构例没有画像；菠萝的否定保留 |
| 优化后英文独立运行 | 五例全部最终通过，52.02 秒 | 正例为 bananas/oranges，否定为 dislikes pineapple；纯问题一次存储冲突后重试，其他四例零重试 |

不将“一次当前保存路由通过”写为所有弱模型都有效，也不编造准确率提升：基线中文本来就通过。此次收益是消除提示词歧义、补直接决策规则，并留下可重跑的实际入库回归。

测试采用独立语言进程，避免把前半批中文历史对英语输出的影响混入提取准确性指标。跨语言已有画像场景出现跟随历史语言的现象已记录，尚未形成单独语言稳定性验收。

### 新发现的既有运行时冲突

- 两种原始 L1 提示词均要求无候选时返回空 `details`，本轮没有删除该规则。
- Core 完成提炼时在 `engine.rs` 第 6136 行把 `pending.analysis_details` 包装为 `Some`，进入已完成回合。
- 存储 `lib.rs::validate_turn_analysis_state` 第 3511 行附近明确拒绝存在但为空的摘要。
- 英文纯询问反例出现 `StorageConflict: turn analysis metadata conflicts with its durable state`，一次重试后完成。源码确认空摘要与存储约束冲突这条路径存在；本次未保存该失败尝试的完整 L1 内容，因此不把此错误日志单独作为失败载荷确为为空的证明。
- 此项是原提示词与现有存储契约的既有差异，需要后续协调完成状态与空提取语义。不能通过生成虚假长期事实、填充无依据摘要或放宽 JSON 约束掩盖。
- 本轮没有改动生产存储或引擎，也不能据最终重试成功宣称首次执行零错误。

### 当前融合版结构与资源验证

- 十份提示词中共十四个完整 JSON 示例成功解析。
- 资源契约十八项通过，包括资源长度/哈希、完整语言包覆盖、不可变快照和别名。
