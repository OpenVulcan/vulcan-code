# 文件变更集 V1 失败恢复审核报告

## 审核目标

验证文件编辑工具在创建、修改、删除与移动生命周期中始终产出合法的 V1 ChangeSet；当工具结果校验、持久化或投影失败时，当前 Provider 请求与逻辑轮次必须确定性终止，界面必须显示可诊断错误，且不得继续派发新的 Provider 请求。

## 审核范围

- 文件工具结果的生命周期与修改契约
- 工具提交前的 ChangeSet 校验
- 工具完成投影屏障的失败类型与错误传播
- 单工具及并行工具批次的致命持久化失败处理
- Provider V1 活跃请求的失败收口与轮次终止
- 历史持久化错误与实时界面错误提示
- Continue 资格与恢复入口安全性
- 相关单元测试、集成测试和回归验证

## 工作区隔离规则

- 仅修改本报告覆盖台账中归属本任务的文件。
- 对已被其他会话修改的文件，先核对差异；无法安全隔离时不修改并记录阻塞或替代方案。
- 编译或测试失败必须按本任务改动相关性归因；确认属于其他会话范围的失败只记录，不越界修复。

## 实现与验证基线

- 原生文件新建与修改已使用不同的公共结果构造；新建只携带生命周期正文，修改只携带修改块。
- 原生写入、删除、移动、精确编辑、Apply Patch 与旧编辑预览在提交前均经过规范 V1 ChangeSet 解析器校验。
- 工具投影屏障具备带原始原因的拒绝回执，运行时映射为不可重试的 `ToolDurabilityFailure`。
- Core 在单工具与批次准备阶段直接传播致命错误；并发批次会先汇合已启动兄弟，再停止 Provider 循环。
- 服务流保留首个边界错误；后续请求准备在本地拒绝，不再次进入唯一 V1 preparation owner。
- 首错后仍允许已经启动的兄弟工具可靠提交 `ToolFinished`，同时拒绝任何新的批次、工具开始或下一次 Provider 准备。
- 活动 API 失败会生成 `Failed/Unknown/Forbidden` 的 ApiStats、唯一 SystemError、关闭 Turn，并允许新的根输入。
- 已成功持久化 API 后若实时生命周期投影失败，会保留原成功 ApiStats，追加独立 SystemError 并关闭 Turn；已有失败 ApiStats 不重复记错。
- API 中断与 Turn 关闭的两份私有事件回执会在候选发布前合并为唯一 revision，满足 `SessionHandle` 的单次修改不变量。
- 终态物理存储首次失败时，对同一内存脏修订执行一次幂等重试；持续失败则保留准入 owner。
- 现有 V1 WebUI 会显示 SystemError 的 `redacted_detail`，Continue 选择器只接受 `allowed`，无需新增并行错误状态。
