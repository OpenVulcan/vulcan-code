## 拆分意图与充分性

候选准备、契约比较、每份凭据观测、原子迁移、保存和删除补偿共同拥有同一供应商身份与生命周期，原来散落在请求合同、事务函数和底部助手中。归集为完整领域，不把其中单步补偿或状态判断拆成缺乏上下文的小文件。

没有按custom_provider前缀搬走供应商级模型默认值、模板与逐模型验证：这些代码拥有模型设置合同，留待模型领域继续归集。当前供应商模块的边界已闭合；设置根仍有模型、会话选择、媒体工具与快照等多种职责，不能仅因行数下降就判定02号完成。

## 生产链审核

1. 三个请求/结果类型与探测、保存、移除三个RPC一起迁移，四个候选/激活/观测类型保持模块私有；原crate可见入口由原根明确重导出。
2. 候选准备仅创建隔离描述和内存秘密，编辑必须复用精确供应商现有凭据；无凭据供应商可合法编辑，编辑不接收替换秘密。默认值仍由当前声明和类型定义决定。
3. 契约比较逐条协议路线规范化执行能力；仅展示或Responses执行能力变化不触发连接重验，端点/鉴权等传输契约变化仍验证全部账号。
4. 发现结果维持封闭接纳：Ready直接接受，空/不支持/无效响应只允许显式手工入口，临时失败/限流等只允许显式延期；认证失败、未检查和过期不混入接纳分支。
5. 逐凭据观测绑定稳定凭据身份；临时目录标识按原代码重映射回持久身份，迁移前收集全部结果，任何无效迁移不得部分修改连接图或推理档案。
6. 单协议目标可精确迁移原推理绑定；多协议保留模型的原精确协议，不用供应商默认协议替换。失效绑定继续显式失败关闭。
7. 保存仍从验证开始持有配置事务；全部观测收集后由tokio::spawn提交任务接管事务，保留原取消边界。暂存镜像、秘密创建、配置激活、发布前响应构建及失败补偿顺序全部相同。
8. 协议删除仅清理删除集合拥有的覆盖，新增协议不触发该清理；失效显式模型偏好保留以表达真实错误，不被静默降级。
9. 删除按当前remove_custom_provider_owned_state清理独立清单所有权、模型和连接引用；保留凭据确认门和显式会话路由撤销，不照搬历史自动换模描述。
10. 删除前完整读取待删除秘密，部分删除失败恢复当前及先前引用；后续配置/运行时/发布失败沿原镜像补偿，主错误和恢复错误均保留。
11. 唯一共享身份校验助手向设置父域开放，供剩余模型操作复用；其他内部助手和全部本批字段不扩大可见性。
12. 修正两处“唯一协议”陈旧说明并补齐参数/返回双语注释；无业务表达式、错误字面量、序列化属性或断言变化。
