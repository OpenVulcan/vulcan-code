## 第十三阶段：全局工具与媒体后端

### 理解与拆分理由

搜索/抓取单选、媒体模型准入与后端、原生模型扩展集合、能力默认开关和显式诊断共同拥有全局工具设置。它们与会话元数据的读取/继承/提交不同，归入provider_tools.rs；目标可用性和原生集合验证由全局领域持有并供会话及快照复用。

迁移6请求类型、6服务入口、4共享或组合校验助手，共16节点；直接媒体后端回归随模块迁移。历史Tavily问题仅作为线索，已重新确认当前五项保存入口实际使用工具专用发布事务。

### 关键审核

1. 工具保存继续跳过无关会话模型协调与租约缺失检查，不因迁移换成普通模型发布；原事务、快照预构建、配置激活及失败补偿顺序一致。
2. 搜索/抓取仍用精确连接/目标/能力三元组单选；媒体理解必须使用专门后端接口；生成扩展必须使用完整原生集合，入口互斥校验不合并。
3. 模型代替必须满足共享准入开关、可执行精确账号、对应媒体输入、稳定结构化输出及受支持思考档位，仍由同代际settings_catalog证明，不猜模型或协议能力。
4. 后端切换更新对应全局已保存选项；清除后端只清除后端及选项，不改变独立能力开关；同能力历史全局直连目标继续清理。
5. 扩展集合验证精确目标、非Custom来源、已审查extension_profile及公共模型ID唯一性，保持所有现有拒绝分支。
6. 普通直连能力启用保留至少存在匹配可用目标的当前规则；媒体启用要求完整可执行后端。具体目标保存和会话冲突检查保持原责任，不擅自加严或放宽。
7. 真实搜索/抓取诊断仍是只支持两项能力的生产服务，不因名字含test而移除；本轮没有带真实凭据执行该网络入口。
8. 三个跨领域助手仅向设置父域开放，组合后端检查私有；12个原类型/RPC通过原根重导出，字段仍私有。

## 第十四阶段：会话工具配置与元数据

### 理解与拆分理由

会话配置的V1契约构建、默认继承、显式覆盖、冲突诊断、读取/保存/重建及媒体桥接共同围绕同一元数据权威和投影生命周期。归入session_tools.rs，保留显式方法边界，不把每个转换函数拆成独立文件或复制全局后端验证。

迁移3类型、3RPC及17配置/投影助手，共23节点，七项直接回归整体迁移。

### 关键审核

1. 继续使用SessionProviderToolConfiguration唯一访问入口；已读其生命周期守卫、索引定位和常驻/未加载注册表分支，配置访问不创建会话运行时、不加载Turn历史。
2. 读取仅比较能力投影；差异存在才发布内存视图，提交闭包为空。缺少执行投影是正常重开状态，不创建投影或回写metadata。
3. 保存继续归一化媒体旧直连目标及模式键，在完整冲突校验和快照构建后才于发布提交点调用access.save；不把其他执行、目标或模型字段写入能力附加项。
4. 显式重建不先读取损坏旧附加项，使用默认配置解析并调用access.rebuild；overridden=false保留后续全局继承，不把一次默认值固定成显式覆盖。
5. 未覆盖会话跟随当前全局默认；显式覆盖保持独立，仍清理历史媒体直连目标/非法模式键，并按原规则补齐旧版本缺少的媒体模式。投影变化不等于持久写入授权。
6. 会话可选择后端模式，但精确模型、账号和思考配置来自对应全局已保存选项。校验和桥接在独立配置副本应用模式，不修改全局持久化、不建立第二份精确后端配置。
7. 冲突分析对仅搜索/抓取的会话不派生无关媒体候选；缺失模式/直连目标、不可用后端、无效直连能力和扩展集合仍形成原结构化冲突，不静默改选目标。
8. V1集合按最终序列化能力键排序，嵌套目标也排序；所有字符串键继续由serde封闭枚举解析，非法键显式失败。
9. 11个原可见类型/入口完整保留：6个原pub(super)定义迁为子模块pub(crate)，5个原pub(crate)函数保持不变且原根同名重导出。其余助手和全部字段私有，无新增字段范围调整。
