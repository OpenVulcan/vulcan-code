## 行为与架构边界审核

### 媒体

1. `ProviderExecutionClient.prepared_media` 仍是同一共享容器，构造与克隆不变；缓存项类型只对父模块可见，字段全部私有。
2. 上传前、上传后、内联保留字节对应的指纹检查及协作取消不变；视频缺失声明上传通道时仍失败，不引入Base64回退。
3. 默认复用边界保持供应商、服务入口、上传契约和源内容；凭据与会话作用域由通道声明明确收窄。未按模型或Manifest代际擅自改键。
4. 持久会话引用与无会话工具引用继续使用不同保留策略。工具入口受首次使用、供应商/通道时长和一天上限约束；持久引用不因宿主单调时钟TTL而强制重传。
5. 原两个对外媒体常量通过根重导出；一个crate内工具缓存时长常量保留根定义并被媒体显式导入，原访问路径和作用域都不变。

### Profile映射

1. 请求可读取声明的宿主字段与模型参数；响应只能读取响应正文，禁止请求专有步骤的分支保持。
2. 请求错误仍为分派前执行失败，响应错误仍为协议转换失败；Pointer祖先类型检查、空值删除及空对象裁剪代码均等价。
3. 有界JSON模板继续由既有独立模块提供，不复制模板解释器。
4. 编码前守卫仍执行相同单步映射校验；真实调用已通过源码确认，不仅校验编码后的主链。
5. 4个原crate入口保留根路径，3个执行管线入口仅对父模块可见；内部其余原语不公开。
