## 职责与证据

- 结构扫描识别设置快照/请求合同、连接和OAuth、定制供应商候选验证、模型及用途设置、内部推理、媒体/工具选择、同步补偿、会话选择协调与工作台发布多个不同生命周期。

- 基线两个真实测试模块覆盖47项，不沿用历史数量或猜测tests模块名。

## 为什么需要拆分

接口合同、纯能力校验、候选投影、秘密生命周期、配置变更和工作台发布依赖不同事实；集中一处掩盖各自所有者与测试对应关系。按同一职责持有的类型和方法迁移，用必要的原路径重导出保持RPC/消费者接口。

## 不应拆分与边界

- 同一业务事务的验证、保存、发布与精确补偿不得拆成难以追踪顺序的零碎回调。
- 相似但语义不同的工具发布/模型协调/显式撤销策略不合并。
- 设置快照保持一个清晰组合入口，但各领域的数据类型及投影应根据实际消费关系归属。
- 私有助手仅向设置父域开放；原pub(super)项移入子模块时必须保持实际crate作用域，不能误缩成仅子模块父域或扩大成对外API。
- 不引入新库、Schema、协议或配置兜底，不编辑资源产物或变更业务规则。

## 第四阶段决策：OAuth授权与重新授权

- 当前源码确认两个请求类型、启动/查询/取消/提交四个RPC和重新授权秘密回滚只服务OAuth生命周期，归入 `public_ai_settings/oauth.rs`，不把重新授权事务拆成零碎回调。
- 启动读取当前声明的provider/service/profile并生成授权绑定；提交要求事务成功且当前声明指纹匹配后才取走授权材料，不增加猜测身份、备用授权或协议切换。
- 重新授权保留秘密存在/缺失两个真实分支；已有秘密采用修订比较替换，原来缺失时创建。后续失败按原规则恢复材料并推进修订或删除本次新建秘密，不覆盖并发新修订。
- 新建连接继续复用唯一 `add_public_ai_connection_with_secret`；重新授权的连接变更继续复用 `apply_connection_update`。它们将随完整连接生命周期归集，OAuth层不复制。
- 两个类型与四个RPC保持原根crate作用域重导出；请求字段只在本域读取，保持私有。共享的三种连接请求协议拒绝用例仍留跨层测试，原正反断言全保留，不为制造专属测试文件拆碎或复制。
- 补充四个RPC的参数/返回双语说明，并纠正提交函数说明仅称新连接的不完整表述；实际控制流、错误和补偿语义均不改变。
- 此域职责已形成闭合链，无需将短状态查询与取消再拆文件；02整体仍有大量凭据、配置和发布职责，第四阶段不闭环。
