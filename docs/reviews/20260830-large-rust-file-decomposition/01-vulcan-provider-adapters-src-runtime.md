## 拆分决策与充分性

- 为什么需要拆分：同一文件混合凭据存储、刷新租约、配置代际事务、目录发现、模型选择、媒体准备和异步任务观测等独立职责；修改一种生命周期时需要穿越不相关实现与测试。拆分依据是这些边界，而不是把文件压到指定行数。
- 哪些部分不需要拆分及原因：`PublicAiRuntime` 的共享状态暂保留唯一归属，配置代际、目录和激活事务之间的状态发布顺序不改变；不复制状态、不增加中间服务或改动对外协议。

- 当前拆分是否足够：足够。凭据、目录、激活、选择、投影、修订、执行和测试均已归位；根中 20 个原生产区域节点只保留唯一共享状态、组装和通用入口。继续拆这些共同所有权会增加人为中间层；1507 行查询模块等较大产物仍保持单一投影或完整生命周期，不为缩小行数继续切碎。充分性依据与全部产物审核见终审记录。
