## 第九阶段：用户自有模型生命周期

### 理解与拆分理由

手工模型定义、协议偏好、默认层、模板建议与审查、逐账号手工模型可用性和显式验证共同拥有用户自有模型合同。原来类型、服务与底部校验散布在设置根，应归集完整业务生命周期，不以函数名custom_provider与custom_model前缀机械划界。

迁移13个请求/结果/条目类型、9个服务入口、8个私有助手和一个私有批次上限常量。三项直接回归随领域迁移，快照投影记录仍由投影层持有。

### 关键审核

1. 显式模型验证是可能计费的生产服务，不是旧单元测试。临时配置只为本次显式操作解除pending和模型开关，使用精确账号模型路线及现有最小输入/输出上限/思考策略。
2. 执行身份仍为规范UUID，只有真实执行成功并复核连接归属、服务入口和凭据档案未变化后才解除持久隔离；成功前不改变默认账号和可用状态。
3. 完整模型替换先校验模型与模板决策、重复键及决策所属替换集合，再用候选配置重建覆盖。实际写入复用同一替换函数，不产生候选/持久两套逻辑。
4. 删除判断保留精确账号目录语义；活动和归档会话锁定的模型禁止移除，当前选择与LLM/Embedding/Rerank内部路由逐一检查。其他账号同名模型不被当作替代证据。
5. 锁定会话模型标识仍先在服务状态锁内复制，再离开该锁解析目录，未引入嵌套锁或跨异步持锁变更。
6. 模板建议只查不可变本地目录；Applied要求键、修订和selection完全匹配，Rejected仍验证键和修订。批量建议/保存保持2000上限、非空和去重校验、一次原子发布。
7. 默认层与代码默认值相等时还原继承；候选先校验上下文窗口层和目录覆盖，不把继承值固定写回持久配置。
8. 显式协议偏好只引用当前启用集合，并维持长度前缀组合键/重复键拒绝。手工模型账号开启不能绕过供应商禁用权威。
9. 22个原crate可见入口经原根重导出，所有字段与8助手仍私有；共享身份校验和配置推理句柄直接复用已有领域，不复制或扩大状态边界。

## 第十阶段：通用模型访问与覆盖设置

### 理解与拆分理由

账号访问、模型发布开关、能力层及协议执行层都遵循模型设置候选校验与发布边界，与用户自有模型定义、实际会话选择和只读快照投影不同。归集6请求类型、6服务入口和2内部助手，共14节点；没有把选择算法或会话协调实现复制到新模块。

### 关键审核

1. 账号成员支持判断先去掉该账号访问策略再读取支持目录，不把“被禁用”错误解释为“不属于账号”。账号整体开启仍尊重供应商禁用选择。
2. 单模型/全账号禁用只撤销精确账号及可选模型的活动、归档租约。全局默认可以选择替代，但会话自有provider/connection/model事实不被重写。
3. 模型发布服务取得配置事务后重新读取配置，再从同一settings_catalog代际获取支持事实和候选目录，原并发顺序保留。
4. restore解析当前清单继承值后判断最终是否禁用，不把请求enabled误当恢复后的最终状态；供应商模型撤销范围仍为精确provider/model。
5. 能力空覆盖继续表示还原；非空覆盖保留存在性及能力候选校验。协议执行覆盖不能写上下文/输出限制，保留原字段边界与匹配路线验证。
6. 普通覆盖仍使用普通发布事务；访问撤销使用带精确会话撤销的发布事务。错误字面量、撤销原因码、响应预构建与补偿顺序全部保留。
7. 12个原可见入口经原根重导出，两个内部助手及全部字段私有；所用会话选择和快照助手继续由原设置父域持有。
8. 修正两个账号RPC“修复活动会话”的歧义注释为精确租约撤销；补齐参数/返回双语说明，不更改实际会话策略。
