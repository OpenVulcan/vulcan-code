## 第十五阶段关键事实与行为审核

1. 通用设置保留刷新间隔30至86400秒校验、当前注册供应商身份校验、零优先级恢复继承、系统策略显式校验及固定五节点原子保存。压缩节点未变化时不使现有预算失效。所有入口保持原锁范围、候选预备、发布与失败补偿顺序。
2. 目录只汇总已验证Manifest路由；任一远端发现使账号为Dynamic，否则Fixed优先于Manual，无已验证目录为Unavailable。模型协议仅来自冻结model binding；受阻自定义模型继续使用现有解析器生成精确诊断，不修改绑定或探测备用协议。
3. 模型路由状态使用同一冻结支持目录、注册表与修订；保留完整protocol/source/rule/revision、协议变体和不可用原因。纯生成系统模型保持Provider扩展归属，不混入会话访问或内部LLM候选；Custom会话管理诊断仍可见。
4. 总快照只获取一次settings_catalog_snapshot；运行配置、注册表、三类目录、模板、目标、修订和模型默认值来自同一代际。持久修复诊断来自原配置，健康连接/目录来自可执行投影；用量、目录状态与错误限定于同一健康连接图，不回写用户配置。
5. 无目录/凭据或模型被禁用时，持久覆盖与模板决定仍保留可管理视图；组合键只由后端准确解析。凭据快照及其new整体迁移，保持秘密引用不泄漏、服务/凭据Profile显式错误及当前待验证状态。
6. 整体发布依然分普通模型协调与工具专用发布；媒体和会话模式只使用现行已保存全局后端选项。前十四阶段的秘密补偿、暂存取消、账号访问、精确pending/租约、内部用途与会话元数据边界均通过原314节点等价核验，不改变既有行为。
7. 根只保留4个稳定入口/通用访问节点，全部领域类型与构建方法实际归位。目录纯助手独立于总快照，避免候选层依赖整个快照；每个模块内部事务和紧密相关类型/方法不机械拆散。
