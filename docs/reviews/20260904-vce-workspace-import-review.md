# VCE 工作区迁移五轮审核记录

## 审核目标

确认 `vulcan-context-engine` 作为零运行时消费者迁入 VulcanCode 后，保持领域能力完整、公开契约可用、共同 AI 契约可选复用，并且不影响 VMM、不依赖 CBM、不提前接入存储、监听、工具或页面主链。

发现任何问题时立即修复，并将连续零问题轮数清零。只有连续五轮完整审核均未发现问题后才允许提交。

## 文件覆盖账本

- 根工作区：`Cargo.toml`、`Cargo.lock`、`workspace-hack/Cargo.toml`（只核对和暂存 VCE 自有差异）。
- VCE 清单和许可：`crates/vulcan-context-engine/Cargo.toml`、`LICENSE`、`README.md`。
- VCE 源码：`crates/vulcan-context-engine/src/*.rs` 全部模块。
- VCE 文档：`crates/vulcan-context-engine/docs/*.md`。
- VCE 黑盒测试：`crates/vulcan-context-engine/tests/*.rs`。
- 零接入边界抽查：service bootstrap、NativeToolCatalog、文件监听、VMM 与 VLDB 依赖图。
- Git 边界：暂存区和最终提交不得包含并行 VMM 或其他任务改动。

### 正式计数前发现与修复

1. 工作区 `unsafe_code = forbid` 拒绝独立仓库测试中的自制 RawWaker。已改用 `futures::executor::block_on`，VCE 不再包含 unsafe 块。
2. 工作区 `missing_docs` 暴露 47 个公开枚举字段缺少说明。已逐字段补齐英文在前、中文在后的文档。
3. 严格 Clippy 暴露 4 个可折叠条件和测试夹具中的 panic 式 `unwrap`。已折叠生产条件；测试模块以明确局部属性声明测试不变量失败策略，没有放宽生产代码 lint。
4. README 仍使用独立仓库全目录验证命令。已改为 `-p vulcan-context-engine` 的工作区命令并补充预接入文档入口。
5. `cargo hakari generate --diff` 当前显示的 `chrono`/`num-traits` 变化来自并行 VMM 清单；VCE 只复用既有 `futures`、`serde`、`serde_json`、`sha2`，未修改 `workspace-hack`。
6. 带依赖的全 feature Clippy 会被并行新增 `vulcan-ai-contract::HostAiError` 的 11 个 `result_large_err` 告警阻断；VCE 使用 `--no-deps` 后全目标、全 feature、`-D warnings` 为零问题，完整全 feature 编译与 90 项测试通过。该外部基线不计为 VCE 问题，也未越界修改。

以上发现均发生在正式连续审核计数开始前。下一轮从连续零问题轮数 0 开始。

### 第 1 轮：工作区拓扑与零消费者边界

- 覆盖：全部任务文件、workspace member/dependency、锁文件、反向依赖和全仓调用点。
- 证据：全 feature 90 项测试通过；VCE 全目标严格 Clippy 零问题；格式和 diff 检查通过；`cargo tree -i vulcan-context-engine` 只有 VCE 自身；全仓排除 VCE 目录后仅根 `Cargo.toml` 两处声明命中。
- 结论：未发现问题，连续零问题轮数为 1。

### 第 2 轮：刷新、索引与状态恢复

- 发现：全量 reconcile 会把未出现在文件系统扫描中的新建 explicit overlay 标记为删除，违反“未保存内容在宿主显式 remove 前保持权威”的契约。

- 计数：发现问题后连续零问题轮数清零；本轮不计入连续零问题轮次。

### 重启计数第 1 轮：刷新事务与状态不变量

- 覆盖：全文件复核，重点检查 workspace reconcile、Blob/Chunk 身份、索引准备、分批暂存、CAS 发布、失败中止、checkpoint 和版本化恢复。
- 证据：workspace 10 项、indexing 6 项、state 2 项、engine 16 项定向测试通过；含回归用例的全 feature 91 项测试通过；严格 Clippy 与格式检查通过。
- 结论：未发现问题，连续零问题轮数为 1。

### 后续检索轮发现：重排预算与 Chunk 身份

- 发现一：`rerank_candidate_limit` 只限制返回 `top_n`，实际仍把完整候选集发送给宿主重排能力，违反轻量化预算定义。
- 修复一：按稳定预排序截取候选后再调用重排；响应下标只允许引用实际发送集合，未发送候选继续按原排序追加。
- 发现二：宿主搜索响应只校验命中 ID 的 SHA-256 外形，没有校验该 ID 是否由 Blob、内容哈希和行范围生成。
- 修复二：搜索响应验证新增稳定 Chunk 身份重算比对；伪索引同步生成合法身份。
- 测试：新增重排载荷上限和伪造 Chunk 身份拒绝回归测试。
- 计数：发现问题后连续零问题轮数再次清零；先前 1 轮记录失效，下一轮重新从 0 开始。

### 正式计数前的扩展审查与修复

上一轮清零后继续对全部领域入口、宿主响应和公开可构造类型做扩展审查。以下问题均已修复，因此不计入连续零问题轮次：

1. 检索候选的来源顺序、重排后顺序和覆盖计算之间存在顺序语义不完整。现已保留稳定候选顺序，严格校验重排下标，并按重排结果追加未发送候选；覆盖计算改为顺序保持且使用饱和累计。
2. 来源优先级只识别单一 README 拼写，且路径大小写与分隔符未统一。现已统一路径规范化并识别本地化 README 名称。
3. 无内容变化的刷新仍保留已提交文件内容，造成状态对象长期持有无用源码。现已在提交后释放已索引的文件内容，并保持索引身份不变。
4. 工作区快照、管理快照和公开状态计数缺少交叉不变量校验。现已验证 generation、checkpoint、文件状态、统计计数、诊断计数和嵌入工作区快照的一致性，并将工作区错误显式投影为 VCE 状态错误。
5. Chunk 切分未完整约束换行预算，嵌入批次只校验单条上限而未校验批次总预算。现已统一字符预算，增加批次总和的受检计算与配置校验。
6. `PreparedIndex` 可由外部构造，完成阶段却信任其派生工件。现已在完成阶段根据已验证输入重新构造确定性产物并逐项比对，拒绝伪造或陈旧计划。
7. 精确符号响应只验证通用 Chunk 身份，未验证请求标识符、符号类型和出现位置共同生成的精确命中身份。现已重算符号出现身份并拒绝内容命中冒充精确符号命中。
8. 结构分析器和回退分析器的身份边界不完整。现已在各自分支校验真实分析器身份，保留主分析器与回退分析器的可区分来源。
9. 词法符号回退会把字符串、注释和 `return`/`await` 等表达式误判为声明，并遗漏单字符定义。现已增加保守清洗、表达式前缀排除和单字符声明回归覆盖。
10. 词法调用回退可能从注释或字符串构造虚假调用关系。现已使用同一保守代码清洗路径，并补充误报回归测试。
11. 路径检索响应只校验一般命中，未验证宿主返回的路径文档是否精确对应已请求 Blob。现已重构并比对规范化 `PathDocument` 身份，且保证每个 Blob 只产生一个路径回退候选。
12. Blob 详情缺少作用域身份和区间单调性校验。现已校验请求 Blob、规范路径、内容哈希、Chunk 身份和非递减源码区间。
13. 主机 Embedding 响应可返回 NaN 或无穷向量。现已在维度验证之外拒绝所有非有限分量。
14. 查询改写响应可超过 `max_rewrites`，AI 绑定公开字段也可被构造为空值。现已在宿主边界重新校验数量和全部绑定标识符。
15. 默认检索请求会主动启用 LLM 查询改写，与“AI 不应因多工具而被迫分散调用”的宿主策略冲突。现已默认关闭改写、保留重排，调用方需要时可显式开启。
16. RRF 在极端有限权重下使用 `f32` 中间值可能溢出，路径加权也可能生成非有限分数。现已使用 `f64` 累计并在投影时做有限饱和处理。
17. 刷新只要存在新增 Blob 就全局要求 Embedding，即使所有 Blob 均因大小限制不产生嵌入工作。现已只在确有嵌入计划时校验能力，允许仅提交元数据；空白可选 revision 也会被显式拒绝。
18. 查询分类把自然语言 PascalCase 单词误当成精确符号锚点，扩展名和关键词边界也过宽。现已分离符号锚点与上下文类型提示，约束扩展名、关键词和反引号标识符规则。
19. 查询分面先做空白归一化会丢失原始换行，且未覆盖英文句号与中英文标点。现已从原始查询拆分分面，大小写无关去重，只在至少两个有效分面时扩展，并保留文件名中的句点。

扩展审查后的验证基线：全 feature 共 126 项测试通过；VCE 全目标、全 feature、`--no-deps` 严格 Clippy 零问题；格式检查与文档测试通过。正式连续五轮审核仍从 0 开始。

20. 词法回退按 Chunk 独立清洗时，会丢失跨相邻 Chunk 延续的块注释、字符串、转义和单行注释状态，从而把超长物理行的后续片段误识别为符号。现已让词法状态在同一 Blob 的连续 Chunk 间传递，并在非连续范围、Blob 或路径切换时重置。
21. `SourceRange` 的行数与交叠计算使用普通加法，公开构造器允许的极端 `usize` 范围可触发溢出。现已改为饱和计算并覆盖最大边界。
22. `commit_checkpoint` 直接接纳外部可构造的检查点，可能在成员集合、链身份、版本或 generation 非法时先污染状态。现已改为返回显式错误，在任何写入前完成链、版本、成员和记录 generation 的事务式校验。
23. 查询分面把年份数字和无分隔符的连字符字面量误当作列表标记，查询改写又可接纳提示词回显、过长文本和越界编号。现已收紧列表分隔符，保留自然数字文本，并按 OCE 返回形态清洗、去重和限制改写。
24. AI 工具说明误称一次检索调用会刷新索引，且索引 Blob 的符号字段误称由宿主提供，与当前“宿主维护生命周期、VCE 生成分析产物”的职责不符。现已修正文档与工具描述，不改变公开载荷。
25. 精确符号命中和结构分析只依赖宿主声明的标识符，未验证它是否以完整标识符边界真实存在于对应 Chunk。现已校验路径、Blob、Chunk、范围和标识符边界的一致性，并拒绝子串冒充和分析器虚构符号。
26. Symbol 意图会无条件把定义端点提升到结果首位，而 OCE 的实际路径只在查询明确包含位置或定义提示时执行端点提升。现已将该决策固化在 `QueryPlan` 并由检索执行，普通符号语义查询不再被强制重排。
27. `EmbeddingSpace` 允许 `Some("   ")` 形式的空物理指纹穿过配置、状态、索引绑定和宿主响应校验，无法作为稳定兼容身份。现已统一要求可选指纹只能缺省或非空，并将字符窗口上界改为饱和加法。

上述问题均发生在正式计数重新开始前；任何一项都使此前计数无效。下一轮仍从连续零问题轮数 0 开始。

28. 超长单行切块使用 OCE 的行粒度 occurrence ID，同一行内两个完全相同的片段会生成重复 Chunk ID，使合法源码在暂存校验时失败。最初的合并修复会丢失真实出现位置并破坏跨片段字符串/注释词法状态，已在正式计数前撤回。现仅对行内切分片段把首行 Unicode 字符偏移加入扩展身份，并将偏移贯穿 Chunk、SearchHit、Symbol occurrence、宿主响应与结构分析校验；普通 Chunk 仍保持 OCE 原始 ID。
29. 纯元数据文件观察在新旧 `mtime_ns` 都缺失时，仅凭大小相同就复用旧 Blob，同长度改写会被错误跳过。现已要求复用必须有可靠时间戳；否则宿主必须提供源码或预计算 Blob 身份。
30. 独立 `IndexingEngine` 只校验切块预算，且公开可构造的 `PendingIndex` 可绕过文件大小、NUL、generation、路径和 Blob 准入。现已统一构造预算，并在准备、结构准备和完成阶段重新校验待处理记录；generation 零被保留为空状态，不能进入索引。
31. 查询改写清洗会无条件删除开头数字、按大小写重复召回，并在 `max_queries = 1` 时先越界追加再停止。现已只删除带合法分隔符的编号，保留年份查询，使用大小写无关去重，并在追加前执行预算检查。
32. 源码命中的文本行数可与声明范围不一致，渲染时可能输出越界行号；合成 Path 文档又不能套用源码行数规则。现已为源码 Chunk、宿主 dense/exact/fallback 命中增加精确行数不变量，为 Path 文档保留显式特例，并采用饱和行号渲染。
33. 管理分页可返回与请求相同的游标造成页面循环，文件/Blob 行可报告 generation 零或向量数大于 Chunk 数，预览也可为无意义空串。现已在类型化管理响应边界统一拒绝这些状态。
34. `validate_structure_analysis` 只校验符号，独立调用可接纳重复 Chunk、合成 Path Chunk、非规范 Blob、跨文件集合或自相矛盾身份。现已在结构结果入口完整校验源码 Chunk 集合、分析模式和来源唯一性。
35. 统一 AI 能力不可用时，查询向量和路径向量都会被误报为文档向量用途。现已用实际 `VceAiPurpose` 贯穿能力校验，便于 VulcanCode 的统一路由、配额和诊断。
36. 重试计数与配置都达到 `u32::MAX` 时，饱和加法会永久保持可重试状态。现已用受检加法判定是否存在下一次重试，整数耗尽时明确进入终态并清理暂存。

第二轮扩展审查后的最新基线：全 feature 共 149 项测试通过；全目标、全 feature、`--no-deps` 严格 Clippy 零问题。由于本节仍发现并修复问题，正式连续五轮审核尚未开始，计数保持 0。

37. workspace 隔离测试通过固定向上两级目录寻找根目录，使独立 crate 验证错误落到 `D:\`。现改为从 `CARGO_MANIFEST_DIR` 调用 Cargo，由 Cargo 权威发现外围 workspace，不再依赖检出深度。
38. 同行 Chunk 的词法连续性只比较行号，乱序、重叠或有缺口的结构片段也会错误继承字符串/注释状态；相邻行也未证明上一片段覆盖到换行。现已要求同行 Unicode 偏移精确首尾相接，相邻行要求当前偏移为零且前一片段携带换行，并按偏移稳定排序。
39. VMM 原生集成冻结了共同 Host AI 语义：进程内消费者应使用 `InternalBackground`，不能沿用已删除 sidecar 的 `external_service`，且配置变化后不得缓存陈旧 capability handle。VCE 不构造 caller context/handle，现已把宿主注册与 snapshot 刷新责任写入 README 和预集成/功能契约，并确认领域引擎每次操作重新读取当前能力快照。
40. 偏移身份只进入去重后，同一超长行的不相交片段仍会被行号重叠规则互相排除，路径首 Chunk、稳定排序、管理详情和最终渲染也无法表达精确位置。现已在同行覆盖计算中使用字符区间，把偏移纳入排序和路径回填键，为管理 Chunk 行公开偏移，并在非零时渲染字符位置。
41. 路径规范化先执行 `trim()`，会把合法的首尾空格文件名静默映射到另一文件，违背“原路径参与 Blob 身份”的规则。现已只把真正的空字符串视为空路径，保留路径中的首尾空格原文。
42. 超长行切分通过普通加法表达下一字符边界；虽然当前分支受源文本总字符数约束，边界安全依赖隐式先决条件。现已改用饱和加法并增加极端预算回归，使实现直接表达无溢出的边界语义。
43. 工作区显式覆盖保留与向量聚合依赖先验布尔/集合校验后使用 `expect`，逻辑虽应成立，但公开输入和未来重构可把契约错误升级为进程 panic。现已改为结构化 `Option` 分支与显式 `EmbeddingError`，生产路径不再包含 panic 式提取。
44. 暂存中止请求携带 generation，但回执没有 generation，VCE 只能确认 refresh 名称，无法证明宿主清理的是同一代事务。现已把 generation 加入 `IndexAbortReceipt` 并参与严格回执校验。
45. 查询信号只校验 ASCII 词项的前边界，`user_config` 中的 `use`、`callback_handler` 中的 `call` 等前缀会被误当作引用或调用动词。现已同时要求尾边界，避免代码标识符前缀改变查询意图。
46. 通用 `VceAiPort` 响应只校验声明的向量空间和分段 ID；内容索引稍后会检查聚合维度，但查询向量与路径向量可把错误维度直接传给存储，而且非 `host-ai-contract` 适配器的非有限值没有统一边界。现已在所有向量用途的公共响应入口逐向量校验物理维度和有限值。
47. 当 VCE 配置的物理模型指纹为 `None` 时，向量响应可携带任意 `Some` 指纹并在后续调用中变化，而索引绑定仍固定为 `None`，可能把不同模型向量混入同一空间。现已要求响应与配置的可选指纹完全相等；未知指纹不再作为通配符。

48. ASCII 词项改为双边界匹配后，分类器仍只登记 `use` 等词根，导致合法的 `used`、`references`、`imported` 等完整英语词形不再命中引用意图。现已显式登记支持的完整词形，既不恢复标识符子串误判，也保留原有自然语言查询能力。
