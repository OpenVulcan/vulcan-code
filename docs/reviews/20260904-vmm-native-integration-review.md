## 实现期发现与修复

### F-001 启用持久化与自动绑定顺序相反

- 影响：首次启用时自动绑定会读取到尚未启用的旧配置并失败。
- 修复：先完整预检绑定计划，再持久化启用状态，然后逐项目执行并聚合失败；无论绑定结果如何都刷新快照与项目设置事件。
- 状态：已修复并有配置单元测试。

### F-002 原生删除确认重试使用新命令 ID

- 影响：删除已进入恢复账本后，前端重试会生成新 ID，导致无法读取原删除预览并完成后续配置写回。
- 修复：同一预览生命周期固定复用命令 ID；服务端删除重放允许目录已删除并返回原预览。
- 状态：已修复并有前端请求稳定性测试。

### F-003 仅有连带查询关联时未要求删除确认

- 影响：没有 owner、但仍被其他项目连带查询的记忆项目可能未经明确确认被删除。
- 修复：owner 或 linked 任一非空均要求解除关联确认，并分别显示影响项目。
- 状态：已修复并有前端测试。

### F-004 外置首次配置在启用前调用受启用状态约束的管理能力

- 影响：新外置 gRPC 配置会在保存前被旧的禁用状态阻断。
- 修复：快速配置阶段只执行连接健康与远端 catalog 校验，不再提前调用要求已启用的管理能力。
- 状态：已修复，待最终流程复核。

### F-005 Rerank 响应没有验证候选身份与排序语义

- 影响：Provider 返回重复索引、错误候选 ID、非法分数或逆序分数时仍可能被上游消费。
- 修复：公共契约增加请求关联校验，并由 ConfiguredInference、HostAiPort mock 与 VMM 适配统一使用。
- 状态：已修复并通过契约与服务测试；契约变化已通知 VCE 任务。

### F-006 普通 Core 写入未进入跨 SQLite/LanceDB 恢复账本

- 影响：向量写入后、关系快照提交前中断会产生未记账副作用，不满足 Core mutation 的耐久幂等与恢复要求。
- 修复：所有已提交的普通 `MutationBatch` 使用其稳定 operation ID、幂等键与请求指纹进入同一恢复账本；向量空间元数据在账本准备前耐久化，避免重启恢复依赖进程内 Embedding 指纹。
- 状态：已修复，待补充和执行最终恢复验证。

### F-007 外置首次配置没有向预检动作传递临时连接

- 影响：尚未持久化的 gRPC 地址与凭据不能用于首次健康检查和项目目录加载，导致外置配置无法完成。
- 修复：快速配置预检把连接字段作为请求级临时载荷传递，确认保存前不写入全局配置。
- 状态：已修复并通过前端投影测试。

### F-008 外置固定项目只保存路径而未冻结远端项目 ID

- 影响：远端项目改名后可能失去绑定，违背按 ID 关联要求。
- 修复：固定项目与自动创建项目均在绑定完成后把远端 `project_id` 写入对应 VulcanCode 项目层；名称仅用于展示。
- 状态：已修复并通过服务测试。

### F-009 项目设置缺少创建、绑定与原生连带查询入口

- 影响：自动绑定失败后用户无法按需求在项目设置中恢复，也无法配置 Native 的唯一归属与额外召回项目。
- 修复：项目设置按后端分别提供原生已有/新建绑定、连带查询，以及外置已有项目/自定义三节点创建绑定。
- 状态：已修复并通过前端类型检查与服务测试。

### F-010 Native PostAction 分析是进程内即发即弃任务

- 影响：进程退出或暂时性 Provider 失败会永久丢失已接受回合的后台分析。
- 修复：新增宿主 SQLite 耐久队列、请求指纹、登记/回合原子绑定、启动恢复、有界指数重试和完成后敏感载荷擦除。
- 状态：已修复并通过队列、登记与恢复测试。

### F-011 HostAI 最大执行时长没有形成每次物理请求截止时间

- 影响：长生命周期注册可能使用一次性绝对截止时间，或者配置的最大执行时长完全不约束实际调用。
- 修复：注册句柄不保存一次性绝对期限；每次物理分派用当前时间加 `max_execution_duration_ms`，再与调用上下文及调用方绝对期限取最早值。
- 状态：已修复并通过期限选择测试；语义已通知 VCE 任务。

### F-012 外置固定策略错误地锁死全部启用行

- 影响：用户不能在“默认固定项目”基础上，把个别未绑定项目改成创建独立项目或绑定其他已有项目。
- 修复：全局固定目标只作为行默认值；服务端逐行校验并保留明确覆盖，前端仅物化仍使用默认占位符的行。
- 状态：已修复并通过前后端绑定计划测试。

### F-013 Native 迁移确认没有展示目标迁移前后计数

- 影响：虽然后端预检已返回来源、目标当前值和迁移后值，界面只展示来源计数，用户不能完整评估迁移结果。
- 修复：确认卡同时展示来源当前、目标当前和目标迁移后三组会话、记忆、项目画像与向量计数，记录明细继续可展开查看。
- 状态：已修复并通过前端全量测试。

### F-014 维护幂等键没有绑定完整确认载荷

- 影响：同一命令 ID 改用其他预检版本、指纹或确认标志时，可能错误重放旧结果。
- 修复：删除、迁移、清空的账本类型均纳入项目 ID、预检版本、迁移指纹和风险确认字段；只有完全一致的重试可以重放。
- 状态：已修复并通过维护定向测试。

### F-015 `--all-targets` 暴露复制 Core 测试导入缺失

- 影响：普通库编译通过，但测试目标缺少 `OperationId`，身份分隔符测试还引用了已经归属 contracts 的私有函数。
- 修复：测试模块显式导入公共 ID；分隔符碰撞断言迁回身份派生算法所属的 contracts 测试。
- 状态：已修复；全工作区 `cargo check --workspace --all-targets` 无警告通过，Core 221 项测试通过。

### F-016 后端模式仍可被项目或会话层覆盖

- 影响：手工或残留项目配置可以破坏 Native/ExternalGrpc 全局互斥，并错误解释项目 ID。
- 修复：后端模式只取全局显式选择；仅在全局选择缺失且全局 gRPC 目标非空时保留明确旧配置识别。
- 状态：已修复并新增全局唯一来源测试。

### F-017 外置固定模式没有校验逐行覆盖完整性

- 影响：全局固定目标有效时，某一行的空创建名称或空已有项目选择仍能进入确认步骤，只能由后端拒绝。
- 修复：外置固定模式同时要求全局固定目标和所有逐行决定完整。
- 状态：已修复并通过前端 lint 与全量测试。

### F-018 项目维护未与耐久 PostAction 队列建立并发边界

- 影响：来源项目仍有待分析作业时执行迁移、清空或删除，旧作业可能找不到已移动回合、在清空后回填，或永久重试。
- 修复：全部原生项目功能调用共享读屏障，迁移/清空/删除及归属绑定、解绑、连带召回变更使用写屏障；维护在屏障内拒绝仍有 `intaking/ready` 作业的目标项目，待后台分析完成后必须重新预检。
- 状态：已修复并新增队列载荷作用域一致性测试；待最终并发与全量回归复核。

### F-019 项目归属与连带召回配置分两次提交

- 影响：项目设置先修改写入归属、再修改连带召回；第二次提交失败会留下非用户预期的部分配置，两次提交之间也可被功能调用观察。
- 修复：新增宿主数据平面单事务访问配置接口，在同一个 `BEGIN IMMEDIATE` 事务中写入归属并整体替换有序连带召回；维护层使用单个写屏障，项目设置改为一次动作提交完整配置。
- 状态：已修复并新增事务脚本、重复链接及所有者自链接校验测试；待全量回归复核。

### F-020 个别绑定失败后普通全局配置无法再保存

- 影响：已启用后端只要仍有未绑定项目，任何不带绑定计划的高级设置保存都会被完整覆盖校验拒绝；外置端点本身需要修正时会形成“先绑定才能保存、先保存才能绑定”的死锁。
- 修复：仅在首次启用、活动后端切换或调用方明确提交重试计划时执行全量未绑定对账；同一已启用后端的普通全局编辑允许空计划，既有绑定失败继续由项目设置重试。
- 状态：已修复并新增启用、切换、显式重试与普通保存判定测试；待全量回归复核。

### F-021 已启用状态下切换后端可绕开或无法进入项目对账界面

- 影响：高级设置可直接编辑全局后端，但普通保存不携带逐项目绑定计划；服务端若放行会绕过切换对账，拒绝后总览又没有重新配置入口，用户无法完成受控切换。
- 修复：高级页检测后端变化并转回完整快速配置流程；已启用总览新增“重新配置记忆后端”入口，只有同一后端的普通参数编辑继续直接保存。
- 状态：已修复并新增后端切换门控测试；待前端全量回归复核。

### F-022 LLM 启动排队阶段未持续观察宿主取消

- 影响：Embedding 与 Rerank 会在等待调度期间响应取消，但 LLM 仅在调用前检查一次；若阻塞在启动锁或并发许可，取消不能及时结束等待。
- 修复：LLM 启动 future 与 `HostAiCancellation::cancelled()` 使用同一有偏竞争；尚未发布执行 ID 时取消会直接终止启动，已同时完成时优先接收执行 ID并由后续等待路径完成协作取消。
- 状态：已修复；待 HostAI 全量回归复核。

### F-023 新建登记的默认绑定可能覆盖并发或预存的稳定绑定

- 影响：项目新建登记与自动绑定之间若已经存在中央 Native 所有者或项目层 External `project_id`，无条件应用全局默认会覆盖更早完成的显式选择；同一路径的普通删除后重加实际走工作区恢复分支，不触发该自动绑定路径。
- 修复：改为“已有稳定绑定优先”。Native 在同一个项目变更与功能写屏障内检查现有所有者，只在确实未绑定时应用固定或按 tag 创建的默认；External 在应用默认前复用项目层稳定 ID，且复用提示不依赖远端管理面可用性。
- 状态：已修复并新增外置 ID 复用通知测试；待原生绑定生命周期与全量回归复核。

### F-024 启用对账可能覆盖并发完成的项目级绑定

- 影响：启用向导在预检未绑定集合后才逐项执行；若项目设置在两阶段之间完成手动绑定，Native 与 External 的默认动作会覆盖较新的显式选择，违背“默认只作用于未绑定项目”。
- 修复：Native 计划执行改用受同一项目变更守卫保护的 `if_unbound` 方法；External 自动写入在项目配置文件事务锁内再次读取稳定 ID，仅为空时写入，并把并发显式绑定作为最终结果保留。
- 状态：已修复；待绑定并发语义与全量回归复核。

### F-025 原生模式仍可通过保留的外置配置执行 gRPC 动作

- 影响：切换到 Native 后会按需求保留 External 配置，但普通 gRPC 动作入口没有校验当前全局后端，因此旧端点仍可能被调用；请求级临时连接也可被构造为删除、迁移等非配置动作，破坏全局二选一边界。
- 修复：持久化外置动作现在必须处于全局 ExternalGrpc 模式；请求级临时连接仅允许健康、目录、用户解析和项目确保四项快速配置动作。Native 维护入口改为直接读取全局模式，不再借用外置动作上下文。
- 状态：已修复并新增后端门禁与临时动作白名单测试；待外置全量回归复核。

### F-026 非活动 Native 初始化失败会阻断 External 或禁用模式启动

- 影响：宿主此前无条件以致命方式初始化 Native SQLite、LanceDB、Core 恢复和待分析工作器；即使全局选择 ExternalGrpc 或记忆禁用，本地目录/存储故障也会阻断整个 VulcanCode，两个后端未形成故障隔离。
- 修复：Native 组件改为独立可降级启动单元。仅当“全局已启用且选择 Native”时初始化失败才终止服务启动；ExternalGrpc 或禁用状态记录诊断并继续运行，后续启用 Native 会因维护运行时未就绪而明确失败。
- 状态：已修复；待启动分支编译、回归与最终故障注入复核。

### F-027 Native PostAction 提示载荷仍暴露 gRPC 兼容命名

- 影响：内置 Core 已直接嵌入 VulcanCode，但 PostAction 输入及提示模板仍把近期直接写入命名为 `recent_grpc_memory_writes`，使内部提示契约继续依赖已移除的传输概念。
- 修复：内部载荷与中英文模板统一改为 `recent_direct_memory_writes`，准确表达宿主直接调用或工具写入；不改变公共 HostAI 契约或外置 gRPC 协议。
- 补充修复：同步更新嵌入资源清单的逐文件长度、SHA-256 以及资源契约测试冻结的总字节数，避免提示模板与完整性身份脱节。
- 状态：已修复；Core 配置 47 项、复制 Core 合计 221 项及服务内核 857 项测试通过。

### F-028 HostAI 公共错误体内嵌大型 Provider 错误

- 影响：`HostAiError` 直接内嵌完整 `AiExecutionError`，使每个返回该错误的 Port `Result` 错误分支达到约 784 字节，并导致全工作区严格 Clippy 的 11 个 `result_large_err` 失败。
- 修复：把可选 `route` 与 `provider_error` 分别改为 `Option<Box<ExecutionRouteSnapshot>>` 和 `Option<Box<AiExecutionError>>`；保留字段名、错误语义和 Serde JSON 形状，调用方继续通过解引用读取精确路由与 Provider 诊断。
- 设计边界：大型可选载荷盒装后错误体约 184 字节；剩余尺寸来自必须冻结的 request/operation/effect/command 等稳定关联字段，因此在 `host.rs` 局部说明并豁免 `result_large_err`，不把全部 Port 错误改为双重盒装。
