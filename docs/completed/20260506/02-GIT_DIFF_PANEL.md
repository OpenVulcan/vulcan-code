# 任务目标

在当前 Rust + iced GUI 项目中实现一个可视化 Git Diff 面板，使用左侧“工作区入口”作为目标目录输入源，点击扫描后在中间工作台载入结构化 Diff 结果，展示效果尽量贴近参考图中的“文件列表 + 文件头 + Hunk + 彩色变更行”模式。

# 详细执行步骤

1. 评估当前 GUI 结构与已有纯文本 Diff 载入链路，确认最合适的渲染区域与数据流入口。
2. 设计 Git Diff 的内部数据模型，包括文件级、Hunk 级与行级结构，并实现统一 diff 文本解析逻辑。
3. 将当前扫描逻辑从纯文本预览升级为结构化结果输出，同时保留错误处理与非 Git 目录提示能力。
4. 在中间工作台实现 Diff 面板组件，至少包含文件头、增删统计、Hunk 标题、行号列与增删背景色渲染。
5. 对照参考图优化信息层级与可读性，使其具备“先验证体验，再继续增强”的基础展示效果。
6. 执行格式化与编译验证，回写执行总结并完成计划归档。

# 技术选型

- Git 数据来源：继续优先使用本地 `git` 命令行输出，避免在当前阶段引入新的核心依赖，降低方案切换成本。
- Diff 解析方式：实现项目内的轻量 unified diff 解析器，先覆盖 `diff --patch` 常见结构，再为后续行内高亮和文件折叠留扩展口。
- UI 组件：基于 iced 原生 `scrollable`、`container`、`row`、`column`、`rule`、`button`、`text` 组合渲染，保证与当前工作台结构一致。
- 视觉策略：首版优先贴近代码托管平台常见审查面板，突出文件级摘要、Hunk 分段与行级增删背景色，而不是一次性实现完整编辑能力。

# 验收标准

- 输入一个 Git 仓库目录并点击扫描后，界面中能展示结构化 Diff 面板，而不是单一纯文本块。
- 面板至少具备文件路径、文件级增删统计、Hunk 标题与增删改行内容展示。
- 行内容具备明显的增删视觉区分，包含行号或可替代的定位信息。
- 非 Git 目录、空目录、无差异目录等场景都有明确提示，不出现空白或崩溃。
- 变更后的 GUI 代码能通过 `cargo fmt` 与 `cargo check -p vulcan-code-gui`。
