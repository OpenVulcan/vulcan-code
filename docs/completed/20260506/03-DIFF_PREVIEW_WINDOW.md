# 任务目标

将当前主工作台中的 Git Diff 测试区独立为一个单独窗口，通过按钮点击打开或聚焦该窗口，使 Diff 审查面板能够脱离主布局单独调整结构，同时继续复用现有工作区扫描与 Diff 数据状态。

# 详细执行步骤

1. 评估当前单窗口运行模型与 Diff 面板嵌入位置，确认多窗口改造所需的运行时切换点。
2. 将应用运行方式从单窗口 `application` 调整为支持多窗口的 `daemon + window::open` 模式。
3. 新增主窗口与 Diff 预览窗口的生命周期状态，补齐打开、聚焦、关闭与退出逻辑。
4. 将主工作台中的 Diff 区域替换为“独立窗口启动卡片”，保留摘要与状态说明。
5. 将结构化 Diff 审查面板迁移到独立窗口中，并保留重新扫描工作区的入口。
6. 执行格式化与编译验证，完成执行总结并归档计划文件。

# 技术选型

- 多窗口运行时：使用 iced 当前官方示例对应的 `daemon` 与 `window::open` 能力，避免引入额外窗口管理层。
- 状态共享策略：继续由单一 `VulcanWorkbench` 状态持有 Diff 数据，让主窗口与 Diff 窗口共享同一份扫描结果。
- 交互策略：主窗口负责工作区与整体控制，Diff 窗口负责结构调试与视觉调整，减少布局耦合。
- 窗口管理：通过 `window::Id` 跟踪主窗口与 Diff 窗口，支持重复点击时聚焦已有窗口而不是无限创建新窗口。

# 验收标准

- 主工作台中不再内嵌完整 Diff 审查面板，而是显示一个可打开独立窗口的入口区域。
- 点击“打开 Diff 窗口”后可以出现专门的 Diff 预览窗口，再次点击时会聚焦已有窗口。
- 独立 Diff 窗口中能继续展示当前结构化 Diff 面板，并支持重新扫描工作区。
- 关闭窗口后的状态能正确回收，不会导致程序进入异常状态。
- GUI 代码可通过 `cargo fmt` 与 `cargo check -p vulcan-code-gui`。
