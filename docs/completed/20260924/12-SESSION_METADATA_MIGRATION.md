# 会话元数据自动升级

## 目标

优先修复旧会话缺少 `business_hook.binding.observes_user` 导致配置无法载入的问题；建立以版本号驱动的元数据升级入口，供后续字段变动复用。代理交互遗漏修复继续保留在第 11 号计划。

## 实施步骤与技术选择

1. 元数据版本独立演进，当前版本从 1 升为 2；运行状态和压缩文件仍使用各自的现有版本。
2. 所有元数据读取统一经过版本识别和逐版本迁移；未来版本、损坏数据和未知旧格式明确拒绝，不能用默认值掩盖问题。
3. 首个迁移只补充缺失的用户观察标记；根据绑定对应的原始回合事件判定，代理任务不触发用户记忆。已存在的标记原样保留并验证。
4. 升级在独立内存副本完成，类型及归属验证通过后，保存原始字节备份，再原子替换元数据。失败保留原文件；重读幂等。
5. 正常写入和升级发布共用文件级锁，取得锁后重读，避免升级覆盖并发的新状态；不改变会话修订、配置、正文或完成状态。
6. 显式供应商能力重建仍只修改其授权子树，经过同一迁移算法，不因修复能力而绕过版本校验。
7. 添加定向迁移、失败保护、重读及并发测试；补充未来开发规范与执行记录，独立提交。

## 验收标准

- 旧用户回合、代理任务回合、空绑定及已包含字段的旧版本都能正确处理。
- 当前版本不写盘、不重复备份；未来版本和无法确认来源的旧数据不覆盖。
- 升级后的正常加载及配置读取通过；升级失败不会破坏旧元数据。
- 文档明确新增迁移的步骤、版本权威和必要测试，并说明应用更新后才运行新的升级逻辑。

## 决策记录

- 用户本次明确要求自动升级，替代先前未发布阶段不兼容历史数据的约定。
- `observes_user` 涉及记忆观察权限，不采用全局默认 `true` 或字段缺失即猜测的处理。
- 自动升级只转换已定义的元数据版本，不把任意历史缺失字段都补为空对象。

## 执行变更总结

### 核心修复与调整概述

已建立模式 1 到模式 2 的自动迁移，修复缺少 `observes_user` 的读取错误。当前版本只读取；旧版本经来源判断、类型验证、原字节备份和原子发布后返回。普通写入和升级共享文件锁。已补充以本次迁移为样例的开发契约及必读入口。

### 文件变更清单

- 新增：`crates/vulcan-workspace-store/src/workspace_store/session_v1/metadata_migration.rs`。
- 新增：`crates/vulcan-workspace-store/src/workspace_store/session_v1/tests/metadata_migration.rs`。
- 新增：`docs/contracts/session-metadata-migrations.md`。
- 修改：`crates/vulcan-session-core/src/v1/config.rs`，统一版本常量及新建会话版本。
- 修改：存储层 `documents.rs`、`layout.rs`、`mod.rs`、`tests.rs`，接入迁移、共用路径和更新契约断言。
- 修改：`AGENTS.md`，增加元数据变更的按需契约入口。
- 删除：无。

### 关键代码调整详情

- `read_metadata` 统一接入迁移入口；取得锁后重新读取，不拿旧快照覆盖并发发布。
- `migrate_v1_to_v2` 只转换已知字段形状；缺失标记的绑定按精确起始事件判断，代理任务不获得用户记忆观察权限。
- 版本顺序分派与发布分离；显式能力重建复用同一转换算法及原字节备份。
- 备份冲突、字段损坏、未来版本和来源不明均保持原元数据不变。
- 新增可选真实会话副本验证，默认忽略，必须显式提供目录才运行；不在仓库保存用户会话数据。

### 验证与注意事项

- 迁移定向测试：8 项通过，真实快照测试默认忽略。
- 用户所报会话的临时副本：迁移及完整加载通过，原 metadata 字节未改变。
- 会话存储正确性回归：73 项通过、2 项显式验收测试忽略。
- 元数据模型测试：2 项通过；工作区存储所有目标编译检查通过。
- 扩大范围时遇到已有约九万条记录性能测试长时间执行，已停止自有测试进程并从正确性回归排除该性能项；同时启动的重链接曾因测试程序仍运行而失败，停止后重试通过，不属于迁移逻辑失败。
- 不自动重启用户 Core。新版本编译并运行后，首次读取旧会话将自动升级。此次未修改实际会话、供应商配置及并行界面修改。
- 第 11 号代理交互遗漏修复仍在进行，不将其计为本次元数据修复已经完成。
