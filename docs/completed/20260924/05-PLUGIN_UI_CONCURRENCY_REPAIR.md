# 插件页面切换阻塞修复方案

## 一、状态与目标

- 日期：2026-09-24；当天任务序号：05。
- 状态：已完成；实现、定向回归、三平台上游验证、实际页面测量及重连复核完成。未执行的平台与并行测试边界见最终记录。
- 范围：VulcanCode 插件界面请求生命周期、插件持久运行时调度，以及 LuaSkills System lease 工作目录隔离。
- 不兼容历史应用数据：当前应用未发布，不新增旧数据迁移、旧字段别名或双轨宿主适配。
- 并行边界：不修改其他会话正在调整的基础控件、视觉样式、供应商配置、VCE 模块。

### 目标

1. RTK 统计、使用统计和 Context7 设置读取能够并发推进；慢插件不能占用其他插件的执行入口。
2. 快速切走、返回时复用相同的在途只读请求，不因重新挂载而反复执行相同统计。
3. 初始化、停用、更新、超时和取消均有明确归属；实际执行结束前不能提前释放 VM 的独占权。
4. 修复不依赖扩大线程池或 VM 池，也不依赖增加界面动画掩盖等待。
5. 保存准确的阶段耗时与回归证据，分别证明源代码性质、自动化并发性质和实际界面改善。

## 二、已查证的现状与基线

### 2.1 现场测量

在本机运行中的 Debug 页面，使用浏览器网络事件记录请求发出到收到响应的耗时。未读取或输出凭据，未执行 Context7 的联网测试。

| 再次进入 RTK | statistics-get | 3.83 秒 |
| 使用统计单独进入 | dashboard-get | 84 毫秒 |

### 2.2 调用与占用顺序

页面挂载 → 插件 SDK invoke → HTTP RPC → service_invoke_plugin_action → invoke_action → 获取持久 UI 运行时 → 插件 operation_gate → spawn_blocking → LuaEngine 读锁 → System lease → 进程级 cwd 锁 → Lua 与同步宿主调用 → 返回结果并释放执行资源。

确认的问题：

1. 普通技能池不是本次瓶颈。System lease 使用专用 VM；宿主引擎读锁允许不同租约进入。
2. LuaSkills 0.5.7 在整段 System Lua 执行期间持有进程级 cwd 锁；外部进程与数据库等待发生在该锁内部。
3. System lease 即使省略 cwd，也会解析为包根并保存 Some(cwd)。单删宿主字段不能解决问题。
4. 所有 UI 插件共用初始化锁，而且命中已有运行时也先等待该锁。创建或排空一个慢租约会扩大阻塞范围。
5. 插件切走只忽略旧页面结果，没有取消实际 Action。RTK 与使用统计的在途去重保存在组件实例内，重新挂载后失效。
6. RTK 设置页一挂载就读取统计；statistics-get 顺序执行两个 gain 命令，各自超时 5 秒。旧组件卸载后，已成功完成的统计不会写入模块缓存。
7. Lua 指令超时通过指令钩子检测，不会主动唤醒等待中的互斥锁，也不能直接打断正在运行的同步宿主函数。

## 三、设计决策与原因

### 决策一：修复 System lease 的路径模型

采用租约级逻辑工作目录，插件执行不再修改宿主进程工作目录。cwd 仍存在并保留授权校验，其含义变为该租约解析相对路径的基准。

原因：cwd 是进程属性，增加 VM 或线程无法隔离它。只缩短加锁区间、先切目录后放锁，仍会造成跨插件路径串用。当前插件进程解析已经产生明确的可执行文件和子进程 cwd，具备保留行为并去掉宿主 chdir 的基础。

实施要求：

- 在 LuaSkills 上游正式源码中调整 System lease；具体仓库位置与维护分支由实施前查明，不把注册表源码当作工作区。
- 路径上下文唯一归属租约。包根、授权工作区、目录对象身份校验继续保留。
- 审核所有相对路径入口：受管文件 API、io 兼容层、loadfile/dofile、require 搜索器、动态库路径、进程与受管 Node/Python 运行时。
- 文件访问按租约目录解析为绝对路径；模块搜索路径使用已授权的绝对根；子进程通过 Command.current_dir 设置自己的工作目录。
- 原生扩展和 FFI 若依赖进程 cwd，必须明确修正其调用参数或放到独立受管进程。不能假定 Lua 包装能拦截原生代码的全部相对路径访问。
- 禁止在 System lease 中直接切换宿主进程 cwd；无法按该契约运行的入口必须明确拒绝，不能静默退回全局锁模式。
- 普通文件型 runLua 仍可能临时改变进程 cwd，因此 System lease 的依赖装载和宿主回调也必须完全不依赖当时的进程 cwd；不能只移除 eval 周围的锁。
- 同一 System VM 仍保持单次执行独占，不允许为追求并发同时调用同一 Lua 状态。
- 上游修复需要正式版本及依赖升级；是否保留其他上游使用者的旧行为由上游契约决定。VulcanCode 只依赖一个明确的新版本和新语义，不做协议探测。

未选用插件独立进程作为当前默认方案：它能隔离进程 cwd，但需要新增 Lua 宿主回调 IPC、生命周期与故障恢复，涉及范围更大。若原生扩展审计证明无法实现逻辑路径隔离，应记录证据后另行设计进程隔离方案，不能宣称已完成本方案。

### 决策二：持久运行时按插件和用途同步

- 初始化键为插件标识加运行时用途，Hook 与 UI 保持原有隔离。
- 全局注册表锁仅用于短时间查找、发布和移除记录，不跨 await，不在锁内执行 Lua、读取大文件或等待关闭。
- 同一键使用稳定的运行时槽位，包含代次、初始化状态、运行时句柄与生命周期同步对象。
- 命中当前代次且可运行的句柄直接复用；同一键的并发首次调用等待同一次初始化。
- 初始化完成前重新检查插件启用状态和代次。失效的初始化结果必须排空并关闭，不能重新插回注册表。
- 停用或更新先关闭该键的入场资格，再排空执行；不得让新初始化越过正在进行的停用。
- 移除记录必须比较当前槽位身份，不能让旧任务删除新代次记录。
- 不以代次直接创建无限增长的锁表；槽位在生命周期结束且无人持有时回收。

保留现有租约容量限制，并对待入场请求设置有界队列；取消、超时的排队项立即移除。解除跨插件锁不等于无上限创建阻塞任务。具体容量以现有权威限制及压测为依据，所有引用共用一个定义。

原因：已有 UI 请求不该被别的插件初始化拖住，同时需要避免初始化、关闭、重新启用之间出现重复租约和错误复活。

### 决策三：请求生命周期由宿主管理，组件只订阅结果

新增宿主侧插件查询协调器，保存在页面组件之外。插件模块缓存继续负责代码加载，查询协调器负责业务请求，两者不能混为一类缓存。

插件 Action 增加明确的只读与变更分类，字段名称在实现时统一落入清单类型和校验，不按 action 名称后缀猜测。现有所有调用方同步调整，不保留旧格式自动推断。

| Action 类型 | 切走后的行为 | 再次进入 |
| --- | --- | --- |
| 相同参数的在途只读请求 | 移除页面订阅，保留请求直至有界完成 | 复用同一个请求 |
| 已被新筛选替代且尚未执行的查询 | 取消排队资格 | 按新筛选提交 |
| 已运行且失去订阅的只读请求 | 当前阶段允许有界完成；结果按有效代次进入允许的缓存 | 命中相同请求或有效缓存 |
| 保存、删除等变更请求 | 提交后继续完成并记录终态 | 读取实际结果，不把卸载解释为回滚 |

查询身份必须包含：服务运行代次、插件启用代次、Action、有效参数、会话或工作区归属。宿主持有归属，不允许插件伪造任意缓存命名空间。

本次前端协调器在单个渲染进程内共享，不宣称跨窗口自动合并。后端继续承担执行互斥、权限和资源容量限制；取消请求必须绑定原发起客户端及调用标识，不能凭插件标识取消其他窗口的任务。Action 分类由经校验的清单和宿主执行策略决定，前端传入“只读”不能改变后端授权。

每个请求保留订阅计数和实际状态。仅当没有订阅者、未开始执行且属于可丢弃查询时，才允许取消；新订阅与取消同时发生时必须原子地选择复用或重新入场。配额查询、连接测试或任何消耗远端资源的调用不得仅因返回数据而归入可自动重放的只读查询。

缓存规则：

- 在途去重与已完成结果缓存分别建模；失败请求不能永久保留为已拒绝 Promise。
- 只缓存声明允许的只读投影；凭据明文、变更结果和临时授权不能进入通用结果缓存。
- 缓存容量和保留时间有唯一配置来源，并在实施时以测量确定，不复制多个独立字面量。
- 停用、卸载、更新、服务重连以及相关配置变更会使对应条目失效。失效前发出的旧请求即使成功，也不能重新写入新代次缓存。
- 用户手动刷新只发起一次新的读取；已有同键刷新在途时继续复用，不连续叠加请求。
- 动态“截至现在”必须显式区分查询意图与冻结后的实际时间范围。同一次在途读取复用它的固定时间快照；下一次主动刷新取得新的时间。不能简单删除 endAtMs 来合并本应不同的历史范围。
- 使用统计的分页投影与完整投影分别保存身份；禁止把只含某张表的结果当作完整仪表盘缓存。

原因：页面卸载不等于底层任务结束。把请求放在组件外才能跨导航复用，并允许成功结果正常进入缓存。

### 决策四：统计只在需要时读取

- RTK 基础设置只读取 settings-get；首次进入其使用统计区域时才调用 statistics-get。
- RTK 复用现有统计有效期，统一到查询协调器策略；页面卸载不丢弃已经开始且仍有效的统计结果。
- 使用统计按当前区域选择概览、明细或价格请求；切换筛选时合并尚未执行的旧查询。
- Context7 保持 bootstrap-get 的单次初始化投影，使用相同请求生命周期管理，不添加隐式联网测试。

原因：用户只调整 RTK 设置时，不应该付出两个统计子进程的执行成本。按需读取是减少工作量的补充，不替代底层锁修复。

### 决策五：取消与执行资源必须分离

本次交付包括排队取消、请求复用、超时可观测和安全排空；不把同步原生代码的强制中断当作现有能力。

- Action 从入场开始创建唯一截止时间，初始化等待、执行锁等待、执行与宿主调用都使用剩余预算。清单 timeout_ms 是预算来源。
- 尚未开始的操作可以取消。获取执行资格后再次校验取消状态、代次和剩余时间。
- 已开始的同步执行由运行时监督任务持有执行许可和租约句柄。浏览器断开、HTTP Future 丢弃或等待超时，都不能提前释放 operation_gate。
- 禁止通过 abort 一个 spawn_blocking 的等待句柄来宣称已停止实际 Lua。
- 外部进程以 Action 剩余预算与自身上限的较小值执行，超时终止所拥有的进程树并确认退出。
- 数据库等待使用剩余预算；仅丢弃 Rust Future 不代表 SQL 已终止。需要核实本地数据库中断能力，未支持时如实记录后台清理状态，不能把连接提前复用为完全空闲。
- Lua 指令钩子负责可协作执行的截止检查；不可中断的原生调用继续占有其租约，直到实际返回。超时后该句柄不能接收新的执行。
- 初始化与关闭也必须被监督；取消初始化等待时不能遗失后来创建成功的租约。
- UI 必须区分“停止等待”和“任务已取消”。变更操作超时但提交结果未知时，查询该任务实际状态，不自动重放。
- 运行中的同步原生函数立即取消属于后续能力：需要 LuaSkills、外部进程和数据库共同支持。其交付不能阻塞本次跨插件隔离与导航去重，但不能计为已经完成。

原因：提前解锁比页面等待更危险，会导致同一 VM 的新旧执行重叠或变更被重复提交。

## 四、可观测性

为每次 Action 记录稳定调用标识、插件与 Action 标识、启用代次及下列时间：入场、初始化等待、插件执行锁等待、阻塞线程开始、引擎锁等待、Lua 执行、宿主进程或数据库调用、清理、终态。

- 终态包括成功、失败、执行前取消、超时及仍在清理；不记录凭据、完整参数、SQL 正文或查询返回值。
- 保留总耗时与阶段耗时；不能仅测 HTTP 耗时后推断底层锁耗时。
- 日志可关联页面请求与实际执行；开发环境可观察各插件在途数和等待阶段。
- 不在普通插件页面展示“租约、线程池”等实现细节；用户只看到加载、刷新、错误和重试。

## 五、实施顺序与提交边界

1. **基线与回归夹具**：记录版本、运行源码身份、请求耗时；建立两个独立插件的阻塞/放行夹具，证明当前共享锁问题。提交测试与诊断基础。
2. **LuaSkills 根因修复**：核实正式工作区，完成 System 路径入口审计、逻辑工作目录与跨平台回归，发布可消费版本。上游单独提交。
3. **宿主升级与锁收敛**：升级唯一依赖版本、按插件和用途调整初始化及排空、监督实际执行资源。分别提交依赖接入和运行时修复。
4. **查询协调器**：完善 Action 分类、代次投影、在途去重、失效、排队取消和结果边界。提交清晰的宿主契约及实现。
5. **三个插件接入**：RTK 按需加载并移除实例级缓存权威；Context7 与使用统计接入，保证筛选、分页和刷新语义。按插件独立提交。
6. **资源部署与验收**：按项目规则使用正式同步入口，不直接修改 output。核对运行中的插件包与源码一致，再执行实际页面切换测量。
7. **文档闭环**：逐项验收、补全执行变更总结，全部完成后迁移至 docs/completed/20260924/05-PLUGIN_UI_CONCURRENCY_REPAIR.md。

## 七、验收标准

### 7.1 并发与目录正确性

- 使用可控制的阻塞夹具：插件 A 已进入宿主等待但未放行时，插件 B 的快速 Action 能完成。通过事件顺序断言证明并发，不用“睡几毫秒后猜测”。
- 同一插件 UI lease 仍严格串行；Hook 与 UI 运行时按既有隔离边界工作。
- A、B 的相对文件访问和子进程 cwd 始终属于各自授权目录；包含同名文件、中文路径、空格路径与链接替换校验。
- 同时运行普通文件型 runLua 时，System lease 文件访问、模块装载和子进程不受进程 cwd 变化影响。
- Linux、Windows、macOS 的路径与子进程测试必须有实际执行证据；未执行平台明确列出，不能由编译通过代替。

### 7.2 导航与缓存

- RTK 基础设置不发 statistics-get；进入统计区域后才发送。
- 同键只读请求在“进入、切走、返回”期间实际后端执行一次；旧订阅离开不影响新订阅。
- 快速切换十次不线性堆积十个相同请求；在途请求数能恢复稳定。
- 配置保存、插件更新、停用重启后，旧结果不能覆盖新代次。
- 失败可重试，手动刷新有效，统计时间范围与分页数据不混用。
- 变更操作不会因返回页面被自动重发；组件卸载不会产生错误成功提示。

### 7.3 生命周期与取消

- 同插件同时首次进入只创建一个租约；不同插件初始化互不等待。
- 初始化中停用、执行中停用、更新后立即重开都有确定终态，无旧代次重新入库。
- 取消排队请求后不再执行；仅停止 HTTP 等待不会提前释放正在使用的 VM。
- 同步任务未结束时不复用其租约；执行结束后资源归还或隔离关闭，无静默泄漏。
- Action 截止预算覆盖等待与执行；外部命令超时后所拥有进程树确实退出。

### 7.4 实际页面性能

- 在与基线相同的环境，重复采样单独 Context7，以及 RTK 统计在途时的 Context7。
- 暖加载下，Context7 在 RTK 慢操作期间的第九十五百分位请求耗时目标不超过 200 毫秒，且不随 RTK 的秒级等待线性增长；记录机器负载和样本量。
- 200 毫秒是本次验收目标，不复制成运行时超时配置；主要正确性门槛仍为阻塞夹具的明确并发事件顺序。
- 使用统计必须分别测小数据和具有代表性的大数据查询；84 毫秒的单个样本不能替代大数据验收。
- 页面点击本身能即时切换；耗时展示与后台请求一致，不用空白占位制造已经完成的假象。

### 7.5 验证资源与并行工作

- 先执行受影响前端定向测试与类型检查，再执行目标 Rust crate 的定向测试或 cargo check --all-targets。
- 遵守仓库默认编译与测试并发上限；涉及共享引擎、工作目录、端口的测试串行执行。
- 每个独立修复单独中文提交；只暂存本任务文件，不包含并行视觉改动。
- 不默认运行整个工作区的全部测试；仅为具体风险扩大验证。

### 最终执行变更总结

#### 1. 核心修复与决策

- **目录隔离**：正式上游改为租约逻辑目录，宿主升级至 0.5.9。根因是进程级目录锁覆盖整个同步执行，因此不能通过扩大线程池解决。上游发布、撤回有缺陷的中间版本及三平台证据见前文。
- **真实所有权**：按插件和用途同步初始化及排空；监督任务保留运行中的 VM 执行门。等待方取消与实际任务完成分离，防止同一 VM 并发执行。
- **初始化竞态**：发布旧初始化结果前再次校验代次；失败创建或关闭后的原始租约保留供排空，避免取消等待导致租约身份遗失。初始化加载也使用 Action 的剩余预算。
- **读取与变更**：清单明确声明效果；读取可共享，变更不自动重发。运行实例、上下文和精确参数共同确定查询身份。配置事件触发的读取等待已提交写入返回，避免把写入前数据当新结果。
- **导航与筛选**：普通卸载保留共享任务；筛选信号在最后一个订阅者离开后撤回排队资格。先从共享表移除，再发送取消，解决新订阅与撤回竞速。注册前状态明确为空，取消只轮询状态至原请求结束，不重放业务操作。
- **数据库**：系统统计及插件私有 SQLite 都传递剩余预算和专属连接中断；真实阻塞操作返回后才释放门。定时器使用析构守卫，正常结束和异常展开均清理。原生连接初始化、文件系统和不支持中断的原生调用仍由监督任务持有至返回，不谎报强制停止。
- **统计减负**：RTK 基础设置不执行统计；使用统计默认范围用空结束标记表达“截至当前”，服务冻结实际时间；分页和完整投影分别去重。Context7 保留单次初始化，无隐式联网调用。
- **诊断口径**：实现总耗时、初始化、执行门、阻塞队列、引擎锁、引擎操作、宿主回调及清理阶段。区间有包含关系，不能简单求和。没有引入逐子进程内部阶段计时；受管进程等待包含于引擎操作阶段，数据库回调可单独测量。此口径明确补充第四节，不把包络耗时伪称细粒度进程耗时。
- **验证旧夹具**：使用统计 SQL 已移除按日明细字段，旧模拟行仍携带该字段并缺少必需的可空耗时字段；按当前真实 SQL 和 Schema 更新夹具。价格编辑已经改为弹窗，更新对应断言；删除已经不存在的清理页面测试，后端清理 Action 测试仍保留。未恢复已删除产品功能。
