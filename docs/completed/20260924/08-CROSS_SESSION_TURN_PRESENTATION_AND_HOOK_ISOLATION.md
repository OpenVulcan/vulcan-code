# 跨会话任务回合展示与用户记忆隔离

## 一、目标与已确认语义

日期：2026-09-24。状态：代码修复、定向验证和页面展示核对完成。

1. 用户提示词的排队保留用户输入语义。
2. 会话之间显式排队保留排队语义；目标空闲认领后开启新的任务回合。
3. 运行中插队归当前回合，不能拆分为新的人类提示词回合。
4. 代理排队与插队均不作为用户输入记录到用户记忆；独立代理任务不触发用户画像与完成回写。
5. 无用户提示词的回合仍正确组织思考、工具组、最终回答、任务结果和统计。

## 二、根因与决策记录

| 决策点 | 源码事实 | 本次处理及原因 |
| --- | --- | --- |
| 回合来源 | 后端认领已创建代理任务回合，但前端隐式分组依赖前一可见行恰好为统计 | 按规范回合标识分组，不根据可见行邻近关系推断回合 |
| 排队卡片位置 | 消息可能在前一回合仍运行时已接纳 | 根据精确认领效果把收到的任务卡放到认领位置，避免提前拆散上一回合 |
| 工具前思考 | 原分组失败后没有进入现有思考与工具归并链路 | 修复回合归属后复用现有归并逻辑，不增加第二套思考渲染器 |
| 结果与统计 | 本地任务结果可在统计提交后才落盘 | 仅展示层按结果终态回合放到对应统计前；保留原序号、时间和持久顺序 |
| 用户观察 | 代理任务原先跳过预检查，但仍可创建用户事件、画像和完成请求 | 独立保存是否观察用户的生命周期策略；跳过外部派发，保留内部关联和清理 |
| 恢复安全 | 续跑统一使用继续执行来源，单看本次来源无法识别原任务 | 将观察策略存入业务归属，恢复时校验，不让重启把代理任务变成用户任务 |
| 真实用户操作 | 代理执行期间仍可能有真实人类排队或回答 | 公共事件派发保持原行为，仅过滤代理自动生命周期；新增实际通知回归测试 |
| 记忆寿命 | 终态消费和调用前注册独立于外部钩子派发 | 两处均检查观察策略，防止没有用户输入仍消耗临时记忆寿命 |

## 四、执行变更总结

### 1. 核心修复与调整概述

展示按可靠协作效果绑定回合，执行按原始来源隔离用户记忆生命周期。用户排队与代理排队分别处理，不伪造人类输入，也不跳过内部完成清理。

### 2. 文件变更清单

新增：

- `apps/vulcan-code-web/src/service/conversation-collaboration-turn-layout.ts`：共享协作回合展示定位。
- 本执行记录。

修改：

- 前端 `conversation-branch-presentation-v1.ts`、`conversation-event-display-projection.ts`、`conversation-timeline.ts`：两条展示入口共用定位，按规范回合分组。
- 前端 `conversation-branch-workspace-v1.test.tsx`、`conversation-v1-display-renderer.test.tsx`：回归场景与文案断言。
- 前端中英文文案文件：区分会话任务与子代理。
- 运行时 `conversation_hooks` 的类型、运行时、画像请求、完成请求和测试：保存、恢复并执行观察策略。
- `workbench_prompt_turn.rs` 及其测试：代理准备不注册用户记忆生命周期。
- 服务内核 `execution_report_memory.rs`、`session_business_hook.rs`：终态消费过滤及恢复归属校验。
- 会话核心 `v1/business_hook.rs`、`v1/document/business_hook.rs` 及测试：持久策略、来源一致性及不可变冲突检查。
- `docs/contracts/ask-and-markdown-interaction.md`：展示与记忆边界契约。

删除：无。

### 3. 关键代码调整详情

- 新增共享展示定位函数，按投递身份读取目标效果，并按终态回合定位任务结果。
- 分支时间线允许规范代理任务直接开启过程分组，无需人类气泡作为锚点。
- 业务归属新增用户观察策略；画像和完成请求在策略关闭时返回保留关联的空结果。
- 停止路径先释放内部归属，再跳过代理任务的外部用户通知。
- 真实用户事件的公共派发不受代理任务生命周期开关全局封锁。
