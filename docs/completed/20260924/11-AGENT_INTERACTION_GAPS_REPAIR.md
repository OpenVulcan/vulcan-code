# 代理交互遗漏修复

## 目标与范围

修复统一等待在恢复、目标读取异常、多工作返回、迟到结果归属及交叉提问中的交互遗漏。只修改协作领域、规范投递、对应界面与定向测试，不改供应商配置及并行任务文件。

## 执行步骤

1. 区分异常报告去重与工作实时存活，恢复原问题后重新检查实际执行。
2. 区分确认缺失与读取失败；无法确认时保留任务，不伪造中断，不阻塞其他目标结果。
3. 统一所有等待出口的剩余工作、待答问题及检查错误摘要。
4. 保持明确任务和问题唤醒、通知与迟到答案只保存的既有规则，补齐状态说明。
5. 为迟到答案及跨会话任务结果附原问题或任务引用，显示准确归属，不泄露技术编号。
6. 验证交叉提问，明确需回答的问题优先处理；限制单次通知注入，保留可靠顺序及最终结果优先级。
7. 定向验证、独立中文提交、记录决策和未执行的验收；完成后迁移文档。

## 技术选择

- 复用规范参与者、投递及执行记录，不增加第二套消息状态机。
- 异常诊断只确认一次，但不能让诊断确认阻止实时状态检查。
- 读取错误单独报告为检查失败；缺失必须以明确的存储或运行时事实证明。
- 元数据不替代正文；正文仍只经带标签上下文交付，界面复用现有协作卡。
- 通知不产生回复义务，不强行打断正在执行的其他工具；模型收到问题后回复或明确无法回答，再继续等待。

## 验收条件

- 已报告执行丢失的问题在对方恢复后仍可等待；同一异常不刷屏。
- 目标读取异常不结算任务；一个目标出错不会吞掉其他目标消息。
- 每种等待返回均说明剩余工作与待答问题，已收到部分消息不等于全部完成。
- 迟到答案和结果能识别原问题或任务；保存与加入上下文状态不混淆。
- 互相提问能够离开等待；通知洪峰不挤掉问题和最终结果，不丢失延后通知。
- 后端目标与测试目标可编译，定向回归通过，前端类型及相关展示测试通过。

## 决策与过程记录

- 本次按当前源码重新确认，不把前轮五次复查视作所有交互场景已覆盖。
- 当前工作树干净；继续按文件和补丁保护随后出现的并行修改。

- 恢复问题时必须再次检查真实执行所有者，不能因为先前报告过丢失就跳过。报告确认只去除相同工作、结果和原因的重复通知。
- 读取错误不能证明目标不存在；新增精确元数据存在性查询，以强类型路径缺失作为证据。损坏文件保留工作并返回逐目标检查错误。
- 交叉提问通过返回待答摘要让模型离开等待；不增加结束时必须回答所有问题的约束，也不把阶段通知变成问题。
- 通知条数上限在选择器唯一声明，总正文预算引用已有宿主信封上限。延后消息保持已接纳，不截断、不提前确认。
- 迟到结果使用独立引用信封，避免修改已有结果分块及持久凭据验证。原请求摘要按 UTF-8 边界截取，完整结果保留独立正文预算；撤权时不给出原请求引用。
- 新增 `needs_reply`、`check_failed` 的模型说明与界面状态，避免工具已返回后仍显示等待中。结果卡展开后显示原任务，不显示内部编号或技术详情。
- 用户追加的元数据自动升级已优先完成，见 `docs/completed/20260924/12-SESSION_METADATA_MIGRATION.md` 和提交 `50902fb`，本计划不重复计算该工作。
- 复查发现截止时间已耗尽时，丢失子任务首次报告原因与持久重放可能不同，现统一两者并用内部零预算回归覆盖，防止重复提醒。

### 关键代码调整详情

- `inspect_work` 分离单目标检查；`participant_storage_missing` 通过规范索引及精确路径判断缺失。读取失败不产生终态。
- `reported_work` 按成功持久化的工具输出确认报告；`report_identity` 同时纳入工作、结果、原因，实时检查不受确认记录抑制。
- `inbox_snapshot` 使用当前回合和冻结请求前沿获取消息及待答事项；每个等待出口使用相同摘要结构。
- `pending_projections` 在原接纳顺序内优先非通知事实，保留延后通知等待下一请求。
- `append_late_result_context` 仅在跨回合时追加引用；与完整答案或结果分块处于同一暂存修改，失败整体回滚。既有结果凭据和历史正文不重写。
- 卡片复用既有布局、翻译和 Markdown 链路；原任务只从强类型结果接纳记录读取，撤权不披露。
- 独立提交：统一等待修复 `18ecfe2`；迟到结果引用与本完成记录随后独立提交。
