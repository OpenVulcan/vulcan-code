# 已停止执行的回合准入修复

## 目标

普通新输入不能因为缺少助手最终回复或回合结束标记而永久失败。运行状态由宿主实际执行所有权决定；持久化开放回合仅表示历史业务尚未结算。

## 已确认问题

报告会话的第十四回合保留开放标识，主执行已经手动停止，子任务已经可靠完成。停止仅中断活动接口，接口之间停止没有关闭业务回合；冷加载保留可继续回合，普通发送直接调用领域根输入准入并被拒绝。

## 决策与理由

1. 在已有普通发送预留下校验实际执行所有权，再允许收尾旧回合。领域文档不能从缺少结束标记推断进程仍在运行。
2. 旧回合停止、新输入和运行控制必须原子提交。输入校验失败不得先结束旧回合；重试旧请求不能结束后来启动的回合。
3. 旧回合记为停止，不伪造成功回复。已有真实接口统计和用户正文保留。
4. 显式继续保留原通道。普通新输入表示用户选择新回合，不要求先点击继续或补齐成功标记。
5. 活动流、内核执行、答疑准备、终态持久化所有者阻止清理。未交付子任务结果保留归属，不以删除义务绕过等待。
6. 冷加载和重启后的普通发送使用同一准入校验，不根据磁盘中的运行标签自行认定存在活进程。

## 步骤与验收

- [x] 增加无执行者的根输入原子转换，覆盖没有接口、接口中断、接口完成但未关闭回合。
- [x] 将真实执行及准入预留校验接入普通发送，保留显式继续。
- [x] 验证运行者不能被清理、重试不关闭新回合、错误输入不修改旧回合、重建后可发送。
- [x] 定向领域和服务层测试，检查测试目标编译。
- [x] 整理独立提交内容，记录验证边界与变更总结。

## 注意事项

不直接编辑用户会话数据，不自动发起模型请求，不合入并行会话修改。源码验证与当前核心进程生效分开报告。

## 执行变更总结

### 一、核心修复与调整概述

普通根输入现在必须证明持有精确发送预留，且没有内核执行、活动流、答疑准备或终态持久化所有者，才可收尾前序开放回合。前序回合按停止结算，和新输入及运行控制一起原子落盘。不需要助手最终正文、成功接口标记或事先存在的回合结束标记。

重启不自动丢弃可继续的业务历史。用户明确点击继续时保留原协议；普通新输入进入同一个空闲准入通道，不再因这些历史回合被永久拒绝。未交付子任务仍通过原有恢复及结果发布机制处理，不能直接删除或伪造完成。

### 三、关键代码调整详情及决策复核

1. 不放宽原有严格根输入方法的领域约束。新增宿主明确证明执行结束后使用的入口，避免任何调用方仅凭旧标记自行结束活动执行。
2. 在准备结果工作器结算之后重新校验精确预留及运行时所有者，随后保留原发送守卫直到准备完成。
3. 新领域转换先执行正常准入校验。原请求重试直接返回原回执，错误输入不会提前关闭历史回合。
4. 缺失接口终态时补充进程中断事实；已有真实接口终态逐条保持不变。旧回合采用停止结果，最后可靠观察时间用于时长，不把整个离线时间算成运行耗时。
5. 复核发现普通冷恢复刻意保留尚未派发的继续请求。新输入替代时改用明确的中断转换，避免继续保留该请求而再次阻塞闭合；已有继续请求恢复测试同时保留。
6. 不关闭尚未交付结果的子任务所属回合或辅助执行，避免结果归属被破坏。报告案例在子结果已经可靠完成后，新输入正常准入；迟到结果重试保持幂等。
