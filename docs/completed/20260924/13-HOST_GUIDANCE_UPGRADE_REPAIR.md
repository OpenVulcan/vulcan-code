# 宿主指引升级与锁定基线修复

## 目标

修复升级程序后，旧会话保存的宿主消息指引被新文本逐字校验拒绝，导致请求无法发送的问题。保留已锁定提示词和历史前缀，给后续指引更新建立明确的版本识别与动态追加机制。

## 执行步骤

1. 查明锁定基线初始化、持久恢复、请求重建与动态上下文同步的真实链路。
2. 从版本历史登记已存在的宿主指引，保持身份字段校验，未知内容继续明确拒绝。
3. 复用持久动态上下文链路追加当前指引，保证同版本只追加一次、旧前缀不变、压缩后有效说明仍可恢复。
4. 覆盖旧会话继续请求、重复请求、重载、刷新或压缩，以及非法指引拒绝的回归。
5. 定向测试与测试目标编译检查，记录决策和限制，独立中文提交。

## 技术选择

- 不重写旧基线，不通过清空会话或取消校验绕过问题。
- 指引文本版本与元数据结构版本分开，沿已有动态上下文通道更新，不新增并行状态机。
- 当前指引和受支持历史文本必须来自源码版本事实；不凭名称允许任意正文。
- 保留其他会话正在修改的浏览器服务发现与拒绝测试。

## 验收条件

- 使用旧版宿主指引的会话可以继续准备请求，锁定基线与历史消息前缀不变。
- 最新说明以带标签的流内用户消息出现，不进入顶部系统提示词或用户记忆钩子。
- 重复请求及重载不重复追加；压缩和基线刷新遵循各自已有归属契约。
- 非法来源字段和未登记正文仍拒绝，失败不留下部分上下文修改。
- 相关定向回归与全目标编译检查通过，执行记录完整。

## 决策记录

1. **保留锁定基线。** 原因是它参与既有请求前缀与压缩检查点，直接替换正文会改变历史和缓存；从源码历史精确登记五版内容，旧版识别后保持原字节。
2. **复用动态上下文。** 既有链路已经提供生产者身份、持久指纹、原子发布、失效标记和压缩回填；不另建升级标记或第二套状态机，也不改变元数据结构版本。
3. **以持久运行时为准。** 在上下文修改锁内读取已初始化基线；组合器重新生成的最新候选不具有覆盖旧基线的权限。
4. **仍拒绝损坏内容。** 只接纳已登记正文和合法身份字段；不是放松为“名称看起来正确即可”。非法基线在动态上下文发布之前失败。
5. **保留协作与界面边界。** 升级使用仅供应商可见的上下文事件，不生成用户输入、记忆钩子或新的聊天卡片。其他会话的前端清理与服务发现改动不纳入本提交。
6. **验证真实准入流程。** 首轮新增回归的夹具漏建活动请求配置，被既有守卫拒绝；修正夹具，改用正常物理准入与终态提交生成旧会话，不通过补默认值绕过守卫。

## 执行变更总结

### 1. 核心修复与调整概述

消除“程序指引更新后，旧会话被最新全文比较拒绝”的回归。旧正文作为已登记基线继续使用，最新语义在正常请求前通过既有可靠上下文生产者追加。未绕过请求准入、模型配置校验、锁定基线身份校验或动态上下文原子发布。

### 2. 文件变更清单

**新增：**

- `crates/vulcan-ai-contract/src/host_message/guidance.rs`：追加式历史版本目录与精确识别。
- `crates/vulcan-service-kernel/src/agent_stream/provider_v1_sink/host_guidance.rs`：基线版本校验与动态升级生产者。
- `crates/vulcan-service-kernel/src/agent_stream/provider_v1_sink/tests/host_guidance.rs`：隔离持久化、物理准入、幂等与压缩回归。
- `docs/contracts/host-message-guidance-versions.md`：后续指引变更规则与验证入口。

**修改：**

- `crates/vulcan-ai-contract/src/host_message.rs`：从版本目录导出当前指引，保持调用方接口。
- `crates/vulcan-service-kernel/src/agent_stream/provider_v1_sink.rs`：已登记旧基线原样接纳，新基线仍添加当前正文。
- `crates/vulcan-service-kernel/src/agent_stream/provider_v1_sink/context_injection.rs`：在现有完整生产者清单中同步指引升级。
- `AGENTS.md`：增加条件性契约入口。

**删除：** 无。计划完成后迁移到完成目录，日期与序号不变。

### 3. 关键代码调整详情

- 固定指引版本通过唯一数组顺序派生，历史精确文本来自源代码提交，最新正文未改写。
- 初始基线校验调用版本识别函数，已知旧正文不会被当成损坏；身份字段仍逐项校验。
- 升级输入优先读取已初始化的持久运行时，只有尚未初始化时才读取候选基线；与上下文发布共用修改锁。
- 通过稳定生产者键复用持久去重与压缩回填。当前基线不需要覆盖层时，沿既有上下文移除语义追加失效事实。
- 测试夹具曾因缺少活动请求配置以及一次修改中推进多个修订失败；已调整为独立的真实准入、正文发布、终态提交与压缩操作。最终全部验收通过。

### 4. 遗留问题与注意事项

- 必须重新编译并启动新 Core 后生效；本次没有替换运行中的 Core，也没有修改用户真实会话文件。
- 本地测试验证请求准备与持久化，不宣称已完成真实供应商联网验收或远端缓存命中验证。
- 测试链接阶段仍打印微软链接器“正在创建库和对象”的既有提示；没有新增 Rust 死代码警告。现有两项关闭代理测试打印隔离夹具会话未注册的诊断，但断言通过。
- 未登记或被篡改的指引继续报错，避免将损坏内容当成合法版本。
- 其他会话的前端、服务发现及暂存删除内容均保留，不纳入本次提交。
