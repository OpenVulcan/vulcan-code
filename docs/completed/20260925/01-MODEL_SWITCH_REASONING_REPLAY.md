# 模型切换时的推理历史回放修复

状态：代码修复与本地验收完成。真实供应商在线验收尚未执行。

## 目标与事实

- 用户报告会话 `1ebdeef1-322e-48ee-8324-62e5e49f1e44` 从 Qwen 切到 DeepSeek 后，在本地准备请求阶段被拒绝，尚未访问供应商。
- 当前源码把外来路由的规范推理文本与原生签名回放一起拒绝；通用 Responses 编码又会丢弃无签名推理。
- 底层共享错误常量及流式错误封装混入中文，需要改为英文；界面展示独立处理。

## 决策与依据

1. 原生回放仍严格匹配供应商、连接、端点、协议和模型，避免跨路由复制加密数据、签名及供应商消息标识。切换路由使用账本已有的规范文本与工具调用，不改写存储历史。
2. 通过已存在的请求内消息归属旁路数据，为声明明文回放契约的 Responses 目标重建规范推理项。保持消息和工具调用顺序。跨路由且目标未声明明文思考契约时，使用标明历史来源的普通助手文本，防止通用编码器丢弃可见历史；没有发生切换时保持原规则。
3. 旁路信息仅存在内存，不改变元数据版本。保留精确原生项数量，区分同一消息中的原生前缀与规范内容，防止丢失或重复。
4. 保留缺失封套、空推理、不可用原生项及最终线路丢失推理的校验，不以跳过推理解决报错。
5. 底层错误统一英文；界面解析器识别新英文前缀及已经持久化的旧前缀。界面翻译继续属于展示层。
6. 根据用户追加要求核对 DSH 后，跨路由的纯不透明推理块不进入新请求；仍保留存储封套，可在切回原路由时使用。不能把加密数据或脱敏占位符伪造成可恢复的明文。
7. 模型身份通知复用持久动态上下文生产者 `dynamic.model_selection`，以带标签的 User 消息追加。依据实际冻结请求及最近主生成请求比较，不依据界面临时选择。正文绑定当前身份，避免准备失败后又切回原模型时留下错误身份；重试、思考强度变化和摘要模型调用不重复改变身份。

协议依据：[DeepSeek Responses 官方说明](https://api-docs.deepseek.com/guides/responses_api/) 明确支持明文 `reasoning.content`，不支持 `summary` 与 `encrypted_content`。

### 行为矩阵

| 场景 | DSH 通用多协议路径 | DSH 原生 DeepSeek Messages |
| --- | --- | --- |
| 同供应商、同协议、同模型 | 保留合法签名；允许空可见文本的加密思考原样回放 | 校验封套类型、版本、模型及块对齐后保留思考签名 |
| 同协议切模型 | 可见思考转普通文本，移除思考及工具签名 | 保留明文 thinking，去掉跨模型签名 |
| 切供应商或协议 | 与跨模型同样处理；不把旧协议元数据伪装为新协议元数据 | 外来封套不可信时记录降级诊断，按规范内容重建 |
| 脱敏思考 | 仅精确原模型可回放；切换时省略不透明块 | 此原生路径未声明同等 redacted 类型，不能推断支持 |
| 只有密文、可见文本为空 | 原路由可保留原生签名；跨路由省略该块 | 无可用跨模型签名，不恢复密文内容 |
| 无签名但存在可见思考 | 跨模型转普通文本；目标 Anthropic 还按其模型能力选择普通文本或空签名 thinking | 直接使用无签名 thinking |
| 工具调用与结果 | 去掉跨模型工具签名；按目标约束映射 ID，并同步映射结果 ID | 按原规范 ID 校验调用与结果配对 |
| 回放元数据损坏或版本不支持 | 记录诊断后退回规范历史 | 记录诊断后不再使用原生签名 |

### 通知与回放分别处理

DSH 在下一次实际请求接纳时追加英文 User 通知，说明此前回复由旧模型生成、会话现在由新模型继续。供应商和模型相同、只调整思考强度、空请求或已取消请求不追加。它比较实际组装选择与最新请求头，避免请求中途换模型。

本项目原 `RequestConfigChanged` 事件仅为界面可见，不能据界面提示推断 AI 已知道切换。此次保留界面事件，新增请求准备边界的动态身份生产者；消息追加在原上下文末端，不重写锁定 System 基线。

### 不直接照搬的行为

- DSH 的通用转换还会补造缺失工具结果、跳过错误或中止的助手记录。本次不引入这些逻辑：本项目已有持久化工具终态与配对校验，补造结果可能掩盖实际执行状态。
- 本次不会把已损坏的同路由原生封套静默当成有效数据。可移植的路由切换与数据损坏是不同事实，后者仍保留明确错误。
- 可见摘要只是已记录文本，不代表恢复了完整加密思考；任何转换都不尝试解密，也不向新供应商传递旧签名。
- 本地源码与编解码测试不等于所有供应商在线接受验证；不宣称跨协议切换已完成全面联网验收。

### 💻 关键代码调整详情

1. `resolve_projected_assistant_replay`：同路由优先使用持久原生项；外来路由移除原生项和签名，保留规范正文及工具调用。只有可见内容为空的外来推理块被省略，存储封套不变。

3. `model_selection_input`：比较最近主生成请求与当前冻结请求的供应商、模型和已知协议。正文只绑定当前身份，使相同目标的重试幂等；持久通知存在时，即使派发前切回原模型，也会更新回正确身份。摘要请求不发布或撤销该通知。
4. 实际准备入口先可靠发布动态上下文，再捕获最新会话快照重建请求，因此通知同时进入请求正文和预算测量。
5. 最终线路校验仍然执行，后置自定义投影删除推理仍会报错；没有通过关闭校验来消除用户的报错。
