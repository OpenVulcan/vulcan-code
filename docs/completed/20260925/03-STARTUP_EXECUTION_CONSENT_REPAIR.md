# 启动恢复误派发旧会话修复

状态：已完成。代码修复、定向回归、五轮自审与真实核心重启验收均已闭环。

## 目标

服务启动、页面打开和历史会话载入不得自行执行之前失败或中断的用户任务。恢复历史状态与重新取得执行许可必须分离，保留用户明确继续和正常运行期间协作消息的执行语义。

## 执行步骤

1. 根据本地持久事件和当前源码确认截图会话的原始失败、重启时间及后续派发来源；仅读取本次必要字段，不输出凭据。
2. 追踪启动协作恢复、普通业务恢复、历史载入及显式继续入口，确定旧任务执行许可的错误来源。
3. 修复恢复准入，补足必要终态投影，防止遗留未闭合标记授权后台执行；保持正常协作及用户明确操作不变。
4. 添加定向回归，覆盖失败会话、中断会话、初次用户输入、协作恢复和显式继续。
5. 核对并行 StepFun 用量修复和运行资源，记录边界，不混入其修改。
6. 记录决策、测试和运行验收结果，独立中文提交。

## 验收标准

- 启动恢复或只读载入不发出旧普通用户任务的供应商请求。
- 失败或中断的遗留回合不会使新输入永久被拒绝，也不会表现为仍在执行。
- 用户明确继续或提交新输入仍可运行；运行期间合法协作消息处理不受影响。
- 不通过删除用户历史、忽略持久化错误或关闭公共终态校验掩盖问题。
- 本任务提交仅包含归属本任务的源码、回归和文档。

## 实施决策及原因

1. 删除普通主业务的启动自动派发入口及专用准备分支，包含未发布首个业务钩子的初次用户任务。原因：历史已保存只能证明旧任务存在，不能证明用户同意在新的进程继续执行。
2. 保留有明确投递来源的协作恢复和结算入口。原因：本次缺陷来自扫描所有普通开放回合的额外分支；删除整个协作恢复会破坏已有消息和子任务结果的可靠投递。
3. 不因查看历史而强制闭合所有旧回合。原因：可继续的中断任务需要保留原回合和显式继续凭据；新输入已有基于实际执行者缺席的原子旧回合收口机制，回归同时验证该机制。
4. 删除仅服务于自动启动的未使用类型与查询包装，保留显式授权续跑所需的钩子状态恢复能力。原因：不留下被误用即可重新引入自动执行的闲置代码。
5. 不改元数据持久字段及版本，不直接改用户历史，也不删除已被自动生成的文件。原因：这是执行准入错误；重写历史会掩盖真实副作用。
6. 供应商用量问题单独核对。当前源码和运行资源里的 StepFun 清单均为第 4 版且文件摘要相同，针对累计流式用量的修复属于并行修改；截图错误是 02:29 的旧事件，本任务不覆盖该修复。
