# Agent Skills 独立面板、目录与元数据设计方案（2026-07-11）

## 1. 结论先行

本方案建议把当前“技能”能力正式拆成两个顶层产品域：

1. **提示词技能（Agent Skills）**：独立为与“智能体”“LuaSkills”同级的一级面板，负责兼容开放 Agent Skills 标准的提示词技能发现、分类、查看、编辑、启停、来源与多语言展示。
2. **LuaSkills**：将当前一级“技能”面板改名为“LuaSkills”，保留现有 LuaSkills 技能目录作为第一页，原来的第二项“AgentSkills”改成“LuaSkills 设置”。

本轮只规划 Agent Skills。LuaSkills 仅确定导航边界与命名，不设计其设置页内部功能。

Agent Skills 的核心原则是：

- `SKILL.md` 始终遵循开放标准，不把 VulcanCode 私有展示字段塞进标准顶层字段。
- 技能目录保持可移植，不为分类而移动或改写第三方技能包。
- 分类是独立的逻辑目录层，通过稳定标识和外部索引自动同步。
- 模型触发元数据与用户界面展示元数据分离，多语言不会暗中改变模型的技能触发语义。
- 系统技能只读，用户技能可编辑；用户同名技能继续覆盖系统技能，但界面必须展示覆盖关系和原始来源。

## 2. 本方案依据

### 2.1 当前仓库真实状态

当前实现已经具备以下基础：

- 顶层区域标识目前包含 `chat`、`skills`、`agents`、`memory`、`settings`。
- 当前“技能”区域内部包含 `lua` 与 `agent` 两个子页面。
- Agent Skills 已经具有独立的刷新响应和版本投影，并非必须继续依附 LuaSkills。
- Agent Skills 已支持全局启停、单技能启停、项目级继承/启用/停用覆盖，以及智能体级提示词技能策略。
- Agent Skills 当前从系统根和用户根加载，默认用户根为 `~/.vulcan/code/skills`，默认系统根位于其 `.system` 子目录。
- 当前扫描器只扫描两个根目录的直接子目录，并读取其中的 `SKILL.md`。
- 同名技能由后扫描的用户层覆盖系统层。
- 当前 `SKILL.md` 只解析 `name` 与 `description`。
- 当前可选 `vulcan.yaml` 只承载 `interface.display_name`、`short_description`、小图标、大图标和品牌色。
- 当前 WebUI 技能行仅投影名称、显示名、描述、系统/用户作用域、启用状态、路径、图标与正文。
- 智能体目录已经具有分类、双语展示元数据、来源、包、版本、更新时间、覆盖关系和恢复默认等成熟模型，可作为 Agent Skills 的交互参考。

### 2.2 开放 Agent Skills 标准基线

开放规范要求一个技能目录至少包含 `SKILL.md`。标准 frontmatter 字段为：

- 必填：`name`、`description`。
- 可选：`license`、`compatibility`、`metadata`、实验性的 `allowed-tools`。
- `name` 需要符合小写字母、数字与连字符约束，并与直接父目录名一致。
- 技能可附带 `scripts/`、`references/`、`assets/` 等资源目录。
- 标准采用渐进式披露：启动时只加载名称与描述，命中后加载正文，资源按需读取。

因此，VulcanCode 不应把 `categoryId`、多语言对象、来源对象等复杂结构新增为 `SKILL.md` 的私有顶层字段。

## 3. 产品边界与命名

### 3.1 顶层导航

建议目标导航如下：

| 一级区域 | 定位 | 本轮变化 |
| --- | --- | --- |
| 对话 | 会话与执行 | 不变 |
| 提示词技能 | Agent Skills 管理 | 新增独立一级区域 |
| 智能体 | 系统/用户智能体管理 | 不变，作为交互参考 |
| LuaSkills | Lua 工具技能与配置 | 由原“技能”区域改名 |
| 记忆 | 记忆管理 | 不变 |
| 设置 | 全局设置 | 不变 |

中文主名称建议使用“提示词技能”，副标题或帮助文案使用“Agent Skills”。英文使用“Agent Skills”。这样能直接说明它与 LuaSkills 工具技能的差异。

### 3.2 LuaSkills 面板最小调整

现有 `skills` 一级区域在迁移期可保留内部路由标识，界面名称改成 LuaSkills。其二级导航调整为：

1. **技能列表**：保持当前 LuaSkills 列表、安装、更新、启停、卸载和工具注册状态能力。
2. **LuaSkills 设置**：替换原来的 AgentSkills 选项。

Agent Skills 的卡片、刷新、全局开关和详情入口全部迁出该区域。LuaSkills 设置的具体字段不属于本轮范围。

### 3.3 Agent Skills 面板职责

独立面板负责：

- 扫描与刷新目录。
- 目录分类与筛选。
- 系统、用户、覆盖、来源和状态展示。
- 标准元数据与 Vulcan 展示元数据查看。
- 用户技能创建、编辑、复制、删除和目录打开。
- 系统技能只读查看、创建用户覆盖和恢复默认。
- 加载诊断与标准合规诊断。
- 全局、单技能状态管理。

项目级覆盖仍保留在项目设置中；智能体级提示词技能策略仍保留在智能体编辑器中，它们消费同一个 Agent Skills 目录，不重复建立数据源。

## 4. Agent Skills 页面信息架构

### 4.1 页面整体布局

复用智能体页面的布局与组件语义：

- 左侧：目录与来源导航。
- 顶部：标题、统计、搜索、状态筛选和页面动作。
- 主区：紧凑技能行/卡片列表。
- 详情：右侧抽屉或详情对话框。
- 编辑：用户技能编辑表单。
- 问题：非致命加载与合规问题区域。

不建议继续使用当前简单卡片网格，因为它无法容纳分类、来源、覆盖关系、多语言状态和合规诊断。

### 4.2 左侧目录

固定入口：

1. 全部技能。
2. 系统技能。
3. 用户技能。
4. 已覆盖系统技能。
5. 未分类。
6. 加载问题。

其后展示默认分类与用户分类。每项展示图标、当前语言名称、技能数量和可选问题数量。

收起侧栏时复用智能体分类的浮动菜单交互。

### 4.3 顶部工具区

建议提供：

- 搜索：跨规范名称、各语言显示名称、描述、作者、来源标签与分类搜索。
- 状态筛选：全部、已启用、已停用、存在问题。
- 来源筛选：系统、用户、本地目录、Git、受管安装、未知来源。
- 刷新：重新扫描并提交完整的版本化目录投影。
- 新建：创建用户技能。
- 导入：选择本地技能目录或 Git 来源；具体安装器可在后续阶段实现。
- 打开目录：打开用户 Agent Skills 根目录。
- 全局开关：保留当前 Agent Skills 全局启停能力。

### 4.4 技能列表行

每行建议展示：

- 图标、品牌色、当前语言显示名称。
- 规范名称 `name`。
- 当前语言短描述；无本地化时展示明确的回退结果。
- 分类。
- 来源与作用域徽标。
- 启用状态。
- 标准合规状态。
- 资源摘要，例如脚本、引用、资产数量。
- 覆盖提示，例如“用户版本覆盖系统版本”。
- 版本与更新时间；来源没有提供时不虚构。

行级动作根据所有权变化：

- 系统技能：查看、启停、创建用户副本/覆盖、打开目录。
- 用户技能：查看、编辑、复制、启停、删除、打开目录。
- 用户覆盖：查看、编辑、启停、恢复系统默认。

### 4.5 详情与编辑

详情页签建议为：

1. **概览**：显示名、描述、分类、来源、版本、协议、兼容性和状态。
2. **说明**：渲染 `SKILL.md` 正文。
3. **资源**：只读树展示 `scripts/`、`references/`、`assets/` 与其他文件。
4. **元数据**：分别展示标准 frontmatter、Vulcan 扩展和外部覆盖结果。
5. **诊断**：规范错误、缺失资源、图标错误、来源完整性与覆盖冲突。

用户技能编辑器复用智能体编辑器的表单风格，分为：

- 基础：规范名称、模型触发描述、正文。
- 标准：协议、兼容性、作者/版本等字符串元数据、实验性允许工具。
- 展示：中英文显示名、短描述、图标、品牌色。
- 目录：分类选择。
- 来源：只读来源信息；用户自建技能显示“本地用户创建”。

模型触发描述必须与本地化 UI 短描述分开编辑，并在界面中解释前者会影响模型何时选择技能。

## 5. 分类设计

### 5.1 为什么使用逻辑分类

不建议把技能移动为 `根目录/分类/技能/SKILL.md`：

- 当前扫描器只扫描根目录直接子级。
- 许多兼容客户端也按配置根目录的直接子技能目录发现技能。
- 分类移动会改变路径、破坏来源管理和更新器定位。
- 一个技能可能需要多个标签，但物理目录只能有一个父目录。

因此技能物理结构保持：

```text
skills-root/
  my-skill/
    SKILL.md
    vulcan.yaml          # 可选
    scripts/             # 可选
    references/          # 可选
    assets/              # 可选
```

分类由独立目录索引管理，不改写第三方技能包。

### 5.2 默认分类

建议内置以下稳定分类，分类 ID 固定使用英文连字符格式：

| 分类 ID | 中文 | 英文 | 典型内容 |
| --- | --- | --- | --- |
| `general` | 通用 | General | 通用工作流与个人效率 |
| `engineering` | 工程开发 | Engineering | 编码、架构、框架与语言 |
| `quality` | 测试与质量 | Testing & Quality | 测试、评审、调试与质量保障 |
| `operations` | 运维与自动化 | Operations & Automation | CI/CD、终端、部署与自动化 |
| `data` | 数据 | Data | 表格、数据库、分析与可视化 |
| `documents` | 文档与内容 | Documents & Content | 文档、PDF、演示与内容生产 |
| `design` | 设计与媒体 | Design & Media | UI、图像、音视频与设计系统 |
| `research` | 研究与检索 | Research | 搜索、调研、知识整理 |
| `security` | 安全 | Security | 安全检查、合规与风险分析 |
| `integrations` | 集成 | Integrations | 外部服务、连接器与平台协作 |
| `uncategorized` | 未分类 | Uncategorized | 没有显式分类的技能 |

默认分类由系统资源提供，用户不能删除，可调整展示顺序但不修改其稳定 ID。后续新增默认分类必须向后兼容。

### 5.3 用户分类

用户可以新增、修改、排序和停用自定义分类。自定义分类需要：

- 稳定 `categoryId`。
- 默认名称与可选描述。
- `zh-CN`、`en-US` 等本地化展示字段。
- 图标、颜色、排序值。
- 创建时间、更新时间。

删除非空分类时只移除分类关联，技能回到“未分类”；不得删除技能。

### 5.4 分类归属与优先级

一个技能第一版只设置一个主分类，预留字符串标签数组但不在第一版 UI 开放多分类。

分类解析优先级：

1. 用户外部覆盖索引中的显式分类。
2. 技能自身 `vulcan.yaml` 的显式分类。
3. 系统内置清单中的分类。
4. `uncategorized`。

禁止根据名称或描述进行不可解释的模糊自动分类。未来若增加 AI 推荐，只能生成待确认建议，不能直接持久化。

### 5.5 自动同步规则

“自动同步分类目录”定义为每次目录刷新时，以技能扫描结果和分类索引构建新的逻辑目录快照：

1. 加载系统默认分类。
2. 加载用户分类定义。
3. 扫描系统技能根和用户技能根。
4. 验证标准结构并建立规范技能记录。
5. 加载包内 `vulcan.yaml`。
6. 加载外部覆盖索引。
7. 按确定性优先级解析分类、显示元数据和来源。
8. 生成分类计数、未分类列表、孤立关联与冲突诊断。
9. 原子提交新的版本化 Agent Skills 目录投影。

同步行为必须满足：

- 新增技能会自动出现在其显式分类或“未分类”中。
- 删除技能只清理自动生成的关联，不删除用户分类。
- 分类 ID 不存在时技能进入“未分类”，同时产生诊断。
- 空分类保留，方便用户后续继续使用。
- 同名用户覆盖出现时，列表默认展示有效用户版本，并保留系统版本作为覆盖来源详情。
- 技能规范名称变更视为新技能；只有经过显式重命名操作时才迁移其外部分类与展示覆盖。
- 文件监听只负责触发带防抖的完整重扫，不增量猜测最终状态；手动刷新和启动扫描使用同一条路径。

## 6. 元数据标准

### 6.1 三层元数据模型

#### 第一层：开放标准 `SKILL.md`

VulcanCode 应完整解析并校验：

```yaml
---
name: pdf-processing
description: Extract and process PDF files. Use when a task involves PDFs.
license: Apache-2.0
compatibility: Requires Python 3.12+
metadata:
  author: example-org
  version: "1.2.0"
allowed-tools: Bash(python:*) Read
---
```

其中 `name`、`description` 参与模型发现；其他标准字段进入详情、诊断与后续策略层。未知标准兼容字段应保留但不自行赋予运行时语义。

#### 第二层：包内 `vulcan.yaml`

`vulcan.yaml` 当前使用 v3 的可选 VulcanCode 展示扩展：

```yaml
schema_version: 3
interface:
  display_name: "PDF Processing"
  short_description: "Extract, fill, merge, and inspect PDFs"
  emoji: "📄"
  color: "#DC2626"
  locales:
    zh-CN:
      display_name: "PDF 处理"
      short_description: "提取、填写、合并与检查 PDF"
catalog:
  category_id: "documents"
origin:
  kind: "github"
  label: "example-org/skills"
  url: "https://github.com/example-org/skills/tree/main/pdf-processing"
```

当前实现只读取并写入上述 snake_case v3 字段；技能展示统一使用 `emoji` 与 `color`，不再加载技能包图片作为图标。

#### 第三层：外部目录覆盖索引

建议放在 Agent Skills 用户根目录的宿主管理子目录中，例如：

```text
~/.vulcan/code/skills/.vulcan/
  categories.yaml
  catalog-overrides.yaml
  origins.yaml
```

该层用于：

- 不修改第三方技能包的用户分类。
- 用户自定义显示名与多语言补充。
- 受管安装来源、版本、提交号与完整性记录。
- 系统技能的用户展示覆盖。
- 显式重命名时的关联迁移记录。

外部索引是宿主管理状态，不参与 Agent Skills 跨客户端标准，不注入模型上下文。

### 6.2 建议领域模型

建议将当前扁平 `AgentSkillSummary` 扩展为以下概念，字段名仅作为设计草案：

```text
AgentSkillRecord
├─ skillKey                 # 内部稳定键，scope + name
├─ name                     # 标准规范名称
├─ scopeKey                 # system | user
├─ effective               # 是否为同名解析后的有效版本
├─ overrideOf              # 可选，被覆盖的 system:name
├─ standardMetadata
│  ├─ description
│  ├─ license
│  ├─ compatibility
│  ├─ metadata
│  └─ allowedTools
├─ interfaceMetadata
│  ├─ displayName
│  ├─ shortDescription
│  ├─ locales
│  ├─ icons
│  └─ brandColor
├─ catalogMetadata
│  ├─ categoryId
│  └─ tags
├─ origin
│  ├─ kind
│  ├─ label
│  ├─ url
│  ├─ version
│  ├─ revision
│  ├─ managed
│  └─ integrity
├─ resources
├─ state
├─ paths
└─ diagnostics
```

`skillKey` 用于界面和目录归属，模型仍按标准 `name` 选择技能。系统与用户同名时不能再只保留最后一条记录后丢失覆盖来源，应同时保留原始记录与有效记录关系。

## 7. 多语言标准

### 7.1 分离两类文本

- **模型文本**：`SKILL.md.description` 与正文。它们决定模型发现与执行，不因 WebUI 语言切换而变化。
- **展示文本**：显示名称、短描述、分类名称与来源标签。它们可以本地化，只服务用户界面。

第一版不支持为同一技能按 UI 语言切换不同正文，也不自动翻译模型触发描述。否则同一个技能会因界面语言不同而改变运行时行为。

### 7.2 语言标签与回退链

语言键使用规范 BCP 47 标签，首批编辑器明确支持 `zh-CN` 与 `en-US`，读取层允许其他合法标签。

展示回退顺序：

1. 当前完整语言标签，例如 `zh-CN`。
2. 同语言前缀的确定性匹配，例如 `zh`。
3. 包内默认 `displayName` / `shortDescription`。
4. 标准 `name` / `description`。

不建议沿用“英文永远优先”的编辑器默认策略；读取应优先当前界面语言，保存时默认字段可继续由英文或作者指定的默认语言提供。

### 7.3 搜索行为

搜索索引包含全部语言的展示名称与短描述，但结果只渲染当前语言文本。这样中文用户可以搜索英文原名，英文用户也能搜索中文别名，不会改变技能运行时元数据。

## 8. 来源与所有权标准

### 8.1 来源和作用域必须分开

- 作用域回答“技能当前由哪一层生效”：系统或用户。
- 来源回答“技能最初从哪里来”：内置、本地创建、本地导入、Git、受管目录或未知。

不能继续用当前 `scope` 文案同时承担来源含义。

### 8.2 来源类型

建议稳定枚举：

- `builtin`：应用内置系统技能。
- `local-created`：用户在 VulcanCode 中创建。
- `local-import`：从本地目录导入。
- `git`：从 Git URL 安装或同步。
- `managed`：由外部受管目录或未来市场安装。
- `unknown`：只能确认文件存在，不能确认来源。

只有安装/导入流程能够写入可信来源记录。扫描任意目录时不得根据文件内容猜测 Git URL、作者或版本。

### 8.3 来源展示字段

来源至少包含：

- 类型、标签、链接。
- 是否受管。
- 版本与修订号。
- 安装时间与最后同步时间。
- 可选内容摘要或完整性哈希。
- 协议信息来自标准 `license`，不在来源对象中重复制造另一份事实。

本地手工放入用户根的技能显示“本地目录 / 来源未登记”，不能伪装成用户创建或 Git 安装。

## 9. 扫描、解析与状态合并

### 9.1 扫描边界

第一阶段继续只扫描系统根和用户根的直接子技能目录，以保持现有行为和跨客户端兼容。宿主管理目录 `.system` 与 `.vulcan` 必须显式排除。

未来若支持额外技能根，应通过显式配置的根列表增加，而不是递归扫描任意深度。

### 9.2 标准校验

解析器需要补齐：

- `name` 长度、字符、连字符和目录同名校验。
- `description` 长度校验。
- `license`、`compatibility`、`metadata`、`allowed-tools` 解析。
- frontmatter 类型错误与未知结构诊断。
- 图标和资源引用必须限制在技能根内。

无效技能不进入模型可用目录，但要作为问题项显示。禁止为了加载更多技能而模糊兼容错误字段名。

### 9.3 状态解析

保留当前优先级：

```text
全局总开关 > 会话覆盖 > 项目覆盖 > 全局单技能覆盖 > 全局默认值
```

独立页面展示的是全局层状态；项目设置和会话调试可以展示其各自的最终状态来源。用户技能覆盖系统技能时，状态仍按规范名称继承，除非显式迁移策略决定分离。

### 9.4 修订与事件

沿用现有 `AgentSkillsCatalogUpdate` 的完整领域投影和 revision 接受规则。分类、来源、多语言和诊断必须与技能列表在同一修订中原子提交，避免目录计数和列表短暂不一致。

## 10. 服务与前端模块建议

### 10.1 运行时与解析层

重点改造：

- `crates/vulcan-prompt-skills`：标准 frontmatter、v2 扩展元数据、分类索引、来源索引、覆盖关系与诊断。
- `crates/vulcan-service-api`：扩展 Agent Skills 目录、分类、来源、资源和编辑请求结构。
- `crates/vulcan-service-kernel`：独立目录投影、扫描刷新、用户技能写操作、分类操作与打开目录服务。
- `crates/vulcan-provider-config`：保留运行时启停状态；目录展示状态不应继续塞入 provider 配置。

分类和来源索引建议放入工作区存储/应用数据层，而不是 provider 配置文件。

### 10.2 WebUI

建议重构边界：

- 新建独立 `components/features/agent-skills/`。
- 当前 `components/features/skills/` 收敛为 LuaSkills 专属目录并择机重命名。
- `MainAreaId` 增加独立 Agent Skills 区域；内部路由迁移需要兼容旧持久化值。
- 复用智能体页面的分类菜单、来源行、状态筛选、多语言表单与详情布局，并提取真正通用的共享组件。
- 不直接复制整个 `AgentsArea.tsx`，避免形成第二个两千行级单文件。

### 10.3 建议服务动作

在现有刷新和启停动作基础上，后续新增：

- 打开用户技能目录。
- 读取技能详情与资源树。
- 创建/保存用户技能。
- 删除用户技能。
- 创建系统技能的用户覆盖。
- 恢复系统默认。
- 保存分类定义与排序。
- 设置技能分类。
- 保存用户展示元数据覆盖。
- 导入本地目录或 Git 来源。

所有文件写操作必须校验目标仍在用户技能根内，并使用临时目录加原子替换，不能直接覆盖到一半。

## 11. 兼容与迁移

### 11.1 路由迁移

- 旧 `skills/agent` 导航自动迁移到新的 Agent Skills 一级面板。
- 旧 `skills/lua` 迁移到 LuaSkills 的“技能列表”。
- 旧顶层 `skills` 内部 ID 可以短期保留，但对外文案必须统一为 LuaSkills。
- 持久化的最后访问区域遇到旧值时执行一次确定性映射。

### 11.2 元数据迁移

- 现有 `vulcan.yaml` 继续只读兼容。
- 编辑旧技能时升级为正式 schema v2。
- 未提供扩展元数据的标准技能仍能完整加载，显示名回退到 `name`，短描述回退到 `description`。
- 不自动写回或格式化第三方 `SKILL.md`。
- 首次启动分类索引时，内置技能按系统清单归类，其他技能进入“未分类”。

### 11.3 覆盖迁移

当前扫描通过同名覆盖而丢失系统行。迁移后需要保留两个源记录，并生成一个有效解析关系。现有全局、项目和会话状态仍以规范名称为键，避免升级后状态丢失。

## 12. 实施阶段

### 第一阶段：标准解析与领域模型

- 完整解析 Agent Skills 标准字段并严格校验。
- 建立系统/用户双记录与有效覆盖关系。
- 扩展服务 API，保持现有启停兼容。
- 增加分类、来源、多语言和诊断模型。

验收重点：现有技能加载结果不回退，普通标准技能无需 `vulcan.yaml` 即可加载。

### 第二阶段：逻辑目录与自动同步

- 内置默认分类。
- 用户分类和外部覆盖索引。
- 确定性同步、孤立关联诊断、版本化投影。
- 文件监听与手动刷新共用完整重扫路径。

验收重点：新增、删除、覆盖、分类删除与无效分类引用都能得到稳定结果。

### 第三阶段：独立只读面板与导航迁移

- 新增 Agent Skills 一级区域。
- 原技能区域更名为 LuaSkills。
- 迁移 Agent Skills 列表、详情、启停、刷新和问题展示。
- LuaSkills 二级导航调整为“技能列表 / LuaSkills 设置”。

验收重点：两个领域不再共享子页面状态，刷新响应只更新各自领域。

### 第四阶段：用户编辑与来源管理

- 用户技能创建、编辑、复制、删除、覆盖和恢复默认。
- 多语言展示元数据编辑。
- 本地目录/Git 导入及可信来源记录。
- 资源树与标准合规诊断。

验收重点：系统技能永远只读，第三方技能不被扫描器静默改写，失败写入可回滚。

### 第五阶段：体验收敛

- 与智能体页面统一分类导航、来源链接、空状态、错误状态和响应式布局。
- 增加大目录性能测试、搜索索引与可访问性检查。
- 清理旧 Agent Skills 子页路由与兼容代码。

## 13. 关键验收标准

### 标准兼容

- 符合开放规范且仅包含 `SKILL.md` 的技能可以加载。
- 全部标准 frontmatter 字段可以解析、展示和诊断。
- 技能名称与父目录不一致时明确报错且不进入模型目录。
- 分类与本地化不会改变 `SKILL.md` 的模型触发描述。

### 分类同步

- 系统默认分类稳定存在并支持中英文。
- 用户分类不会因刷新或暂时为空被删除。
- 新技能、删除技能、同名覆盖和分类缺失都有确定结果。
- 目录计数、列表、详情和问题项属于同一个 revision。

### 来源与所有权

- 系统、用户和用户覆盖可以明确区分。
- 未登记来源显示未知，不进行推测。
- 受管来源能够显示 URL、版本、修订与同步时间。
- 恢复默认只删除用户覆盖，不影响系统技能。

### UI 与导航

- Agent Skills 与智能体、LuaSkills 同级。
- 原技能页面只保留 LuaSkills 领域。
- LuaSkills 二级导航为“技能列表 / LuaSkills 设置”。
- Agent Skills 具备目录、搜索、状态、来源、详情和诊断体验。
- 项目设置和智能体编辑器继续消费同一 Agent Skills 目录。

## 14. 明确非目标

本方案不包含：

- LuaSkills 设置页的具体字段和交互。
- LuaSkills 包格式或运行时协议调整。
- Agent Skills 在线市场设计。
- Agent Skills 安全沙箱与脚本权限体系的完整重构。
- 自动翻译技能正文或按 UI 语言切换不同模型提示词。
- 基于 AI 的自动分类落库。
- 本轮直接修改任何业务代码。

## 15. 实施前需要确认的重大决策

正式进入实现前建议确认以下三项：

1. 一级面板中文名称采用“提示词技能”，还是直接显示“Agent Skills”。本方案推荐前者，并把 Agent Skills 作为副标题。
2. 用户技能编辑器是否在第一期同时交付。本方案推荐先完成只读独立面板与目录同步，再交付写入能力，降低迁移风险。
3. `vulcan.yaml` v2 最终字段命名采用 camelCase 还是延续现有 snake_case。本方案倾向延续 YAML 生态和当前文件的 snake_case，示例中的 camelCase 仅表达领域结构，实施时必须一次定稿。

除这三项外，其余设计可以按阶段推进，不需要改变 Agent Skills 开放标准。

## 16. 插件来源补充（2026-07-15）

Agent Skills 目录现已增加独立的 `Plugin` 来源，用于接收插件包 `skills/` 目录贡献：

- 规范名称固定为 `<plugin-id>:<local-skill-name>`，不会与系统或用户同名覆盖层混淆。
- 有效分类强制为宿主内建只读 `plugins` 分类，图标统一使用 `🧩`；插件内分类元数据只保留在源文件中，不改变宿主导航。
- 来源摘要保留插件名称、版本、仓库 URL 和规范标识；GitHub 来源沿用统一可点击来源链接。
- 插件 Skill 可查看正文、资源与来源详情，但不允许编辑、删除、复制、单项启停、恢复默认或重新分类。
- 服务端根据插件目录快照执行所有权校验，前端操作权限仅用于展示，不承担安全边界。
- 插件启停后，Agent Skills 与插件、智能体目录通过同一 `pluginCatalogChanged` revision 原子替换。

插件来源不改变 Agent Skills 开放标准，也不把插件文件复制或转换为用户 Skill；其唯一生命周期所有者始终是插件包。
