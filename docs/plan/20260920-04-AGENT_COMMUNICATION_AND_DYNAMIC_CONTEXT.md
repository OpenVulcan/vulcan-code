本期保留已有父子代理树、任务启动和方向引导的业务语义。独立会话之间建立协作关系，不改写父子归属。独立会话协作面向已存在的会话；自动创建新会话、任意跨项目访问和同级子代理绕过父级策略不由本方案隐含开放。

图片理解等工具目录、媒体能力或模型配置本身变化造成的请求变化，沿用其真实变更语义。本方案重点修复记忆、模式和其他动态宿主提示被提前或重复投影的问题，不承诺所有请求永远命中缓存。

## 三、已确认的需求基线

| 编号 | 必须满足的规则 |
| --- | --- |
| R01 | 稳定顶部提示保留；全部非顶部的宿主提示文本统一使用按事件时点追加的 `User` 加版本化功能标签。 |
| R02 | 真实用户、助手历史、原生工具调用与结果、媒体结构保持各自身份。标签不授予权限，不用于认证或从自由文本触发发送。 |
| R03 | 启动任务与方向插队均属于任务完成链；插队改变原任务方向，不取消执行、不新建任务、不要求单独中途回复；最终 Assistant 是终态回报，接收方无须为此再确认。 |
| R04 | 临时问答属于独立事务，双方均可提问；需要作答时通过工具回答指定 `question_id`，不得用最终 Assistant 代替；允许没有答复。 |
| R05 | 提问持久接纳后立即返回问题 ID，提问者可继续工作，需要答案时再单独等待。新问题必须能唤醒正在等待的接收方。 |
| R06 | 通知与问题均不阻塞双方任务正常完成；发送立即返回，只有主动调用等待工具才等待。等待超时不自动撤销问题，晚到答案仍归原问题事务。 |
| R07 | 主会话当前任务所属的子任务未结束时，主逻辑 turn 不得正常完成。子到主消息插入原 turn，不能凭物理执行结束另开父业务任务。 |
| R08 | 自然完成且空闲的合法目标可自动执行一次仅答疑，回答可选，一次辅助执行结束后返回空闲，原任务仍保持完成。 |
| R09 | 主到子或独立会话提问遇到明确暂停/停止目标时拒收，明确告知目标已停止；不静默排队恢复。 |
| R10 | 子到主为独立方向。`MainOnly` 只停止主执行而保留子代理时，允许子代理的问题自动恢复主会话处理，仍关联原父任务和 turn。 |
| R11 | 独立会话首版允许同项目查找、读取、提问和引导；跨项目需用户明确授权。父子归属与工具策略仍然有效。 |
| R12 | 临时记忆或提示到期后保留已经发送的历史正文，追加失效标记；压缩时排除失效内容，不逐请求删除或替换旧正文。 |
| R13 | 阶段进度等单向通知不要求回复，独立于任务启动、方向引导和问题；运行中收到消息后在下一合法边界自然插队。 |
| R14 | 代理通知、问题、答案和任务回报使用独立交互框，展示来源与目标，视觉上区别真实用户提示词。 |

2026-09-21 用户修订：R06 替代此前“发出的问题必须先获答或撤销才能结束”的规则。父任务等待所属子任务结束的 R07 保留；消息未结与业务任务完成分别管理。

“子任务结束”包括有明确结果的成功、失败或停止，不要求关闭可复用的会话或面板。`MainOnly` 的答疑许可不自动解除 Goal 暂停，也不授权新增业务任务。

## 四、设计选型与实现边界

1. **领域与表示分离。** 保存宿主拥有的类型化消息、来源和关联；统一信封只负责模型可见表示。动态提示选用固定 User 角色，协议差异集中处理工具、媒体、相邻消息合并及合法插入边界。
2. **两套生命周期。** 任务启动/引导/最终回报沿任务链；临时问答沿问题链。既有 TaskRuntime 管理父子树；服务内核负责独立会话目录、授权和跨会话投递，不能由任意目标 ID 绕开父子检查。
3. **持久事实优先。** 正式设计采用来源会话拥有协作操作和问题权威记录、目标会话拥有投递与消费记录的组织方式，复用 V1 的可靠修改与落盘回执。两份会话文档不假定具备跨文档原子事务，使用可恢复的待投递记录和幂等接纳衔接。
4. **索引不是第二份权威。** 运行时 mailbox、查询索引、界面缓存及唤醒通知均可重建；不能以它们的丢失宣布问题已消失。具体 V1 新事件、摘要和索引 Schema 由 P00/P01 查明现有基元后冻结，不能先写入无版本扩展。
5. **统一正常完成条件。** 服务层、Hook、V1 持久 turn 和子代理返回必须依据同一份任务归属与未结事项做完成判定。不得让界面显示等待而持久 turn 已经完成。
6. **分开任务与执行目的。** 正常任务执行、原 turn 内协作答疑、自然空闲目标仅答疑分别记录目的。实际模型和工具消耗照常计量，答疑不能冒充原子任务第二次完成或重复回报统计。

以上架构进入实施。若现有持久基元无法满足设计，在工作报告中记录精确差异、替代方案与选择理由后更新设计；不能以纯内存队列或多路径猜测代替。所有新增结构按当前单一契约实现，不加入历史兼容分支。

## 五、现有事实与必须处理的缺口

分析基于 `efc2d58c805448bb88b0d202a09ed2079378b7aa` 附近的当前脏工作树。相关模块有并行改动；实施前重查符号和调用链，不将研究行号视为固定版本接口。

| 缺口 | 现有依据与需要处理的内容 |
| --- | --- |
| 父 turn 的完成条件不一致 | `provider_v1_sink::accept_terminal` 调用 `SessionV1Handle::complete_successful_turn`；后者检查已有待回流记录，未同步检查仍运行的子任务。服务层另有 `AwaitingSubagents`。统一权威完成门，不能只增加界面判断。 |
| 缺少双向临时问答闭环 | 现有 mailbox Message 没有问题状态；子代理策略禁用通用 `ask` 等工具。补齐专用工具、状态和完整暴露链。 |
| 多目标等待会延迟问题处理 | 现有显式 `wait_agent` 有全目标满足条件。问题须独立于任务终态优先唤醒；普通 mailbox 通知还存在取走语义，不能承担问题权威存储。 |
| 发送回执丢失后的身份不稳 | 当前 inbox 入队时生成投递 ID。补齐副作用之前的稳定操作身份、可靠接纳、同键重试和状态查询。 |
| 主会话停止存在模式差异 | `StopConversationRunMode` 明确存在 MainOnly 与 MainAndSubagents。停止规则、父消息路由与答疑恢复必须共同处理这一区别。 |
| 动态信息前置或重复 | TTL 指引前移、Plan 请求层与历史双来源、VMM 差量和环境前置 User、非 V1 整包 System 等均需逐源迁移。 |
| 压缩与尾段加载不足以表达新问答 | 更新严格 V1 Schema，增加权威摘要和精确恢复；不能期待模型摘要保存 ID 和路由，不实现历史格式迁移。 |

这些是静态事实或静态风险；本轮没有复现运行故障或验证缓存计量。

## 六、完整工作分解

### P00：冻结事实边界与落盘基元

- [ ] 记录实施起点的提交、脏文件所有者和当前资源版本；隔离本任务修改范围。
- [ ] 核实父任务、逻辑 turn、物理 API、执行代际、项目权威身份的唯一来源，建立字段来源表。
- [ ] 核对普通索引会话与嵌入子任务的实际存储 locator；索引失败或定位缺失时返回明确状态，不通过猜目录、标题或其他候选路径绕过。
- [ ] 沿 V1 事件、元数据、尾段加载、发布与恢复确认新增协作事实的写入组织；确认来源文档关闭后仍可提交答复回执的合法修改入口。
- [ ] 对齐来源/目标归档和删除契约：未结协作阻止来源物理删除，归档保留既有问答的控制面结算；明确删除后的终态标记和迟到操作处理。
- [ ] 查清 `transient_prefix` 实际消费者；未找到则定位缺失点，不把它误列为顶部合并问题。
- [ ] 核实所有注册 Profile 与实际可达生产路由；确认新工具名称没有冲突。
- [ ] 冻结事件/元数据 Schema、投影版本、存储索引和当前契约恢复清单；契约差异记录选择理由并修订正式设计后实施。

交付物：当前字段来源表、权威写入调用链、最终 Schema 变更表、实际路由清单。P00 未闭合的事实不得以猜测进入产品代码。

### P01：领域契约与身份

- [ ] 定义任务启动、方向引导、问题、答案、撤销、上下文更新与失效的类型化语义。
- [ ] 增加独立单向通知语义与 `send_notification` 工具，通知没有答复义务，不伪装成任务引导或问题。
- [ ] 增加稳定操作标识、问题 ID、投递 ID、来源/目标关联、逻辑任务绑定、版本及幂等冲突规则。
- [ ] 区分真实用户输入、宿主生成字段和不可信正文；定义上下文可见来源摘要及正文转义。
- [ ] 区分任务终态、问答结算、投递进度、执行状态，禁止一个通用状态字段承担全部含义。

### P02：可靠投递、查询与恢复

- [ ] 来源持久记录与待投递事项在同一可靠修改中提交，落盘后才返回接纳回执。
- [ ] 目标按投递 ID 幂等接纳，保存原 turn 或仅答疑绑定；发送侧回执与目标已读分别记录。
- [ ] 答案和撤销以问题权威记录串行结算；通知、目标展示与原调用回执均可重复修复。
- [ ] 重启重建未结问题、待投递事项和必要索引；覆盖仅加载活动尾段的情况。
- [ ] 提供按稳定 ID 和修订查询的服务能力；记录失败与不可确认状态，禁止未知结果盲重发。

### P03：父子完成门与运行目的

- [ ] 在唯一权威准入内协调子任务预留、开始、终态、待回流、问题接纳及父 turn 完成。
- [ ] 问题与通知不进入业务正常完成阻塞条件；保留未结事务用于查询、迟到投递、恢复及删除保护。
- [ ] 模型提前输出最终文本时保留文本和未完成状态，不先发布任务完成再补救。
- [ ] 增加原 turn 内答疑和自然空闲仅答疑的执行目的及结束入口；答疑结束不重复 SubagentReturn、不触发原 Goal 自动续轮。
- [ ] 落实 MainOnly 的子到主恢复例外；MainAndSubagents 取消后的迟到消息不得重启旧任务。
- [ ] 停止、失败、关闭、归档、删除及代际替换均形成明确状态，不将历史“已停止”与自然空闲混同。

### P04：统一消息信封与中立投影

- [ ] 在中立边界区分顶部基线、流内宿主事件、真实用户、助手、原生工具和媒体。
- [ ] 实现版本化功能标签、确定性转义、大小约束和逻辑事件到物理消息/内容块的投影记录。
- [ ] 稳定顶部一次说明信封语义；动态事件按时点追加，禁止反向修改已发送消息。
- [ ] 以请求/turn/工具调用身份接收模型结果；不根据模型自由文本的标签寻址或执行操作。

### P05：逐项迁移动态生产者

- [ ] TTL 隐藏指引从历史前缀改为发生时点的事件；有效期在原逻辑 turn 边界计算。
- [ ] Goal/Plan 保留强类型宿主状态和限制，模型镜像改为流内事件；移除 Plan 请求级重复副本。
- [ ] VMM 基线与刷新差量分开；差量、Persistent 块和环境变化在触发时追加。
- [ ] 审计锚点注入、当前用户文本改写、系统 Hook、工具说明、代码库路由、压缩/摘要用途提示和继续提示。
- [ ] 非 V1 与 ExcludedNonSession 不再将全部动态层渲染成首条 System；单次请求用途明确独立基线。
- [ ] 普通过期追加一次带版本的失效事件；压缩时排除失效指令，保留原始审计记录。

### P06：全部生产协议的结构兼容

- [ ] 沿真实生产编码链验证 Codex 原生、标准 Responses、Chat、Anthropic、Gemini 各入口；注册但不可达的 Profile 单独记账，不宣称贯通。
- [ ] 基线继续走原协议顶部入口；动态宿主节点只走 User，不建立 Developer/System 动态选路阶梯。
- [ ] 保持原生工具调用和结果配对、内容块顺序、相邻 User 合并、媒体引用及工具续轮要求。
- [ ] 不合法的插入点延期到下一合法物理边界；不得等待整个业务任务最终回答才投递临时问题。
- [ ] 对漏入顶部的动态事件、未知信封版本和无法保真的结构返回明确错误，不静默换协议或探测降级。

### P07：双向临时问答与等待

- [ ] 实现发送即返回、按 ID 查询、单独等待、工具回答和显式撤销。
- [ ] 回答工具向回答方返回提交回执；答案另交提问方。原提问工具结果不得事后改写。
- [ ] 真实等待工具可接收原生答案结果；无等待工具时通过流内答案事件交付，记录交付游标避免重复新通知。
- [ ] 任一需要回答的问题都能使多目标任务等待或问题等待返回，且不被计作任务完成。
- [ ] 等待不占执行/事务锁；双向互问可继续调度，依赖循环和无法回答明确暴露。
- [ ] 停止拒收、回答与撤销竞争、已接纳后目标停止、通知丢失等均按设计结算。

### P08：父子工具完整暴露

- [ ] 保留现有启动/排队/引导的业务入口，明确内部语义映射及任务最终回报绑定。
- [ ] 现有 `send_message(delivery_mode=queue)` 绑定独立排队任务及其最终回报，`interrupt` 绑定原活动任务的引导；不因复用子会话而混淆两次任务的 final。
- [ ] 注册专用问答工具与参数 Schema，补齐桥接、模式可见性、策略、准备、执行、流事件和结果投影。
- [ ] 子代理获准询问其真实父会话、回答自己的问题收件；不能通过开放通用人类 Ask 绕过角色限制。
- [ ] 更新稳定的父子身份说明与工具说明，区分工具接纳回执、问题答案和任务最终回复。

### P09：独立会话协作与权限

- [ ] 服务目录提供同项目有限摘要和有界读取，不向模型暴露原始完整工作台或任意路径读取。
- [ ] 为已有独立会话提供启动/引导、提问、等待和结果查询入口；绑定真实会话 ID 与来源操作。
- [ ] 项目归属由宿主确定；跨项目授权须记录主体、来源、目标、动作范围、修订和撤销。
- [ ] 目录、读取、接纳、实际正文交付和回复都核对授权；失效授权返回明确结果，不静默扩权。
- [ ] 普通会话不伪装成子代理，父子会话也不能绕到独立会话通道逃避归属检查。

### P10：压缩与新契约恢复

- [ ] 原始问答/授权事实不依赖模型摘要；压缩后重建仍有效状态、未结问题及必要的当前身份。
- [ ] 新事件和元数据采用单一当前版本；新契约的封口历史与活动尾段均能恢复相同问答状态，不实现旧格式迁移。

| A12 | 来源提交后崩溃、目标接纳后崩溃、答复提交后通知丢失、落盘失败、重启恢复均无静默丢失和虚假成功。 |

| A18 | 子代理发送阶段通知后继续工作；主代理在合法边界收到通知，不产生回答义务或新任务；通知、问答和真实用户输入采用清楚区分的交互框。 |
