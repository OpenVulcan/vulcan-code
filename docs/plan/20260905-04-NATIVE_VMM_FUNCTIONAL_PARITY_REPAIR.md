### 1.2 什么才算能力对齐

每一项必须同时满足：

1. **语义层**：输入内容、选择范围、算法阶段、输出含义、业务状态变化与外置基线一致，或有明确且可验证的增强。
2. **接入层**：原生实际运行入口确实调用该实现，而非只在参考存储、测试驱动或未使用函数中存在。
3. **使用层**：应由用户控制的功能有可用界面，应由 AI 使用的功能完成工具注册、参数构建、执行及结果投影。
4. **验收层**：确定性行为有外置参考样本和原生结果对比；真实模型效果有独立评估，不能用静态测试代替。

“返回成功”“有同名字段”“有两级 LLM 调用”“保留了默认常量”均不足以独立证明功能对齐。

## 2. 已冻结的产品与架构边界

1. 部署方式全局二选一：原生或外置 gRPC。切换保留另一模式数据与配置；不自动迁移、清空或删除。
2. 原生代码由 VulcanCode 的 Rust 工作区独立维护。沿用现有 `vulcan-memorymesh-core-*` 模块和宿主适配层，不恢复独立 VMM 服务、FFI、Go SDK 或 `vmm-local`。
3. 原生使用宿主管理的 VLDB，数据位于 `.vulcan/code/vmm`，SQLite 与 LanceDB 分离。知识库、VCE、VMM 只共享宿主能力，不共享业务表和索引。
4. 原生只有固定用户 ID 1，但必须保留用户画像；一级记忆项目可以有多个，并分别维护项目画像。
5. 默认记忆项目 ID 1 在创建结构时建立、禁止删除、允许改名。兜底依据 ID，不依据 `default` 名称。
6. 新项目默认绑定固定记忆项目；可改为按 VulcanCode 项目 tag 自动创建。全局默认修改只影响后续自动绑定，不回写已有绑定。
7. 启用时列出未绑定项目，默认按全局规则生成方案，允许逐行创建并绑定或绑定已有项目。新增目录成功后展示实际绑定结果；失败明确提示，允许手动重绑。
8. 每个会话写入唯一归属项目。连带查询只扩大读取范围，不能把写入或覆盖权限扩散到被连带项目。
9. 项目迁移是移动内容及归属关系，不复制、不自动删除源项目；冲突会话直接加 `-1/-2` 后缀，向量改归属、不重新嵌入。项目画像随归属移动，个人画像不做项目迁移。
10. 项目清空删除项目级信息，包括项目画像、Session、Turn 与关联记忆，保留个人画像。项目删除前准确列出绑定影响；ID 1 不可删除。
11. 外置保留可配置的 `vulcan/space` 自动创建前缀，也允许绑定规则外的完整三节点项目。外置查询范围、迁移和维护逻辑由其服务负责。
12. 所有 VMM 分析模型强制关闭思考，界面不显示思考档位；结构化正文与思考内容分离。继续使用共同宿主 AI 契约，不创建 VMM 专用 Provider。
13. 提示词、PII、Noise 用户修改写入 `.vulcan/code/vmm/config` 对应目录，不覆盖权威资源；分类、有效文件单视图、高亮编辑、默认锁定、解锁及保存确认继续保留。
14. 不增加旧版数据清空、旧产品兼容迁移或自动重放历史对话逻辑。开发环境旧数据由用户按既有约定自行处理。

## 8. 验收策略

### 8.1 三层证据

1. **确定性业务对照**：对同一合成数据，运行外置规则与原生规则，比较中间载荷、候选集合、状态变化和最终对象。时间、ID 和批准的原生项目映射统一归一；不能归一掉实际语义差异。
2. **宿主真实装配验收**：使用真实宿主 VLDB/SQLite/LanceDB，经过 NativeVmmClient、Driver、服务动作和公开协议；AI 可用可控测试 Provider 返回确定结果。它证明集成链，不证明真实模型提炼质量。
3. **真实模型质量验收**：使用用户已配置并允许测试的同一模型、相同关闭思考设置与结构化模式，比较中英文、多轮指代、直写去重、用户画像和项目画像。单独记录调用消耗及实际结果；没有运行时明确标记待验收，不用模拟调用冒充。

### 8.2 核心场景清单

| 场景 | 关键断言 |
| --- | --- |
| 用户陈述喜欢西瓜和葡萄，随后询问饮食偏好 | 提炼输入保留事实；普通记忆与用户画像按规则生成；后续检索和画像可见 |
| 三轮以上同 Session 指代与澄清 | PreCheck 的 DETAILS/RAW_TURN 窗口和 PostAction 已提炼参考窗口正确，不跨 Session |
| 主动写入后多轮自然对话 | 已观察直写不持续重复发送，新直写只进入正确窗口 |
| 中文查询只命中摘要 | 宿主全文通道真实命中，融合后的结果可解释 |
| 高分语义近似但关键词相反 | L2 仍依据真实内容和情境反驳判断，不用高分代替采纳 |
| 大代码、日志和自然语言事实混合 | 机器文本按基线折叠，有价值事实保留，实际业务载荷预算正确 |
| 前后各三轮详情与迁移后查询 | 准确邻接 ID、稳定 Memory/Turn ID、项目与 Session 边界正确 |
| 原生项目 A 归属 A、连带 B/C | 召回可见 B/C，写入与替代只有 A 授权；详情不越权 |
| 用户画像、项目画像自然语言新增/修改/删除 | 两类目标独立，Full/Split 不重复，项目维护不误删个人画像 |
| 归档、回收、恢复、永久清除、重新启用 | 状态表全部合法转换；没有隐式聊天重发或自动复活 |
| 按 Turn 回收且画像独立维护 | 预览集合和执行集合一致，两类画像均保留，不接受隐含画像删除字段 |
| 默认绑定、补绑、改名、项目迁移与清空 | ID 绑定稳定，ID 1 不可删除，新的水位/状态/全文索引同步 |
| 全局与项目策略分别修改 | 当前有效值来源正确，下一命令生效，已开始命令保持冻结 |
| 自动维护与手动维护 | 使用相同有效保留策略；热窗口、画像到期、闲置 Session 和回收站期限符合设置 |
| 原生/外置来回切换 | 配置与数据保留，页面只显示当前模式支持项，调用路径明确 |
| 老会话编辑第一条与新会话首次发送 | 规范用户消息 ID 仍准确；新增会话管理不能破坏已修复的提示词编辑流程 |

### 8.3 质量指标与停止条件

- 确定性场景不得存在未解释差异；批准的差异逐条登记原因和测试，不用统一“原生化”标签豁免。
- 真实模型评估冻结同一数据集、事实标签、模型与参数，记录结构化输出有效率、必需事实召回、错误新增、画像误归属和重复提炼。
- 不捏造“99.9%”测试结论。真实模型样本不足时不宣布达到该成功率；出现原生独有退化样例必须定位并修复或经用户确认，不能靠增加重试掩盖。
- 不以确定性测试全部通过替代真实链路或功能入口验收。
- 已提交修改同样纳入最终审核；每轮记录逐文件覆盖、发现和证据。新发现导致连续清洁计数清零。
