# 宿主推理调度注册约定

## 权威来源

公共类型位于 `crates/vulcan-ai-contract/src/inference.rs`，能力注册与执行校验位于 `crates/vulcan-service-kernel/src/internal_ai.rs`，队列与预算位于 `crates/vulcan-service-kernel/src/configured_inference.rs`。以当前源码和测试为准。

## 授权与调度分别声明

`InferenceCallerContext.usage_scope` 仍决定模型路由的授权用途，必须与配置路由严格一致。新增的 `scheduling_class` 只决定受信内部调用的执行队列，不授予模型、消费者配置档、操作或会话访问权限。

| 调度类别 | 行为 | 准入约束 |
| --- | --- | --- |
| `ByUsageScope` | 保留原用途范围对应的队列 | 保留全部既有用途与会话身份校验 |
| `InternalQuery` | 内部查询使用前台容量 | 仅宿主持有的内部授权用途可注册，不允许外部服务或交互用途借此改写授权 |

类别仅存在于非序列化的宿主调用方上下文，不加入工具参数、模型请求、模型配置或外部服务请求正文。宿主注册表保存完整调用方上下文，复制能力句柄后篡改类别会被拒绝。需要不同类别时，由宿主签发独立注册身份，不修改已签发句柄。

## 语义引擎接线

- 同一个项目运行时注册索引能力和查询能力，共用一个消费者配置档、模型路由、调用方身份与预算。
- 文档向量使用索引注册；查询向量、查询改写及候选重排使用查询注册。选择依据为已定义的核心调用目的，不解析工具提示词来判断优先级。
- 查询注册标识为该运行时索引注册标识加 `:query`。不同运行时以唯一运行时标识隔离，旧读取方与后继索引运行时不会相互注销。
- 两份能力均验证同一冻结向量契约；激活失败清理已注册能力，拆卸尝试注销两份能力并报告失败。模型兼容确认与重建规则不因调度分流改变。
- 记忆、知识库、模型测试等现有调用方当前使用 `ByUsageScope`，不在此次接入中改变其业务调度。未来需要查询／后台分流时复用同一公共规则，另行核实调用目的、注册生命周期及预算。

## 容量、公平性与取消

本次不提高原总并发、后台并发或外部服务并发上限。内部查询使用已有前台容量，同时保留调用方并发、输入、速率、截止时间和取消预算。即使存在后台等待队列，后台槽已满时也不能用公平性让行规则阻塞空闲的前台容量；槽位释放后，后台队首仍获得有限等待的推进机会。

## VCE 异步向量 Batch

VCE 的首次初始化与显式全量重建可以在冻结模型绑定明确声明 `embedding_batch` 时使用供应商异步
Batch。能力快照包含有效任务数、请求项、请求/结果字节、文件配额、接口频率、轮询间隔、取消及清理
规则；VCE 必须先生成并持久化全部源码节点、逻辑向量批次、远端任务范围和精确负载摘要，再开始上传
或提交。增量更新、查询向量、查询改写和重排不走该通道。

文件型 Batch 的上传与任务创建是两个独立状态：`uploading` 期间进程中断会保留“上传结果不确定”，
不能自动重传；已持久化文件 ID 后的 `submitting` 中断会进入“提交结果不确定”，并仅通过供应商支持的
精确文件 ID 与任务元数据查询恢复。已持久化 Batch ID 的任务只轮询原任务。每次状态观测将供应商
`request_counts` 投影到 VCE 作业进度；取消会尽力取消全部已提交任务，但只保存供应商实际返回的状态。

远端完成后先按现有逻辑批次边界逐条持久化向量，再标记远端任务成功并清理临时输入文件。这样页面
刷新和进程重启都可以从稳定作业 ID 继续观察或恢复，不会因内存状态消失而新建远端任务。供应商未
声明 Batch、模型不在精确绑定范围内或当前操作不是初始化/重建时，保持原同步行为。

## 必须保持的验证

1. 后台向量响应持续暂停时，前台查询经实际共同服务完成，而不是提前结束后台工作。
2. 受信类别不能扩展路由授权，伪造能力句柄不能提升类别，注销查询注册不影响其他运行时。
3. 保持总容量上限，超时或取消清理排队票据及许可。
4. 完整聊天实际消费语义工具与文件工具结果；更新发布前后分别读取正确检查点。

调度专项和真实本地协议组合验收已经通过；这不替代整个语义方案的最终完整审核或其他消费者未来接线的独立验证。
