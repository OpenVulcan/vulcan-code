Vulcan Code 0.1.5 では、モデルごとに既定の圧縮ウィンドウを設定できるようにし、デスクトップアプリを 1 つのウィンドウで起動するようにし、更新を自動確認する間隔を選べるようにしました。

### コンテキストウィンドウ

```ui-checklist
ok | モデルごとの既定値 | 有効な会話モデルごとに、新しいセッションの既定の圧縮ウィンドウを設定できます：システム既定、モデルに従う、固定の段階、またはカスタムサイズ。既存のセッションには影響しません
ok | カスタムウィンドウ | カスタムサイズはトークン数、または千を表す K（例：235K）で入力でき、100K 以上でモデルのウィンドウ以下です。入力欄の横のウィンドウ選択からもカスタムサイズに切り替えられます
ok | モデルの切り替え | セッション中にモデルを切り替えると、切り替え先モデルの既定ウィンドウを使うか確認し、承認するまで何も変わりません。現在のウィンドウが切り替え先モデルに収まらない場合は、切り替えを拒否せずモデルに従う設定に戻ります
ok | ターミナル画面 | TUI の設定でもモデルごとに既定ウィンドウを設定できます
```

### 更新

```ui-checklist
ok | 確認間隔 | 更新を自動確認する間隔を選べます：1 時間ごと、6 時間ごと、12 時間ごと、または毎日。既定は 6 時間ごとで、変更は再起動なしで反映されます
ok | ソフトウェア更新ページ | 設定のソフトウェア更新ページを並べ替えました：まず現在のバージョンと確認・修復、次に更新の設定、最後に見つかった更新と、それに含まれる各バージョンの更新内容を新しい順に表示します。更新ダイアログも同じバージョン一覧を使います
ok | Linux での再起動 | Linux でデスクトップアプリから起動した Core が、更新後に「再起動中」のまま止まらず正しく再起動します
```

### デスクトップアプリ

```ui-checklist
ok | 1 つのウィンドウで起動 | 起動用の別ウィンドウは開かなくなりました。ワークベンチウィンドウが起動画面と実際の起動段階や失敗の内容を表示し、Core の準備ができるとそのまま画面を開きます
ok | 起動時の外観 | 起動画面は前回使った言語と外観を引き継ぎます。初回起動はシステムに従います
ok | アプリのアイコン | Linux のドックと macOS の Dock に汎用アイコンではなく Vulcan Code のアイコンが表示されます。アプリをもう一度開くと起動中のウィンドウが前面に出ます
```

### 修正

```ui-checklist
ok | 埋め込みモデル | 出力次元を調整できる埋め込みモデル（例：Qwen3-Embedding-8B、32〜4096 次元）が、すべての応答を拒否しなくなりました
ok | 回答コンポーネント | トーン未指定のコールアウトと 4 列の所見行が、コードブロックに戻らず正しく表示されるようになりました。WebUI と TUI の両方で修正されています
```

### インストーラー

```ui-checklist
ok | macOS のワンライナーインストール | macOS で curl のパイプ経由でインストールスクリプトを実行しても、キーボード入力を読み取れるようになりました
ok | macOS アプリ | インストーラーが作成する macOS アプリにアイコンが付き、完了時にアプリの場所を表示します
ok | Linux のメニュー項目 | Linux のメニュー項目が実行中のウィンドウと対応し、ドックに固定したアイコンからアプリを開けます
```
