Vulcan Code 0.1.12 讓需要重新安裝的更新也在應用程式內完成，並修正了 macOS 視窗按鈕與圖示，以及部分供應商拒絕標題與驗證請求的問題。

### 更新到此版本

```ui-checklist
ok | 增量更新 | 從 0.1.8 至 0.1.11 更新時只下載有變化的檔案；更早的版本仍以完整更新的方式安裝
ok | 在應用程式內完成重新安裝 | 今後需要重新安裝的更新不再轉到官網下載：只下載有變化的檔案，已安裝的瀏覽器、Electron、Node 等基礎資源直接沿用，重新啟動後由安裝程式自動完成
ok | Windows 安裝版 | 由 Windows 安裝程式安裝的副本，今後的此類更新使用小型簽署更新套件，不再下載完整安裝程式
```

### 介面

```ui-checklist
ok | macOS 視窗按鈕 | 只保留系統的視窗按鈕，不再重複顯示自繪的最小化、最大化與關閉按鈕，綠色按鈕恢復系統的並排與全螢幕選單
ok | macOS 圖示 | Dock 與未執行時的應用程式圖示與其他應用程式大小一致
ok | 模型服務帳戶卡片 | 卡片有了隨介面縮放的最小寬度，額度列不再擠成多行
ok | 設定精靈 | 已登入 OpenVulcan 帳戶且尚未設定判定模型時，判定步驟預設選取雲端判定模型；確認前不會儲存
```

### 模型與供應商

```ui-checklist
ok | 請求修正 | 工作階段標題、設定中的模型驗證與專職助手的提示詞草擬現在帶上快取範圍，OpenCode Go 不再回傳 400，Codex Responses Lite 也不再拒絕這些請求
ok | 雲端平台分類 | CommandCode、OpenCode Go、Open Design、OpenRouter 與 TokenRhythm 歸為雲端平台；共用的模型資訊依官方、雲端平台、中轉的順序採用
ok | 核心模型清單 | 模型本身的能力與上限統一記錄在核心模型清單中，由各供應商規則繼承；供應商清單狀態頁會標出繼承自核心清單的欄位
```
